개요

AI Kiosk WebApp은 음성 대화로 카페 메뉴를 주문할 수 있는 키오스크용 React 단일 페이지 애플리케이션입니다. 사용자는 메뉴 화면에서 마이크 버튼으로 말을 걸어 "아메리카노 한 잔" 같은 자연어 주문을 하거나 메뉴를 질문할 수 있고, 백엔드 LLM 에이전트 서버가 의도를 해석해 응답을 돌려주면 앱이 그 내용을 음성으로 안내합니다. 음성 입력(STT)부터 LLM 질의, 음성 출력(TTS), 장바구니, 결제(카드 삽입), 영수증 출력, 주문 완료까지 키오스크 주문 플로우 전체를 화면으로 제공합니다.

대상 단말은 삼성 갤럭시 탭 S8 태블릿으로, 924x1480 고정 해상도의 세로형 키오스크 형태로 운용됩니다. 입력 방식은 터치와 음성 두 가지이며, 앱은 Android 태블릿의 WebView 안에서 구동되도록 설계되어 있습니다. 실제로 음성 인식 모듈은 브라우저 마이크를 직접 쓰는 경로 외에 window.android.requestSpeechToText 등 Android WebView 네이티브 브리지를 호출하는 경로를 함께 갖추고 있어, 단말의 네이티브 STT 기능에 위임할 수 있도록 구성되어 있습니다.

한국어와 영어 2개 언어를 지원하며 기본 언어는 한국어입니다. 음성 합성은 KT GiGA Genie TTS와 Azure Speech TTS를 설정으로 전환할 수 있고, 음성 인식은 Microsoft Azure Cognitive Services Speech SDK를 사용합니다. 다국어 문구(i18n)는 구글 스프레드시트에서 동기화해 생성하는 운영 도구를 갖추고 있습니다.

사업 맥락
AX/DX Client Team이 TPI 대상으로 진행한 AI Kiosk 과제의 프런트엔드 파트입니다. Confluence Environment 문서 기준 대상 단말은 Galaxy Tab S8, 해상도 924x1480(Fixed), 입력 이벤트는 터치와 음성입니다. UI 라이브러리는 React이며 빌드 시스템은 Vite입니다(문서에는 테스트용 대안으로 Solid도 병기되어 있으나 본 저장소는 React로 구현되어 있습니다).

주요 기능

음성 주문 (STT)
Azure Speech SDK 기반 음성 인식으로 "아메리카노 한 잔" 같은 자연어 발화를 텍스트로 변환합니다. 연속 인식과 1회 인식(startSpeechRecognitionOnce) 두 방식을 제공합니다.
LLM 자연어 질의
queryManager가 kiosk.altimedia.com/api의 LLM 에이전트 서버에 질의해 주문 의도·메뉴 안내·일반 질문을 해석합니다. 현재 auto_query 경로를 사용합니다.
음성 안내 (TTS)
LLM 응답 메시지를 음성으로 합성해 재생합니다. 언어·설정에 따라 KT GiGA Genie TTS와 Azure TTS(ko-KR-SunHiNeural, en-US-JaneNeural)를 분기합니다.
Android WebView STT 브리지
브라우저 마이크 외에 window.android.requestSpeechToText 네이티브 브리지로 단말 STT에 위임하고 window.handleSTTResult 콜백으로 결과를 수신하는 경로를 제공합니다.
메뉴 카탈로그
Data.js에 커피·주스·티·벌크업(고단백) 등 카테고리별 메뉴와 옵션(온도·시럽 등)을 정의하고 메뉴 이미지를 glob으로 로드합니다.
주문 옵션 처리
온도(HOT/ICE)·블렌드·기타 옵션을 음성과 터치로 선택합니다. 옵션이 하나뿐이면 기본값을 자동 적용하는 등 음성 주문 로직을 보정합니다.
장바구니 · 매장/포장
cart-store로 담은 메뉴와 매장 식사/포장(Here/To-go) 여부를 관리하고 합계를 계산합니다.
결제 · 카드 삽입 시뮬레이션
결제 화면에서 카드 삽입·영수증 출력 단계를 PNG 시퀀스 애니메이션(usePNGSequence)으로 표현하며 주문을 마무리합니다.
STT 인식 보정(PhraseList)
메뉴명과 "아아", "뜨아", "한잔", "시럽 추가" 같은 카페 구어체를 Azure STT PhraseList에 등록해 한국어 주문 인식 정확도를 높입니다.
다국어 (i18n) 지원
i18next/react-i18next로 한국어·영어를 지원하며 기본 한국어, 폴백 영어입니다. 언어에 따라 STT 인식 언어와 TTS 음성이 전환됩니다.
미조작 타이머 · 도움말
메뉴 화면에서 일정 시간 미조작 시 도움말 팝업을 띄우거나 홈으로 복귀시키는 inactivity 타이머를 운용합니다.
볼륨 제어
VolumeManager·useAndroidVolume·volume-store로 단말 볼륨과 음성 안내 볼륨 레벨을 관리합니다.
세로 대화면 줌 보정
부팅 시 window.innerHeight / 1480 비율로 zoom을 조정해 924x1480 세로형 키오스크 화면에 레이아웃을 맞춥니다.
디버그 오버레이
Debug 모드(Config.js)와 Debugger 오버레이로 음성 상태·로그를 화면에서 확인합니다. 로그 레벨은 빌드 인자로 제어합니다.
릴리스 ZIP 패키징
release 모드 빌드 시 vite-plugin-zip-pack으로 산출물을 날짜·버전·네트워크 정보가 담긴 ZIP으로 묶어 키오스크 배포에 사용합니다.

아키텍처 · 모듈 구조

계층 · 외부 연동

화면 계층(page/component)은 zustand 스토어를 구독하고, 음성/LLM 매니저는 앱 전역(window)에서 동작합니다. 외부 연동은 세 갈래입니다. 첫째, LLM 에이전트 서버(https://kiosk.altimedia.com/api/)에 주문·질의 요청을 보냅니다. 둘째, 음성 인식은 Azure Cognitive Services Speech SDK(리전 koreacentral/swedencentral)를 사용하거나 Android WebView 네이티브 브리지에 위임합니다. 셋째, 음성 합성은 KT GiGA Genie OpenAPI(openapi-de.gigagenie.ai)의 TTS 엔드포인트 또는 Azure TTS를 사용합니다. 다국어 데이터는 빌드 외 운영 단계에서 구글 스프레드시트와 동기화됩니다.

보안 유의
.env와 .spreadsheet.env에 Azure Speech API 키, KT 클라이언트 시크릿, 구글 서비스 계정 정보 등 실제 자격증명이 포함된 채 저장소에 커밋되어 있습니다. 키 회수·로테이션 등 형상 관리에 유의가 필요합니다.

핵심 동작 흐름

1) 부팅 · 초기화 시퀀스

  1. 로그/i18n 초기화main.jsx가 빌드 인자에 따른 로그 레벨을 설정하고 i18n(ko 기본)을 로드합니다.
  2. STT PhraseList 등록Data.js의 메뉴명을 ko/en으로 추출해 Azure STT PhraseList에 등록하고, "아아·뜨아·한잔·시럽 추가" 등 구어체를 보강합니다.
  3. 화면 줌 보정window.innerHeight / 1480 비율로 body zoom을 조정해 924x1480 세로형 키오스크 레이아웃에 맞춥니다.
  4. 매니저 초기화App.jsx가 QueryManager·AzureSTTManager·LLMManager·KT/Azure TTSManager·VolumeManager를 초기화해 window에 노출합니다.
  5. 홈 진입createHashRouter가 /(Home)로 진입하고 사용자 조작을 대기합니다.

2) 음성 주문 처리 흐름

  1. 발화 캡처(STT)메뉴 화면에서 마이크 버튼을 누르면 Azure STT(또는 Android 브리지)가 발화를 인식해 텍스트로 변환합니다.
  2. STT 결과 보정STTModifier로 마침표 제거 등 결과를 정제하고 voice-state-store에 반영합니다.
  3. LLM 질의LLMManager.querySequence가 이전 대화와 신규 발화를 합쳐 auto_query 엔드포인트로 LLM 에이전트 서버에 POST합니다.
  4. 의도 반영응답에 따라 메뉴·옵션을 장바구니에 반영합니다. 옵션이 하나뿐이면 기본값을 자동 적용합니다.
  5. 음성 안내(TTS)응답 message를 TTSManager.handleTts로 합성합니다. 한국어는 KT TTS(기본), 영어/설정 시 Azure TTS로 재생합니다.

3) 결제 · 완료 흐름

  1. 장바구니 확인/purchase/cart에서 담은 메뉴와 매장/포장(Here/To-go) 여부, 합계를 확인합니다.
  2. 결제 진행/purchase/pay에서 결제를 시작하고 /purchase/card로 카드 삽입 단계를 안내합니다.
  3. 시퀀스 애니메이션usePNGSequence로 카드 삽입·영수증 출력 PNG 시퀀스 애니메이션을 재생해 진행 상태를 표현합니다.
  4. 영수증 · 완료/purchase/receipt 영수증 출력 후 /complete로 이동해 주문을 마무리하고 홈으로 복귀합니다.

빌드 · 실행

빌드/실행은 모두 package.json의 npm 스크립트와 Vite 기반입니다. 락파일은 .gitignore로 제외되어 있어 의존성 설치가 선행되어야 합니다.

# 의존성 설치
npm install

# 개발 서버 (vite serve)
npm run serve

# 빌드 후 미리보기 (호스트 노출)
npm run preview          # vite build + vite preview --host
npm run preview-nolog    # 로그 레벨 INFO로 빌드 후 미리보기
npm run preview-rel      # release 모드 빌드 후 미리보기

# 릴리스 빌드 (production, 로그 INFO, 네트워크 Prod, dist → release/*.zip)
npm run release          # vite build --mode release -- log=false live=true

# 린트
npm run lint

# i18n 다국어 JSON 생성 (구글 스프레드시트 동기화)
npm run i18n             # node --env-file=.env.spreadsheet spreadsheet.js

빌드 인자 동작은 vite.config.js에 정의되어 있습니다. log=false → APP_LOG_LEVEL=INFO, log=true → DEBUG이고, live=true → APP_NETWORK=Prod, live=false → Stag입니다. mode === "release"일 때 CSS 인라인/압축과 에셋 청크 분리 후 vite-plugin-zip-pack으로 release/<날짜>_<APP_NAME>_<APP_VERSION>_<APP_NETWORK>_<APP_LOG_LEVEL>.zip 산출물을 생성합니다.

base: "./" 및 no-crossorigin 플러그인으로 file 프로토콜/크로스오리진 제약 환경(키오스크 WebView)을 고려한 산출물을 만듭니다. 클라이언트에는 APP_ 프리픽스 환경변수만 주입됩니다(envPrefix: "APP_").
