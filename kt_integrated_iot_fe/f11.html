권한 기반 사이트 전환 제어

SiteGuard·checkPermission이 사용자 권한 레벨(hasRole)에 따라 사이트 간 전환을 판정합니다. 부적합 접근 시 WebSocket을 해제하고 세션을 정리한 뒤 로그인으로 이동합니다.

기능 개요

사용자 권한은 USER_ROLES 5단계입니다. 인덱스 0(서비스 고객)부터 4(플랫폼 관리자)까지이며, hasRole(targetLevel)이 세션 사용자(user.userRoleId)의 권한 인덱스가 목표 레벨 이상인지 판정합니다. 즉 hasRole(4)는 플랫폼 관리자, hasRole(3)은 서비스 관리자 이상을 의미합니다.

SiteGuard는 라우팅 최상위(/:site)에서 먼저 URL의 site가 ALLOWED_SITE_PATHS에 있는지 확인합니다. 다음으로 현재 세션 사이트(currentSite)와 이동 대상 사이트(target)를 checkPermission에 넘겨 전환 가능 여부를 판정합니다. 같은 사이트로의 이동이거나 대상이 없으면 항상 허용합니다.

checkPermission 규칙은 다음과 같습니다. 플랫폼 관리자(hasRole(4))는 모든 전환을 허용합니다. 서비스 관리자(hasRole(3))는 Air Map ↔ 과천, SafeMate 4종 상호 간 전환만 허용하고 그 외는 거부합니다. 나머지 권한은 다른 사이트로의 전환을 허용하지 않습니다. 판정이 부적합(!isValidAccess)이면 useEffect에서 WebSocket을 disconnect()하고 sessionStorage.clear()한 뒤 /:urlSite/login으로 리다이렉트합니다.

설계 포인트
세션 정리와 WebSocket 해제를 부적합 접근 시 즉시 수행해, 권한 없는 다른 사이트의 실시간 채널·토큰이 남지 않도록 합니다. 보호 진입 자체는 별도로 ProtectedRoute가 세션 site.code 유무로 한 번 더 가립니다.

관계. SiteGuard가 checkPermission·hasRole로 전환을 판정하고, 부적합 시 WebSocket을 끊으며, 적합하면 ProtectedRoute 보호 진입으로 넘깁니다.

핵심 코드

src/routes/route.tsx — 권한 기반 전환 판정
const checkPermission = (prevSite, nextSite) => {
  if (!nextSite || prevSite.code === nextSite.code) return true;
  if (hasRole(4)) return true;                       // 플랫폼 관리자: 모두 허용
  if (hasRole(3)) {                                  // 서비스 관리자: 제한 허용
    if (prevSite.code === SITE_CODES.AIRMAP && nextSite.code === SITE_CODES.GWACHEON) return true;
    if (prevSite.code === SITE_CODES.GWACHEON && nextSite.code === SITE_CODES.AIRMAP) return true;
    // SafeMate 4종 상호 전환 허용 ...
  }
  return false;
};
src/routes/route.tsx — 부적합 시 세션·WebSocket 정리
const isValidAccess = checkPermission(target, currentSite);
useEffect(() => {
  if (!isValidAccess) {
    disconnect();              // STOMP 연결 해제
    sessionStorage.clear();    // 토큰/사이트/사용자 세션 정리
  }
}, [isValidAccess]);
if (!isValidAccess) return <Navigate to={`/${urlSite}/login`} replace />;
