기능 개요

세 게시판 도메인은 동일한 목록/상세/편집 패턴으로 구성됩니다. 공지(/notice → NoticeList/Detail/Edit), 자료실(/resource → ResourceList/Detail/Edit), 문의(/contact-us → ContactUsList/Detail/Edit + Reply)입니다. 데이터는 boardApi의 공통 게시판 엔드포인트(/bff/monitor/boards/*)와 도메인별 엔드포인트(boards/notice, boards/resources)를 사용합니다.

boardApi의 함수 시그니처는 (params, unitServiceCode?, config?: AxiosRequestConfig) 형태로 통일되었습니다. 인터셉터가 헤더를 주입하더라도 사이트 전환 직후처럼 세션이 아직 갱신되지 않은 시점을 대비해 호출부가 unitServiceCode를 직접 실어 보낼 수 있고, config로 React Query의 signal과 skipError를 함께 넘겨 화면 이탈 시 요청을 취소하고 삭제된 글 조회 같은 실패에 오류 팝업을 띄우지 않습니다. 목록·공지 목록의 startDate/endDate는 선택 파라미터로 바뀌어, 조회기간을 비우면 전체 기간을 조회합니다. 공지사항 목록·문의 목록의 기본 조회기간도 최근 1주가 아니라 빈 값([null, null])이며, 두 값이 모두 있을 때만 날짜 파라미터를 만들어 보냅니다.

캐시 키는 도메인별 queryKeys 모듈(noticeKeys·resourceKeys·contactUsKeys)로 모았습니다. 모든 키가 ['boards', 도메인, unitServiceCode, ...]로 시작해 사이트가 다르면 캐시가 절대 섞이지 않고, list·detail·edit·navigation·popup을 계층으로 나눠 CRUD 직후 무엇을 비울지 정확히 지정할 수 있습니다. 등록·수정·삭제 성공 시 목록·이전/다음 탐색 캐시는 removeQueries로 아예 제거하고(invalidateQueries는 오래됨 표시만 하고 데이터를 남겨 수정 폼이 저장 전 값으로 초기화되는 문제가 있었습니다), 상세·편집 캐시는 refetchType: 'none'으로 무효화만 해 방금 지운 글을 곧바로 다시 조회하지 않습니다. 삭제는 요청 전에 cancelQueries로 진행 중인 상세 조회를 먼저 끊습니다. 수정 폼은 isDetailFetching이 끝난 응답으로만 초기화해, 캐시에 남아 있던 값으로 먼저 채워진 뒤 최신 응답이 무시되는 일을 막습니다.

상세·편집에서 목록으로 돌아가는 경로는 pages/boardNavigation.ts가 담당합니다. 목록에서 상세로 들어갈 때 withBoardListHistory(searchParams)로 라우트 state에 히스토리 깊이를 심고, 상세에서 편집으로 한 단계 더 들어가면 advanceBoardListHistory(state)가 깊이를 늘립니다. 복귀 시 returnToBoardList()가 그 깊이만큼 navigate(-depth)로 되돌아가 브라우저 뒤로가기 이력이 어긋나지 않게 하고, 깊이 정보가 없으면 목록 경로로 replace 이동합니다. 목록 화면은 노출 개수·정렬을 바꾸면 page를 1로 되돌리고, 마지막 행을 지워 복원된 페이지가 전체 페이지 수를 넘으면 마지막 유효 페이지로 자동 이동합니다.

첨부 파일은 boardApi.uploadFile()/fileList()/downloadFile()/deleteFile()로 관리합니다. 업로드 UI는 공통 컴포넌트 CustomFile이 담당하는데, accept에 지정된 확장자 목록과 실제 파일 확장자를 대조해 허용되지 않으면 입력을 비우고 선택을 취소합니다. 용량은 limitSize를 초과하면 경고 모달(Alarm)을 띄웁니다.

자료실 편집(ResourceEdit)은 SMART GREEN 병해충 도감 성격의 확장 필드(영문명·기주식물·증상·병해충 발생 현황·방제 방법 등)를 다루며, 저장은 smartGreenApi.postResource()/putResource()(/bff/monitor/boards/resources)로 처리합니다. 대표 사진은 base64 인라인 전송이 아니라 파일 업로드로 먼저 파일 ID를 받은 뒤 thumbnailImage로 전달하는 방식이며, 수정 진입 시 확장 필드는 상세 응답의 extendData(snake_case 컬럼 english_name·host_plant 등)와 매칭해 채웁니다. 서버 응답 필드명이 extendedData가 아니라 extendData인 것이 확인되어 상세·편집 양쪽 참조가 정정되었습니다.

편집 화면은 기존 첨부를 보존하도록 보완되었습니다. 수정 진입 시 상세 응답의 fileId와 extendData.thumbnail_image를 existingFileId/existingThumbnailId로 잡아 두고, 새로 업로드하지 않으면 저장 payload에 그 값을 그대로 실어 보냅니다. 파일명은 boardApi.fileList(fileId)로 originalName을 조회해 CustomFile의 displayName으로 표시하고, 사용자가 첨부를 제거하면 기존 ID·파일명도 함께 해제합니다. 상세 화면(ResourceDetail)의 대표 사진도 URL 필드(logoImageUrl) 대신 extendData.thumbnail_image 파일 ID를 기준으로 fileList → downloadFile로 blob을 받아 URL.createObjectURL로 표시하며, 값이 바뀌거나 언마운트될 때 이전 object URL을 revokeObjectURL로 회수합니다. 목록(ResourceList)은 정렬·행 수 변경 시 이전 검색 상태가 잔류하지 않도록 page·rowCount·order·filter·keyword를 담은 새 객체로 검색 파라미터를 통째 교체합니다.

최근 KT 보안성 검증 반영으로 자료실에서 허용하지 않는 확장자 업로드 시 노출되던 alert 문구가 제거되는 등 첨부 처리 정책이 강화되었습니다. 문의(Q&A)는 운영자가 답변(Reply)을 등록하는 흐름을 포함하며, 문의 목록의 등록 버튼은 hasRole() 권한 판정으로 고객(서비스 고객) 계정에서만 노출되고 관제요원 이상 관리자 계정에서는 숨겨집니다. 문의 목록의 조회 버튼은 선택한 필터·정렬·조회기간을 초기화하지 않고 그대로 조회합니다.

공지사항에는 팝업 노출 기능이 추가되었습니다. 등록·수정 화면에 "팝업으로 표시" 체크박스가 생겨 popupYn을 registNotice/editNotice payload에 함께 보내며, 동시에 노출할 수 있는 개수는 MAX_POPUP_NOTICE_COUNT(3개)로 제한합니다. 편집 화면은 boardApi.noticePopupList()로 현재 팝업 대상 목록을 받아 수정 중인 글 자신을 제외하고 세어(otherPopupCount) 한도에 다다르면 체크박스를 막고 안내 문구를 띄웁니다. Home 진입 시에는 modal/notice/NoticePopup이 /bff/monitor/boards/notice/popup 목록을 등록 시간 최신순으로 정렬해 최대 3개까지 계단식(STACK_OFFSET 40px)으로 겹쳐 보여줍니다. 최신 공지가 화면 정중앙의 기준 카드가 되고 오래된 공지일수록 좌상단으로 밀려나며, 카드를 닫아도 언마운트하지 않고 visibility만 감춰 남은 카드가 재배치되지 않습니다. "오늘하루 보지 않기"는 게시글 단위 쿠키(noticePopupHide_<boardSequence>)를 그날 23:59:59 만료로 심어 처리하고, 첨부는 공통 DownloadButton으로 노출합니다. 이 버튼은 unitServiceCode를 fileList·downloadFile 헤더에 명시 전달하고 캐시 키도 ['files', unitServiceCode, fileId]로 사이트별로 분리하도록 정비되었으며, 아이콘 + 밑줄 텍스트로 그리는 variant="link" 표시 형태가 함께 추가되었습니다.

설계 포인트
확장자 검증을 업로드 공통 컴포넌트(CustomFile)에 두어 자료실·문의·기타 첨부가 동일한 보안 정책을 공유합니다. 검증 실패 시 입력 value를 비워 잘못된 파일이 폼에 남지 않게 합니다.

흐름. 목록·상세·편집 화면이 게시판 API로 글을 관리하고, 첨부는 CustomFile이 확장자·용량을 먼저 검증합니다. 대표 사진은 URL이 아니라 파일 ID이므로 상세·편집 모두 fileList로 실제 파일 항목을 찾아 표시하며, 저장 시에는 새로 올린 파일만 업로드하고 미변경 항목은 기존 ID를 그대로 전달합니다. 저장·삭제 후에는 목록 캐시만 제거하고 상세·편집 캐시는 재요청 없이 무효화한 뒤, 기록해 둔 히스토리 깊이만큼 되돌아갑니다. Home 진입 시에는 팝업 노출 공지가 최대 3개까지 계단식으로 표시됩니다.

const handleFileChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  const file = e.target.files?.[0] ?? null;
  if (!file) { setValue(null); return; }

  if (accept) {
    const allowedExt = accept.split(',').map((v) => v.trim().replace('.', '').toLowerCase());
    const ext = file.name.split('.').pop()?.toLowerCase();
    if (!ext || !allowedExt.includes(ext)) {
      e.target.value = '';      // 허용되지 않은 확장자 → 선택 취소
      setValue(null);
      return;
    }
  }
  if (limitSize && file.size > limitSize) { setOpen(true); /* 용량 초과 경고 */ return; }
  // ...
};

// 대표사진(extendData.thumbnail_image)은 파일 ID라 fileList → downloadFile로 blob을 받아 object URL로 표시
useEffect(() => {
  const thumbnailFileId = data?.extendData?.thumbnail_image;
  if (!thumbnailFileId) { /* 이전 URL revoke 후 null */ return; }

  let revoked = false;
  (async () => {
    const listRes = await boardApi.fileList(thumbnailFileId);
    const rows = listRes?.result?.rows ?? listRes?.rows ?? [];
    const fileItemSequence = rows[0]?.fileItemSequence;
    if (!fileItemSequence) return;

    const blobRes = await boardApi.downloadFile(fileItemSequence);
    const blob = blobRes?.data instanceof Blob ? blobRes.data : new Blob([]);
    if (revoked) return;
    const url = URL.createObjectURL(blob);
    setThumbnailUrl((prev) => { if (prev) URL.revokeObjectURL(prev); return url; });
  })();

  return () => {
    revoked = true;
    setThumbnailUrl((prev) => { if (prev) URL.revokeObjectURL(prev); return null; });
  };
}, [data?.extendData?.thumbnail_image]);

export const withBoardListHistory = (state: RouteState | undefined, depth = 1): RouteState => ({
  ...(state ?? {}),
  [LIST_HISTORY_DEPTH_KEY]: depth,
});

export const advanceBoardListHistory = (state: unknown): unknown => {
  const depth = getBoardListHistoryDepth(state);
  if (!depth) return state;
  return withBoardListHistory(asRouteState(state), depth + 1);
};

export const returnToBoardList = ({ navigate, routeState, listPath, listState }) => {
  const depth = getBoardListHistoryDepth(routeState);
  if (depth) {
    navigate(-depth);   // 뒤로가기 이력을 어긋나지 않게 되감는다
    return;
  }
  navigate(listPath, { replace: true, state: listState });
};
