기능 개요

과천 관제센터는 config.ts의 SITE_LIST에서 별도 code: 'GWACHEON'으로 정의되지만 realcode는 Air Map과 동일한 001ENV301입니다. 즉 데이터 출처(단위서비스코드)는 Air Map과 같으면서 측정망 운영용 화면만 분리한 진입점입니다. 진입 경로는 운영 반영 과정에서 /gwacheon/...에서 /airmon/...으로 변경되었습니다(Air Map은 /airbiz). SITE_CODES.GWACHEON이 path === 'airmon'으로 사이트를 역참조하므로 로고·배경·브라우저 탭 제목 분기도 모두 이 경로를 기준으로 동작합니다.

특화 화면은 pages/overview/gwacheon 아래에 모여 있습니다. 통신 상태(CommunicationStatus/CommunicationStatusDetail), 미수신(NoReception/NoReceptionDetail), 센싱 오류(SensingError), 전송 실패(TransmissionFailure)가 라우트로 등록되어 있습니다. 각 화면은 디바이스 유형(실내·실외·청정기·악취/소음 등)·사업 유형(BIZ/CSV) 필터와 지역(시도/군구/동) 검색을 제공하며, 지역 필터는 첫 항목을 자동 선택하지 않고 미선택(전체 조회) 상태로 시작합니다.

데이터는 gwacheonApi의 측정망 전용 엔드포인트(gwacheon/summary, gwacheon/collection-status, gwacheon/reception-fault, gwacheon/sensing-error, gwacheon/transmission-error)에서 조회합니다. 각 목록은 download 플래그로 같은 경로에 .csv를 붙여 CSV 다운로드를 겸하며, 미수신 화면은 HandlerStatusModal을 통한 조치 처리(gwacheonApi.action → reception-fault/action)를 함께 지원합니다. 조치상태(미조치/조치중/완료)·미조치사유(임시철거/장비이설/출입불가/기타)는 실제 운영 코드값으로 정의되어 있고, 미수신 상세 조회(receptionFaultDetail)는 응답의 lastMeasuredDate를 화면 필드 updateDate로 매핑해 정합성을 맞춥니다.

홈 지도의 과천 마커 요약 팝업(SummaryDialogGwacheon)은 전용 단건 조회로 분리되었습니다. 이전에는 미수신 상세(receptionFaultDetail)를 그대로 재사용하면서 현재 상태를 조치 상태(handlerStatus) 값의 유무로 판정해, 실제 통신 상태와 어긋나게 표시되는 문제가 있었습니다. 지금은 gwacheonApi.deviceDetail(serviceTargetId, deviceId)이 GET /bff/monitor/gwacheon/{serviceTargetId}/{deviceId}로 장치 단건을 조회합니다. 요청·응답 규격은 미수신 단건 조회와 같고 statusName(정상/비정상) 필드만 추가되며, lastMeasuredDate→updateDate 매핑도 동일하게 적용합니다. 팝업은 statusName === '정상'일 때만 정상으로 표시하고 그 외 값(null 포함)은 안전하게 비정상으로 처리하며, 구분(사업유형/디바이스유형)·장비ID·CTN·SERIAL·IMEI·USIM·관리부서·주소에 더해 위도·경도가 새로 추가되었습니다. 위경도는 목록 조회(devices/location) 응답이 마커 자체에 properties.lat/properties.lng로 이미 들고 있는 값을 우선 쓰고, 없거나 빈 문자열이면(그래서 ??가 아니라 ||로 연결) 단건 조회 응답의 latitudeValue/longitudeValue로 폴백합니다. 표시값은 formatCoordinate()가 담당하는데, B/E가 위경도를 "37.33976700000000"처럼 소수점을 0으로 채워 내려주므로 값은 그대로 두고 의미 없는 끝자리 0만 잘라냅니다. React Query 키도 gwacheon_reception_fault_detail에서 gwacheon_device_detail로 바뀌어 두 조회의 캐시가 섞이지 않습니다.

미수신 현황 목록(NoReception)의 "최근 측정일시" 컬럼은 B/E의 reception-fault 응답 규격 변경에 맞춰 createdDate(생성일시) 대신 updateOn(마지막 수신일자)을 노출하도록 정정되었습니다. 상세(NoReceptionDetail)에도 위도·경도 항목이 추가되어 latitudeValue/longitudeValue를 같은 formatCoordinate()로 표시하며, 통신 상태 상세(CommunicationStatusDetail)와 미수신 상세 모두 페이지 상단 경로(breadcrumb) 표기가 "서비스 설정"에서 실제 메뉴명인 "서비스 현황"으로 정정되었습니다.

통신 상태 상세(CommunicationStatusDetail)는 목록 행 클릭 시 전달받은 deviceId(경로)·serviceTargetId(state)로 gwacheonApi.collectionStatusDetail을 호출해 제조사·국소명·모델명·운용센터·모국 ID·유지보수 담당 등 실제 장비 정보를 조회합니다(초기의 더미 데이터 표시에서 실 API 연동으로 전환). 담당자 이름·연락처는 maskValue로 마스킹하고, KT 지도(ktGms.Map)는 문자열 위경도를 숫자로 변환해 [경도, 위도] 순서의 center로 표출하며, 줌·최대 줌은 config.ts의 공용 상수 DEFAULT_MAP_CENTER·DEFAULT_MAX_ZOOM_LEVEL을 사용합니다.

홈 화면의 과천 전용 위젯(components/widget/gwacheon)은 자동 갱신 대상으로 편입되었습니다. 서비스 현황·미수신·전송 오류 표를 그리는 GcTableWidget, 센싱 오류 현황 GcSensorErrorStatus, 실시간 수집률 GcRealTimeDetection이 모두 createAutoRefreshQueryOptions({ scope: 'home', fetcher })로 쿼리를 구성합니다. fetcher는 호출 모드를 인자로 받아 백그라운드 갱신일 때 { requestMode: 'background', skipError: true, timeout: AUTO_REFRESH_REQUEST_TIMEOUT_MS }를 API 옵션으로 넘겨, 화면 조작 중인 사용자에게 오류 팝업이 뜨지 않게 합니다. 실시간 수집률·센싱 오류 위젯은 서비스 대상이 바뀌어도 캐시가 섞이지 않도록 queryKey에 serviceTargetId를 포함하도록 정리되었습니다(connectionList→realtimeStatus, item_list→sensingFaultStatus).

위젯 표기·안정성 결함도 함께 정리되었습니다. GcTableWidget은 헤더 문구가 잘못 복사돼 있던 부분을 실제 의미(계·전체단말)로 고치고, 등급 범례가 Minor로 중복되던 두 항목을 Major·Critical로 정정했습니다. 또 응답 도착 전 data가 undefined인 채로 NormalTable에 전달돼 data.length 접근에서 크래시가 나던 문제를 data ?? []로 막았습니다. GcSensorErrorStatus는 응답의 원시 항목 키를 그대로 찍던 것을 공용 getPropertyLabel()(utils/airQualityGrade)로 변환해 미세먼지·초미세먼지·오존 같은 한글 라벨로 표시합니다.

종합 현황(pages/overview/gwacheon/index.tsx)은 scope: 'overview'로 자동 갱신에 참여합니다. 다만 사용자가 조회 중일 때 화면이 갑자기 새로고침되면 안 되므로, 고객사·등급·행 수·페이지·검색 버튼 등 모든 조작 핸들러에서 postponeAutoRefresh()를 호출해 타이머를 연장합니다. 데이터 조회는 gwacheonApi.summary(params, download, options)로 세 번째 인자에 요청 옵션을 받도록 확장되었습니다. 홈 지도 마커는 “과천은 시/도를 선택했을 때만 조회” 가드가 남아 있어 지역 기본값이 ‘전체’(빈 문자열)로 바뀐 뒤 진입 직후 마커가 아예 표시되지 않던 문제가 있었고, 해당 가드를 제거해 미선택 시 areaId를 생략하고 전체를 조회하도록 바로잡았습니다.

사이트 정체성도 분리되었습니다. 과천은 Air Map과 같은 로고를 쓰던 것에서 벗어나 전용 로그인 로고(loginGwacheon.svg/loginGwacheon_d.svg)와 전용 배경(bg_gwacheon-login.png)을 사용하며, AuthLayout·Login 모두 경로가 아니라 SITE_CODES.GWACHEON 코드로 먼저 분기합니다. 하단 푸터의 ‘에어코리아’ 외부 링크는 성격에 맞게 에어맵과 과천에서만 노출하도록 조건이 붙었습니다.

설계 포인트
과천을 별도 사이트 코드로 두어 권한 전환 제어(기능 11)에서 Air Map ↔ 과천 전환을 명시적으로 허용하면서, 실제 데이터는 같은 realcode로 일관되게 조회합니다. 자동 갱신 대상 판정도 경로가 아닌 세션 사이트 코드(site?.code === SITE_CODES.GWACHEON)로 하기 때문에 경로 변경의 영향을 받지 않습니다.

흐름. 측정망 특화 화면이 gwacheonApi로 통신 상태·오류 목록을 조회하고, 상세는 목록 행의 serviceTargetId·deviceId로 collectionStatusDetail을 실 호출합니다. CSV 다운로드·조치 처리도 같은 API 모듈이 담당하며, 종합 현황은 사용자 조작이 없을 때만 백그라운드로 다시 조회합니다. 홈 지도 마커 요약 팝업은 전용 단건 조회 deviceDetail의 statusName으로 현재 상태를 표시합니다.

src/api/gwacheon.ts — 측정망 전용 목록 + CSV 겸용 · 미수신 조치 · 상세 필드 매핑
export const gwacheonApi = {
  summary: (params, download?) =>
    apiClient.get(`/bff/monitor/gwacheon/summary${download ? '.csv' : ''}`, { /* responseType blob */ }),
  sensingError: (params, download?) =>
    apiClient.get(`/bff/monitor/gwacheon/sensing-error${download ? '.csv' : ''}`, { /* ... */ }),
  action: (params) =>
    apiClient.post(`/bff/monitor/gwacheon/reception-fault/action`, { ...params }),  // 미수신 조치

  receptionFaultDetail: async (serviceTargetId, deviceId) => {
    const res = await apiClient.get(
      `/bff/monitor/gwacheon/reception-fault/${serviceTargetId}/${deviceId}`,
    );
    if (res.data?.result) {  // 응답의 lastMeasuredDate를 화면 필드 updateDate로 매핑
      const { lastMeasuredDate, ...rest } = res.data.result;
      res.data.result = { ...rest, updateDate: lastMeasuredDate };
    }
    return res.data;
  },

  // 과천관제센터 장치 단건 조회 (지도 마커 요약 팝업 전용)
  // reception-fault 단건 조회와 요청/응답 규격 동일 + statusName(정상/비정상) 추가
  deviceDetail: async (serviceTargetId, deviceId) => {
    const res = await apiClient.get(`/bff/monitor/gwacheon/${serviceTargetId}/${deviceId}`);
    if (res.data?.result) {
      const { lastMeasuredDate, ...rest } = res.data.result;
      res.data.result = { ...rest, updateDate: lastMeasuredDate };
    }
    return res.data;
  },
};

// 좌표는 B/E가 "37.33976700000000"처럼 소수점 자리를 0으로 채워 내려준다.
// 값은 그대로 두고 의미 없는 끝자리 0만 지워 표기한다
export const formatCoordinate = (value: unknown): string => {
  if (value == null || value === '') return '-';
  const text = String(value).trim();
  if (!text.includes('.')) return text;
  return text.replace(/0+$/, '').replace(/\.$/, '');
};
