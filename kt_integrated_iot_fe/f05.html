기능 개요

Summary 화면(pages/summary/index.tsx)은 세션의 site.code에 따라 사이트별 요약 컴포넌트(airmap/DashBoard, aidx/Overall, SafeMate 4종, smartgreen/overall)를 분기 렌더링합니다. 추가 분석 화면으로 AI산업안전DX 설비 이용률(EquipmentUtilization)·자원환경(ResourceEnvironment), SMART GREEN 생육 디바이스 분석(GrowthDevice), 측정소 분석(StationAnalysis) 등이 라우팅에 등록되어 있습니다. Air Map 종합분석(airmap/DashBoard)은 측정위치별·미세/초미세먼지 측정기 위치별·한달 기준값별·시간대별·주의지역 Top5 분석 유형을 제공하며, 조회 월 기준으로 startDate/endDate를 산출해 airmapApi.getAreaAnalytics를 호출합니다. 페이지 최초 진입 시 기본 조건(실외 측정위치별 분석)으로 자동 조회하며, Worst5 화면에서 전달된 state가 있으면 해당 설치유형·주제를 반영합니다. 주제(segment)·전월 대비 옵션 변경 시에는 현재 피커에서 선택한 조회 월을 queryMonth에 다시 반영해 이전 검색의 월이 남는 문제를 방지합니다. 전국 측정소 서비스대상(AIRMAPNATIONAL)에서는 지역·구역 조회를 중단하고 안내 문구를 표시합니다.

Air Map 종합분석의 표출 항목과 조회 방식도 정리되었습니다. 실외 공기질(by_location · segment 02) 탭은 getAnalyticsProperties()가 pm10,pm25,temp,humi를 요청하도록 바뀌어 표가 'PM10 측정치(평균) · PM2.5 측정치(평균) · 온도(℃) · 습도(%)' 구성이 되었고, PM10·PM2.5의 신호등 열과 VOCs·CO 열은 제거되었습니다. 측정위치별 분석은 서버 페이징이라 page·rowCount 상태를 하위 ByLocationView에서 상위 DashBoard로 끌어올려 조회 파라미터(page는 0-base로 변환)에 싣습니다. 이렇게 하지 않으면 페이지를 눌러도 재조회가 일어나지 않습니다. 조회 조건이 바뀌거나 노출 개수를 바꾸면 첫 페이지로 되돌려, 조건만 바뀐 채 뒤쪽 페이지에 머물러 빈 결과가 나오는 것을 막습니다. 화면 헤더의 '전체 분석 다운로드'는 여러 analyticsType을 이어 붙여 CSV를 받던 방식을 버리고 전용 엔드포인트 airmapApi.getAreaAnalyticsXlsx(/bff/monitor/airmap/device/area/analytics.xlsx)로 xlsx를 받습니다. 이 엔드포인트는 주제 구분(analyticsType)을 받지 않고 서버가 전체 주제를 담아 주며, 측정항목은 FULL_DOWNLOAD_PROPERTIES(pm10,pm25,temp,humi,db)로 고정 전달하고 고르지 않은 지역 값은 빈 문자열 대신 undefined로 두어 쿼리에서 아예 빠지게 합니다. 표 하단의 'CSV 다운로드'는 종전 analytics.csv 그대로입니다. 시간대별 분석의 전월값은 현재값에서 증감분을 뺀 값인데 그대로 빼면 부동소수점 오차가 노출되므로(25.1 - 25.0이 0.10000000000000142로 표시), subtractDecimal()이 두 값 중 긴 소수 자릿수에 맞춰 반올림합니다.

측정소별 분석(stationAnalysis/airmap)의 실외 공기질 분석은 측정항목에서 '유동인구'가 빠지고 '온도'(temp)가 추가되었습니다. 여기서도 헤더의 '전체 분석 다운로드'가 airmapApi.getDeviceAnalyticsXlsx(/bff/monitor/airmap/device/analytics.xlsx) 기반 xlsx로 바뀌었는데, 이 엔드포인트는 properties·startDate·endDate·serviceTargetId만 받고 segment·deviceIds·size·page는 지원하지 않습니다. 조회 기간은 탭이 고른 조회연도를 상위와 나눠 써야 하므로, 연도 → 기간 변환을 getAnalyticsYearRange()로 뽑아 탭이 onDateRangeChange로 올려 주고 상위도 같은 함수로 초기값(올해)을 만들어 첫 렌더부터 빈 기간이 나가지 않게 합니다. 측정항목은 FIXED_ANALYTICS_PROPERTIES(pm10,pm25,humi,temp,db)를 씁니다.

차트는 components/chart 아래의 Nivo 래퍼들(NivoStackedBarChart, NivoGroupedBarChart, NivoLineChart, NivoPie, NivoComposedChart 등)을 사용합니다. 각 래퍼는 @nivo/bar·@nivo/line 등의 Responsive* 컴포넌트를 감싸고, useChartBar·useChartLine·useChartTheme 훅으로 데이터 가공과 라이트/다크 테마를 적용합니다. useChartBar는 데이터와 keys·groupMode로 Y축 최대/최소값·눈금(tickValues)·마진을 계산하며, 선택 인자 minMaxValue로 Y축이 최소한 기준선 값까지는 포함하도록 보장해 기준선이 차트 밖으로 벗어나는 것을 방지합니다. 막대 차트의 막대·툴팁은 CustomBar·CustomTooltipLayer 커스텀 레이어로 렌더링하며, 게이지·일부 커스텀 시각화에는 D3가 함께 쓰입니다. NivoLineChart에는 X축에 실제로 표시할 눈금만 지정하는 xAxisTickValues가 추가되었고(미지정 시 종전대로 모든 데이터 포인트에 눈금 표시), 시리즈의 모든 점이 비어 있으면 lines 레이어를 렌더 목록에서 제외해 빈 라인 차트가 잘못된 SVG 경로를 만들지 않게 했습니다.

막대 렌더링은 스택 세그먼트 가독성을 중심으로 재편되었습니다. 전체 합 대비 값이 극단적으로 작으면 세그먼트 높이가 1px 미만이 되어 보이지 않는데, 높이만 키우면 이웃 세그먼트를 덮어버립니다. 그래서 CustomBar는 스택 순서(stackKeys)를 받아 기준선(값 0의 y좌표)에서부터 아래 세그먼트들의 보정된 높이를 누적해 자기 위치를 다시 계산하고, 각 세그먼트에 minSegmentHeight만큼의 최소 높이를 보장합니다(NivoStackedBarChart 기본값 3px). 값이 0인 세그먼트는 렌더링되지 않으므로 맨 아래 판정과 누적 계산에서 모두 제외하며, 둥근 모서리 반지름은 막대 높이(양끝 둥근 세그먼트는 절반)로 제한해 경로가 스스로 교차하며 형태가 깨지는 것을 막습니다. 높이 보정 때문에 막대와 hover 영역이 어긋나므로 막대 path는 pointerEvents: 'none'으로 두고 툴팁은 CustomBarTooltipLayer의 투명 hover 영역이 전담하며, fullColumnHover로 hover 영역을 컬럼 전체 높이까지 넓혔습니다.

색상 전달 규약도 정리되었습니다. CustomTooltipLayer는 막대 색을 더 이상 chartColors 배열에서 인덱싱하지 않고 Nivo가 계산한 bar.color를 그대로 쓰며, 라인 시리즈 색만 lineColors로 받습니다. NivoComposedChart의 chartColors는 배열뿐 아니라 막대별로 색을 계산하는 함수도 받을 수 있게 되었고, 함수를 넘긴 경우 배열 인덱싱이 불가능하므로 resolvedLineColors가 lineColors → 기본색 순으로 폴백합니다. 값 기반 등급색은 airQualityGrade의 makeGradeBarColor(grade, fallback)가 만들어 주며, Air Map 마커 상세 차트가 이를 사용합니다. 측정 항목 키를 화면 표시명으로 바꾸는 PROPERTY_LABELS·getPropertyLabel()도 함께 추가되어 API 원본 키(temp/humi/PM2.5 등)가 화면에 그대로 노출되지 않습니다.

데이터는 React Query로 도메인 API(예: rooftopDoorApi, intFireDetectorApi, airmap·smartGreen 모듈 등)에서 조회합니다. AI산업안전DX 설비가동률분석(EquipmentUtilization)은 서비스대상을 FIXED_SERVICE_TARGET_ID('KT')로 고정해 조회하고, 조회 기간 기본값은 getDefaultDateRange()로 호출 시점에 산출하며(모듈 로드 시점에 고정되던 dayjs 버그 수정), 조회 버튼 클릭 시 searchTrigger를 queryKey에 포함해 파라미터 변경 여부와 무관하게 항상 재요청합니다. 요약 화면의 다운로드 버튼은 downloadFileFromResponse로 Content-Disposition 기반 파일 저장을 수행합니다.

AI산업안전DX 종합분석(summary/aidx/Overall)은 집계 단위(unit)와 조회 기간이 어긋나 있던 부분을 맞췄습니다. getPickerTypeByUnit()이 단위에 따라 날짜 피커 종류를 정하고(일별 → 월 선택, 월별 → 연 선택, 그 외 → 일 선택), getDateRangeByUnit()이 같은 기준으로 조회 시작·종료 시각과 차트 시간 포맷을 함께 산출합니다. 이전에는 차트 전용 쿼리만 하루 범위·HOUR 고정으로 따로 조회했는데, 지금은 표·차트·다운로드가 모두 같은 단위와 기간을 씁니다. 요청에는 serviceType이 추가되었고, 피커 종류가 바뀔 때 날짜가 오늘로 초기화되지 않도록 CustomPicker에 resetOnPickerTypeChange={false}를 넘깁니다. 측정 항목 ID는 한글 키를 쓰던 '총누적량'·'누적투입량'을 accuweight로, collReduceweight를 collreduceweight로 통일했습니다. 15분 단위 조회에서는 x축 라벨이 겹치므로 정시(HH:00) 값만 xAxisTickValues로 남기고 xAxisFormat이 분 부분을 잘라 시간별 조회와 같은 표기(HH)로 맞춥니다. 그래프 데이터 자체는 15분 단위 그대로 유지합니다.

기간 조회에는 공용 상한이 도입되었습니다. utils/dateRange의 DATE_RANGE_LIMIT_DAYS(90일)를 CustomRangePicker의 maxRangeDays로 넘겨 달력에서 그 이상 선택을 막고, SearchItemBox의 notice에 dateRangeLimitNotice() 문구를 함께 노출합니다. 조회기간 무제한으로 504 타임아웃이 나던 AI산업안전DX 설비가동률분석과, SMART GREEN 생육 디바이스 분석·종합현황 화면에 적용되었습니다. CSV 다운로드는 화면 페이지네이션과 무관하게 항상 전체를 받도록 page: 0·size: MAX_DATA_ROW로 통일했습니다.

SMART GREEN 분석 화면들은 날짜·기간 단위를 바꿀 때 applied 상태를 부분 갱신하던 방식을 버리고, 조회 버튼과 동일한 정규화를 거친 draft 전체를 한 번에 적용합니다. 이전에는 아직 조회를 누르지 않은 골프장·코스·홀 선택이 반영되지 않은 채로 조회가 나가 화면 표시와 실제 조회 대상이 어긋났습니다. 데이터가 없을 때의 안내는 인라인 문구 대신 공용 EmptyState 컴포넌트로 교체되었습니다. AI산업안전DX 자원환경 분석의 '지역' 옵션은 구역 목록(commonApi.areaList) 대신 시/도 단위(regionsApi.getUnitSido)로 바뀌었고, 선택값을 API 규격에 맞춰 sidoNm으로 그대로 전달합니다. 서비스대상이 '전체'인 경우에는 현재 서비스 형태에 속한 대상들의 시/도를 모아 중복 제거 후 노출합니다.

설계 포인트
차트 데이터 가공 로직을 useChartBar/useChartLine 훅으로 분리해, 동일한 Nivo 래퍼를 여러 사이트·지표에서 재사용합니다. 라벨 한글화는 labelMap으로 키→라벨 매핑을 주입합니다.

관계. Summary가 도메인 API로 통계를 받아 Nivo 래퍼로 그리고, 데이터 가공·테마는 차트 훅이 담당합니다. 막대 형상 보정과 툴팁 hover 영역은 CustomBar·CustomBarTooltipLayer가 나눠 맡고, 색은 시리즈 고정색과 값 기반 등급색 두 방식을 모두 지원합니다.

src/components/chart/NivoStackedBarChart.tsx — Nivo + 차트 훅 조합
import { ResponsiveBar } from '@nivo/bar';
import useChartBar from '@/hooks/useChartBar';
import CustomBarTooltipLayer from './CustomTooltipLayer';
import useChartTheme from '@/hooks/useChartTheme';
import CustomBar from './CustomBar';

interface NivoStackedBarChartProps {
  data: { [key: string]: any }[];
  indexBy: string;
  keys: string[] | undefined;
  chartColors?: string[];
  labelMap?: { [key: string]: string }; // 키를 한글 라벨로 매핑
  maxValueScale?: number; // 최대값 스케일 조정 비율

// 아래쪽 세그먼트들의 '보정된' 높이를 누적해 자기 위치를 다시 계산한다.

    && stackKeys && myStackIndex >= 0 && barValue > 0 && height > 0) {
  const pxPerUnit = height / barValue;        // nivo가 계산한 스케일 역산

  let rawHeightBelow = 0;                     // 아래 세그먼트들의 원래 높이 합
  let adjustedHeightBelow = 0;                // 보정 후 높이 합
  for (let i = 0; i < myStackIndex; i++) {

    if (value <= 0) continue;                 // 렌더링되지 않으므로 자리도 차지하지 않는다
    rawHeightBelow += value * pxPerUnit;
    adjustedHeightBelow += Math.max(value * pxPerUnit, minSegmentHeight);
  }

  const baseline = y + height + rawHeightBelow;
  actualHeight = Math.max(height, minSegmentHeight);
  adjustedY = baseline - adjustedHeightBelow - actualHeight;
}
