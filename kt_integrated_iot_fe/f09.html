기능 개요

AI 에이전트 모달(modal/aiagent/index.tsx)은 좌측 사이드바(layout/Sidebar.tsx)에서 openAgent 상태로 열리는 드래그·리사이즈 가능한 플로팅 다이얼로그입니다. 좌측 Thread 패널에서 대화 스레드를 선택·추가·삭제하고, 우측 Message 영역에서 대화 내용을 주고받습니다. 스레드 목록은 aiAgentApi.getThreads()로 조회하고, 새 스레드는 regiestThread('USER'), 삭제는 deleteThread(threadId)로 처리합니다.

메시지 전송은 aiAgentApi.request(threadId, message)로 이뤄지며, 성공 응답을 메시지 목록에 추가합니다. 최초 질의 후 서버가 스레드 제목을 부여하면(data.threadName) 스레드 목록을 갱신합니다. 스레드 전환 시 getMessages(threadId)로 기존 대화를 불러와 역순 정렬해 표시합니다.

에이전트 응답의 분리 수신 경로는 전역 WebSocketProvider에 마련되어 있습니다. 수신 메시지에 threadId가 있고 에이전트가 활성(isActiveAgent)인 경우에만 setLastMessage로 라우팅되어, 관제 이벤트(lastEvent)와 채널을 공유하면서도 분리 보관됩니다. 다만 현재 소스에서 모달이 lastMessage를 구독하거나 setActiveAgent를 호출하는 코드는 없으며, 대화 표시는 request의 REST 응답만으로 완결됩니다.

설계 포인트
에이전트 응답과 관제 이벤트가 같은 STOMP 큐로 들어오므로, threadId 존재 여부와 isActiveAgent 플래그를 함께 검사해 두 흐름을 안전하게 갈라냅니다(기능 04 참고).

시퀀스 다이어그램

sequenceDiagram autonumber participant UI as AiAgent 모달 participant API as aiAgentApi participant WS as WebSocketProvider UI->>API: getThreads() API-->>UI: 스레드 목록 (useQuery) UI->>UI: send() 사용자 메시지 즉시 추가 UI->>API: request(threadId, message) API-->>UI: 응답 result(messages 추가, threadName 오면 refetch) Note over WS: 같은 STOMP 큐로 이벤트 도착 WS->>WS: stompData.threadId && isActiveAgent ? alt 에이전트 응답 WS->>WS: setLastMessage (lastMessage 컨텍스트 보관) else 관제 이벤트 WS->>WS: setLastEvent (다른 화면) end UI->>API: getMessages(threadId) (스레드 전환 시) API-->>UI: 이전 대화(역순 표시)

흐름. 모달은 스레드/메시지를 REST만으로 완결 처리합니다. WebSocketProvider는 threadId·isActiveAgent 판별로 에이전트 응답을 관제 이벤트와 분리해 lastMessage에 보관하지만, 현재 모달이 이를 구독하지는 않습니다.

클래스 다이어그램

classDiagram class AiAgent { -currThreadId -messages -title +addThread() +closeThread() +send() +resetMessages() } class Thread { +threadList +chageThread(id) +addThread() } class Message { +messages } class aiAgentApi { +getThreads() +regiestThread(origin) +deleteThread(id) +getMessages(id) +request(id, message) } class WebSocketProvider { +lastMessage +isActiveAgent +setActiveAgent(bool) } AiAgent o-- Thread : 스레드 패널 AiAgent o-- Message : 메시지 영역 AiAgent ..> aiAgentApi : 스레드/메시지 CRUD

관계. AiAgent 모달이 Thread·Message 하위 컴포넌트를 조합하고 REST(aiAgentApi)로 대화를 처리합니다. WebSocketProvider는 에이전트 응답 분리 라우팅(lastMessage)을 갖추고 있으나 현재 모달과 직접 연결되어 있지는 않습니다.

핵심 코드

src/api/aiAgent.ts — 스레드·메시지 엔드포인트
export const aiAgentApi = {
  getThreads: () => apiClient.get('/bff/monitor/threads', { params: { page: 0, size: MAX_DATA_ROW } }).then((r) => r.data),
  regiestThread: (origin: string, threadId?: string) =>
    apiClient.post('/bff/monitor/threads', { origin, threadId }).then((r) => r.data),
  deleteThread: (threadId: string) => apiClient.delete(`/bff/monitor/threads/${threadId}`).then((r) => r.data),
  getMessages: (threadId: string) => apiClient.get(`/bff/monitor/threads/${threadId}/messages`, { params: { page: 0, size: MAX_DATA_ROW } }).then((r) => r.data),
  request: (threadId: string, message: string) =>
    apiClient.post(`/bff/monitor/threads/${threadId}/messages`, { message }).then((r) => r.data),
};
src/contexts/WebSocketProvider.tsx — 에이전트 응답 분리 수신
if (stompData.threadId && isActiveAgent) {
  if (isActiveAgent) {
    setLastMessage(stompData);   // AI 에이전트 응답만 분리 보관
  }
} else if (stompData) {
  setLastEvent(stompData);       // 그 외 관제 이벤트
}
