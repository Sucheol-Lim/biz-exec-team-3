기능 개요

로그인 화면(pages/auth/Login.tsx)은 Formik 폼에 입력된 ID/비밀번호로 로그인합니다. 제출 시 먼저 commonApi.getRsakey(id)로 사용자별 RSA 공개키(modulus·exponent)와 randomString을 받아, encryptPassword(utils/rsa.ts)로 비밀번호를 PKCS#1 v1.5 패딩 후 RSA 암호화합니다. RSA 키 발급은 보안 취약점 조치로 아이디를 URL 경로가 아닌 요청 body로 전달하는 POST /bff/monitor/rsakey로 변경되었습니다. 이어 executeRecaptcha('login')으로 reCAPTCHA v3 토큰을 발급받습니다.

암호화된 비밀번호·randomString·reCAPTCHA 토큰을 묶어 commonApi.login()으로 전송하며, 토큰은 X-RECAPTCHA-TOKEN 헤더로 함께 전달됩니다. 응답이 OK라도 약관 미동의(stipulationYn이 N)면 토큰을 저장하지 않고 약관 동의 모달(Terms)을 먼저 띄웁니다. 모달이 commonApi.updateUserStipulation(POST /bff/monitor/users/stipulation)으로 동의를 등록하면 로그인을 재호출해 그때 토큰을 발급받습니다(약관 동의한 경우에만 토큰 발급). 권한 충족(플랫폼 관리자이거나 unitServiceCodes에 대상 realcode 포함) 시 accessToken과 함께 refreshToken·site를 세션에 저장합니다. 자동 갱신(auto-refresh) 주기에서 토큰을 회전해야 하므로 두 토큰을 함께 보관하도록 바뀌었습니다. 이어 accessToken의 JWT payload에서 추출한 사용자 id(getTokenPayloadId)로 상세를 조회해 사용자 정보·서비스 대상을 세팅한 뒤 홈으로 이동합니다. 서비스 대상 세팅(settingServiceTarget)은 호출 때마다 페이지·크기를 직접 넘기던 commonApi.serviceTargets({ page: 0, size: 10000 }) 대신, 고정 파라미터를 품은 공용 헬퍼 commonApi.headerServiceTargets()를 사용합니다. 이 헬퍼는 sortField: 'SERVICE_TARGET_NAME'·sortOrder: 'ASC'를 함께 보내므로 로그인 직후 세팅되는 목록도 헤더 드롭다운과 같은 이름순으로 정렬됩니다. 목록에서 세션 사이트의 realcode와 unitServiceCode가 일치하는 항목만 남긴 뒤, 사용자의 serviceTargetIds·권한(hasRole(2))에 따라 기본 선택 대상을 정합니다. getTokenPayloadId는 Login 내부 지역 함수에서 utils/token.ts 공용 유틸로 분리되었습니다.

로그인 실패·차단 응답은 화면 안에서 분기 처리합니다. 비밀번호 오류 횟수 초과로 415(path가 /bff/monitor/token) 응답을 받으면 임시 비밀번호가 등록된 이메일로 발송되었다는 고정 안내 팝업을 띄웁니다. 반복 실패 차단은 HTTP 429 + 코드 AUTH-013 + 같은 path 세 조건을 모두 만족할 때만 전용 안내 팝업(CommonModal)으로 노출하도록 좁혀졌습니다. 이전에는 입력창 아래 텍스트 메시지였으나, 415와 동일하게 모달로 통일했습니다. 그 외 오류는 기존대로 “아이디 또는 비밀번호가 일치하지 않습니다”를 표시합니다.

비밀번호 변경 안내는 로그인 응답 시점에 getNeedPwType(loginResult)로 한 번에 판정합니다. temporaryPasswordYn === 'Y'면 TEMP, 아니면 passwordChangeYn === 'Y'일 때 EXPIRE로, 임시 비밀번호가 만료 안내보다 우선합니다. 판정 결과가 있으면 서비스 대상 세팅이 끝난 뒤 세션 사용자 단위로 스코프된 hideTodayPopup 쿠키(userScopedCookieName('hideTodayPopup'))를 먼저 확인해, "오늘 그만보기"가 설정돼 있으면 TEMP/EXPIRE 구분 없이 안내 팝업을 건너뛰고 곧바로 goHome()합니다. 쿠키가 없을 때만 ChangePwConfirm 안내 팝업으로 이어집니다. 이 쿠키명은 사용자 로그인 이후에만 산출 가능하므로(setSessionStorage('user') 이후), 판정은 항상 로그인 응답을 처리한 뒤에 이뤄집니다.

비밀번호 변경(ChangePassword)이 성공하면 서버에서 기존 토큰이 무효화되므로 화면에 남지 않고 재로그인으로 보냅니다. moveToLoginAfterPasswordChange가 WebSocket을 disconnect()하고 sessionStorage.clear()한 뒤 window.location.replace('/{sitePath}/login')으로 이동해, 로그인 화면이 같은 URL이더라도 컴포넌트 상태까지 초기화합니다. 이전 비밀번호 재사용은 441 + path가 /bff/monitor/users/myinfo일 때만 “이전에 사용한 비밀번호입니다” 안내를 띄우고 새 비밀번호 입력값을 비웁니다. 비밀번호 만료 연장(extendPassword) 요청은 user?.id가 없을 때 문자열 결합(user?.id + '')으로 'undefined'가 그대로 서버에 전송되던 경로를 막아, 값이 없으면 요청 자체를 던지지 않습니다. ChangePwConfirm의 "오늘 그만보기" 체크박스가 심는 hideTodayPopup 쿠키도 이제 userScopedCookieName('hideTodayPopup')으로 로그인 사용자 단위로 스코프되어, 같은 브라우저를 쓰는 다른 사용자에게 숨김 상태가 전파되지 않습니다. path로 판별하는 이유는 SMART GREEN 디바이스 비밀번호(POST /bff/monitor/devices/password)의 441과 섞이지 않게 하기 위함입니다. 또한 모달 본문을 <form>으로 감싸고 숨김 username 입력과 autoComplete(current-password/new-password)를 지정해, 브라우저 자동입력이 헤더 검색창을 잘못 채우던 문제를 막았습니다.

개인정보 마스킹은 maskValue(type, value) 유틸이 전화번호·ID·IP·이메일 타입별 규칙으로 일부 문자를 *로 가립니다. 마스킹 해제는 ChangeMask 모달로 사유·인증을 거쳐 평문을 조회하며(userDetail(..., mask, reason)), OTP(Otp)·비밀번호 변경(ChangePassword) 등 추가 인증 모달이 함께 제공됩니다. 내 정보 관리(My)는 서버가 마스킹해 내려준 id를 표시하고 마스킹해제 버튼을 다시 노출합니다.

에어맵·AI산업안전DX·스마트그린에 이어 한전 AMI 로그인 화면에도 개인정보 처리방침 링크가 노출됩니다(PRIVACY_POLICY_CODES). PrivacyPolicy 모달이 비로그인 허용 BFF 약관 목록 API(getTermsList('PRIVACY', ...))로 콘텐츠를 조회하고, 콘텐츠 안의 {{AIRMAP_PRIVACY_ICON_*}} 플레이스홀더는 로컬 이미지(/assets/privacy/*.png) 태그로 치환(replacePrivacyPlaceholders)한 뒤 DOMPurify.sanitize를 거쳐 HTML로 렌더링합니다. 약관 모달(Terms)의 HTML 콘텐츠 렌더링에도 동일하게 DOMPurify sanitize가 적용되어 있습니다.

로그인 화면의 사이트별 외형과 안내도 config 상수로 분기합니다. LOGIN_CONTACT_INFO에 등록된 사이트(현재 Air Map)는 화면 하단에 이메일 문의·기업고객센터 연락처를 노출하고, 값이 하나도 없으면 영역 자체를 렌더링하지 않습니다. 로고·배경은 경로 변경(air→airbiz, dx→factorydx, gwacheon→airmon)에 맞춰 갱신되었고, 과천 관제센터는 Air Map과 같은 경로 그룹이지만 사이트 코드(SITE_CODES.GWACHEON)로 먼저 분기해 전용 로고(loginGwacheon.svg)와 전용 배경(bg_gwacheon-login.png)을 사용합니다. 같은 탭에서 토큰이 남은 채 로그인 화면에 다시 들어온 경우, 예전에는 곧바로 홈으로 튕겼지만 이제는 다른 사이트일 때만 세션을 정리하고 로그인 화면에 머무릅니다.

설계 포인트
RSA 암호화는 외부 키 노출 없이 비밀번호 평문이 네트워크에 흐르지 않도록 클라이언트에서 수행합니다. rsa.ts는 BigInt 기반 modPowInt(Square-and-Multiply)로 모듈러 지수승을 구현해 별도 의존성 없이 동작합니다.

흐름. RSA 키 수신(POST body) → 비밀번호 암호화 → reCAPTCHA 토큰 발급 → 로그인 요청 순서로 진행됩니다. 권한 충족 시 accessToken·refreshToken을 함께 저장하고, getNeedPwType 결과가 있고 사용자 스코프 hideTodayPopup 쿠키가 없을 때만 비밀번호 변경 모달로 이어져 변경 성공 시 세션을 비우고 재로그인시킵니다. 415는 임시 비밀번호 발송 안내, 429+AUTH-013은 차단 안내 팝업으로 분기합니다.

src/pages/auth/Login.tsx — RSA 암호화 + reCAPTCHA 로그인
const { data: rsaResult } = await rsaQuery.refetch();
const { exponent, modulus, randomString } = rsaResult.result;
const encryptedPassword = encryptPassword(formik.values.password, modulus, exponent);
const recaptchaToken = await executeRecaptcha('login');
const payload = { id: formik.values.userId, password: encryptedPassword, randomString, recaptchaToken };
const loginResult = await loginMutation.mutateAsync(payload);
if (loginResult.message === 'OK') {
  const nextNeedPwType = getNeedPwType(loginResult);   // TEMP 가 EXPIRE 보다 우선
  setNeedPwType(nextNeedPwType);

  if (loginResult.result.stipulationYn === 'N') {
    setLoading(false);
    setOpenTerms(true);          // 동의 완료 시 resultTerms(true) → login() 재호출
  } else if (loginResult.result.userRoleId === USER_ROLES[4].roleId
      || (target?.realcode && loginResult.result.unitServiceCodes.includes(target.realcode))) {
    // 이후 자동 조회 cycle에서 token을 회전할 수 있도록 두 token을 함께 보관한다
    setSessionStorage('refreshToken', loginResult.result.refreshToken);
    setSessionStorage('accessToken', loginResult.result.accessToken);
    setSessionStorage('site', target);
    settingUserInfo(loginResult, nextNeedPwType);
  }
}

const moveToLoginAfterPasswordChange = (result: { message?: string }) => {
  if (result?.message !== 'OK') return;

  const site = getSessionStorage('site');
  const sitePath = site?.path || window.location.pathname.split('/')[1];

  // 기존 token 무효화 후 로그인 화면이 동일 URL일 수 있어 컴포넌트 상태까지 초기화한다
  disconnect();
  sessionStorage.clear();
  window.location.replace(`${window.location.origin}/${sitePath}/login`);
};

// TEMP/EXPIRE/CHANGE 는 모두 PUT /bff/monitor/users/myinfo 로 귀결되므로 path 로 판별해야
// SMART_GREEN(POST /bff/monitor/devices/password) 쪽 441 과 안 섞인다
if (errorData?.code === '441' && errorData?.path === '/bff/monitor/users/myinfo') {
  openError({ status: '400', message: {
    title: '사용할 수 없는 비밀번호',
    content: '이전에 사용한 비밀번호입니다. 다른 비밀번호를 사용하세요.', action: '' } });
  formik.setFieldValue('newPw', '');

src/utils/token.ts — JWT payload 사용자 ID 추출 유틸 분리
// access token의 JWT payload에서 인증 사용자 ID를 추출한다.
export const getTokenPayloadId = (accessToken?: string | null) => {
  if (!accessToken) return '';
  try {
    const payload = accessToken.split('.')[1];
    if (!payload) return '';

    const normalizedPayload = payload.replace(/-/g, '+').replace(/_/g, '/');
    const paddedPayload = normalizedPayload.padEnd(Math.ceil(normalizedPayload.length / 4) * 4, '=');
    const decodedPayload = JSON.parse(window.atob(paddedPayload));

    return typeof decodedPayload?.id === 'string' ? decodedPayload.id : '';
  } catch (error) {
    log.error(error);
    return '';
  }
};
src/utils/util.ts — 타입별 개인정보 마스킹
export function maskValue(type, value): string | null {
  if (type == null || value == null) return null;
  switch (type) {
    case 'phone': /* 6~8번째 자리를 * 로 */ return value.replace(/\d/g, ...);
    case 'id':    return value.length <= 3 ? '***' : value.slice(0, -3) + '***';
    case 'email': /* local 뒤 3자리 마스킹 */ return `${local.slice(0, -3)}***@${domain}`;
    default:      return value.length <= 1 ? '*' : value.slice(0, -1) + '*';
  }
}
