기능 개요

본 콘솔은 KT가 개별 운영하던 여러 IoT 서비스를 하나의 React SPA로 통합합니다. 어떤 서비스에 진입했는지는 URL 첫 세그먼트(/:site)로 결정되며, config.ts의 SITE_LIST가 각 서비스의 path(airbiz, factorydx, fire-detector, emergency-door, fire-monitoring, emergency-bell, ami, smart-green, airmon)와 단위서비스코드(code/realcode)를 매핑합니다. Air Map·AI산업안전DX·과천 관제센터의 URL 세그먼트는 각각 air→airbiz, dx→factorydx, gwacheon→airmon으로 변경되었고, SITE_CODES·SITE_MENU·화면 내 navigate() 경로가 모두 새 path를 기준으로 재정렬되었습니다.

라우터(routes/route.tsx)는 최상위 경로를 모두 /:site로 두고, SiteGuard가 URL의 site가 SITE_LIST에 존재하는지(ALLOWED_SITE_PATHS) 먼저 검사합니다. 유효하면 로그인 화면(AuthLayout) 또는 보호 화면(ProtectedRoute → MainLayout)으로 분기하고, 같은 화면 컴포넌트(예: Home, Summary, HistoryMain)가 세션의 site.code를 읽어 사이트별 위젯·테이블·차트를 다르게 렌더링합니다.

로그인 시 선택한 사이트의 realcode는 세션에 저장되어 이후 모든 API 요청의 unitServiceCode 헤더로 주입됩니다. 즉 같은 코드베이스가 사이트 코드에 따라 데이터·메뉴·외형을 분기하는 멀티 테넌트 구조입니다.

헤더의 사이트 전환 메뉴(SITE_MENU)에서 AI산업안전DX는 AIENVDX_SERVICE_TYPE_LIST(산업대기질·자원순환·산업환경·탄소중립·제조공정)를 매핑해 serviceType 단위 하위 메뉴로 전개됩니다. 여기에 유형을 좁혀 보던 중 최초 로그인 직후처럼 전체를 총괄하는 상태로 되돌아가기 위한 '전체' 항목이 추가되었습니다. 이 상태는 실제 SVC_TYPE 값과 겹치지 않는 AIDX_ALL_SERVICE_TYPE('ALL')로 표현하고, 사이드바 서브타이틀·브라우저 탭 제목 등의 라벨은 getDxServiceTypeLabel()이 일괄 변환합니다. 사이트를 전환할 때(Sidebar.changeSite) 상단 서비스 대상 목록은 전용 함수 commonApi.headerServiceTargets()로 조회하며, 서비스대상명 오름차순(sortField: 'SERVICE_TARGET_NAME', sortOrder: 'ASC') 정렬 조건이 호출부가 아니라 API 계층 상수(HEADER_SERVICE_TARGET_PARAMS)에 고정되었습니다. 보호 라우트에는 위젯 설정 페이지(widget-settings)가 추가되었고, 접근 허용 서비스타입은 WIDGET_SETTING_SERVICE_TYPES·isWidgetSettingServiceType으로 중앙 관리합니다(현재 제조공정 전용). 한편 SMS 수신 동의 페이지(/:site/sms-consent)는 SiteGuard·ProtectedRoute를 타지 않는 독립 공개 라우트로 추가되었으며, 이때 :site는 사이트 코드가 아니라 이 페이지 전용 브랜드 키(air/safemate)로만 판별됩니다.

보호 라우트 중 홈(index·home)과 종합현황(overview)은 화면 컴포넌트를 AutoRefreshRoute로 감싸 자동 갱신 바운더리 안에 둡니다. AutoRefreshRoute는 useParams()로 읽은 :site와 스코프를 합친 `${sitePath}:${scope}`를 key로 써서, 사이트가 바뀌면 하위 AutoRefreshBoundary가 통째로 재마운트되고 새 주기 타이머(AUTO_REFRESH_INTERVAL_MS — 5분에서 1분으로 단축)가 현재 시각 기준으로 다시 시작됩니다. 즉 사이트 분기 구조가 자동 갱신 수명주기의 경계까지 그대로 정의합니다.

설계 포인트
과천 관제센터(GWACHEON)는 별도 code를 갖지만 realcode는 Air Map과 동일한 001ENV301입니다. 즉 데이터 출처는 Air Map과 같되 화면(특화 관제)만 분리한 진입점이며, URL 세그먼트만 airmon으로 분리되어 있습니다.

흐름. URL 첫 세그먼트가 SiteGuard를 거쳐 검증되고, 홈·종합현황은 AutoRefreshRoute를 한 겹 더 지나 자동 갱신 바운더리 안에서 렌더됩니다. 화면 컴포넌트는 세션의 site.code를 읽어 해당 서비스 전용 UI를 그립니다.

관계. config가 사이트 메타 목록을 보유하고, ThemeRoutes가 이를 근거로 SiteGuard를 통해 분기합니다. 홈·종합현황만 AutoRefreshRoute를 한 겹 더 거치며, 각 화면은 SITE_CODES 상수로 사이트별 동작을 결정합니다.

핵심 코드

src/config.ts — 사이트 목록과 코드 상수 정의
export const SITE_LIST = [
  { code: '001ENV301', realcode: '001ENV301', title: 'Air Map', path: 'airbiz' },
  { code: '001ENV302', realcode: '001ENV302', title: 'AI산업안전DX', path: 'factorydx' },
  { code: '001SAF100', realcode: '001SAF100', title: 'SafeMate', subTitle: '지능형 화재 감지기', path: 'fire-detector' },
  // ... SafeMate 4종 / 한전 AMI / SMART GREEN ...
  { code: 'GWACHEON', realcode: '001ENV301', title: 'Air Map', subTitle: '과천 관제센터', path: 'airmon' },
];

export const SITE_CODES = {
  AIRMAP: SITE_LIST.find((s) => s.path === 'airbiz')?.code || '',
  DX: SITE_LIST.find((s) => s.path === 'factorydx')?.code || '',
  // ...
  GWACHEON: SITE_LIST.find((s) => s.path === 'airmon')?.code || '',
} as const;

// AI산업안전DX 유형 미지정('전체'). 실제 SVC_TYPE 값과 겹치지 않아야 한다
export const AIDX_ALL_SERVICE_TYPE = 'ALL';

export const getDxServiceTypeLabel = (serviceType?: string | null): string => {
  if (serviceType === AIDX_ALL_SERVICE_TYPE) return '전체';
  return AIENVDX_SERVICE_TYPE_LIST.find((item) => item.id === serviceType)?.label ?? '';
};

// 헤더 사이트 전환 메뉴: AI산업안전DX 는 '전체' + serviceType 하위 메뉴로 전개
export const SITE_MENU = [
  // ...
  {
    title: 'AI산업안전DX',
    children: [
      { code: '001ENV302', realcode: '001ENV302', title: '전체',
        path: 'factorydx', serviceType: AIDX_ALL_SERVICE_TYPE },
      ...AIENVDX_SERVICE_TYPE_LIST.map((item) => ({
        code: '001ENV302', realcode: '001ENV302',
        title: item.label,      // 산업대기질/자원순환/산업환경/탄소중립/제조공정
        path: 'factorydx', serviceType: item.id,
      })),
    ],
  },
  // ...
];
src/routes/route.tsx — 모든 경로를 /:site 아래에 두는 가드
const ALLOWED_SITE_PATHS = SITE_LIST.map((s) => s.path);

const SiteGuard = ({ children }: { children: React.ReactNode }) => {
  const { site } = useParams();
  if (!site || !ALLOWED_SITE_PATHS.includes(site)) {
    return <Error />;            // 미등록 사이트면 에러 화면
  }
  // ... 권한 기반 전환 검사(checkPermission) 후 children 렌더 ...
  return children;
};

// routes 최상위: { path: '/:site', element: <SiteGuard><Outlet /></SiteGuard> }

// SMS 수신 동의 페이지: SiteGuard/ProtectedRoute 를 타지 않는 독립 공개 라우트
{
  path: '/:site/sms-consent',
  element: <SmsConsentPage />,
},

// MainLayout 하위: 홈·종합현황은 자동 갱신 바운더리로 감싼다
{ index: true,        element: <AutoRefreshRoute scope="home"><Home /></AutoRefreshRoute> },
{ path: 'home',       element: <AutoRefreshRoute scope="home"><Home /></AutoRefreshRoute> },
{ path: 'overview',   children: [
  { index: true,      element: <AutoRefreshRoute scope="overview"><Overview /></AutoRefreshRoute> },
  // detail/:serviceTargetId/:modelId/:lineNumber 등 하위는 바운더리 밖
]},
src/modules/autoRefresh/AutoRefreshRoute.tsx — :site 변경 시 바운더리 재마운트
// route site(:site)가 바뀌면 key가 바뀌어 AutoRefreshBoundary가 통째로 재마운트되고,
// 새 Boundary가 현재 시각 기준 새 1분 timer를 시작한다.
const AutoRefreshRoute = ({ scope, children }: AutoRefreshRouteProps) => {
  const { site } = useParams();
  const sitePath = site ?? '';

  return (
    <AutoRefreshBoundary key={`${sitePath}:${scope}`} sitePath={sitePath} scope={scope}>
      {children}
    </AutoRefreshBoundary>
  );
};
