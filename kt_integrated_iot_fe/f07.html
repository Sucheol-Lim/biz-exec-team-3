디바이스·서비스대상·구역 관리

디바이스, 서비스 대상, 구역(Zone)을 목록·상세·등록·수정·삭제하는 관제용 관리 페이지를 제공합니다. 각 도메인은 list / detail/:id / edit/:id 라우트로 구성됩니다.

기능 개요

관리 페이지는 세 도메인으로 나뉩니다. 디바이스(/devices → DeviceList · DeviceRegisterList · DeviceDetail · DeviceEdit), 서비스 대상(/service-targets → ServiceTargetList/Detail/Edit), 구역(/zones → ZoneList/Detail/Edit)입니다. 라우팅은 각 도메인마다 목록(index), 상세(detail/:id), 편집(edit/:id) 패턴으로 통일되어 있습니다. 같은 라우트 트리에는 이후 위젯 설정 화면(widget-settings)과, SiteGuard를 거치지 않는 독립 공개 라우트인 SMS 수신동의 페이지(/:site/sms-consent)가 추가되었습니다.

API는 BFF의 /bff/monitor/* 경로를 사용합니다. 디바이스는 deviceApi.deviceList()/deviceDetail()/deleteDevice(), 구역은 commonApi의 areaList/areaDetail/registArea/editArea/deleteArea 및 구역-디바이스 연동(areaDeviceList/areaDeviceRegist/areaDeviceDelete — 목록은 페이지·검색 타입·키워드 파라미터를 지원), 서비스 대상은 serviceTargets/serviceTargetDetail/deleteServiceTarget이 담당합니다. 마커 설정은 areaMarkersList/areaMarkersUpsert로 구역 단위 마커를 관리합니다. deviceApi에는 관리 CRUD 외에 위젯·현황용 조회(통신상태 수신 현황 connectionStatusReceived, 탄소중립 일별 수거 중량 collWeight/collReduceWeight)가, commonApi에는 사용자 약관 동의(updateUserStipulation)와 무인증 공개 페이지에서 호출하는 SMS 수신동의(smsConsent — fire-and-forget이라 항상 skipError) 엔드포인트가 추가되어 있습니다.

조회는 React Query로 페이지네이션·필터(검색 타입·키워드·정렬·삭제 포함 여부)를 적용하고, 등록/수정/삭제는 Mutation으로 처리한 뒤 목록을 무효화·갱신합니다. 모든 요청은 ApiClient 인터셉터가 Bearer 토큰과 unitServiceCode 헤더를 자동 주입하고(세션에 site가 없으면 URL 첫 경로 세그먼트로 보정), 응답 오류 중 BPG- 코드의 업무 검증 오류는 서버 메시지를 그대로 오류 다이얼로그에 노출합니다. 구역 편집 화면의 KT 지도 SDK 지도는 좌표값을 parseFloatLatData/parseFloatLngData와 DEFAULT_MAP_CENTER 공용 상수로 fallback 처리합니다.

설계 포인트
구역(Area) API는 download 플래그로 같은 엔드포인트를 /areas.csv + responseType: 'blob'으로 재사용해 목록 조회와 CSV 다운로드를 한 함수로 처리합니다.

시퀀스 다이어그램

sequenceDiagram autonumber participant List as DeviceList / ZoneList / ServiceTargetList participant RQ as React Query participant API as deviceApi / commonApi participant Client as ApiClient (interceptor) participant BFF as BFF /bff/monitor List->>RQ: useQuery(목록 + 필터) RQ->>API: list(params) API->>Client: GET (Authorization, unitServiceCode 주입) Client->>BFF: /bff/monitor/devices | /areas | /targets BFF-->>List: rows + paging List->>API: detail/:id 조회 또는 등록/수정/삭제 API->>BFF: GET/POST/PUT/DELETE BFF-->>List: 결과 → 목록 invalidate/refetch

흐름. 목록·상세·편집 화면이 도메인 API를 통해 BFF에 CRUD를 수행하며, 인증 헤더는 ApiClient 인터셉터가 일괄 주입합니다.

클래스 다이어그램

관계. 관리 화면이 deviceApi·commonApi를 통해 CRUD를 수행하고, 두 모듈 모두 ApiClient(공통 인터셉터)를 거쳐 BFF와 통신합니다.

핵심 코드

src/api/device.ts — 디바이스 조회/상세/삭제
export const deviceApi = {
  deviceList: (deviceRequest: DevicesRequest) =>
    /* GET /bff/monitor/devices */ /* ... */,
  deviceDetail: (serviceTargetId: string, deviceId: string) =>
    apiClient.get(`/bff/monitor/devices/${serviceTargetId}/${deviceId}`).then((res) => res.data),
  deleteDevice: (serviceTargetId: string, deviceId: string) =>
    apiClient.delete(`/bff/monitor/devices/${serviceTargetId}/${deviceId}`).then((res) => res.data),
};
src/api/common.ts — 구역(Area) CRUD와 다운로드 겸용 목록
areaList: (params, download?) =>
  apiClient.get(`/bff/monitor/areas${download ? '/areas.csv' : ''}`, {
    responseType: download ? 'blob' : 'json',
    params: { ...params },
  }).then((res) => (download ? res : res.data)),
registArea: (params) => apiClient.post('/bff/monitor/areas', { ...params }).then((r) => r.data),
editArea: (areaId, params) => apiClient.put(`/bff/monitor/areas/${areaId}`, { ...params }).then((r) => r.data),
deleteArea: (areaId) => apiClient.delete(`/bff/monitor/areas/${areaId}`).then((r) => r.data),
