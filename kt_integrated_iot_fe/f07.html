디바이스·서비스대상·구역 관리

기능 개요

관리 페이지는 세 도메인으로 나뉩니다. 디바이스(/devices → DeviceList · DeviceRegisterList · DeviceDetail · DeviceEdit), 서비스 대상(/service-targets → ServiceTargetList/Detail/Edit), 구역(/zones → ZoneList/Detail/Edit)입니다. 라우팅은 각 도메인마다 목록(index), 상세(detail/:id), 편집(edit/:id) 패턴으로 통일되어 있습니다. 같은 라우트 트리에는 이후 위젯 설정 화면(widget-settings)과, SiteGuard를 거치지 않는 독립 공개 라우트인 SMS 수신동의 페이지(/:site/sms-consent)가 추가되었습니다.

API는 BFF의 /bff/monitor/* 경로를 사용합니다. 디바이스는 deviceApi.deviceList()/deviceDetail()/deleteDevice(), 구역은 commonApi의 areaList/areaDetail/registArea/editArea/deleteArea 및 구역-디바이스 연동(areaDeviceList/areaDeviceRegist/areaDeviceDelete — 목록은 페이지·검색 타입·키워드 파라미터를 지원), 서비스 대상은 serviceTargets/serviceTargetDetail/deleteServiceTarget이 담당합니다. 마커 설정은 areaMarkersList/areaMarkersUpsert로 구역 단위 마커를 관리합니다. deviceApi에는 관리 CRUD 외에 위젯·현황용 조회(통신상태 수신 현황 connectionStatusReceived — swagger 갱신에 맞춰 조회대상(targetDeviceType: 실외/소음/악취/미세먼지) 선택 인자가 추가되어 넘기지 않으면 전체를 반환합니다, 탄소중립 일별 수거 중량 collWeight/collReduceWeight)가, commonApi에는 사용자 약관 동의(updateUserStipulation)와 무인증 공개 페이지에서 호출하는 SMS 수신동의(smsConsent — fire-and-forget이라 항상 skipError) 엔드포인트가 추가되어 있습니다.

조회는 React Query로 페이지네이션·필터(검색 타입·키워드·정렬·삭제 포함 여부)를 적용하고, 등록/수정/삭제는 Mutation으로 처리한 뒤 목록을 무효화·갱신합니다. 모든 요청은 ApiClient 인터셉터가 Bearer 토큰과 unitServiceCode 헤더를 자동 주입하고(세션에 site가 없으면 URL 첫 경로 세그먼트로 보정), 응답 오류 중 BPG- 코드의 업무 검증 오류는 서버 메시지를 그대로 오류 다이얼로그에 노출합니다. 구역 편집 화면의 KT 지도 SDK 지도는 좌표값을 parseFloatLatData/parseFloatLngData와 DEFAULT_MAP_CENTER 공용 상수로 fallback 처리합니다.

도메인 API 시그니처에는 공통 요청 옵션 ApiRequestOptions(requestMode·skipError·signal·timeout만 뽑아낸 axios 설정 타입)가 선택 인자로 추가되었습니다. deviceApi.deviceList/deviceDetail/deviceImage/markerList/propertyDetail 등 조회 계열이 모두 이 옵션을 받아 호출부에서 AbortSignal과 백그라운드 요청 모드를 내려보낼 수 있습니다. commonApi에는 토큰 갱신(refreshToken)과 상세코드 목록 조회(getDetailCodes(groupCode) — 예: KEPCO_HQ 한전본부 목록)가 추가되었고, 서비스 소개 조회는 unitServiceCode를 인터셉터가 항상 주입하므로 serviceTargetId 인자를 없애고 getServiceIntro(introType)로 단순화되었습니다.

서비스 대상 목록 조회는 내부 공용 함수 getServiceTargets(params, unitServiceCode)로 한 번 감싸고, 화면 상단(헤더·사이드바)에서 쓰는 전체 목록은 commonApi.headerServiceTargets(unitServiceCode)로 따로 노출했습니다. 이 호출은 고정 파라미터 HEADER_SERVICE_TARGET_PARAMS(page 0·size 10000·sortField: 'SERVICE_TARGET_NAME'·sortOrder: 'ASC')를 쓰므로, 상단 서비스 대상 목록이 항상 이름순으로 정렬되어 나옵니다. Header·Sidebar가 직접 serviceTargets({ page: 0, size: 10000 })를 부르던 자리는 모두 이 함수로 교체되었습니다.

디바이스 등록·수정 화면(DeviceEdit)은 사이트별 하위 화면을 React.lazy + Suspense로 분리 로딩하도록 바뀌었습니다. 정적 import 시절에는 현재 사이트에서 쓰지 않는 사이트의 지도 SDK까지 함께 로드되어 등록 화면이 중단되는 문제가 있었기 때문입니다. AI산업안전DX 등록 화면(DeviceEditAidx)은 모델·구역 목록의 queryFn 안에서 formik.setFieldValue를 호출하던 구조를 걷어내고, 조회 결과를 useEffect에서 "등록 모드이고 값이 비어 있을 때만" 채우도록 옮겨 반복 갱신을 없앴습니다. 설치일 CustomPicker에는 resetOnPickerTypeChange={false}를 주어, pickerType 변화로 날짜가 오늘로 되돌아가지 않게 했습니다.

스마트그린 관리 화면은 헤더의 가상 "전체" 항목(ALL_SERVICE_TARGET, id ALL)을 서비스대상 선택지에서 제외하도록 정리되었습니다. 미선택 상태가 이미 전체 조회이기 때문입니다. 디바이스 목록(DeviceListSmartGreen)과 AI산업안전DX 디바이스 목록(DeviceListAidx)의 CSV 다운로드 버튼이 다시 활성화되었고, 다운로드는 화면 입력값(draft)이 아니라 실제 적용된 searchParams를 사용하도록 바로잡혔습니다. 서비스대상 목록·CSV는 smartGreenApi.serviceTargets(params, download, site.realcode)로 unitServiceCode 헤더를 명시 전달하고, 코스 삭제 후 현재 페이지가 비면 앞 페이지로 이동합니다. 디바이스 편집(DeviceEditSmartGreen)은 서비스대상(골프장) 변경 시 설치 코스·홀과 deviceName1/2를 초기화하되 useRef 가드로 최초 마운트에서는 건너뛰어, 수정 진입 시 기존 값이 지워지지 않게 합니다.

설계 포인트
구역(Area) API는 download 플래그로 같은 엔드포인트를 /areas.csv + responseType: 'blob'으로 재사용해 목록 조회와 CSV 다운로드를 한 함수로 처리합니다. 한편 자동 갱신(AutoRefreshRoute)은 home·overview 라우트에만 적용되므로, 이 관리 화면들은 주기적 백그라운드 갱신 대상이 아니라 사용자의 조회·저장 동작으로만 갱신됩니다.

관계. 관리 화면이 deviceApi·commonApi·smartGreenApi를 통해 CRUD를 수행하고, 세 모듈 모두 ApiClient(공통 인터셉터)를 거쳐 BFF와 통신합니다. 조회 계열 함수는 ApiRequestOptions를 선택 인자로 받아 AbortSignal·요청 모드·타임아웃을 호출부에서 지정할 수 있습니다. 디바이스 등록·수정은 DeviceEdit이 사이트 코드로 분기하되 하위 화면을 지연 로딩해, 쓰지 않는 사이트의 지도 SDK가 함께 끌려오지 않게 합니다.

src/api/device.ts — 디바이스 조회/상세/삭제
export const deviceApi = {
  deviceList: (deviceRequest: DevicesRequest, options?: ApiRequestOptions) =>
    apiClient
      .get('/bff/monitor/devices', { params: deviceRequest, ...options })
      .then((res) => res.data),
  deviceDetail: (serviceTargetId: string, deviceId: string, options?: ApiRequestOptions) =>
    apiClient
      .get(`/bff/monitor/devices/${serviceTargetId}/${deviceId}`, options)
      .then((res) => res.data),
  deleteDevice: (serviceTargetId: string, deviceId: string) =>
    apiClient.delete(`/bff/monitor/devices/${serviceTargetId}/${deviceId}`).then((res) => res.data),
};

// src/types/api.d.ts — 조회 계열이 공통으로 받는 요청 옵션
export type ApiRequestOptions = Pick<
  import('axios').AxiosRequestConfig,
  'requestMode' | 'skipError' | 'signal' | 'timeout'
>;

type ServiceTargetListParams = {
  size: number;
  page: number;
  serviceTargetName?: string;
  serviceTargetId?: string;
  serviceType?: string;
  sortField?: 'SERVICE_TARGET_NAME';
  sortOrder?: 'ASC' | 'DESC';
};

const HEADER_SERVICE_TARGET_PARAMS: ServiceTargetListParams = {
  page: 0,
  size: 10000,
  sortField: 'SERVICE_TARGET_NAME',
  sortOrder: 'ASC',
};

const getServiceTargets = (params: ServiceTargetListParams, unitServiceCode?: string) =>
  apiClient.get('/bff/monitor/targets', {
    headers: { ...(unitServiceCode && { unitServiceCode }) },
    params: {
      ...params,
      serviceTargetId: params.serviceTargetId?.trim() || undefined,
      serviceTargetName: params.serviceTargetName?.trim() || undefined,
      serviceType: params.serviceType?.trim() || undefined,
    },
  }).then((res) => res.data);

serviceTargets: getServiceTargets,
headerServiceTargets: (unitServiceCode?: string) =>
  getServiceTargets(HEADER_SERVICE_TARGET_PARAMS, unitServiceCode),
