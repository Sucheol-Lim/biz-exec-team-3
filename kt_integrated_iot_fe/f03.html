기능 개요

DashboardMap은 react-grid-layout의 Responsive + WidthProvider를 사용해 위젯 카드를 격자에 배치합니다. 컨테이너 크기에 맞춰 cols와 maxRows를 동적으로 계산하고, config.ts의 GRID_LAYOUT_* 상수로 격자 단위·여백을 정합니다. 저장된 위젯 목록은 getSavedWidgets(site.code, 'map_' + serviceType, savedWidgets)로 사이트·서비스타입별로 불러옵니다. 저장분이 없으면 types/widget.ts의 사이트별 기본 배치(defaultAirmapAirCard·defaultAirmapAirMap 등)로 대체하고, Air Map 지도형에서는 normalizeWidgets가 message_stats_kpi 위젯의 높이를 고정 보정합니다. 저장분 판정 기준은 길이가 아니라 저장 속성의 존재 여부로 바뀌었습니다. 예전에는 저장값 길이가 0이면 기본 배치로 되돌아가 위젯을 전부 닫아도 다음 진입에서 되살아났는데, 지금은 hasOwnProperty로 해당 type 키가 있는지 먼저 보고 명시적인 빈 배열은 '위젯 0개' 설정으로 인정합니다. Air Map 기본·추가 목록에서는 '장애(미수신) 현황'(failure_status) 위젯이 제거되었습니다. 위젯 추가 팝업 목록은 getAvailableWidgets(code, type)이 반환하며, 스마트그린의 '디바이스 생육 현황'(device_growth_status)은 카드형에서만 추가할 수 있도록 availableSmartGreenWidgetsCard로 분리했습니다(지도형 제외). 스마트그린 기본 배치의 위젯별 최소 크기(mW/mH)도 상향 조정되었습니다.

각 카드는 WidgetComp(components/widget)가 위젯 type에 따라 적절한 위젯 컴포넌트(예: OverAllStatus, EventOccurrence, DeviceStatus, WeatherInfo, AMI/SMART GREEN 위젯 등)를 골라 렌더링합니다. Air Map에는 상태별 색상 범례 위젯(status_color_legend → StatusColorLegend)이 신설되어 지도형·카드형 기본 배치와 추가 가능 목록에 모두 포함되었습니다. 범례 색상은 hex를 직접 박지 않고 airQuality의 GRADE_CONFIG를 단일 소스로 참조하므로, 지도 마커·차트의 등급색과 항상 같은 값을 씁니다. 위젯 목록과 배치는 commonApi.widgetList()로 조회하고 registWidget·editWidget·deleteWidget으로 영속화합니다. 이와 별개로 관리 메뉴에 위젯 설정 페이지(widget-settings)가 신설되어, config.ts의 WIDGET_SETTING_SERVICE_TYPES(isWidgetSettingServiceType)로 허용된 서비스타입 — 현재 AI산업안전DX 제조공정 전용 — 에서만 메뉴가 노출됩니다.

편집 모드(isEditMode)에서만 드래그·리사이즈가 허용되며, onLayoutChange가 변경된 좌표·크기를 위젯 상태에 반영합니다. limitBottom이 카드가 격자 최대 행(GRID_LAYOUT_MAX_ROWS)을 넘지 않도록 보정합니다. 편집 종료 시 WidgetControl이 변경 배치를 저장합니다.

카드 헤더의 닫기 버튼은 더 이상 WidgetComp가 직접 처리하지 않습니다. WidgetProps가 setWidgets 대신 onRequestClose(widget) 콜백을 받도록 바뀌어, 실제 제거 정책은 DashboardMap·DashboardCard가 결정합니다. 두 화면 모두 handleRequestClose에서 남은 위젯이 하나뿐이면 곧바로 지우지 않고 Alarm 확인 팝업(pendingCloseWidget)을 띄워 "홈 화면의 모든 위젯이 사라집니다."를 안내한 뒤 확인을 받습니다. 제거 자체(closeWidget)는 편집 모드가 아닐 때만 onChangeSavedWidgets(site.code, widgetLayoutType, nextWidgets)로 즉시 저장하고, 편집 모드에서는 저장 버튼을 누르기 전까지 draft 상태로만 유지합니다. 위젯이 0개가 된 카드형 화면에는 격자 위에 "표시할 위젯이 없습니다. 위젯 편집 버튼 클릭 후 원하는 위젯을 배치해 보세요."라는 빈 상태 문구를 겹쳐 보여 주며, 이 문구는 배치 로드가 끝난 뒤(isWidgetLayoutLoaded) 비편집 상태에서만 노출하고 pointerEvents: 'none'으로 두어 아래 조작을 막지 않습니다. 지도형은 위젯이 0개여도 지도 구성을 그대로 유지합니다.

'위젯 0개'를 유효한 설정으로 인정하면서 기존 저장값과의 해석 충돌이 생기므로, 브라우저 저장 설정(localStorage 키 zpdlxl-dkdldhxl-zjafig)에 스키마 버전(widgetLayoutVersion, 현재 WIDGET_LAYOUT_VERSION = 2)이 도입되었습니다. useLocalStorage가 선택 인자로 migrate 함수를 받아 첫 렌더 전에 변환을 끝내고 결과를 즉시 다시 기록하므로 구버전 값이 화면에 노출되지 않습니다. 변환기 migrateWidgetLayoutConfig는 구버전의 빈 배열을 저장 속성째 제거해(과거 로직에서는 기본 배치로 해석됐던 값이므로) 기존 사용자 화면을 유지하고, Air Map 저장 배치에서 제거된 failure_status 위젯을 함께 걷어냅니다. 아울러 onChangeSavedWidgets는 prev를 직접 변경하던 방식을 버리고 immutable 갱신으로 새 객체를 반환합니다 — 같은 참조를 돌려주면 useLocalStorage의 setState가 Object.is로 변경 없음이라 판단해 재렌더를 건너뛸 수 있기 때문입니다. 위젯 On/Off 표시 여부도 같은 저장소에 사이트 단위로 남습니다(hiddenWidgetSites · onChangeHideWidgets(code, hide)). 이때 사용자 지역 관리 패널의 임시 강제 숨김은 HeaderProvider의 별도 상태(forceHideWidgets)로 분리되어 사용자 선호값(userHideWidgets)을 덮어쓰지 않습니다.

대시보드 위젯은 사용자가 새로고침하지 않아도 최신 값을 유지해야 하므로, modules/autoRefresh 모듈이 신설되어 주기적 배경 갱신을 담당합니다. 각 위젯은 createAutoRefreshQueryOptions({ scope, fetcher })로 React Query 옵션을 만들고, 이 팩토리가 queryFn(화면 조회)과 meta.autoRefresh.backgroundFetch(배경 갱신)를 같은 fetcher로 묶습니다. 덕분에 두 경로가 같은 API·같은 변환을 공유하고, 배경 경로만 requestMode: 'background'·skipError: true·30초 타임아웃(AUTO_REFRESH_REQUEST_TIMEOUT_MS)을 덧붙여 실패해도 오류 팝업을 띄우지 않습니다. meta는 해당 사이트가 자동 갱신 대상일 때만 붙이므로(isAirMapAutoRefreshTarget 등), 대상이 아닌 사이트에서는 위젯이 종전대로 동작합니다.

실제 스케줄러는 AutoRefreshBoundary입니다. 마운트 시 AUTO_REFRESH_INTERVAL_MS 타이머를 걸고(policy.ts에서 5분으로 시작했다가 1분으로 단축), 발화하면 QueryCache에서 meta.autoRefresh.scope가 자신의 스코프와 같은 활성 Query만 모아 배경 갱신 배치를 돌립니다. 배치 직전에 commonApi.refreshToken으로 세션 토큰을 먼저 회전시키며, 응답의 access token JWT에서 뽑은 id(getTokenPayloadId)가 요청 당시 사용자와 다르면 커밋하지 않습니다. 갱신 결과를 캐시에 반영하기 전에는 canCommitBackgroundResult()가 dispose·pause 세대·사이트 일치·Query 인스턴스 동일성·활성 여부·foreground 진행 여부·dataUpdateCount/errorUpdateCount 불변을 모두 확인해, 늦게 도착한 응답이 최신 화면 데이터를 덮어쓰지 못하게 막습니다. 탭이 숨겨지거나 오프라인이면 타이머를 걷고 재예약하지 않습니다. 전체 기능은 VITE_AUTO_REFRESH_ENABLED 플래그로 켜고 끕니다.

위젯 편집 중에 화면이 갱신되면 편집 상태가 흔들리므로, DashboardMap·DashboardCard는 isEditMode가 켜지는 동안 pauseAutoRefresh()를 호출하고 편집이 끝나는 시점(effect cleanup)에 resumeAutoRefresh()로 새 주기를 시작합니다. 위젯 내부의 필터 변경처럼 사용자가 방금 조작한 직후에는 postponeAutoRefresh()로 유휴 타이머만 뒤로 미룹니다. useAutoRefreshActivity()는 바운더리 밖이나 플래그 OFF 상태에서도 항상 안전한 no-op 기본값을 돌려주므로 호출부에 분기가 필요 없습니다.

설계 포인트
비편집 상태에서는 빈 격자 영역의 클릭이 아래 지도로 전달되도록 부모 Stack의 pointerEvents를 none으로 두고, 각 카드 Box만 auto로 두어 지도와 위젯이 한 화면에 공존합니다. 자동 갱신 쪽에서는 pausedRef·hiddenRef 같은 상태를 모두 ref로 관리해, pause/resume이 일어날 때마다 바운더리가 재렌더되어 하위 위젯 트리 전체가 다시 그려지는 일을 피합니다.

export const getSavedWidgets = (code, type, widgetData, isDefault?) => {
  const normalizeWidgets = (widgets) => {
    if (!widgets) return widgets;
    if (code === SITE_CODES.AIRMAP && type.startsWith('map')) {
      return widgets.map((widget) =>
        widget.type === 'message_stats_kpi'
          ? { ...widget, h: 18, mH: widget.mH ?? 12 }
          : widget,
      );
    }
    return widgets;
  };

  // 저장 속성 부재는 기본값, 명시적 []는 위젯 0개 설정으로 구분한다.
  const hasSaved = Object.prototype.hasOwnProperty.call(widgetData?.[code] ?? {}, type);
  const saved = hasSaved ? widgetData[code][type] : null;
  if (hasSaved && Array.isArray(saved) && !isDefault) {
    return normalizeWidgets(saved);
  } else {
    switch (code) {
      case SITE_CODES.AIRMAP:
        return normalizeWidgets(type.startsWith('card') ? defaultAirmapAirCard : defaultAirmapAirMap);
      // ... 사이트 코드별 기본 배치 분기
    }
  }
};

// 위젯 추가 팝업: 스마트그린 '디바이스 생육 현황'은 카드형에서만 추가 가능
export const getAvailableWidgets = (code: string, type: string): Widget[] => {
  switch (code) {
    case SITE_CODES.AIRMAP:
      return availableAirmapWidgets;
    case SITE_CODES.SMART_GREEN:
      return type.includes('card') ? availableSmartGreenWidgetsCard : availableSmartGreenWidgets;
    default:
      return getSavedWidgets(code, type, null, true) ?? [];
  }
};

  if (storedConfig?.widgetLayoutVersion === WIDGET_LAYOUT_VERSION) return storedConfig;

      // Air Map 저장 배치에서 제거된 '장애(미수신) 현황' 위젯을 걷어낸다
      const normalizedWidgets =
        siteCode === SITE_CODES.AIRMAP && Array.isArray(widgets)
          ? widgets.filter((widget) => !isFailureStatusWidget(widget))
          : widgets;

      if (Array.isArray(normalizedWidgets) && normalizedWidgets.length === 0) return;
      migratedLayouts[type] = normalizedWidgets;
    });

    migratedSavedWidgets[siteCode] = migratedLayouts;
  });

  return { ...storedConfig, widgetLayoutVersion: WIDGET_LAYOUT_VERSION,
           savedWidgets: migratedSavedWidgets };
};

src/modules/autoRefresh/createAutoRefreshQueryOptions.ts — foreground/background가 같은 fetcher를 공유
// foreground/background가 동일 API·동일 transform(fetcher)을 공유하도록 강제하는 factory.
// backgroundFetch는 select 이전의 raw shape을 그대로 반환해야 하므로, fetcher 자체가
// select 없는 순수 fetch+transform 함수여야 한다.
export function createAutoRefreshQueryOptions<TData>({ scope, fetcher, meta }) {
  return {
    queryFn: ({ signal }: { signal?: AbortSignal }) => fetcher({ mode: 'foreground', signal }),
    meta: {
      ...meta,
      autoRefresh: {
        scope,
        backgroundFetch: () => fetcher({ mode: 'background' }),
      },
    } satisfies QueryMeta,
  };
}

src/modules/autoRefresh/AutoRefreshBoundary.tsx — 배경 갱신 커밋 가드
const canCommitBackgroundResult = ({ startedQuery, baselineDataUpdateCount,
                                     baselineErrorUpdateCount, pauseGeneration }) => {
  if (disposedRef.current) return false;
  if (pausedRef.current) return false;
  if (pauseGeneration !== pauseGenerationRef.current) return false;   // pause 이전 요청
  if (!isSiteSynchronized()) return false;                            // 사이트 전환됨

  const currentQuery = queryClient.getQueryCache()
    .find({ queryKey: startedQuery.queryKey, exact: true });

  if (!currentQuery || currentQuery !== startedQuery) return false;   // Query 인스턴스 교체
  if (!currentQuery.isActive()) return false;                         // 화면에서 사라짐
  if (currentQuery.state.fetchStatus === 'fetching') return false;    // foreground 진행 중

  // 요청 시작 이후 화면에서 이미 갱신됐다면 덮어쓰지 않는다
  return currentQuery.state.dataUpdateCount === baselineDataUpdateCount
      && currentQuery.state.errorUpdateCount === baselineErrorUpdateCount;
};
