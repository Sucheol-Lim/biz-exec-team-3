기능 개요

이력 화면(pages/history/HistoryMain.tsx)은 세션 site.code로 SafeMate 4종 등 사이트별 이력 컴포넌트(HistoryFire, HistoryBell, HistoryMonitor, HistoryRoof)를 분기 렌더합니다. 각 이력 화면은 기간·서비스대상·검색어 등 필터를 받아 도메인 API로 페이지네이션 조회를 수행합니다. 이벤트 발생 이력은 logEventApi.eventList() 같은 로그 엔드포인트로 가져오고, 디바이스 제어/등록/삭제 이력과 문자 발송 이력도 각 도메인 모듈에서 제공합니다.

모든 요청은 ApiClient의 요청 인터셉터가 Bearer 토큰과 unitServiceCode 헤더를 자동 주입합니다. 로그인 직후처럼 세션에 site가 아직 없으면 URL 첫 경로 세그먼트로 SITE_LIST를 조회해(resolveUnitServiceCodeFromPath) unitServiceCode를 한 번 더 보정합니다. 조회된 이력은 테이블로 렌더링되며, 다운로드 버튼은 responseType: 'blob'으로 요청한 응답을 downloadFileFromResponse에 넘깁니다. 이 함수는 응답의 content-disposition 헤더에서 filename*=UTF-8'' 또는 filename="..." 패턴을 정규식으로 파싱해 실제 파일명을 추출하고, 없으면 fallback 파일명을 사용합니다.

추출된 파일명으로 임시 a 엘리먼트를 만들어 URL.createObjectURL 링크를 클릭시킨 뒤, 즉시 제거하고 revokeObjectURL로 자원을 해제합니다. 즉 별도 다운로드 라이브러리 없이 브라우저 기본 동작으로 파일을 저장합니다.

조회 기간은 공용 상수 utils/dateRange.ts의 DATE_RANGE_LIMIT_DAYS(90일)로 제한하고, 기간 선택기 옆에 dateRangeLimitNotice() 안내 문구를 노출합니다. 국가관측망 현황(NationalNetworkStatus), 스마트그린 생육·디바이스 이력(GrowthHistory·DeviceHistory) 등이 maxRangeDays로 이 상수를 공유해, 서버에서 기간 초과 오류를 받기 전에 화면 단에서 먼저 막습니다. 스마트그린 이력 화면의 기간 단위는 DAY/WEEK/MONTH/INSTALLED(설치일 직접 선택)로 통일되었고, 조회·다운로드가 같은 검색 조건(서비스대상·디바이스)을 쓰도록 applied 상태를 통째로 교체하는 방식으로 정리되었습니다.

CSV 다운로드 경로도 화면별로 정비되었습니다. 국가관측망 현황은 buildLogsParams()로 조회·다운로드 파라미터 생성을 한곳에 모아 페이징만 다르게(MAX_DATA_ROW, page 0) 넘기며, 조회 전에는 downloadDisabled로 버튼을 잠급니다. Air Map 측정소별 현황·공기질 비교는 swagger 규격에 맞춘 전용 엔드포인트(airmapDeviceCollectionsLogsDownload, airmapDeviceCollectionsLogsCompareDownload — .../air-quality-compare.csv)로 분리했고, AI산업안전DX 설비 이력은 facilityAnalyzeList 대신 facilityHistoryList(.../collection/facility/logs.csv)를 호출하도록 교체되었습니다. 전문가 분석 보고서 다운로드는 존재하지 않는 목록 CSV 경로 대신 첨부 파일 흐름(boardApi.fileList(fileId) → downloadFile(fileItemSequence) → downloadFileFromResponse)으로 바뀌어, 원본 파일명(originalName)으로 저장하고 첨부가 없으면 안내 팝업을 띄웁니다.

다운로드 형식은 화면 헤더의 "전체(전체분석) 분석 다운로드"만 xlsx로 분리되었습니다. Air Map 측정소별 현황은 airmapDeviceCollectionsLogsXlsx(.../devices/collections/logs.xlsx), 종합 분석 측정위치별은 airmapApi.getAreaAnalyticsXlsx(.../device/area/analytics.xlsx), 측정소별 분석은 airmapApi.getDeviceAnalyticsXlsx(.../device/analytics.xlsx)를 호출하며, 각 화면 하단 표의 "CSV 다운로드"는 기존 .csv 엔드포인트를 그대로 씁니다. xlsx 계열은 형제 CSV 엔드포인트와 파라미터가 달라 size·page를 받지 않으므로, 요청 타입도 DeviceCollectionsLogsXlsxRequest처럼 별도로 정의해 슬롯별 serviceTargetId/deviceId 쌍(KT·국가망·선택)만 전달합니다. 전체분석 다운로드는 서버가 측정소 최소 1개를 요구하므로, 아무 측정소도 고르지 않았으면 요청 전에 안내 팝업을 띄웁니다.

전 측정소 다운로드(airmapDeviceCollectionsLogsDownload)에는 swagger 갱신에 맞춰 serviceTargetId 파라미터가 추가되었고, 조회 기간은 MAX_ALL_STATIONS_DOWNLOAD_DAYS(31일)로 제한됩니다. 기간이 31일을 넘으면 "31일치만 다운로드 가능합니다" 확인 팝업을 띄우고, 확인 시 startDate를 endDate 기준 MAX - 1일 전으로 보정해 시작일·종료일 포함 정확히 31일이 되도록 잡습니다. 버튼은 탭과 무관한 페이지 헤더에 있어 현재 보고 있는 탭(상세 공기질 / 공기질 비교)의 조회 조건을 useRef로 최신값을 읽어 채택합니다.

목록형 이력·조회 화면은 노출 개수를 바꾸면 첫 페이지로 되돌리도록 통일되었습니다. 서버 페이징이라 페이지를 옮긴 상태에서 10 → 20으로 늘리면 남아 있던 page로 존재하지 않는 구간을 요청해 조회가 에러로 끝나기 때문입니다. SafeMate 이력(HistoryFire·HistoryRoof), 전문가 분석 보고서 목록, 국가관측망 현황이 모두 같은 방식(handleRowCountChange 또는 setPage(1))으로 처리합니다. 국가관측망 현황의 기준단위 선택지에는 기존 일·시간·5분에 더해 MIN10·MIN1이 추가되었습니다.

2026-09-01~09-16 사이 전문가 분석 보고서(ExpertAnalysis)는 API·화면이 함께 서비스대상 단위로 재편되었습니다. 목록 조회는 airmapApi.getExpertReports(swagger에 없던 /bff/monitor/boards.csv 기반)를 걷어내고 boardApi.reportList(GET /bff/monitor/boards/report)로 옮겨, 헤더에서 선택한 serviceTargetId가 필수 파라미터가 되었습니다. 헤더 서비스대상이 없으면 조회 자체가 enabled: false로 비활성화되고, 대상이 바뀌면 첫 페이지로 되돌립니다. 등록도 boardApi.add 대신 registReport(POST .../boards/report)로 옮겨 같은 serviceTargetId를 함께 보내며, 검색 카테고리 값도 swagger enum과 맞춰 소문자(all/reportName/registrant)에서 대문자(ALL/TITLE/CREATORID)로 바뀌었습니다(소문자로 보내면 검색조건이 적용되지 않습니다). 응답 식별자도 BoardVO.boardSequence가 아니라 전용 reportSequence(ExpertReportRow)로 교체되어, 삭제(boardApi.deleteReport, DELETE .../boards/report/{reportSequence})도 이 값을 씁니다. reportSequence가 없는 행은 삭제 요청 자체를 보내지 않고 실패로 집계하며, 일부만 실패해도 성공한 건은 이미 지워졌으므로 onSuccess/onError 양쪽에서 목록 캐시(expertReports 전체 prefix)를 invalidateQueries로 갱신한 뒤 "n건 삭제/스킵" 메시지를 구분해 보여줍니다. 목록 헤더에도 표를 좁혀 온 서비스대상명을 표시하기 위해, 페이지 타이틀이 headerServiceTarget.serviceTargetName이 있으면 "대상명 전문가 보고서"로 바뀝니다.

등록·삭제 버튼은 hasRole(1)(관제요원 이상)일 때만 노출되어 서비스 고객 계정에서는 다운로드만 가능합니다. 등록 팝업은 파일 선택창을 직접 여는 방식(<input type="file" hidden>)에서 전용 다이얼로그(ReportRegisterPopup)로 바뀌어, 공용 CustomFile에 MAX_FILE_SIZE(10MB, config.ts) 기반 limitSize를 넘겨 하단 용량 카운터와 초과 알림을 함께 노출합니다. 삭제 확인·알림 팝업(DeleteConfirmPopup·AlertPopup)은 직접 그리던 Dialog를 걷어내고 저장소 공통 팝업(@/modal/Alarm)으로 교체되어 버튼 variant·모서리·폭이 다른 화면과 통일되었으며, 알림의 확인 버튼은 okContent로 전달해 회색(soft)이 아닌 primary 색으로 렌더됩니다. 다운로드는 첨부 크기에 따라 시간이 걸릴 수 있어 클릭과 동시에 DownloadNoticePopup(안내 문구)을 띄우고 완료·실패 시 호출부가 닫는 방식으로 바뀌었습니다.

설계 포인트
파일명 한글이 깨지지 않도록 filename*=UTF-8''(RFC 5987) 형태를 우선 매칭합니다. ApiClient 응답 인터셉터는 최근 두 가지가 바뀌었습니다. TanStack Query가 화면 이탈·Query 교체 시 AbortSignal로 취소한 요청은 axios.isCancel로 걸러 오류 팝업을 띄우지 않고 취소 상태를 그대로 전달하며, skipError 요청의 조기 reject는 제거되어 skipError라도 401 인증 오류 처리(세션 정리 후 로그인 이동)는 반드시 통과합니다. 조회 기간 초과(BPG-4006/BPG-4007/BPG-4008) 같은 BPG-* 업무 검증 에러는 서버 message를 그대로 에러 다이얼로그에 노출합니다.

핵심 코드

src/api/ApiClient.ts — Content-Disposition 기반 파일 저장
export function downloadFileFromResponse(res: AxiosResponse<Blob>, fallbackFileName = 'download.csv') {
  const blob = new Blob([res.data], { type: res.headers['content-type'] });
  const url = URL.createObjectURL(blob);
  const disposition = res.headers['content-disposition'];
  const fileName =
    disposition
      ?.match(/filename\*=UTF-8''([^;]+)|filename="([^"]+)"/)
      ?.slice(1).find(Boolean) ?? fallbackFileName;
  const link = document.createElement('a');
  link.href = url; link.download = fileName;
  document.body.appendChild(link); link.click();
  link.remove(); URL.revokeObjectURL(url);
}

  (error) => {
    // TanStack Query가 화면 이탈·Query 교체 시 AbortSignal로 취소한 요청은
    // 서비스 장애가 아니므로 오류 팝업을 표시하지 않고 취소 상태를 그대로 전달한다.
    if (axios.isCancel(error)) {
      return Promise.reject(error);
    }

const getDaysSpan = (info: AirmapDateRangeSearchInfo | null): number | null => {
  if (!info?.startDate || !info?.endDate) return null;
  return dayjs(info.endDate).diff(dayjs(info.startDate), 'day') + 1;
};

const handleAllStationsDownloadClick = () => {
  const daysSpan = getDaysSpan(activeSearchInfoRef.current);

// fileId → fileList로 첨부 목록 조회 → fileItemSequence별 blob 다운로드
const downloadMutation = useMutation({
  mutationFn: async (rows: BoardVO[]) => {
    let downloaded = 0;
    for (const row of rows) {
      if (!row.fileId) continue;
      const listRes = await boardApi.fileList(row.fileId);
      const fileItems = listRes?.result?.rows ?? [];
      for (const item of fileItems) {
        if (!item?.fileItemSequence) continue;
        const blobRes = await boardApi.downloadFile(item.fileItemSequence);
        downloadFileFromResponse(blobRes, item.originalName || item.name || row.title);
        downloaded += 1;
      }
    }
    return downloaded;
  },
  onSuccess: (downloaded: number) => {
    if (downloaded === 0) showAlert('선택한 보고서에 첨부된 파일이 없습니다.');
  },
  onError: () => showAlert('다운로드에 실패했습니다.'),
});

const deleteMutation = useMutation({
  mutationFn: async (rows: ExpertReportRow[]) => {
    const deletable = rows.filter((row) => row.reportSequence != null);
    const skipped = rows.length - deletable.length;
    const results = await Promise.allSettled(
      deletable.map((row) => boardApi.deleteReport(row.reportSequence)),
    );
    const failed = results.filter((r) => r.status === 'rejected').length + skipped;
    return { total: rows.length, failed, skipped };
  },
  onSuccess: async ({ total, failed, skipped }) => {
    await invalidateReports();   // expertReports 캐시 전체 invalidate (조회조건이 다른 캐시도 갱신)
    if (failed === 0) return showAlert('삭제되었습니다.');
    if (skipped === total) return showAlert('보고서 정보를 확인할 수 없어 삭제할 수 없습니다. 목록을 새로 고친 뒤 다시 시도해주세요.');
    if (failed === total) return showAlert('삭제에 실패했습니다.');
    showAlert(`${total - failed}건을 삭제했습니다. ${failed}건은 삭제하지 못했습니다.`);
  },
});
