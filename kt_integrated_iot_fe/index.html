개요

본 과제는 KT가 개별적으로 운영하던 여러 IoT 서비스를 하나의 웹 콘솔에서 통합 관제하기 위한 프론트엔드입니다. 사이트(서비스) 단위로 화면이 분기되며, 지도 기반 현황, 종합 현황, 이력, 통계 요약, 디바이스·서비스 대상·구역 관리, 공지·자료실·문의, SMS 발송·알림, AI 에이전트 대화 등 관제 운영에 필요한 기능을 단일 애플리케이션으로 제공합니다.

대상 플랫폼은 웹 브라우저 기반 데스크톱 관제 콘솔입니다. React 19 + Vite 기반의 SPA로 구현되어 있으며, 엔트리 HTML의 타이틀은 "KT IoT"입니다. 화면은 사이트 단위로 진입하며 URL은 모두 /:site 세그먼트로 시작합니다.

src/config.ts의 SITE_LIST·SITE_MENU에 정의된 대상 서비스는 Air Map(대기질 측정 관제, 과천 관제센터 별도 진입점 포함), AI산업안전DX(산업대기질·자원순환·산업환경·탄소중립·제조공정 등 환경 DX), SafeMate(지능형 화재 감지기·옥상 비상문·소방시설 모니터링·지능형 비상벨 4종), 한전 AMI(AMI 회선·공사 현황 관제), SMART GREEN(생육 디바이스 관제)입니다.

사업 맥락 (Confluence 근거)
각각 존재하던 KT의 IoT 서비스들을 하나로 통합하는 과제입니다. R&R 상 KT가 IoT 플랫폼을, H2Net이 통합 관리 F/E·BFF·Edge 서버·Mobile App을, Altimedia가 전체 UX 및 통합 관제 F/E와 관제용 일부 관리 페이지(AXDX Client)를 담당합니다. 본 저장소는 그중 관제 F/E(지도형·카드형)에 해당합니다.

사용자 권한(USER_ROLES)은 서비스 고객 / 서비스 관제요원 / 서비스 운영자 / 서비스 관리자 / 플랫폼 관리자 5단계로 구분되며, 라우팅 단에서 권한 레벨에 따라 사이트 간 전환을 제어합니다. 인증은 reCAPTCHA v3·RSA 키 기반 로그인과 BFF(Back-end For Front-end) API를 통해 이뤄집니다.

상용 전환 현황 (팀 확인 기준, 2026-08)
위 5개는 코드(SITE_LIST)에 구현되어 있는 서비스 종류를 정리한 것으로, 실제 상용 전환 여부와는 별개입니다. 수행3팀 확인 기준 현재 상용 전환이 완료된 서비스는 에어맵, 과천(관제센터, 별도 과제로 취급), AI산업안전DX, SMART GREEN, 한전 AMI 5개입니다. SafeMate(및 하위 4개 서비스)는 상용화가 1년 뒤로 유예되었습니다. 과천은 코드상으로도 에어맵과 site code(GWACHEON)·URL(airmon)이 분리된 별도 항목이라 별도 과제로 구분하는 근거가 있고, SafeMate 관련 git log상 다수의 "KT미노출요청" 커밋도 이 유예 결정과 맥락이 닿아 있는 것으로 보입니다.

주요 기능

멀티 사이트 통합 관제
Air Map·AI산업안전DX·SafeMate(4종)·한전 AMI·SMART GREEN을 하나의 콘솔에서 사이트 단위로 분기해 관제합니다. URL은 모두 /:site로 시작합니다.
지도형 대시보드
KT 자체 지도 SDK(kt-map-sdk-js / geomaster / geoanalysis) 기반으로 디바이스·시설물·이벤트 마커를 지도에 표출하고, 마커 다이얼로그·그리기 컨트롤을 제공합니다.
카드형 종합 현황
react-grid-layout 기반 위젯 그리드로 실시간 디바이스·시설물 현황, 이벤트 현황 등을 카드 형태로 구성합니다. 배치와 위젯 On/Off 상태는 사이트별로 저장되며, 저장 스키마는 버전 기반으로 마이그레이션됩니다.
실시간 이벤트 수신
STOMP over WebSocket으로 관제 이벤트를 실시간 수신합니다. GZIP 페이로드를 pako로 해제하고, 알림(Alarm)·이벤트 마커로 라우팅합니다.
통계 요약·분석
Nivo·D3 차트로 측정소별 비교, 이벤트·디바이스 통계, AI산업안전DX 설비 이용률·자원환경, SMART GREEN 생육 디바이스 분석 등을 시각화합니다.
이력 조회
이벤트 발생 이력, 디바이스 제어·등록/삭제 이력, 문자 발송 이력 등을 조회하고 Content-Disposition 기반 파일 다운로드를 지원합니다.
디바이스·서비스대상·구역 관리
디바이스, 서비스 대상, 구역(Zone)을 목록·상세·등록·수정·삭제하는 관제용 관리 페이지를 제공합니다.
SMS 발송 및 알림 설정
이벤트 대상에 대한 SMS 발송(sms-send)과 알림 설정(sms-alert-settings)을 운영합니다. 수신자용 무인증 SMS 수신동의 페이지(sms-consent)도 제공합니다.
AI 에이전트 대화
WebSocket의 threadId·isActiveAgent 판별로 에이전트 응답을 분리 수신하며, aiagent 모달에서 스레드·메시지 기반 대화를 제공합니다.
게시판·자료실·문의
공지사항(notice), 자료실(resource), 문의(contact-us)를 목록·상세·편집 단위로 제공합니다. 홈 진입 시 팝업 공지를 최대 3개까지 계단식으로 노출하며, 자료실은 파일 확장자 제한 등 보안성 검증이 반영되어 있습니다.
권한 기반 사이트 전환 제어
SiteGuard·checkPermission이 권한 레벨에 따라 사이트 간 전환을 판정합니다. 부적합 접근 시 WebSocket 해제·세션 정리 후 로그인으로 이동합니다.
보안 로그인·마스킹
RSA(jsrsasign) 암호화와 Google reCAPTCHA v3 토큰 기반 로그인, 개인정보 마스킹/해제, OTP·비밀번호 변경 등 인증 모달을 제공합니다.
과천 관제센터 특화 화면
Air Map 하위 과천 진입점에 통신 상태·미수신·센싱 오류·전송 실패 등 측정망 운영 특화 화면을 별도로 제공합니다.
테마·레이아웃 커스터마이징
MUI 테마(palette·typography) 커스터마이징과 사이트별 메뉴 구성, 화면 배경색·로고 설정, 위젯 설정 화면(widget-settings, 제조공정DX 전용) 등 운영 환경에 맞춘 외형 조정을 지원합니다.

아키텍처 · 모듈 구조

React 19 SPA로, src/main.tsx에서 다수의 Provider 트리를 구성하고 src/routes/route.tsx가 사이트 가드와 코드 스플리팅된 페이지 라우팅을 담당하는 단일 페이지 구조입니다. 데이터 패칭은 TanStack React Query, 클라이언트 상태는 Redux Toolkit과 다수의 React Context로 분리되어 있으며, 실시간 채널은 STOMP WebSocket Provider가 전역으로 관리합니다.

주요 모듈 · 클래스

모듈/파일역할
src/main.tsx앱 부트스트랩. ReCaptcha → Config → Header → MUI 테마 → QueryClient → WebSocket → HomeMapState → DrawControl → BrowserRouter → AliveScope → ErrorDialog → Routes 순으로 Provider를 구성합니다. Alt + V로 버전/업데이트 일자를 표시합니다.
src/config.ts사이트 목록(SITE_LIST), 메뉴(SITE_MENU), 권한(USER_ROLES), 레이아웃/그리드 상수, AI산업안전DX 서비스 타입 등 전역 상수를 정의합니다. AI산업안전DX 메뉴는 서비스 타입 5종(산업대기질·자원순환·산업환경·탄소중립·제조공정)에 유형 미지정을 뜻하는 '전체'(AIDX_ALL_SERVICE_TYPE) 항목이 더해진 하위 메뉴로 분화됩니다. 로그인 화면 하단 문의처는 LOGIN_CONTACT_INFO에 사이트 코드별로 정의합니다. 홈 위젯 저장 스키마 버전(WIDGET_LAYOUT_VERSION)과 사이트별 위젯 On/Off 저장소(hiddenWidgetSites) 기본값도 여기에서 관리합니다.
src/routes/route.tsx모든 경로가 /:site로 시작. SiteGuard가 URL site 유효성과 권한 기반 전환 가능 여부(hasRole)를 검사하며 페이지는 전부 React.lazy로 스플리팅됩니다. /:site/sms-consent는 SiteGuard·ProtectedRoute를 타지 않는 무인증 공개 라우트로 별도 등록됩니다. 핵심 동작 흐름

1. 앱 부팅 · 인증 시퀀스

  1. 앱 부트스트랩main.tsx가 #root에 React 19 루트를 마운트하고 ReCaptcha·Config·Header·MUI 테마·QueryClient·WebSocket·HomeMapState·DrawControl·Router·AliveScope·ErrorDialog Provider 트리를 순서대로 구성합니다.
  2. 사이트 진입 · 가드 검사/:site 경로로 진입하면 SiteGuard가 URL의 site가 SITE_LIST에 있는지, 세션 사이트와 이동 대상 간 전환이 권한 레벨상 허용되는지 검사합니다.
  3. 로그인 (RSA + reCAPTCHA + 약관 동의)AuthLayout 아래 Login에서 RSA 키로 암호화한 자격증명과 reCAPTCHA v3 토큰(X-RECAPTCHA-TOKEN)을 bff/monitor/token으로 전송하고 accessToken·site 정보를 세션에 저장합니다. 약관 미동의 계정(stipulationYn=N)은 약관 동의(이용·수집이용·제3자 제공) 팝업과 동의 API 호출을 거쳐 재로그인해야 토큰이 발급됩니다.
  4. 보호 라우트 진입ProtectedRoute가 세션 site.code 유무로 로그인 여부를 판단해 MainLayout 아래 보호된 화면으로 진입시킵니다. 이후 모든 API 요청은 Bearer 토큰과 unitServiceCode 헤더를 자동 주입합니다.
  5. WebSocket 구독commonApi.subscription()으로 큐 ID를 받아 세션에 저장한 뒤 STOMP 채널을 구독해 실시간 관제 이벤트 수신을 시작합니다.

2. 실시간 이벤트 수신 처리

  1. 메시지 수신STOMP 채널로 메시지가 도착하면 페이로드 앞 바이트(0x1f 0x8b)로 GZIP 압축 여부를 판별합니다.
  2. 해제 · 파싱압축이면 pako.inflate로 해제하고 UTF-8 디코딩 후 JSON으로 파싱합니다.
  3. 라우팅 분기threadId가 있고 AI 에이전트가 활성(isActiveAgent)이면 lastMessage(에이전트 응답)로, 그 외에는 lastEvent(관제 이벤트)로 라우팅합니다.
  4. 화면 반영 · 알림관제 이벤트는 지도 마커·위젯·Alarm으로 반영하고, 연결 오류 시 최대 5회 재시도 후 오류 처리합니다.

3. 데이터 조회 · 다운로드 흐름

  1. 조회 요청페이지 진입 시 React Query 훅이 도메인 API 모듈을 호출하며, ApiClient가 baseURL·인증 헤더를 적용해 BFF REST API로 요청합니다.
  2. 캐싱 · 렌더링응답은 React Query 캐시에 저장되고 차트(Nivo/D3)·테이블·위젯으로 렌더링됩니다. KeepAlive로 페이지 전환 시 상태가 보존됩니다.
  3. 파일 다운로드이력·통계 다운로드 요청은 downloadFileFromResponse가 Content-Disposition 헤더를 해석해 파일로 저장합니다. 목록 하단의 CSV 다운로드는 *.csv 엔드포인트를, 에어맵 종합/측정소별 분석의 '전체 분석 다운로드'는 analytics.xlsx 엔드포인트를 blob으로 받아 처리합니다.
  4. 오류 처리401이면 세션을 비우고 /:site/login으로 리다이렉트하며, 그 외 오류는 공통 ErrorDialog(네트워크 오류 status 999)로 표시합니다.

4. 유휴 자동 갱신 (auto-refresh)

  1. Boundary 마운트Home·Overview 라우트를 감싼 AutoRefreshRoute가 {sitePath}:{scope}를 key로 AutoRefreshBoundary를 마운트합니다. 사이트가 바뀌면 key가 바뀌어 Boundary가 통째로 재마운트되고 새 타이머가 시작됩니다.
  2. 타이머 예약기본 1분(AUTO_REFRESH_INTERVAL_MS) 주기로 다음 실행을 예약합니다. 폐기(disposed)·일시정지(paused)·문서 비가시(hidden)·오프라인·세션 사이트 불일치 중 하나라도 해당하면 예약을 건너뜁니다.
  3. 사용자 활동 반영조회 조건 변경 등 사용자 활동이 있으면 useAutoRefreshActivity의 postponeAutoRefresh로 다음 실행 시각을 미루고, 위젯 편집모드처럼 갱신이 곤란한 구간은 pauseAutoRefresh/resumeAutoRefresh로 멈췄다 재개합니다.
  4. 토큰 갱신 후 백그라운드 조회실행 시점에 세션 스냅샷(userId·accessToken·refreshToken)을 확인해 commonApi.refreshToken으로 토큰을 갱신한 뒤, 활성 Query의 meta.autoRefresh.backgroundFetch를 호출해 화면 로딩 표시 없이 데이터를 다시 가져옵니다.
  5. commit 가드응답 도착 시 폐기·일시정지·pause 세대 불일치·사이트 불일치·Query 인스턴스 교체·비활성 Query·foreground 조회 진행 중·조회 시작 이후 dataUpdateCount 변동을 순서대로 검사해, 하나라도 걸리면 결과를 버리고 캐시를 덮어쓰지 않습니다.
비활성화 스위치
자동 갱신은 VITE_AUTO_REFRESH_ENABLED 환경 변수가 'true'일 때만 동작합니다. 플래그가 꺼져 있거나 Boundary 밖에서 호출돼도 useAutoRefreshActivity는 항상 no-op 기본값을 돌려주므로 호출부는 분기 없이 동일하게 작성합니다.

빌드 · 실행

package.json의 scripts와 vite.config.ts를 근거로 합니다. 패키지 매니저는 npm입니다.

# 의존성 설치
npm install

# 개발 서버 (Vite dev, VITE_ 환경변수 로드)
npm run dev

# 환경별 빌드 (dev / sandbox 모드 — CI에서도 사용)
npm run build:dev
npm run build:sand

# 프로덕션 모드 미리보기 빌드 + 미리보기 서버
npm run preview          # vite-build 후 vite preview --host
npm run preview-rel      # release 모드 빌드 후 미리보기

# 빌드 산출물 미리보기
npm run vite-preview

# Vite 캐시 정리
npm run clean:vite       # scripts/clearViteCache.js 실행

# release 빌드 (log/live 플래그 조합 4종 순차 생성 → release/*.zip)
npm run release

환경 설정은 .env.local·.env.sandbox(ENV_NAME local) / .env.dev(ENV_NAME testbed) / .env.prd(ENV_NAME prd, API https://biz.airmap.kt.com) 4종에서 VITE_API_PATH(REST API), VITE_WEBSOCKET_SERVER(STOMP WebSocket), VITE_KT_MAP_API_KEY(지도 SDK 키), VITE_RECAPTCHA_SITE_KEY, VITE_API_SESSION_TIMEOUT, VITE_AUTO_REFRESH_ENABLED(유휴 자동 갱신 on/off), 버전·업데이트 일자 등을 정의합니다. VITE_ENV_NAME === 'local'이면 라우팅에 개발용 가이드 화면(Guide)이 추가됩니다. 기존 .env.prod는 .env.prd로 이름과 값이 정리되면서 VITE_WEBSOCKET_SERVER 항목이 빠졌습니다.

산출물 형태는 vite.config.ts가 command(serve/build)와 mode에 따라 분기합니다. mode === 'release'일 때 esbuild minify·CSS 단일 번들·vite-plugin-zip-pack으로 release/에 YYYYMMDD_<APP_NAME>_<VERSION>_<NETWORK>_<LOG_LEVEL>_.zip 형태로 패킹합니다. CLI 인자 log/live로 로그 레벨(DEBUG/INFO)과 네트워크 환경(Prod/Stag)을 주입합니다. geoanalysis 워커 파일은 빌드 시 public/assets · dist/assets로 복사됩니다. GitHub Actions CI는 브랜치별로 ci-dev.yml(dev push)과 ci-main.yml(main push)로 분리되어 있으며, Azure Key Vault에서 사내 Nexus 자격증명을 받아 npm ci → vite build --mode prd -- log=false live=true 빌드 후 산출물 zip과 Trivy 스캔용 번들을 Azure Blob Storage(컨테이너 prd)에 업로드하고, 후속 trivy 잡에서 취약점 스캔을 수행합니다.

주의
build:prod 스크립트는 vite build --mode prod 뒤에 node scripts/zip.js를 호출하지만, 현재 저장소에는 scripts/zip.js가 없고(존재 파일은 clearViteCache.js뿐) .env.prod도 .env.prd로 이름이 바뀌어 prod 모드로는 운영 환경 변수가 로드되지 않습니다(확인 필요 — CI는 --mode prd를 사용합니다). 또한 package.json의 description·main·homepage 등 일부 메타와 README.md는 Vite React 템플릿 기본값이 남아 있어 실제 프로젝트 내용과 일치하지 않습니다.

2026-08-07 ~ 2026-08-28(135 커밋, 병합 제외 96 커밋)은 게시판·홈 위젯·에어맵 분석 다운로드를 운영 피드백에 맞춰 다듬는 작업이 중심입니다. 가장 손이 많이 간 영역은 게시판(공지사항·자료실·문의)으로, 세 화면 모두 queryKeys.ts를 두어 쿼리 키를 unitServiceCode 단위로 정리하고 CRUD 직후 상세 재요청을 막도록 캐시 정합성을 손봤으며, 목록 복귀 동선은 src/pages/boardNavigation.ts가 라우트 state에 쌓인 깊이를 읽어 뒤로가기 횟수를 계산하도록 바뀌었습니다. 여기에 공지사항 팝업 노출(popupYn)이 새로 붙어, 홈 진입 시 /bff/monitor/boards/notice/popup으로 받은 팝업 공지를 src/modal/notice/NoticePopup.tsx가 최대 3개(MAX_POPUP_NOTICE_COUNT)까지 계단식으로 겹쳐 띄우고 "오늘 하루 보지 않기"를 쿠키로 기억합니다. 팝업 GUI는 목업 개정에 따라 여러 차례 재조정되었습니다. 홈 위젯 쪽에서는 에어맵의 "장애(미수신) 현황" 위젯이 제거되고, 이미 저장된 사용자 레이아웃을 정리하기 위해 src/utils/widgetLayoutConfig.ts와 WIDGET_LAYOUT_VERSION 기반 마이그레이션이 도입되었습니다. 위젯 On/Off 표시 상태도 hiddenWidgetSites로 사이트별 영속화되었고, 저장값이 빈 배열이면 "위젯 0개"로 인정하도록 기본값 판정 규칙이 정리되었습니다. 에어맵 분석은 종합 분석·측정소별 분석의 "전체 분석 다운로드"가 area/analytics.xlsx·device/analytics.xlsx 엔드포인트를 쓰는 xlsx로 전환되었고, 전 측정소 다운로드에 조회 조건·정렬(orderType)·serviceTargetId가 반영되면서 최대 조회 기간이 31일로 제한되었습니다. 측정 항목도 실외 공기질 탭에 온도·습도가 추가되고 유동인구·신호등·VOCs·CO가 빠지는 식으로 조정되었으며, 조회 기준단위에 10분·1분이 추가되었습니다. 알림 SMS 설정에는 소음 항목과 카드 되돌리기 버튼이 들어갔고, 임계치와 문구를 짝으로 검증하도록 저장 규칙이 정리되었으며 수신자 삭제 API는 값이 있는 알람 템플릿 시퀀스만 전달하도록 바뀌었습니다. 한전 AMI는 종합현황 화면이 KPI 카드 제거·필터/상세 필드 매핑 재정비로 크게 개편되었고, 한전본부 목록은 하드코딩 대신 useKepcoHqOptions가 KEPCO_HQ 공통코드를 조회하도록 정리되었습니다. 그 밖에 스마트 검색 결과를 접근 가능한 메뉴 기준으로 걸러내는 smartSearchFilter.ts 추가, 산업안전DX 디바이스 등록 화면의 지도 SDK 로딩·반복 갱신 오류 수정, 과천 관제센터 마커 팝업 전용 단건 조회(gwacheonApi.deviceDetail) 도입, 취약점 리포트에 따른 의존성 상향(dompurify 3.4.13 등)이 이뤄졌고, 유휴 자동 갱신 주기는 5분에서 1분으로 단축되었습니다.
