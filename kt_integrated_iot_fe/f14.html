기능 개요

ThemeCustomization(themes/index.tsx)은 ConfigContext의 mode(라이트/다크)를 읽어 createTheme로 MUI 테마를 생성합니다. 색상은 palette(mode), 글꼴·타이포는 typography, 컴포넌트 기본 스타일은 getComponents(theme, mode)로 분리해 주입합니다. 생성된 테마는 ThemeProvider로 전체 앱에 적용되고 CssBaseline로 기본 스타일을 초기화합니다.

테마는 mode가 바뀔 때만 재생성되도록 useMemo로 메모이즈됩니다. ThemeCustomization은 main.tsx의 Provider 트리에서 ConfigProvider·HeaderProvider 아래에 위치해, 설정 상태가 테마에 즉시 반영됩니다. 사용자가 라이트/다크를 전환하면 지도 틴트 레이어(기능 02)나 로그인 로고(getLogo(type, mode))처럼 모드에 의존하는 화면 요소도 함께 바뀝니다.

레이아웃·메뉴는 config.ts 상수가 결정합니다. SITE_MENU는 서비스 그룹(Air Map·AI산업안전DX·SafeMate·SMART GREEN·한전 AMI)별 하위 메뉴를 정의하고, DRAWER_FULL_WIDTH·HEADER_HEIGHT·FOOTER_HEIGHT 등 레이아웃 치수와 GRID_LAYOUT_* 위젯 격자 상수도 함께 둡니다. 사이트 진입 경로는 운영 반영 과정에서 air→airbiz, dx→factorydx, gwacheon→airmon으로 바뀌었고, 로고·배경을 경로로 분기하던 Sidebar·AuthLayout·Login의 getLogo/getBg도 같은 값으로 갱신되었습니다.

AI산업안전DX 그룹은 AIENVDX_SERVICE_TYPE_LIST(산업대기질·자원순환·산업환경·탄소중립·제조공정) 5개에, 유형 필터를 해제하는 전체 항목(AIDX_ALL_SERVICE_TYPE = 'ALL')이 맨 앞에 추가되어 같은 경로(factorydx)에 serviceType만 다른 6개 전환 메뉴가 되었습니다. 사이드바 서브타이틀과 브라우저 탭 제목은 AIENVDX_SERVICE_TYPE_LIST를 직접 뒤지던 코드를 공용 getDxServiceTypeLabel(serviceType)으로 통일해 ‘전체’ 상태까지 한 함수로 처리합니다. 위젯 설정 메뉴(widget-settings)는 WIDGET_SETTING_SERVICE_TYPES(현재 제조공정 ENVSMAT30203 전용)와 판별 함수 isWidgetSettingServiceType으로 노출을 제어합니다. 테마 설정 화면(pages/theme/ThemeSetting)에서 외형 옵션을 조정할 수 있습니다.

메뉴 목록 자체는 getMenuList(siteCode, serviceType)가 사이트 코드별 switch로 조립합니다. AI산업안전DX는 서비스 고객(!hasRole(1))일 때 종합 현황·서비스대상 관리·디바이스 관리를 넣지 않고 구역 관리만 제조공정에서 예외적으로 노출하며, 한전 AMI는 KT 요청으로 주석 처리돼 있던 현황·배전선로 작업현황 메뉴가 다시 노출되도록 복구되었습니다. 헤더 서비스대상 드롭다운은 공용 serviceTargetList를 유형 구분 없이 전체로 보관하되(설비가동률분석 등 관리자용 유형 전환 라디오가 전체 목록을 필요로 함), 화면에 뿌릴 때만 getDisplayOptions()로 현재 user.serviceType에 맞춰 걸러 냅니다. 목록 조회는 Header·Sidebar·로그인 직후 세팅이 각각 commonApi.serviceTargets({ page: 0, size: 10000 })를 부르던 것을 공용 헬퍼 commonApi.headerServiceTargets()로 통일해, 세 경로 모두 이름순(sortField: 'SERVICE_TARGET_NAME', sortOrder: 'ASC')으로 같은 순서를 받습니다. 메뉴 조립 함수도 순수 함수 buildMenuList와 캐시를 갱신하는 getMenuList로 나뉘어, 사이드바 렌더와 무관하게 임의 사이트·유형의 메뉴를 다시 계산할 수 있습니다.

사용자별 외형·배치 설정은 ConfigProvider가 useLocalStorage로 브라우저 로컬 스토리지 한 키(zpdlxl-dkdldhxl-zjafig)에 통째로 보관합니다. 보관 항목은 mode·miniDrawer에 더해 사이트별 위젯 배치(savedWidgets), 사이트별 위젯 On/Off 상태(hiddenWidgetSites), 저장 포맷 버전(widgetLayoutVersion)까지 확장되었습니다. 위젯 On/Off는 예전엔 화면 상태로만 남아 새로고침하면 초기화됐지만, onChangeHideWidgets(code, hide)로 배치와 같은 사이트 단위 영구 설정이 되었습니다. 갱신 함수(onChangeSavedWidgets·onChangeHideWidgets)는 이전 상태를 직접 고쳐 같은 참조를 돌려주던 방식에서, 새 객체를 반환하는 immutable 갱신으로 바뀌었습니다. 같은 참조를 돌려주면 useLocalStorage의 setState가 Object.is로 변경 없음이라 판단해 재렌더를 건너뛸 수 있기 때문입니다.

저장 포맷이 바뀔 때를 대비해 마이그레이션 훅도 들어갔습니다. useLocalStorage(key, defaultValue, migrate)는 세 번째 인자로 변환 콜백을 받아 첫 렌더 전에 저장값을 변환하고, 결과가 달라졌으면 그 자리에서 다시 기록해 구버전 값이 화면에 잠깐이라도 노출되지 않게 합니다. 다른 탭에서 온 storage 이벤트 값도 같은 변환을 거칩니다. 실제 변환기 migrateWidgetLayoutConfig는 저장된 widgetLayoutVersion이 WIDGET_LAYOUT_VERSION(현재 2)과 다를 때만 동작해, Air Map에서 제거된 장애(미수신) 현황 위젯(type === 'failure_status')을 걸러내고 빈 배열로 남은 배치 항목은 아예 제거합니다. 구버전 로직에서 빈 배열은 기본 위젯으로 해석됐기 때문에 그대로 두면 기존 사용자 화면이 바뀌기 때문이며, 마이그레이션 이후 저장된 빈 배열만 위젯 0개로 인정합니다.

사이트별 외형 분기도 몇 가지 정리되었습니다. 푸터의 ‘에어코리아’ 외부 링크는 성격에 맞게 Air Map과 과천 관제센터에서만 노출하도록 조건이 붙었고, 과천은 Air Map과 같은 경로 그룹이지만 SITE_CODES.GWACHEON으로 먼저 분기해 전용 로그인 배경(bg_gwacheon-login.png)과 전용 로고(loginGwacheon.svg)를 사용합니다. 로그인 화면 하단 문의처는 LOGIN_CONTACT_INFO 맵에 등록된 사이트에만 렌더링됩니다. 전역 스타일(index.css)에는 지도 이종 클러스터 툴팁용 클래스(.cluster-marker-row·.cluster-marker-icon·.cluster-marker-name)가 추가되어, 다크 모드에서 라벨 색을 별도로 덮어씁니다.

레이아웃 셸(MainLayout·main.tsx)에는 렌더 크래시에 대한 최후 방어선으로 ErrorBoundary(components/ErrorBoundary.tsx)가 2단으로 신설되었습니다. variant="content"는 MainLayout의 Outlet만 감싸 페이지 렌더가 예외를 던져도 사이드바·헤더·푸터 셸은 그대로 유지한 채 "다시 시도" 버튼으로 콘텐츠 영역만 복구하고, resetKey로 받은 location.pathname이 바뀌면 오류 상태가 자동으로 리셋됩니다(같은 라우트 안에서 파라미터만 바뀌는 detail/:id 같은 경로가 전체 리마운트되지 않도록 key 재마운트 방식 대신 state 비교 방식을 씁니다). variant="global"은 main.tsx에서 Routes 전체(셸·로그인 화면 포함)를 감싸는 최후 경계로, "새로고침" 버튼이 window.location.reload()를 호출합니다. React가 스스로 복구하는 오류(콘솔의 #520류)는 이 경계에 도달하지 않고 기존처럼 콘솔에만 남습니다.

로그아웃 경로의 크래시·정리 누락도 함께 정리되었습니다. Header의 로그아웃 처리는 순서를 세션 정리 → WebSocket 해제로 뒤집고 disconnect()를 try/catch로 감싸, 소켓 해제가 실패해도 sessionStorage.clear()에 도달하지 못해 인증 정보가 남는 일이 없게 했습니다. Sidebar는 로그아웃 직후 세션이 비워진 채로 다시 렌더될 수 있다는 전제로 isCurrSite의 site.code 접근과 DX 서브타이틀 갱신 useEffect의 site.code 비교를 모두 옵셔널 체이닝으로 바꿨습니다(가드가 없으면 TypeError가 나고 React가 전체 루트를 동기 렌더로 복구하는 콘솔 오류 #520이 남았습니다). 즐겨찾기 토글 아이콘을 다루는 PageLayout은 메뉴 캐시가 아직 채워지지 않은 콜드 로드 첫 렌더에서 menu?.id + '' 같은 문자열 결합으로 'undefined'를 그대로 즐겨찾기 payload에 저장하던 경로를 막아, 클릭 시점에 메뉴를 다시 조회해 유효한 값일 때만 전송합니다. useFavorite 훅에도 같은 방어가 한 번 더 들어가, 다른 호출 경로가 생겨도 오염이 재발하지 않습니다.

설계 포인트
palette·typography·components를 파일로 분리하고 mode를 인자로 받는 팩토리 형태로 둬서, 라이트/다크 두 모드를 같은 테마 구성으로 일관되게 생성합니다. 사이트·권한에 따른 차이는 테마가 아니라 config 상수와 getMenuList 조립 단계에 모아, 테마 생성 로직이 사이트별 분기로 오염되지 않게 했습니다.

흐름. ConfigContext의 mode가 바뀌면 ThemeCustomization이 테마를 재생성해 ThemeProvider로 전역에 반영합니다. 사이트·서비스 유형 전환은 테마와 별개로 Sidebar가 getDxServiceTypeLabel·getMenuList로 서브타이틀과 메뉴를 다시 구성합니다. 모드·서랍·위젯 배치 등 사용자 설정은 useLocalStorage가 한 키에 저장하며, 저장 포맷 버전이 다르면 첫 렌더 전에 변환합니다.

관계. ThemeCustomization이 ConfigContext의 mode를 구독해 palette·typography·components로 테마를 조립하고, 레이아웃·메뉴는 config 상수와 getMenuList가 결정합니다. 사용자 설정 값 자체는 useLocalStorage가 보관하고, 저장 포맷 변경은 migrateWidgetLayoutConfig가 흡수합니다.

핵심 코드

src/themes/index.tsx — mode 기반 MUI 테마 생성
export default function ThemeCustomization({ children }: Props) {
  const { mode } = useContext(ConfigContext);
  const theme = useMemo(
    () => createTheme({ palette: { mode, ...palette(mode) }, typography }),
    [mode],
  );
  theme.components = getComponents(theme, mode);
  return (
    <ThemeProvider theme={theme}>
      <CssBaseline />
      {children}
    </ThemeProvider>
  );
}

class ErrorBoundary extends React.Component<ErrorBoundaryProps, ErrorBoundaryState> {
  state = { hasError: false, resetKey: this.props.resetKey };
  static getDerivedStateFromError() { return { hasError: true }; }
  // resetKey(예: location.pathname)가 바뀌면 리마운트 없이 오류 상태만 되돌린다
  static getDerivedStateFromProps(props, state) {
    if (props.resetKey !== state.resetKey) return { hasError: false, resetKey: props.resetKey };
    return null;
  }
  componentDidCatch(error, info) { log.error(`[ErrorBoundary:${this.props.variant}]`, error, info.componentStack); }
  render() {
    if (!this.state.hasError) return this.props.children;
    const isGlobal = this.props.variant === 'global';
    return (
      <Stack sx={{ padding: isGlobal ? 0 : `${HEADER_HEIGHT}px 0 ${FOOTER_HEIGHT}px 0` }}>
        <Text>화면을 표시하는 중 문제가 발생했습니다</Text>
        <Button onClick={() => isGlobal ? window.location.reload() : this.setState({ hasError: false })}>
          {isGlobal ? '새로고침' : '다시 시도'}
        </Button>
      </Stack>
    );
  }
}
