기능 개요

ThemeCustomization(themes/index.tsx)은 ConfigContext의 mode(라이트/다크)를 읽어 createTheme로 MUI 테마를 생성합니다. 색상은 palette(mode), 글꼴·타이포는 typography, 컴포넌트 기본 스타일은 getComponents(theme, mode)로 분리해 주입합니다. 생성된 테마는 ThemeProvider로 전체 앱에 적용되고 CssBaseline로 기본 스타일을 초기화합니다.

테마는 mode가 바뀔 때만 재생성되도록 useMemo로 메모이즈됩니다. ThemeCustomization은 main.tsx의 Provider 트리에서 ConfigProvider·HeaderProvider 아래에 위치해, 설정 상태가 테마에 즉시 반영됩니다. 사용자가 라이트/다크를 전환하면 지도 틴트 레이어(기능 02)나 로그인 로고(getLogo(type, mode))처럼 모드에 의존하는 화면 요소도 함께 바뀝니다.

레이아웃·메뉴는 config.ts 상수가 결정합니다. SITE_MENU는 서비스 그룹(Air Map·AI산업안전DX·SafeMate·SMART GREEN·한전 AMI)별 하위 메뉴를 정의하고, DRAWER_FULL_WIDTH·HEADER_HEIGHT·FOOTER_HEIGHT 등 레이아웃 치수와 GRID_LAYOUT_* 위젯 격자 상수도 함께 둡니다. 사이트 진입 경로는 운영 반영 과정에서 air→airbiz, dx→factorydx, gwacheon→airmon으로 바뀌었고, 로고·배경을 경로로 분기하던 Sidebar·AuthLayout·Login의 getLogo/getBg도 같은 값으로 갱신되었습니다.

AI산업안전DX 그룹은 AIENVDX_SERVICE_TYPE_LIST(산업대기질·자원순환·산업환경·탄소중립·제조공정) 5개에, 유형 필터를 해제하는 전체 항목(AIDX_ALL_SERVICE_TYPE = 'ALL')이 맨 앞에 추가되어 같은 경로(factorydx)에 serviceType만 다른 6개 전환 메뉴가 되었습니다. 사이드바 서브타이틀과 브라우저 탭 제목은 AIENVDX_SERVICE_TYPE_LIST를 직접 뒤지던 코드를 공용 getDxServiceTypeLabel(serviceType)으로 통일해 ‘전체’ 상태까지 한 함수로 처리합니다. 위젯 설정 메뉴(widget-settings)는 WIDGET_SETTING_SERVICE_TYPES(현재 제조공정 ENVSMAT30203 전용)와 판별 함수 isWidgetSettingServiceType으로 노출을 제어합니다. 테마 설정 화면(pages/theme/ThemeSetting)에서 외형 옵션을 조정할 수 있습니다.

메뉴 목록 자체는 getMenuList(siteCode, serviceType)가 사이트 코드별 switch로 조립합니다. AI산업안전DX는 서비스 고객(!hasRole(1))일 때 종합 현황·서비스대상 관리·디바이스 관리를 넣지 않고 구역 관리만 제조공정에서 예외적으로 노출하며, 한전 AMI는 KT 요청으로 주석 처리돼 있던 현황·배전선로 작업현황 메뉴가 다시 노출되도록 복구되었습니다. 헤더 서비스대상 드롭다운은 공용 serviceTargetList를 유형 구분 없이 전체로 보관하되(설비가동률분석 등 관리자용 유형 전환 라디오가 전체 목록을 필요로 함), 화면에 뿌릴 때만 getDisplayOptions()로 현재 user.serviceType에 맞춰 걸러 냅니다.

사이트별 외형 분기도 몇 가지 정리되었습니다. 푸터의 ‘에어코리아’ 외부 링크는 성격에 맞게 Air Map과 과천 관제센터에서만 노출하도록 조건이 붙었고, 과천은 Air Map과 같은 경로 그룹이지만 SITE_CODES.GWACHEON으로 먼저 분기해 전용 로그인 배경(bg_gwacheon-login.png)과 전용 로고(loginGwacheon.svg)를 사용합니다. 로그인 화면 하단 문의처는 LOGIN_CONTACT_INFO 맵에 등록된 사이트에만 렌더링됩니다. 전역 스타일(index.css)에는 지도 이종 클러스터 툴팁용 클래스(.cluster-marker-row·.cluster-marker-icon·.cluster-marker-name)가 추가되어, 다크 모드에서 라벨 색을 별도로 덮어씁니다.

설계 포인트
palette·typography·components를 파일로 분리하고 mode를 인자로 받는 팩토리 형태로 둬서, 라이트/다크 두 모드를 같은 테마 구성으로 일관되게 생성합니다. 사이트·권한에 따른 차이는 테마가 아니라 config 상수와 getMenuList 조립 단계에 모아, 테마 생성 로직이 사이트별 분기로 오염되지 않게 했습니다.

관계. ThemeCustomization이 ConfigContext의 mode를 구독해 palette·typography·components로 테마를 조립하고, 레이아웃·메뉴는 config 상수와 getMenuList가 결정합니다.

핵심 코드

src/themes/index.tsx — mode 기반 MUI 테마 생성
export default function ThemeCustomization({ children }: Props) {
  const { mode } = useContext(ConfigContext);
  const theme = useMemo(
    () => createTheme({ palette: { mode, ...palette(mode) }, typography }),
    [mode],
  );
  theme.components = getComponents(theme, mode);
  return (
    <ThemeProvider theme={theme}>
      <CssBaseline />
      {children}
    </ThemeProvider>
  );
}

export const AIDX_ALL_SERVICE_TYPE = 'ALL';
export const getDxServiceTypeLabel = (serviceType?: string | null): string => {
  if (serviceType === AIDX_ALL_SERVICE_TYPE) return '전체';
  return AIENVDX_SERVICE_TYPE_LIST.find((item) => item.id === serviceType)?.label ?? '';
};

// 위젯 설정(widget-settings) 메뉴 노출 — 현재 제조공정(ENVSMAT30203) 전용
export const WIDGET_SETTING_SERVICE_TYPES = [AIDX_MANUFACTURING_PROC] as const;
export const isWidgetSettingServiceType = (serviceType: string | null | undefined) =>
  WIDGET_SETTING_SERVICE_TYPES.some((type) => type === serviceType);
