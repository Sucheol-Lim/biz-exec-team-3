기능 개요

이 앱은 별도 런처를 두지 않고 메인 재생 화면인 PlaybackActivity 자체가 단말의 홈 화면을 겸합니다. AndroidManifest.xml에서 이 액티비티는 android:launchMode="singleInstance"로 선언되어 시스템 전체에 인스턴스가 하나만 존재하며, 인텐트 필터에 category.HOME·category.LEANBACK_LAUNCHER·category.LAUNCHER를 모두 등록해 부팅 직후와 리모컨 홈키 입력 시 이 액티비티가 전면에 올라옵니다.

이미 떠 있는 단일 인스턴스에 새 인텐트가 도착하면 onCreate()가 아니라 onNewIntent()가 호출됩니다. 이 콜백은 CAS 팝업·부팅 다이얼로그 표시 여부, VOD 재생 중 여부, MgmtManager 연결 상태 등을 점검해 새 인텐트를 무시하거나 처리하도록 분기합니다.

최초 부팅(프로세스 기동) 시의 onCreate()는 더 이상 곧바로 플레이어 초기화·네트워크 대기 예약을 하지 않습니다. setContentView() 직후 ctrl/BootNetworkChecker를 생성해 start(listener)로 백그라운드 점검을 맡기고, 기존에 onCreate()가 하던 나머지 초기화(핸들러 생성, NetworkStateManager 초기화, 데이터 유무에 따른 즉시 재생/네트워크 대기 메시지 예약 등)는 새로 분리된 initPlayerAndStartPlayback()으로 옮겨져 체크가 끝난 뒤(성공 또는 타임아웃) 호출됩니다. 이는 단말-공유기 간 연결은 정상이지만 공유기-외부(인터넷) 연결이 지연되는 현상에 대응하기 위한 것으로, 내부 대상 IP(192.168.32.16/192.168.32.17)로 ping을 반복 시도해 응답이 오거나 최대 2분이 지나면 다음 단계로 넘어갑니다.

설계 포인트
excludeFromRecents·clearTaskOnLaunch·stateNotNeeded 속성을 함께 지정해 셋톱박스 런처답게 최근 앱 목록에 남지 않고 항상 깨끗한 단일 태스크로 복귀하도록 했습니다. 진입점인 OttApplication은 onCreate()에서 ApplicationLifecycleListener를 등록해 액티비티 생명주기를 추적합니다. 부팅 네트워크 체크가 첫 실패를 확인한 시점에만 comp/NetworkWaitingPopup을 띄우며(성공 시에는 노출되지 않음), 팝업이 떠 있는 동안 PlaybackActivity.dispatchKeyEvent()는 키 이벤트를 팝업으로 위임합니다.

흐름. 단일 인스턴스라 부팅 시에는 onCreate(), 이미 떠 있을 때 들어오는 홈키/인텐트는 onNewIntent()로 분기됩니다. 부팅 경로는 이제 BootNetworkChecker의 외부 연결 확인(성공 또는 2분 타임아웃)을 먼저 거친 뒤 initPlayerAndStartPlayback()에서 네트워크 대기 후 기본 채널 재생으로 이어집니다.

관계. OttApplication이 생명주기 리스너를 등록하고, 단일 인스턴스 PlaybackActivity가 DeviceAPI.DeviceAPIStateCallback을 구현하며 BootNetworkChecker를 생성·시작합니다. BootNetworkChecker는 NetworkWaitingPopup을 소유하고, 팝업이 떠 있는 동안에는 PlaybackActivity가 키 이벤트를 팝업으로 위임합니다.

핵심 코드

app/src/main/AndroidManifest.xml — 런처 인텐트 필터와 singleInstance 선언
<activity
    android:name=".PlaybackActivity"
    android:clearTaskOnLaunch="true"
    android:excludeFromRecents="true"
    android:exported="true"
    android:launchMode="singleInstance"
    android:stateNotNeeded="true">
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.HOME" />
        <category android:name="android.intent.category.DEFAULT" />
        <category android:name="android.intent.category.LAUNCHER" />
        <category android:name="android.intent.category.LEANBACK_LAUNCHER" />
    </intent-filter>
</activity>
PlaybackActivity.java — onCreate는 부팅 네트워크 체크만 시작하고, 나머지 초기화는 콜백에서 진행
protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    setContentView(R.layout.activity_playback);

    // 부팅 네트워크(외부 연결) 체크 시작
    bootNetworkChecker = new BootNetworkChecker(this);
    bootNetworkChecker.start(success -> {
        // success 여부와 상관없이(성공 또는 2분 타임아웃) 여기서 다음 단계 진행
        initPlayerAndStartPlayback();
    });
}

private void initPlayerAndStartPlayback() {
    // 기존에 onCreate에서 하던 플레이어 초기화 / 재생 시작 로직
    handler = new MyHandler(this);
    NetworkStateManager.getInstance().init(this, mNetworkStateHandler);

    Intent intent = getIntent();
    if (intent.getData() == null) {
        handler.sendEmptyMessageDelayed(MSG_BOOTING_NETWORK_WAITING, DELAY_BOOTING_WAITTING);
    } else {
        if (player == null) player = new Player();
        VOD.createPlayer(this, findViewById(R.id.surface_view));
        player.init(handler, this, findViewById(R.id.surface_view), findViewById(R.id.subtitle_view));
        handleIntent(intent);
    }
}
PlaybackActivity.java — dispatchKeyEvent에서 네트워크 대기 팝업으로 키 이벤트 위임
NetworkWaitingPopup popup = bootNetworkChecker != null ? bootNetworkChecker.getPopup() : null;
if (popup != null && popup.isShowing()) {
    return popup.dispatchKeyEvent(event);   // 팝업이 떠 있는 동안 좌우/확인 키를 팝업이 소비
}
return super.dispatchKeyEvent(event);
