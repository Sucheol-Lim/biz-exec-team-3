개요

본 프로젝트는 KCTV 제주(com.kctvjeju.tvapp)의 Android TV 플랫폼용 OTT·라이브 방송 클라이언트 애플리케이션입니다. Android TV의 Leanback 환경에서 동작하는 런처 겸 미디어 재생 앱으로, 셋톱박스(STB) 단말에 프리빌트(prebuilt) 형태로 탑재되는 것을 전제로 설계되어 있습니다. AndroidManifest.xml에서 android.software.leanback 기능을 필수로 요구하고, 메인 액티비티가 HOME·LEANBACK_LAUNCHER 카테고리를 받도록 등록되어 있어 단말의 홈 런처 역할을 겸합니다.

대상 단말은 마르시스(MARUSYS) 계열 셋톱박스(모델 MAU9001D)이며, 운영체제는 Android 14입니다. 산출물 APK의 파일명 접두어가 tvapp-MARUSYS로 고정되어 있고, 단말 벤더별로 android14/marusys·android14/innopia 등의 브랜치가 분기되어 있습니다. 본 문서는 분석 기준 브랜치인 android14/marusys의 실제 소스와 빌드 설정을 근거로 작성되었습니다.

화면 UI는 서버에서 내려받은 iframe(웹 UI 패키지)을 WebView로 로딩하는 웹 애플리케이션과, 미니 EPG·CAS 팝업·푸시 티커 등 네이티브 다이얼로그/오버레이(comp 패키지)가 결합된 하이브리드 구조입니다. WebServiceHandler가 WebView와 네이티브 사이의 JavaScript 브릿지를 담당하여, 웹 UI에서 채널 전환·재생·단말 정보 조회 등의 네이티브 기능을 호출합니다. 미디어 재생은 사내 플레이어 라이브러리(SoorynPlayer/KctvPlayer)를 AAR로 직접 임베드하여 사용합니다.

사업 맥락
이 앱은 KCTV 제주의 기존 Legacy OTT STB를 Android 11에서 Android 14로 업그레이드하고, 마르시스 단말에 맞춰 재정합한 결과물입니다. Legacy 대비 해상도는 1280x720에서 1920x1080으로, CAS는 Digicap 기반으로, VOD 전송은 RTSP에서 HLS로 전환되었으며, 채널 연동 서비스가 별도 APK에서 WebView 시나리오로 통합되었습니다.

주요 기능

홈 런처 겸용
PlaybackActivity가 singleInstance로 동작하며 HOME·LEANBACK_LAUNCHER 인텐트를 받아 단말의 홈 화면 역할을 수행합니다.
실시간 채널 시청
SoorynPlayer(라이브) 기반으로 멀티캐스트 라이브 채널을 재생하며, 채널 맵·프로그램 정보를 ContentProvider로 관리합니다.
VOD / CH-VOD 재생
KctvPlayer(OTT)와 HLS 기반으로 VOD/채널형 VOD를 재생합니다. (Legacy RTSP에서 HLS로 전환)
미니 EPG
MiniEpgBar·MiniEpgDialog로 현재 채널과 주변 편성 정보를 오버레이로 제공합니다.
WebView 하이브리드 UI
서버에서 내려받은 iframe 웹 UI를 WebView로 로딩하고, WebServiceHandler JS 브릿지로 네이티브 기능을 연결합니다.
CAS(수신제한)
ctrl/CAS가 Digicap 계열 수신제한 시스템을 처리하고, PKDialog 등으로 사용자 인증·시청 제한을 안내합니다.
OOB / Inband SI 수신
OOBService가 멀티캐스트 OOB 터널로 version.json·채널·앱 정보 등 서비스 정보(SI)를 수신하고, Inband로 인밴드 데이터를 처리합니다.
클라우드 연동
Alticast 클라우드 SDK(cloud-sdk)와 mod/cloud 어댑터/프록시(Apex 구현)로 북마크·파일 등 클라우드 서비스를 연동합니다.
통합·음성 검색
LocalSearchProvider ContentProvider와 TvProviderSearch로 통합 검색 및 음성 검색을 지원합니다.
NMS 단말 관리
Agent/AgentController와 nms·qi 패키지로 단말·서비스 상태를 조회하고 NMS 서버로 리포트합니다.
푸시 티커
Push와 PushTickerView/TickerView로 푸시 서버에서 전달된 공지·자막 티커를 화면에 표시합니다.
자동 재부팅 스케줄
reboot 패키지의 RebootScheduler/RebootCheckWorker/RebootWorker가 WorkManager로 단말 자동 재부팅을 스케줄링합니다.
3rd Party 앱 모드 제어
app_packages.properties로 normal/hotel/ott 모드별 허용 앱(YouTube, Netflix, TVING, wavve, Disney+ 등)을 정의합니다.
RCU·블루투스 연동
IETP(JNI 기반 RCU 프로토콜)와 Bluetooth로 리모컨 페어링·블루투스 단말 연동을 처리합니다.
다국어 · 호텔 모드
en/ja/zh 다국어 리소스와 호텔 welcome 화면, 키즈 모드 등 운영 시나리오를 지원합니다.

아키텍처 · 모듈 구조

단일 :app 모듈로 구성된 Android 애플리케이션이며, 소스는 108개의 Java 파일(Kotlin 소스 없음)로 이루어져 있습니다. 진입점인 OttApplication이 라이프사이클 리스너를 등록하고, 모든 화면·재생·오버레이를 단일 액티비티 PlaybackActivity(약 5,500 라인)가 총괄합니다. 화면 표현은 WebView 웹 UI가, 미디어 재생·SI 수신·단말 관리는 네이티브 컨트롤러 계층(ctrl/ott)이 담당하는 하이브리드 계층 구조입니다.

계층 · 외부 연동 관계

웹 UI(WebView)는 WebServiceHandler의 JavaScript 인터페이스를 통해서만 네이티브 기능을 호출하고, 실제 재생은 ctrl/Player가 app/libs/ott/에 동봉된 SoorynPlayer/KctvPlayer AAR을 호출하여 수행합니다. 서비스 정보(SI)는 OOBService(멀티캐스트 OOB)와 Inband(인밴드)로 수신하고, SDP/UIM/PUSH/HLS/NMS 등 서버 주소는 BuildConfig 필드로 주입됩니다. 단말 측 외부 연동으로는 KCTV 업데이터 앱(com.kctv.updater, AIDL), 관리 앱(com.kctvjeju.mgmt), Alticast 클라우드 SDK, IETP/RCU JNI(libtvcoietp.so 등), SI 네이티브 래퍼(nativewrapper-release.aar)가 있습니다.

핵심 동작 흐름

부팅 · 기동 시퀀스

  1. 단말 부팅 → 런처 기동단말 부팅 후 HOME/LEANBACK_LAUNCHER 인텐트로 PlaybackActivity가 홈 런처로 기동되고, OttApplication이 라이프사이클 리스너를 등록합니다.
  2. 권한 · 네트워크 확인위치·블루투스·미디어 등 런타임 권한을 체크하고, 네트워크 미연결 시 BootingNetworkErrorDialog로 안내합니다.
  3. 서비스 정보(SI) 수신OOBService가 멀티캐스트 OOB 터널로 version.json·channelInfo·appInfo·barking·avticker 등을 수신해 채널 맵과 단말 설정을 구성합니다.
  4. iframe(웹 UI) 다운로드 · 로딩DownloadWorker가 INBAND_BASE의 iframe.zip을 내려받고, WebView 컨테이너가 다운로드된 웹 UI를 로딩합니다.
  5. 기본 채널 재생채널 맵 기반으로 기본/마지막 채널을 결정하고 ctrl/Player가 라이브 재생을 시작합니다.

채널 전환 · 재생 흐름

  1. 사용자 입력리모컨 숫자/방향키 또는 WebView UI에서 채널을 선택하면, 웹 UI는 WebServiceHandler JS 브릿지로 네이티브에 전환 요청을 전달합니다.
  2. CAS 검증ctrl/CAS가 해당 채널의 수신제한 여부를 확인하고, 필요 시 PKDialog 등으로 인증·시청 제한을 처리합니다.
  3. 플레이어 전환ctrl/Player가 채널 유형에 따라 SoorynPlayer(라이브) 또는 KctvPlayer(OTT/HLS)를 선택하여 스트림을 준비·재생합니다.
  4. OSD · 미니 EPG 표시osd 채널 표시와 MiniEpgBar가 현재 채널·편성 정보를 오버레이로 노출하고, 자막은 media3 SubtitleView로 그립니다.
  5. 시청 이력 · QI 전송시청 이력과 품질 정보(QI)를 nms/qi 핸들러가 NMS 서버로 전송합니다.

단말 관리 · 자동 재부팅 흐름

  1. 관리 세션 연결Agent/AgentController와 MgmtManager가 NMS/관리 서버와 세션을 맺고 단말 상태를 리포트합니다.
  2. 재부팅 스케줄 등록RebootScheduler가 WorkManager로 RebootCheckWorker를 예약하고, 조건 충족 시 RebootWorker를 실행합니다.
  3. 사용자 안내 후 재부팅시청 중이 아닐 때 RebootDialog로 안내한 뒤 단말을 재부팅하며, 관리 서버 연결이 끊기면 reboot 콜백으로 복구를 시도합니다.

빌드 · 실행

빌드는 Gradle Wrapper로 수행하며, 사내 Maven 저장소(mvn.altimedia.com) 접근이 가능한 환경이 필요합니다. 플레이어·관리 라이브러리는 app/libs/에 동봉된 AAR을 직접 참조하므로 별도 외부 게시 저장소 없이 빌드됩니다.

빌드 변형(Variants)

  • Product Flavor (serviceTarget 차원) — livePublish(운영/상용 서버, LIVE_SVR=true, 실 서버 IP), develop(개발/테스트 서버, LIVE_SVR=false, 버전명 -D 접미어, 192.168.152.x 대역).
  • Build Type — release(비디버그, platform 키 서명, release 플레이어 AAR), debug(디버그 가능, debug 플레이어 AAR), staging(debug 기반 + DEVELOP=true).

주요 명령

# 클린
./gradlew clean

# 개발 서버 + 디버그 빌드
./gradlew assembleDevelopDebug

# 상용 서버 + 릴리스 빌드
./gradlew assembleLivePublishRelease

# 전체 디버그/릴리스 빌드
./gradlew assembleDebug
./gradlew assembleRelease

환경 설정 · 산출물

  • 서버 주소(SDP/UIM/PUSH/RESOLVER/HLS/NMS/INBAND 등)는 app/build.gradle의 buildConfigField로 정의되어 BuildConfig에 주입됩니다.
  • 버전은 app/version.properties의 MAJOR.MINOR.POINT(현재 3.14.55)로 산정됩니다.
  • 3rd Party 앱 허용 목록은 app/src/main/assets/app_packages.properties에 normal/hotel/ott 모드별로 정의됩니다.
  • 산출물 APK 기본 파일명은 tvapp-MARUSYS-b0<BUILD_NUMBER>-<version> 형태입니다(BUILD_NUMBER 미설정 시 기본 45, versionCode 기본 1001).
참고
서명은 debug/release/staging 모두 app/signkey/default_platform.jks 플랫폼 키(v1/v2/v3)를 사용합니다. 단말에는 시스템(prebuilt) 앱으로 탑재되며, 운영 단말 업그레이드는 KCTV Management 앱을 통해 진행됩니다.
