개요

본 과제는 음성 기반 AI 주문 키오스크를 SolidJS로 구현한 웹 애플리케이션입니다. 사용자가 마이크에 말을 하면 STT(Speech-to-Text)로 음성을 텍스트로 변환하고, 대화 내용을 LLM 질의 서버로 전송해 주문 의도를 해석하며, 응답 메시지를 TTS(Text-to-Speech)로 음성 안내합니다. 화면에는 커피·티·주스 카테고리의 메뉴를 보여 주고, 장바구니 담기에서 결제·카드 삽입·영수증·완료에 이르는 키오스크 주문 플로우 전체를 제공합니다.

대상 단말은 삼성 Galaxy Tab S8 태블릿이며, 화면 해상도는 924x1480 고정(세로형)으로 정의되어 있습니다. 입력 방식은 터치와 음성을 함께 사용합니다. 앱은 Vite로 빌드된 브라우저 웹앱이지만, 키오스크 단말에서는 Android WebView에 탑재되어 동작하는 것을 전제로 합니다. window.android 네이티브 인터페이스가 존재하면 네이티브 STT를 호출하고, 그렇지 않은 일반 브라우저 환경에서는 Azure Speech SDK로 마이크를 직접 사용하도록 분기합니다.

화면 스케일은 index.jsx에서 window.innerHeight / 1480 비율로 body의 zoom을 조정해 다양한 해상도에 맞춥니다. 빌드는 base: "./"와 no-crossorigin 플러그인을 통해 file:// 프로토콜에서도 동작하도록 구성되어 있어, 별도 웹 서버 없이 단말에 패키징해 띄울 수 있습니다.

성격 — 성능평가용 비교 구현
사내 Confluence(Environment - AI Kiosk)에 따르면 AI Kiosk의 주 UI 라이브러리는 React이고, Solid는 "UI Library for Test"로 명시되어 있습니다. 즉 본 저장소는 동일한 AI 키오스크 기능을 React 버전과 비교·평가하기 위한 SolidJS 구현 산출물입니다. 빌드 시스템(Vite), 대상 단말(Galaxy Tab S8), 고정 해상도(924x1480), 입력 방식(터치·음성)은 규격 문서와 일치합니다.

주요 기능

음성 주문 대화
마이크로 입력한 발화를 STT로 텍스트화하고, 대화 누적 목록을 LLM 질의 서버에 보내 주문 의도를 해석한 뒤 응답을 TTS로 음성 안내합니다.
STT(음성 인식) 이중 경로
Android WebView에서는 window.android 네이티브 STT로 위임하고, 일반 브라우저에서는 Azure Speech SDK의 SpeechRecognizer를 직접 사용합니다.
TTS(음성 합성) 분기
한국어는 KT GiGA Genie OpenAPI TTS(기본 보이스 "다솜"), 영어는 Azure TTS로 분기합니다. 화면 안내 문구는 IBC TTS 경로로 재생합니다.
LLM 질의 시퀀스
이전 대화(previous)와 신규 발화(user)를 묶어 질의 서버의 auto_query로 POST하고, 응답 type(order/new/edit/mix/suggestion 등)에 따라 주문을 검증·정리합니다.
메뉴 카탈로그
커피·티·주스 3개 카테고리의 메뉴를 data.js에 정의하고, 카테고리별 이미지를 import.meta.glob로 로드해 페이지당 8개씩 페이지네이션합니다.
옵션 선택
온도(HOT/ICE), 디카페인, 시럽, 농도(연하게/진하게) 등 음료 옵션을 OptionPopup으로 선택하고 장바구니 항목에 반영합니다.
장바구니 관리
CartStore가 장바구니 항목·총수량·총금액과 매장/포장(here·to go) 선택을 관리합니다.
키오스크 주문 플로우
Home → Menu → Cart → Pay → InsertCard → Receipt → Complete로 이어지는 결제·영수증·완료 화면 흐름을 HashRouter 라우트로 구성합니다.
음성 파형 애니메이션
VoiceSequenceStore가 프레임 이미지를 순환 재생해 "원→물결→직선→원" 상태로 음성 입력 중 시각 피드백을 제공합니다.
효과음 재생
AudioPlayer가 인식 시작 시 siri_open.wav 등 효과음을 재생해 대화 시작·종료를 사용자에게 알립니다.
다국어(i18n)
i18next 기반으로 한국어/영어 리소스를 제공하며, LanguagePopup으로 언어를 전환합니다. 언어 설정에 따라 STT 인식 언어와 TTS 서버가 함께 바뀝니다.
전역 팝업 시스템
popup.jsx가 Portal로 전역 팝업 영역에 마운트하고, PopupStore로 Cart/Help/Language/Option 팝업을 띄웁니다.
file:// 단독 실행
base: "./"와 no-crossorigin 플러그인으로 빌드 산출물이 별도 서버 없이 파일 프로토콜에서 그대로 실행됩니다.
레벨별 로깅
CommonLog.getLog(name)로 모듈별 태그 로그를 남기며, 빌드 인자(log=false/true)로 INFO/DEBUG 레벨을 전환합니다.

아키텍처 · 모듈 구조

SolidJS 단일 페이지 웹앱이며, 화면은 @solidjs/router의 HashRouter로 라우팅합니다. 전역 상태는 createRoot 기반 스토어(src/stores)에 두고, 음성 입출력·LLM 질의 등 부수효과는 매니저 객체(src/voices, src/api)에 분리했습니다. UI는 pages(화면 단위)·popups(팝업)·components(공용 UI)로 나뉩니다.

계층 · 외부 연동

UI 계층(pages·popups·components)은 스토어를 구독해 렌더링하고, 사용자 입력·음성 이벤트는 스토어 → 매니저(voices·api) → 외부 서비스 순으로 흐릅니다. 외부 연동은 세 갈래입니다. (1) Azure Speech(STT/영어 TTS), (2) KT GiGA Genie OpenAPI(한국어 TTS), (3) 사내 LLM 질의 서버(qz7d803.glddns.com:11591)입니다. 단말 측 네이티브 STT는 window.android JavaScript 인터페이스(setSTTCallback·requestSpeechToText·setSpeechConfiguration·stopSpeechToText)로 WebView 호스트와 양방향 통신합니다.

경로 alias는 vite.config.js와 jsconfig.json에 정의됩니다(@=src, @pages, @popups, @components, @assets, @stores, @utils, @voices, @locales). 다만 @components가 vite 설정에서는 src/component로, jsconfig에서는 src/components로 매핑되어 실제 디렉토리(src/components)와 설정 간 불일치가 존재합니다(추정 — 실 빌드 동작은 확인 필요).

핵심 동작 흐름

음성 주문 파이프라인 (STT → LLM → TTS)

  1. 마이크 열기 · STT 시작STTStore가 startSTTAsync로 마이크를 열고 시작 효과음(siri_open.wav)을 재생합니다. 실제 인식은 AzureSTTManager가 담당합니다.
  2. STT 경로 분기Android(window.android 존재) 환경은 네이티브 STT(azureMicOpenAndroid)로, 일반 브라우저는 Azure SpeechRecognizer로 위임합니다. 언어(i18next.language)에 따라 ko-KR/en-US와 리전·엔드포인트를 분기하고 PhraseListGrammar로 인식 정확도를 보강합니다.
  3. LLM 질의LLMStore.asyncQuerySequence가 대화 누적 목록을 만들어 LLMManager.querySequence로 전달하고, LLMManager는 previous/user를 묶어 queryManager.autoQuery로 질의 서버(/api/auto_query)에 POST합니다.
  4. 응답 해석 · 주문 검증응답 type(order/new/edit/mix/suggestion 등)에 따라 주문을 검증(validateOrderQuery)하거나 추천 질의를 정리하고, 결과 message가 "ERROR"인지에 따라 성공/실패 콜백을 분기합니다.
  5. TTS 음성 안내TTSManager.handleTts가 한국어는 KTTTSManager(KT GiGA Genie, 보이스 "다솜"), 영어는 AzureTTSManager로 분기해 응답 메시지를 음성으로 재생합니다.
  6. 시각 피드백VoiceSequenceStore가 파형 프레임 이미지를 "원→물결→직선→원"으로 순환 재생해 음성 입력 상태를 화면에 표시합니다.

키오스크 주문 화면 플로우

  1. Home (대기/시작)/ 경로. 키오스크 시작·음성 안내 대기 화면입니다.
  2. Menu (메뉴 선택)/menu. 커피·티·주스 카테고리를 페이지당 8개로 보여 주고, OptionPopup으로 옵션을 선택합니다.
  3. Cart (장바구니)/purchase/cart. CartStore가 항목·수량·총금액과 매장/포장 선택을 관리합니다.
  4. Pay → InsertCard/purchase/pay → /purchase/insert-card. 결제 진행과 카드 삽입 안내 화면입니다.
  5. Receipt → Complete/purchase/receipt → /purchase/complete. 영수증 출력과 주문 완료로 플로우를 마칩니다.

앱 초기화 시퀀스

  1. 엔트리 렌더index.jsx에서 i18n Provider를 구성하고 window.innerHeight / 1480 비율로 body zoom을 설정한 뒤 App을 렌더합니다.
  2. 매니저/스토어 초기화App.jsx의 onMount에서 VolumeStore·STTStore·AzureTTSManager·LLMManager를 차례로 initialize합니다.
  3. 라우터 진입HashRouter가 /(Home)부터 라우트를 매칭해 화면을 띄우고 음성 주문 대기 상태로 들어갑니다.

빌드 · 실행

의존성 설치 후 package.json 스크립트로 빌드/프리뷰합니다. 루트의 기본 README.md는 SolidJS 템플릿 문서로 npm run dev/npm run build를 안내하지만, 실제 package.json에는 해당 스크립트가 없으므로 아래의 serve/preview/release를 사용해야 합니다.

# 의존성 설치
npm install

# 개발 서버 (vite serve, 호스트 노출)
npm run serve

# 빌드 후 프리뷰 (개발용)
npm run preview          # vite build → vite preview --host
npm run preview-nolog    # 로그 레벨 INFO로 빌드 후 프리뷰

# 릴리스 빌드 (mode=release, dist를 release 폴더에 zip 패킹)
npm run release          # vite build --mode release -- log=false live=true

# 린트
npm run lint

빌드 인자/모드별 동작은 vite.config.js에 정의됩니다. 커맨드라인 인자 log=false|true는 APP_LOG_LEVEL을 INFO/DEBUG로, live=true|false는 APP_NETWORK를 Prod/Stag로 설정합니다. mode === "release"이면 cssCodeSplit:false로 묶고 vite-plugin-zip-pack이 dist를 release/ 아래 YYYYMMDD_앱이름_버전_네트워크_로그레벨.zip 형식으로 압축합니다. mode === "production"은 minify:false 비압축 빌드입니다.

환경변수 prefix는 APP_이며 .env에서 로드합니다(앱 이름 AIKioskWebApp_SOLID, 버전 0.0.0). 빌드 시점에 APP_UPDATE_DATE가 dayjs로 갱신됩니다. 산출물은 dist/ 폴더이며, base: "./" 상대 경로 빌드라 별도 서버 없이 file://로도 열립니다.

보안 주의
.env에 Azure Speech API 키, KT 클라이언트 ID/Key/Secret 등 시크릿이 평문으로 커밋되어 있습니다. 성능평가용 저장소 특성으로 보이나, 실 운영 전 키 분리·교체가 필요합니다.
