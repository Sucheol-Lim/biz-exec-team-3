기능 개요

키오스크 화면 전환은 @solidjs/router의 HashRouter로 구성됩니다. App.jsx가 최상위에서 라우트를 정의하며, 루트(/)는 Home, /menu는 메뉴 화면입니다. 결제 단계는 /purchase 아래 중첩 라우트로 묶여, PurchaseLayout이 공통 헤더와 팝업 영역을 감싸고 그 안에 /cart·/pay·/insert-card·/receipt·/complete 자식 라우트가 차례로 배치됩니다.

전체 주문 흐름은 Home(대기/시작) → Menu(메뉴·옵션 선택) → Cart(장바구니) → Pay(결제) → InsertCard(카드 삽입) → Receipt(영수증) → Complete(완료) 순서입니다. PurchaseLayout은 결제 단계들의 공통 레이아웃으로, 상단에 Header(진행 단계 표시 currProcess)를 두고 자식 화면을 purchaseMain 영역에 렌더하며, 전역 팝업 컴포넌트(Popup)를 함께 마운트합니다. 화면 전환은 각 페이지가 라우터 내비게이션을 호출해 일어나며, 음성 주문 영역(VoiceArea)은 현재 경로(location.pathname)에 따라 위치·버튼 구성을 다르게 합니다.

설계 포인트
HashRouter를 쓰는 이유는 file:// 단독 실행 호환성과 맞닿아 있습니다. 해시 기반 라우팅은 서버 측 경로 처리 없이 정적 파일만으로 동작하므로, 별도 웹 서버 없이 단말에 패키징해 띄우는 키오스크 운용에 적합합니다.

관계. App이 HashRouter로 최상위 라우트를 정의하고, /purchase 중첩 라우트의 자식 페이지들은 모두 PurchaseLayout 안에서 렌더됩니다.

핵심 코드

src/App.jsx — HashRouter 라우트 정의
function App() {
  onMount(() => {
    VolumeStore.initialize();
    STTStore.initialize();
    AzureTTSManager.initialize();
    LLMManager.initialize();
  });

  return (
    <HashRouter>
      <Route path="/" component={HomePage} />
      <Route path="/menu" component={MenuPage} />
      <Route path="/purchase" component={PurchaseLayout}>
        <Route path="/cart" component={CartPage} />
        <Route path="/pay" component={PayPage} />
        <Route path="/insert-card" component={InsertCardPage} />
        <Route path="/receipt" component={ReceiptPage} />
        <Route path="/complete" component={CompletePage} />
      </Route>
    </HashRouter>
  );
}
src/pages/Purchase/PurchaseLayout.jsx — 결제 단계 공통 레이아웃
const PurchaseLayout = (props) => {
  const { children } = props;
  return (
    <div className={classes.purchase}>
      <div className={classes.headerWrapper}>
        <Header currProcess={2} />
      </div>
      <div className={classes.purchaseMain}>{children}</div>
      <Popup />
    </div>
  );
};
