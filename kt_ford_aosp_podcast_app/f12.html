스트리밍 안정화 (리다이렉트·CBR)

CustomHttpDataSource가 첫 요청의 HTTP 리다이렉트 결과(최종 콘텐츠 URL)를 추적해 두고, 이후 버퍼 요청을 그 URL로 직접 보냅니다. MP3 재생을 위해 고정 비트레이트(CBR) 시킹 플래그와 비동기 코덱 큐잉을 적용합니다.

기능 개요

팟캐스트 오디오 URL은 게이트웨이에서 실제 콘텐츠 서버로 HTTP 리다이렉트되는 경우가 많습니다. 매 버퍼 요청마다 리다이렉트 체인을 다시 타면 지연·실패 위험이 커지므로, CustomHttpDataSource는 ExoPlayer 기본 DefaultHttpDataSource를 본떠 만들되 리다이렉트 처리를 직접 수행하고 최초로 도달한 최종 콘텐츠 URL을 contentUrl 필드에 보관합니다. 그 뒤 finishRedirect=true가 되면 makeConnection()은 원래 URL이 아니라 저장된 contentUrl로 곧장 연결해 후속 시킹·버퍼 요청을 안정화합니다(커밋 "redirect 이후 획득한 최종컨텐츠 uri로 다음 버퍼 요청"에 해당).

데이터소스는 WrappedDataSource가 CustomHttpDataSource를 감싸 사용합니다. 읽기 중 TYPE_READ 예외가 나면 직전 DataSpec과 읽은 바이트 수를 보관해 재개 시 위치를 보정하고, 끊김(discontinuity) 신호를 받으면 위치 검증을 건너뜁니다. MP3 콘텐츠 재생을 위해 PodcastExoplayerHelper는 DefaultExtractorsFactory.setMp3ExtractorFlags(FLAG_ENABLE_CONSTANT_BITRATE_SEEKING)로 고정 비트레이트 시킹을 켜고, DefaultRenderersFactory.forceEnableMediaCodecAsynchronousQueueing()으로 비동기 코덱 큐잉을 활성화해 차량 환경에서의 끊김을 줄입니다.

왜 최종 URL을 고정하나
시킹·재버퍼링 때마다 게이트웨이 → 콘텐츠 서버 리다이렉트를 반복하면 매번 30x 왕복 비용과 실패 가능성이 누적됩니다. 한 번 확인한 최종 URL로 직접 붙으면 왕복이 줄고, MP3의 CBR 시킹 플래그와 결합해 색인 없는 MP3에서도 위치 점프가 매끄러워집니다.
