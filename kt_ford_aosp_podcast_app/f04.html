재생 목록

PlayListFragment가 현재 재생 중인 채널의 에피소드 큐(podcastPlayableMediaItems)를 보여주고, 항목을 누르면 playFromMediaId로 곡을 전환합니다. 목록 끝까지 스크롤하면 다음 페이지를 자동 요청합니다.

기능 개요

재생 목록 화면은 새로 네트워크를 호출하지 않고, PodcastViewModel의 getPodcastPlayableMediaItems() LiveData(현재 재생 큐)를 그대로 그립니다. 이 큐는 채널 진입 시 서비스가 채워주고 미디어 세션 큐와 동기화되어 있습니다. PlayListAdapter는 현재 재생 위치(getPlayingIndex())와 재생 상태(updatePlayBackState())를 반영해 재생 중인 항목을 강조합니다.

사용자가 목록 항목을 누르면 해당 항목의 mediaId로 transportControls.playFromMediaId()를 호출해 곡을 전환합니다. 메타데이터·재생 상태·큐가 바뀌면 LiveData 관찰자가 notifyDataSetChanged()로 목록을 갱신합니다. 목록을 바닥까지 스크롤해 SCROLL_STATE_SETTLING 상태에서 더 스크롤할 수 없으면 CUSTOM_ACTION_NEXT_PAGE 커스텀 액션을 보내 서비스의 페이징(에피소드 큐 추가 로드)을 트리거합니다. 화면 상단에는 마이팟 등록/해제 버튼이 있어 현재 채널을 보관함에 토글할 수 있습니다.

큐 = 단일 소스
재생 컨트롤·메인 미니플레이어·재생 목록이 모두 같은 podcastPlayableMediaItems LiveData를 본다는 점이 핵심입니다. 어디서 곡을 바꾸든 세션 큐가 갱신되고 모든 화면이 동시에 동기화됩니다.

흐름. 큐 LiveData를 그대로 렌더링하고, 항목 클릭은 playFromMediaId 곡 전환으로, 바닥 스크롤은 NEXT_PAGE 페이징으로 처리합니다.

핵심 코드

ui/PlayListFragment.java — 항목 클릭으로 곡 전환
playListAdapter = new PlayListAdapter(getViewLifecycleOwner(), podcastViewModel, position -> {
    requireActivity().getMediaController().getTransportControls().playFromMediaId(
        Objects.requireNonNull(podcastViewModel.getPodcastData().getPodcastPlayableMediaItems().getValue())
            .get(position).getDescription().getMediaId(), null
    );
});
ui/PlayListFragment.java — 바닥 스크롤 시 다음 페이지 요청
if (newState == RecyclerView.SCROLL_STATE_SETTLING) {
    int SCROLL_END_DIRECTION_BOTTOM = 1;
    if (!recyclerView.canScrollVertically(SCROLL_END_DIRECTION_BOTTOM)) {
        PodcastData.PodcastCustomAction podcastCustomAction =
            new PodcastData.PodcastCustomAction(Constants.CUSTOM_ACTION_NEXT_PAGE, null);
        podcastViewModel.getPodcastData().setCustomAction(podcastCustomAction);
    }
}
