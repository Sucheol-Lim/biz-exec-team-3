개요

이 앱은 KT가 포드(Ford) 차량에 공급하는 차량용 인포테인먼트(IVI) 플랫폼에 탑재되는 팟캐스트 스트리밍 애플리케이션입니다. AOSP/AAOS 기반의 안드로이드 차량 환경에서 동작하며, 패키지명 com.altimedia.automotive.kt.service.podcast의 automotive 네임스페이스와 가로/세로 멀티윈도우(half/full) 대응 리소스에서 차량 단말용 앱임을 확인할 수 있습니다. 런처에 노출되는 표시 이름은 팟캐스트입니다.

앱은 KT 팟캐스트 게이트웨이(https://egw.gbox.kt.com/gw/podcast/)에서 추천 채널, 인기(랭킹) 채널, 구독 중인 마이팟 채널, 키워드 검색 결과 및 각 채널의 에피소드 목록을 조회합니다. 사용자가 선택한 에피소드는 오디오 스트리밍으로 재생되며, 이전 시청 정보를 저장해 다시 진입했을 때 마지막 청취 항목을 복원합니다. 콘텐츠 원천은 팟빵(podbbang) 계열의 KT 연동 미디어로 보입니다(추정).

화면과 재생 엔진은 안드로이드 표준 미디어 앱 구조인 MediaBrowserService + MediaSession 위에서 분리되어 있습니다. UI(:app 모듈)는 MediaBrowserCompat으로 미디어 서비스에 연결해 콘텐츠 트리를 받아오고, 미디어 서비스(:common 모듈)는 KT 게이트웨이 조회와 ExoPlayer 재생을 담당합니다. 차량 특성상 KT 런처(com.kt.automotive.service.launcher) 및 기가지니 음성(KAS) 제어와 브로드캐스트로 연동하여, 음성 명령으로 인기/추천 팟캐스트를 실행하거나 백그라운드 전환·종료를 처리합니다.

분석 기준 브랜치 안내
분석 대상 브랜치 develop-exoplayer는 미디어 재생 엔진으로 ExoPlayer 2.18.1을 사용하는 계열입니다. 최근 커밋들은 HTTP 리다이렉트 처리(최종 콘텐츠 URI로 다음 버퍼 요청), Duration 갱신, 미디어 세션 활성화 시점, MP3 고정 비트레이트 시킹 등 스트리밍 안정화 작업에 집중되어 있습니다. 동일 저장소에는 develop, develop-aaos, develop-aaos-exoplayer 등 별도 계열 브랜치가 존재합니다.

주요 기능

메인 화면 (추천·인기·마이팟)
추천팟, 인기팟, 마이팟(보관함) 채널 목록을 모아 보여주는 시작 화면(MainFragment)입니다. 미디어 브라우저 트리의 루트별로 묶여 제공됩니다.
채널 에피소드 목록
PodcastFragment가 특정 채널(pid)의 에피소드 목록을 표시합니다. startSeq 기반 페이징으로 다음 페이지를 추가 로드합니다.
오디오 재생 / 컨트롤
PlayControlFragment에서 재생·일시정지·이전/다음 에피소드·시킹을 제어합니다. ExoPlayer가 미디어 세션을 통해 스트리밍을 재생합니다.
재생 목록
PlayListFragment가 현재 재생 중인 채널의 에피소드 큐를 보여주고 항목 선택으로 곡을 전환합니다.
검색
SearchFragment에서 키워드로 채널을 검색합니다. 게이트웨이의 channellist?type=search&keyword= 엔드포인트를 사용합니다.
마이팟 구독 관리
특정 팟을 마이팟으로 등록/해제하고 보관함에서 삭제할 수 있습니다. 구독 목록은 단말의 SharedPreferences에 저장되며 최대 20개까지 관리됩니다(MAX_MYPOD_NUM = 20).
이전 시청 정보 복원
마지막으로 청취한 항목(LastWatchedItem)을 SharedPreferences에 저장해, 앱·서비스 재진입 시 직전 재생 지점을 복원합니다.
기가지니 음성(KAS) 연동
NE-podcast, 인기팟캐스트, 추천팟캐스트, NE-category, NE-search 등 음성 메타데이터를 받아 해당 목록을 띄우거나 첫 채널을 자동 재생합니다.
런처 제어 연동
kas.action.app.back/stop/shutdown/clear 인텐트와 podcast.play 등을 BroadcastReceiver로 수신해 백그라운드 전환·정지·종료·데이터 초기화를 처리합니다.
멀티윈도우·해상도 대응
가로/세로(landscape/portrait) 및 half/full 화면 조합과 단말별 해상도에 맞춰 layout, layout-port, layout-ldpi 등 다중 레이아웃·dpi 리소스를 제공합니다.
야간(Night) 모드
values-night와 drawable-night* 리소스로 야간 테마를 제공하며, 야간 모드 알파(NIGHT_MODE_ALPHA = 0.88)를 적용합니다.
스트리밍 안정화 (리다이렉트·CBR)
CustomHttpDataSource가 HTTP 리다이렉트 후 최종 콘텐츠 URI를 추적해 다음 버퍼 요청에 사용합니다. MP3 재생을 위해 색인 기반 시킹·고정 비트레이트(CBR) 시킹 플래그를 적용합니다.
재생 오류 처리
재생 상태가 STATE_ERROR가 되면 MainActivity가 미디어 플레이어 오류 다이얼로그(PodcastDialog)를 표시합니다. 로드 오류 정책(PodcastLoadErrorHandlingPolicy)도 별도 구현되어 있습니다.
미디어 아이콘 제공
MediaIconContentProvider가 채널/에피소드 썸네일을 ContentProvider로 제공하여 런처·시스템 미디어 표시에 노출되도록 합니다.

계층 · 외부 연동

외부 연동은 크게 세 갈래입니다. 첫째, KT 팟캐스트 게이트웨이(egw.gbox.kt.com)와 Retrofit/OkHttp HTTP 통신으로 채널·에피소드 메타데이터를 조회하고, 실제 오디오 스트림은 ExoPlayer가 (리다이렉트 추적을 거쳐) HTTP로 받아옵니다. 둘째, KT 런처/기가지니와 브로드캐스트·인텐트로 연동하여 음성 명령 실행과 백그라운드/종료 제어를 받습니다. 셋째, 앱 내부적으로 UI와 미디어 서비스가 MediaBrowser/MediaSession custom action(마이팟 ON/OFF/GET/DELETE, NEXT.PAGE)으로 통신합니다. 마이팟 데이터 변경 시에는 notifyChildrenChanged()로 UI에 갱신을 통지합니다.

핵심 동작 흐름

1. 앱 실행 · 콘텐츠 로딩

  1. 실행 진입런처 아이콘, 음성 명령(NE-podcast 등), 또는 런처 인텐트(kas.action.app.start / podcast.play)로 MainActivity가 시작됩니다.
  2. 미디어 서비스 연결PodcastMediaClient가 MediaBrowserCompat으로 PodcastBrowserService에 접속하고, 연결 직후 마이팟 목록 조회(MYPOD.GET)와 세션 데이터를 초기화합니다.
  3. 콘텐츠 트리 조회서비스가 KT 게이트웨이에서 추천(recommend)·인기(channellist?type=ranking)·구독(subscription) 목록을 받아 MediaItem 트리로 노출합니다.
  4. 화면 렌더링MainFragment가 루트별 목록을 표시하고, 사용자는 Navigation 그래프를 따라 채널·에피소드·검색 화면으로 이동합니다.

2. 에피소드 재생

  1. 에피소드 선택사용자가 채널의 에피소드를 선택하면 UI가 미디어 세션 트랜스포트(playFromMediaId 등)로 재생을 요청합니다.
  2. ExoPlayer 재생 준비PodcastSessionCallback → PodcastExoplayerHelper가 CustomHttpDataSource로 콘텐츠 URL을 요청합니다. HTTP 리다이렉트가 발생하면 최종 콘텐츠 URI를 추적해 후속 버퍼 요청에 사용합니다.
  3. 스트리밍 재생MP3 색인 시킹·고정 비트레이트(CBR) 시킹 플래그와 비동기 미디어코덱 큐잉을 적용해 안정적으로 오디오를 재생하고, 재생 시작 시 실제 Duration으로 갱신합니다.
  4. 상태 반영재생 상태는 MediaController 콜백 → PodcastViewModel LiveData로 전달되어 PlayControlFragment의 진행바·버튼에 반영됩니다.
  5. 오류 처리오류 발생 시 상태가 STATE_ERROR가 되고 MainActivity가 오류 다이얼로그를 표시합니다. 마지막 시청 항목은 SharedPreferences에 저장되어 재진입 시 복원됩니다.

3. 음성 · 런처 제어

  1. 제어 인텐트 수신PodcastReceiver 또는 MainActivity의 BroadcastReceiver가 KAS 인텐트(kas.action.app.back/stop/shutdown/clear)와 음성 메타데이터를 수신합니다.
  2. 음성 명령 해석인기팟캐스트·추천팟캐스트(NE-category), 검색어(NE-search), 카테고리 발화(예: "정치 팟캐스트 틀어줘") 등을 해석해 해당 목록을 띄우거나 첫 채널을 자동 재생합니다.
  3. 앱 제어 수행back은 백그라운드 전환, stop/shutdown은 재생 정지·종료, clear는 데이터 초기화로 처리해 런처/음성 시스템과 일관된 동작을 보장합니다.

빌드 · 실행

프로젝트 루트의 Gradle Wrapper를 사용합니다. 릴리스 빌드는 app/version.properties의 버전 값을 자동 증가시키는 커스텀 buildType(release_major / release_minor / release_patch)으로 분리되어 있으며, 디버그를 포함한 모든 buildType이 signingConfigs.release 키스토어로 서명되도록 설정되어 있습니다.

# 디버그 APK 빌드
./gradlew assembleDebug

# 릴리스 빌드 (빌드 시 version.properties가 자동 갱신됨)
./gradlew assembleRelease_patch   # patch 증가
./gradlew assembleRelease_minor   # minor 증가
./gradlew assembleRelease_major   # major 증가

# 클린
./gradlew clean

# 단위 / 계측 테스트
./gradlew test
./gradlew connectedAndroidTest

빌드 산출물 APK 파일명은 kt_ford_podcast_v.<major>.<minor>.<patch><suffix>_<빌드일자>.apk 형식으로 생성됩니다(app/build.gradle의 outputFileName 규칙). 현재 version.properties 기준 버전은 1.0.9입니다. 환경 설정 관련 파일은 루트의 build.gradle(플러그인·ext 버전), settings.gradle(모듈 포함), gradle.properties(android.useAndroidX, android.nonTransitiveRClass), 그리고 app/version.properties(버전 카운터)입니다.

보안 주의
서명 키스토어(keystore/release.keystore.jks, alias kt.ford.podcast)의 store/key 비밀번호가 app/build.gradle에 평문으로 포함되어 있습니다. 외부 공개 시 취급에 주의가 필요합니다(현 상태 그대로 기술).
