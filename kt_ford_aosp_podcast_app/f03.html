오디오 재생 / 컨트롤

PlayControlFragment가 미디어 세션 트랜스포트로 재생·일시정지·이전/다음·시킹을 요청하면, PodcastSessionCallback이 받아 PodcastExoplayerHelper의 ExoPlayer를 구동하고 재생 상태를 다시 UI로 흘려보냅니다.

기능 개요

재생 컨트롤 화면(PlayControlFragment)은 직접 ExoPlayer를 다루지 않고, MediaControllerCompat.getTransportControls()를 통해 표준 미디어 세션 명령(play, pause, skipToNext, skipToPrevious, seekTo, playFromMediaId)만 전송합니다. 명령은 서비스의 PodcastSessionCallback으로 전달되며, 콜백은 각각 PodcastExoplayerHelper의 메서드(start/pause/prepareNext/preparePrev/seekTo/startExoplayer)를 호출합니다.

재생 상태 변화는 ExoPlayer 리스너(PodcastExoplayerListener)가 감지해 updateSessionPlaybackState()로 세션 PlaybackState를 갱신하고, 이는 PodcastControllerCallback.onPlaybackStateChanged() → PodcastViewModel의 LiveData로 흘러 화면의 재생/일시정지 버튼·진행바·이전/다음 버튼 활성화에 반영됩니다. 시킹은 시크바 터치 종료 시점(onStopTrackingTouch)에 계산된 위치로 seekTo()를 호출하며, 좌우 스와이프 제스처로도 이전/다음 에피소드 전환이 가능합니다.

상태 단방향 흐름
UI는 "명령"만 보내고 "상태"는 LiveData로 받습니다. 버튼 이미지·진행바·시크바 활성화는 모두 getPlaybackState().observe() 안에서 STATE_PLAYING/STATE_PAUSED/STATE_BUFFERING/STATE_ERROR를 분기해 결정합니다.

핵심 코드

media/PodcastSessionCallback.java — 세션 트랜스포트 명령 → ExoPlayer 위임
@Override
public void onPlay() {
    podcastPlayerHelper.start();
    podcastPlayerHelper.setPlayerState(PodcastExoplayerHelper.PlayerState.PLAY_STATE_PLAYING);
}

@Override
public void onSkipToNext() {
    podcastPlayerHelper.setHelperPlayWhenReady(true);
    podcastPlayerHelper.prepareNext();
}

@Override
public void onSeekTo(long pos) {
    super.onSeekTo(pos);
    podcastPlayerHelper.seekTo(pos);
}
ui/PlayControlFragment.java — 시크바 종료 시점에 seekTo 전송
@Override
public void onStopTrackingTouch(SeekBar seekBar) {
    isTracking = false;
    MediaControllerCompat.getMediaController(requireActivity())
            .getTransportControls().seekTo(seekPosition);
    startProgress();
    binding.imageSeekDim.setVisibility(View.GONE);
    binding.textSeekTime.setVisibility(View.GONE);
}
