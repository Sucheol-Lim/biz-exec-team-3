채널 에피소드 목록

PodcastFragment가 특정 채널(메뉴 루트 또는 pid)을 구독해 에피소드 목록을 표시하고, 목록 끝까지 스크롤하면 startSeq 기반 페이징으로 다음 페이지를 이어서 로드합니다.

기능 개요

PodcastFragment는 PodcastFragmentArgs로 전달받은 mediaId(인기/마이팟/추천 루트 또는 채널 pid)를 화면 진입 시점에 구독합니다. 서비스의 onLoadChildren()은 이 parentId가 메뉴 루트면 채널 목록(랭킹·구독·추천)을, 일반 pid면 에피소드 목록을 조회합니다. 에피소드 조회는 PodcastRequest.getEpisodeList(EPISODE_LOAD_COUNT=500, pid, "desc", ...)로 최신순 500건을 한 번에 받아 createPlayableEpisodeList()로 재생 가능한 MediaItem 리스트를 만들어 돌려줍니다.

목록을 끝까지 스크롤하면(RecyclerView 바닥 도달) 추가 페이지가 필요합니다. 본 화면의 목록은 채널 항목용이지만, 실제 에피소드 큐의 추가 로딩은 재생 목록 화면과 서비스의 페이징 로직(CUSTOM_ACTION_NEXT_PAGE → getEpisodeListWithStartSeq())으로 처리됩니다. 서비스는 세션 extras의 SESSION_LIST_END_KEY로 더 받을 페이지가 있는지 판단하고, 중복 호출을 막기 위해 isRunningPaging 플래그를 둡니다. 항목 클릭 시에는 해당 채널을 구독해 첫 에피소드를 재생하면서 PlayControlFragment로 이동합니다.

페이징 메커니즘
서비스는 onCustomAction(CUSTOM_ACTION_NEXT_PAGE)에서 startSeq = nowShowingEpisodeList.size()를 시작점으로 다음 EPISODE_LOAD_COUNT건을 요청합니다. 받은 목록은 appendNowShowingEpisodeList()로 누적되어 ExoPlayer 큐와 세션 큐에 함께 반영됩니다.

흐름. 채널 구독 → 최신순 에피소드 500건 수신 → 바닥 스크롤 시 startSeq로 다음 페이지 누적. isEnd가 참이면 더 이상 요청하지 않습니다.

관계. PodcastFragment가 채널을 구독하면 서비스가 PodcastRequest로 EpisodeList를 받아 트리로 변환하고, 페이징 시 startSeq 버전 API를 재호출합니다.

핵심 코드

media/PodcastBrowserService.java — startSeq 기반 다음 페이지 요청
} else if (TextUtils.equals(Constants.CUSTOM_ACTION_NEXT_PAGE, action)) {
    isSendNextChildren.set(false);
    if (!podcastSession.getController().getExtras().getBoolean(Constants.SESSION_LIST_END_KEY, true)
            && !isRunningPaging.get()) {
        isRunningPaging.set(true);
        int startSeq = nowShowingEpisodeList.size();
        PodcastRequest.getEpisodeListWithStartSeq(EPISODE_LOAD_COUNT, startSeq, nowShowingPid, "desc", this, result);
    } else {
        result.sendError(null);
        isSendNextChildren.set(true);
    }
    if (!isSendNextChildren.get()) {
        result.detach();
    }
}
