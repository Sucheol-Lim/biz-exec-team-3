검색

기능 개요

검색은 안드로이드 미디어 앱 표준 검색 경로(MediaBrowserServiceCompat.onSearch())와 음성 검색 경로 두 갈래로 게이트웨이를 호출합니다. 두 경우 모두 최종적으로 PodcastRequest.getSearchResult(SEARCH_COUNT=30, "search", keyword, SEARCH_ROOT_ID, ...)를 실행하며, 이는 Retrofit 인터페이스의 @GET("channellist")에 type=search·keyword 쿼리를 붙여 KT 게이트웨이를 호출하는 것입니다.

onSearch()는 입력 디바운스를 위해 핸들러로 SEARCH_COMPLETE_CHECK_TIME=1000ms 지연 후 검색을 실행하고, 직전 검색 콜백은 removeCallbacksAndMessages(null)로 취소합니다. 결과는 onGetSearchList()에서 최대 30건을 브라우저블 채널 항목으로 변환해 돌려줍니다. 음성에서 들어온 검색(NE-search)은 fromVoice=true로 처리되어 결과 목록을 띄우는 대신 첫 채널의 첫 에피소드를 자동 재생합니다. 화면 클래스 SearchFragment 자체는 골격(레이아웃 바인딩·ViewModel 획득)만 갖춘 상태로, 실제 검색·결과 트리 구성은 서비스 측에서 담당합니다.

근거 메모
SearchFragment.java의 본문 메서드(setRecyclerViewStyle 등)는 현재 비어 있는 스텁이며, 검색 동작의 실질 로직은 PodcastBrowserService.onSearch()와 onStartCommand()의 음성 분기에 구현되어 있습니다. 본 문서는 후자를 기준으로 흐름을 기술합니다.

흐름. 검색 요청은 1초 디바운스 후 channellist?type=search를 호출하고, 일반 검색은 목록을, 음성 검색은 첫 채널 자동 재생을 수행합니다.

핵심 코드

media/PodcastBrowserService.java — 디바운스 후 검색 실행
@Override
public void onSearch(@NonNull String query, Bundle extras, @NonNull Result<List<MediaBrowserCompat.MediaItem>> result) {
    isSentSearchChildren.set(false);
    handler.removeCallbacksAndMessages(null);
    handler.postDelayed(() -> {
        PodcastRequest.getSearchResult(
            SEARCH_COUNT, SEARCH_TYPE_SEARCH, query, SEARCH_ROOT_ID, false, PodcastBrowserService.this, result);
    }, SEARCH_COMPLETE_CHECK_TIME);
    if (!isSentSearchChildren.get()) {
        result.detach();
    }
}
common/network/PodcastApiService.java — channellist 검색 엔드포인트
@Headers("Content-Type: application/json")
@GET("channellist")
Call<PodList> getSearchResult(@Query("count") int count, @Query("type") String type, @Query("keyword") String keyword);
