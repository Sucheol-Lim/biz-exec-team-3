기능 개요

런처 제어는 두 개의 리시버로 나뉘어 처리됩니다. 매니페스트 등록 리시버 PodcastReceiver는 앱이 떠 있지 않아도 동작해야 하는 진입 트리거(podcast.play, kas.action.app.start, kas.action.app.clear)를 받아 서비스를 적절한 extra로 기동합니다. 액티비티 동적 리시버는 MainActivity.onCreate()에서 registerReceiver()로 등록되어 앱이 살아 있는 동안의 제어(back/stop/shutdown/clear)를 처리합니다.

액티비티 리시버의 동작은 다음과 같습니다. kas.action.app.back은 포그라운드 상태일 때 moveTaskToBack(true)로 백그라운드로 내리고, stop/shutdown/clear·podcast.stop은 finish()로 액티비티를 종료합니다. 재생 정지·종료의 실제 미디어 처리는 서비스 측 voiceReceiver가 받아 onStop()(ExoPlayer release·세션 해제)으로 수행하며, clear 진입은 onStartCommand()에서 PodcastPreferenceManager.resetData()로 마이팟·마지막 시청 정보를 초기화합니다.

두 리시버의 역할 분담
매니페스트 리시버는 "앱을 깨우는" 인텐트(start/play/clear)를, 동적 리시버는 "떠 있는 앱을 제어하는" 인텐트(back/stop/shutdown)를 담당합니다. 종료 시 액티비티는 finish(), 서비스는 onStop()으로 각각 정리되어 화면과 재생 자원이 함께 회수됩니다.

핵심 코드

ui/MainActivity.java — back/stop/shutdown/clear 처리
private final BroadcastReceiver broadcastReceiver = new BroadcastReceiver() {
    @Override
    public void onReceive(Context context, Intent intent) {
        switch (intent.getAction()) {
            case Constants.KAS_ACTION_APP_BACK:
                if (getActivityStatus() == ActivityStatus.ACTIVITY_STATUS_FOREGROUND) {
                    moveTaskToBack(true);
                }
                break;
            case Constants.ACTION_STOP_PODCAST:
            case Constants.KAS_ACTION_APP_STOP:
            case Constants.KAS_ACTION_APP_SHUTDOWN:
            case Constants.KAS_ACTION_APP_CLEAR:
                finish();
                break;
        }
    }
};
media/PodcastBrowserService.java — clear 진입 시 데이터 초기화 후 정지
} else if (intent.getBooleanExtra(Constants.KEY_CLEAR_DATA, false)) {
    handler.removeCallbacksAndMessages(null);
    podcastPreferenceManager.resetData();
    if (podcastSessionCallback != null) {
        podcastSessionCallback.onStop();
    }
}
