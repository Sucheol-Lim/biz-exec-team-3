개요

이 저장소는 Android Automotive OS(AAOS) 차량 인포테인먼트 환경에서 동작하는 KT GiGA Genie 기반 음성비서(AVIS, Altimedia Voice Interaction Service) 데모 애플리케이션입니다. AOSP의 packages/apps/Car, frameworks/opt/car, prebuilts/sdk 등 AAOS 빌드에 필요한 일부 소스 트리를 함께 담고 있으며, 실제 과제 산출물인 음성비서 앱은 packages/apps/Car/libs/aaos-apps-gradle-project/car-custom-voice-app 모듈입니다.

앱은 Android 표준 음성 인터랙션 프레임워크(VoiceInteractionService, VoiceInteractionSessionService, RecognitionService)를 구현해 AAOS 시스템의 기본 음성비서(디지털 어시스턴트)로 등록됩니다. 호출어(KWS, Keyword Spotting)는 단말 내장 kwsrnet 엔진과 KT GiGA Genie Inside SDK로 감지하고, 발화 인식·자연어 처리(DialogKit)·TTS 안내·미디어/차량 제어를 Inside 서버와 gRPC/REST로 연동해 수행합니다.

대상 단말은 android.hardware.type.automotive 피처를 필수로 요구하는 AAOS(Android 12, API 31 기반) 차량 헤드유닛입니다. 패키지명은 com.kt.avis.voice 이며 compileSdk 32 / targetSdk 32 / minSdk 31 로 빌드됩니다. 분석 기준 브랜치인 feature/support_stt 에서는 기존 음성비서 기능에 더해 외부 앱이 받아쓰기(STT)를 요청해 인식 결과를 돌려받는 STT 서비스 경로가 추가되었습니다.

사업 맥락
AVIS는 KT의 차량용 음성비서 플랫폼 과제로, 사내 위키 매핑상 "KT AAOS Demokit P1 음성인식 앱"에 해당합니다. 본 데모는 KT GiGA Genie Inside(대화형 AI) 백엔드를 AAOS 차량 환경에 연동해 음성 명령으로 앱 실행·미디어 재생·차량 공조 제어 등을 시연하는 것을 목표로 합니다.
보안 유의
config/*.properties(APP_KEY·CLIENT_SECRET 등)와 keystore/*.jks(서명 키), build.gradle의 키스토어 비밀번호가 평문으로 포함되어 있습니다. 데모용 자산이며 외부 노출에 유의해야 합니다.

주요 기능

시스템 음성비서 등록
VoiceInteractionService를 구현하고 @xml/interaction_service 메타데이터(supportsAssist, supportsLocalInteraction)로 AAOS 기본 디지털 어시스턴트로 등록됩니다.
호출어(KWS) 감지
KwsDetector가 단말 내장 kwsrnet 엔진과 assets/kwsrnet/*.cnsi 모델로 마이크 입력에서 호출어를 상시 감지해 음성 세션을 띄웁니다.
발화 음성 인식
VoiceRecorder가 AudioRecord로 PCM 오디오를 캡처하고 InsideVoiceManager가 Inside SDK 음성 세션으로 발화를 서버에 전달해 인식합니다.
자연어 명령 처리(DialogKit)
InsideDialogKitManager가 Inside gRPC Payload의 의도(intent)/명령(command)을 분류해 앱·미디어·차량 매니저로 라우팅합니다.
앱 실행/제어
GVoiceAppManager가 assets/AppInfoList.json·IntentInfoList.json을 참조해 음성으로 차량 내 앱(내비게이션·미디어 등)을 실행·제어합니다.
미디어 재생 제어
GVoiceMediaManager/Client/Controller가 AAOS car-media-common 기반으로 재생·일시정지·곡 정보 안내 등 미디어 명령을 처리합니다.
차량 공조 제어
GVoiceVehicleManager가 android.car.permission.CONTROL_CAR_CLIMATE 권한으로 공조 등 차량 제어 명령을 수행합니다.
TTS·사운드 안내
ViaGuidancePlayer·ViaMediaPlayer·ViaSoundPlayer가 TTS 응답과 시작/종료 사운드(ding.mp3, Sound2_Marimba.mp3)를 재생합니다.
표준 STT 서비스 경로
feature/support_stt에서 추가된 기능으로, 외부 앱이 START_STT/STOP_STT 액션과 targetAppId로 받아쓰기를 요청하면 인식 결과/오류를 돌려줍니다.
RecognitionService 등록
GRecognitionService가 android.speech.RecognitionService 인텐트와 @xml/recognition_service 메타데이터로 시스템 음성 인식 공급자로 등록됩니다.
SP 미수신 재연동 로직
SP(서비스 플랫폼)에서 데이터를 받지 못한 상태로 발화 요청이 오면 TTS 안내를 제공한 뒤 SP 연동을 재시도합니다(커밋 3904ef6b).
네트워크 상태 모니터링
NetworkStateManager/NetworkStateHandler가 연결 상태를 감시해 음성 세션 동작과 오류 안내를 제어합니다.
사용 로그 수집
UsageCollectionManager가 음성 사용 로그를 수집하고 GVoiceApiClient(Retrofit)로 BO 서버에 전송합니다.
코드 난독화(Allatori)
빌드 시 allatori.xml·runAllatori 태스크로 컴파일 결과에 Allatori 난독화를 적용합니다(커밋 6c315d77).

계층 · 외부 연동

앱은 매니페스트에 :interactor(VoiceInteractionService), :session(SessionService), 그리고 기본 프로세스의 RecognitionService 등 다중 프로세스 구조로 정의됩니다. 프레임워크는 부팅 후 기본 어시스턴트로 설정된 앱의 VoiceInteractionService를 상시 구동하고, 호출어 감지 시 showSession()으로 세션을 띄웁니다. 외부 백엔드 연동은 두 갈래입니다. KT GiGA Genie Inside 서버에는 gRPC(grpc-okhttp/protobuf-lite/stub 1.38.0, live 기준 inside-dev.gigagenie.ai:50109)로 음성 인식·NLU를 연동하고, AVIS SP/BO 서버에는 Retrofit REST(SP_BASE_URL/BO_BASE_URL)로 데이터·사용 로그를 주고받습니다. 시스템 권한(MEDIA_CONTENT_CONTROL, BIND_VOICE_INTERACTION, 차량 공조 권한)을 사용하므로 시스템/플랫폼 서명 환경(AAOS 단말)에서의 설치가 전제입니다(일부 추정).

핵심 동작 흐름

1) 호출어 발화부터 명령 수행까지

  1. 호출어 감지GVoiceInteractionService(:interactor)가 상시 동작하며 KwsDetector(kwsrnet)가 마이크 입력에서 호출어를 감지합니다.
  2. 세션 시작showSession()으로 GVoiceInteractionSessionService(:session)가 세션을 생성하고 시작 사운드와 음성 플레이트 UI를 노출합니다.
  3. 오디오 캡처 · 인식VoiceRecorder가 PCM 오디오를 캡처하고 InsideVoiceManager가 Inside SDK 세션으로 발화를 서버에 전달해 인식·NLU 결과를 받습니다.
  4. 의도 분류InsideDialogKitManager가 gRPC Payload의 의도(intent)/명령(command)을 분류해 적절한 매니저로 라우팅합니다.
  5. 명령 수행GVoiceAppManager(앱 실행)·GVoiceMediaManager(미디어)·GVoiceVehicleManager(공조) 중 해당 매니저가 명령을 실행합니다.
  6. TTS · 사운드 안내ViaGuidancePlayer/ViaSoundPlayer가 TTS 응답과 종료 사운드를 재생하고 세션을 정리합니다. 이후 다시 호출어 대기 상태로 돌아갑니다.

2) STT(받아쓰기) 서비스 흐름 — feature/support_stt

  1. STT 요청 수신외부 앱이 com.kt.avis.action.START_STT 액션과 대상 앱 식별자(targetAppId)를 담아 받아쓰기를 요청합니다.
  2. 인식 시작InsideVoiceManager.startSTT(target)가 상태를 REQ_STT로 전환하고 오디오 포커스를 확보한 뒤 voiceToTextStart()로 인식을 시작합니다.
  3. 결과 전달인식이 완료되면 GVoiceAppManager.stopSpeechToText(userWord)가 결과를 RECOGNITION_RESULT로 대상 앱에 전달합니다(오류 시 RECOGNITION_ERROR/RECOGNITION_UNAVAILABLE).
  4. 종료STOP_STT 액션 또는 stopSTT() 호출로 세션을 정리하고 오디오 포커스를 해제한 뒤 READY 상태로 복귀합니다.

3) SP 미수신 시 재연동

  1. 데이터 미수신 상태 발화SP(서비스 플랫폼)에서 앱/명령 데이터를 받지 못한 상태에서 발화 요청이 들어옵니다.
  2. TTS 안내즉시 명령을 수행하지 않고 안내 TTS를 제공합니다.
  3. SP 재연동 시도SP 연동을 재시도해 데이터를 갱신한 뒤 정상 흐름으로 복귀합니다(커밋 3904ef6b 기준).

빌드 · 실행

빌드 진입점은 packages/apps/Car/libs/aaos-apps-gradle-project 디렉터리의 Gradle Wrapper입니다. 제품 flavor는 dev·tb·production 3종이며, 각 flavor는 config/avis.<flavor>.properties의 서버 URL/키를 BuildConfig 필드로 주입받습니다. 빌드 타입(debug/release)에는 공통으로 config/live_inside.properties가 적용됩니다.

cd packages/apps/Car/libs/aaos-apps-gradle-project

# 음성비서 앱 디버그 빌드 (dev flavor 예시)
./gradlew :car-custom-voice-app:assembleDevDebug

# 릴리스 빌드 (production flavor 예시, 서명 + Allatori 난독화 적용)
./gradlew :car-custom-voice-app:assembleProductionRelease

# 클린
./gradlew clean

버전은 version.properties(MAJOR·MINOR·PATCH)에서 계산되며, 현재 값 기준 versionCode 201 / versionName v0.02.01 입니다. APK 파일명은 avis_voice_<flavor>_<version><-debug|-release>_<빌드일자>.apk 형식으로 생성됩니다. debug/release 모두 signingConfigs.release(keystore/aaos.inside.via.keystore.jks)로 서명합니다.

빌드 전제
compileSdk 32 SDK 플랫폼이 설치되어 있어야 하며, 컴파일에는 prebuilts/sdk/31/system의 시스템 stub(android.jar, android.car-system-stubs.jar)이 부트클래스패스로 주입됩니다. 시스템 권한(MEDIA_CONTENT_CONTROL, BIND_VOICE_INTERACTION, 차량 공조 권한)을 사용하므로 일반 사이드로드 설치만으로는 동작이 제한될 수 있고, 시스템/플랫폼 서명 환경(AAOS 단말)에서의 설치가 전제입니다(일부 추정).
