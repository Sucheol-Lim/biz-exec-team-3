설정 (관리자)

SettingsPage가 단일 라우트(/settings) 안에서 카테고리별 솔루션 작업 설정(WorkConfig)·솔루션별 연동 설정(Integration)·사용자 권한 설정(UserRole) 3개 탭을 제공하는 관리자 설정 화면입니다. 연동 탭은 드래프트/베이스라인 스토어 기반 dirty 가드와 즉시 저장 모델을, 권한 탭은 낙관적 업데이트 기반 역할 변경을 구현하며 권한 3계층(일반운영자/중간관리자/시스템관리자) 정책과 연동됩니다.

기능 개요

설정 메뉴는 src/features/settings/routes.ts가 self-export 하는 단일 라우트 settings로 앱 셸(AppShellContainer) 하위에 등록되며, SettingsPage.vue가 공용 세그먼트형 탭 컴포넌트(VTabs, Reka UI TabsRoot 합성)로 3개 탭을 렌더합니다. 탭 구성은 SETTINGS_TAB_ITEMS 상수에 정의된 카테고리별 솔루션 작업 설정(work) · 솔루션별 연동 설정(integration) · 사용자 권한 설정(roles)이며, 활성 탭은 딥링크 없이 페이지 내부 activeTab ref가 소유합니다. 탭 전환 시 handleTabChange가 가드를 거쳐, 차단되면 마지막 통과 탭(committedTab)으로 롤백하는 구조입니다.

탭1(WorkConfig)은 장르/세부장르 필터 + DataTable + 페이지네이션으로 카테고리 작업 항목을 조회하고 CategoryItemFormModal로 항목 추가/수정을 수행합니다. 솔루션 마스터는 API(E10 /solutions) 응답이 없으면 FE 상수 SETTING_SOLUTIONS(포스터·썸네일·자막·구간마킹·얼굴인식·골라보기·하이라이트·개인화 포스터/하이라이트 9종)로 폴백합니다. 탭2(Integration)는 전체 자동 연동 마스터 스위치 + SolutionIntegrationCard 9장으로 구성되며, useSettingsEditorStore의 드래프트/베이스라인 이중 상태로 dirty를 판정하고 토글·체크 변경마다 전체 스냅샷을 PUT 하는 즉시 저장 모델을 씁니다. 저장 실패 시 직전 저장 상태로 자동 복원됩니다.

탭3(UserRole)은 역할 필터(VSelect) + 키워드 검색 + UserRoleTable로 사용자 목록을 조회하고, 역할 변경(E8 PUT /users/:id/role)은 Vue Query 캐시를 먼저 갱신하는 낙관적 업데이트로 처리합니다. 역할 코드는 OPERATOR/MANAGER/ADMIN 3계층으로, 앱 전역의 권한 판정 컴포저블 useCan(authStore role 기반)이 참조하는 권한 정책의 관리 지점입니다. 모든 API는 SETTINGS_API·USER_API 등 추상 경로 상수를 경유하고 dev에서는 MSW가 인터셉트하며, DTO→도메인 변환은 api/adapters/settings.ts 단일 지점에서만 수행합니다.

2026-08 공통 컴포넌트 정합 라운드에서 설정 화면도 소폭 조정되었습니다. 연동 카드의 스위치는 VSwitch size를 구 명칭 md에서 Figma Draft 명칭 medium으로 교체했고, 탭1·탭3 표의 행 높이는 한동안 --v-table-row-h: var(--table-cell-h-small)(48px)로 명시 핀(P2b, "Figma Size 확정 전" 임시 조치)을 걸고 있었으나 2026-08-20 GUI 실측(Table Structure 1656×60)으로 그 핀이 해소되어 공용 DataTable 기본값 --table-cell-h-medium(60px)을 그대로 씁니다. 한편 LNB는 v0.7 반영으로 'AI 개인화'가 개인화 포스터/개인화 하이라이트로 2분할되고 얼굴인식이 분리되어 13개 메뉴가 되었지만, 연동 탭의 솔루션 마스터(SETTING_SOLUTIONS)는 여전히 9종으로 LNB 메뉴 수와 직접 대응하지 않습니다(모니터링·설정은 솔루션이 아니고, AI Pick은 솔루션 목록에 없습니다).

2026-08-28 설정 3개 탭 전체가 실 BE 경로로 이관되었습니다. 종전 FE 추상 경로(/settings/category-items·/settings/integration·/users·/genres)는 실 BE에 존재하지 않아 live 모드에서는 3개 탭이 통째로 404였습니다. 실계약은 탭1 GET/POST/PUT /api/solution/service(/list, /{solutionId})(설정#1~#3), 탭2 GET /api/solution/link/list + PUT /api/solution/link(설정#4·#5), 탭3 GET /api/users + PUT /api/users/{userId}(설정#6·#8, pathParam은 사번이 아니라 Integer PK userId)입니다. 이관에는 세 가지 축 정합이 함께 따라왔습니다. ① 탭2의 실계약 축은 「솔루션 × 장르쌍」인데 화면은 「솔루션 × 탭1 항목」이라, 두 축의 장르쌍 집합이 실측으로 정확히 일치함(14/14)을 확인하고 어댑터에서 조인해 UI는 그대로 둡니다(마스터 토글은 별도 필드가 아니라 serviceType:'ALL' 행). ② 실 BE 솔루션은 10종(AIPICK 포함)인데 화면 열은 9종(GUI 정본)이라, 저장 시 화면 밖 솔루션이 조용히 꺼지지 않도록 원본 rawServiceList/raw를 왕복 보존합니다. ③ 탭1 장르 필터는 설정 전용 마스터(/genres, G01류)를 폐기하고 공통#13 코드축(genreDisplay, "11"류)으로 통일했습니다(당초 공통#12로 잡았던 인용키는 이후 다른 계약이 그 번호를 차지하며 공통#13으로 재확정) — 그 마스터에는 "전체" sentinel 행(G00)이 없어 필터 로직도 이름(전체) 기준으로 바뀌었습니다. 존재하지 않던 GET /solutions(E10)·GET /me 폴백 조회는 참조 0건과 상시 404만 만들던 코드라 그대로 제거되었고, 솔루션 9열은 SETTING_SOLUTIONS 상수를 정본으로 직접 씁니다.

서버 오류 표시도 이 시점에 바로잡혔습니다. 종전에는 오류 코드를 mock이 만든 형상(body.error.code)에서 읽었는데 실 BE는 공통 엔벨로프라 body.code이고, i18n 사전에도 mock 코드(VAMS-SET-*)만 있어 형상을 고쳐도 매칭될 키가 없었습니다. 그 결과 live에서는 모든 설정 오류가 "오류가 발생했습니다"로 뭉개졌고, 중복 등록(409) 모달의 인라인 에러도 뜨지 않았습니다. 코드 해석 로직이 useSettingsMutations.ts와 WorkConfigTab.vue 두 곳에 복사돼 있던 것을 features/settings/errorCodes.ts 단일 출처로 모으고, 실 BE 코드 7종(VALIDATION_FAILED·BAD_REQUEST·NOT_FOUND·API_NOT_FOUND·LOGIN_REQUIRED·FORBIDDEN·INTERNAL_SERVER_ERROR)를 i18n에 추가했습니다. BE의 message 원문은 내부 표현이 사용자에게 새는 것을 막기 위해 화면에 직결하지 않고 DEV 콘솔에만 남깁니다.

2026-09-03에는 .env.development에서 설정 3개 탭 경로를 실제로 live로 켜(실측 8종 드리프트 0) 이관 작업이 배선 확인을 마쳤고, 자잘한 GUI 재정합도 뒤따랐습니다 — 탭1 테이블 컬럼을 다른 메뉴처럼 유연 폭(grow)으로 바꾸고, 연동 탭 솔루션 카드 순서를 단일 출처로 정리했으며, 3개 탭 공통으로 탭↔섹션 세로 간격을 44px에서 20px로 좁혔습니다.

설계 포인트 — dirty 가드 이중 결선
연동 탭의 미저장 드래프트 보호는 두 경로에 결선됩니다. 같은 페이지 안의 탭 전환은 useSettingsGuard.guardTabChange가, 다른 메뉴로의 라우트 이탈은 onBeforeRouteLeave 훅이 각각 확인 모달(useConfirm)을 띄우고, 이동을 확정하면 resetIntegration()으로 드래프트를 폐기합니다.

src/features/settings/pages/SettingsPage.vue — 탭 전환 가드와 committedTab 롤백
/** 활성 탭 (D1: 내부 상태, 딥링크 없음). */
const activeTab = ref<SettingsTab>('work')
/** 가드를 통과한 마지막 탭 — 차단 시 롤백 기준 */
let committedTab: SettingsTab = 'work'

const { guardTabChange } = useSettingsGuard()

async function handleTabChange(newTab: string) {
  if (newTab === committedTab) return // 현재 탭 재클릭 = 무반응

  // 이 시점 activeTab은 이미 newTab(v-model) — 가드 차단 시 롤백
  const allowed = await guardTabChange(committedTab, newTab)
  if (allowed) {
    committedTab = newTab as SettingsTab
  } else {
    activeTab.value = committedTab // 차단 시 이전 탭으로 롤백
  }
}
src/features/settings/stores/useSettingsEditorStore.ts — 솔루션 토글과 마스터 파생 동기화(V7)
/**
 * 솔루션 개별 토글.
 * 전체 자동 연동(마스터)은 "모든 솔루션이 ON일 때만 ON"으로 파생 동기화(V7).
 * → 하나라도 OFF되면 마스터 OFF / 개별 토글로 전부 ON이 되면 마스터 ON.
 */
function toggleSolution(code: SettingSolutionCode, enabled: boolean): void {
  if (!integrationDraft.value) return
  const solutions = integrationDraft.value.solutions.map((s) =>
    s.code === code ? { ...s, enabled } : s,
  )
  // 마스터 = 모든 솔루션 ON일 때만 ON (하나라도 OFF면 OFF)
  const masterEnabled = solutions.every((s) => s.enabled)
  integrationDraft.value = { ...integrationDraft.value, solutions, masterEnabled }
}
src/features/settings/composables/useSettingsGuard.ts — 탭2 dirty 확인 가드
async function guardTabChange(fromTab: string, toTab: string): Promise<boolean> {
  if (fromTab !== 'integration' || !integrationDirty.value) {
    return true // 탭2 아니거나 dirty 아님 → 바로 허용
  }
  if (fromTab === toTab) return false // 현재 탭 재클릭 = 무반응

  const ok = await confirm({
    titleKey: 'settings.common.leaveConfirm.title',
    messageKey: 'settings.common.leaveConfirm.message',
    confirmKey: 'settings.common.leaveConfirm.confirm',
    cancelKey: 'settings.common.leaveConfirm.cancel',
  })

  if (ok) {
    store.resetIntegration() // 이동 확인 시 드래프트 폐기
  }
  return ok
}
src/features/settings/errorCodes.ts — 실 BE 오류 형상·코드 해석 단일 출처(2026-08-28 신설)
/**
 * 오류 객체 → 서버 코드.
 * `api/http.ts` 는 실패 시 {status, body} 를 붙여 던진다. 실 BE 는 공통 엔벨로프
 * ({code,message,data})이고, mock 일부는 아직 {error:{code,message}} 를 준다 —
 * 전환기 동안 둘 다 읽는다.
 */
export function getSettingsErrorCode(error: unknown): string {
  if (!error || typeof error !== 'object') return 'UNKNOWN'
  const e = error as Record<string, unknown>
  const body = (typeof e['body'] === 'object' ? e['body'] : null) as Record<string, unknown> | null

  if (body && typeof body['code'] === 'string') return body['code'] // 실계약: 엔벨로프 최상위 code
  if (body && typeof body['error'] === 'object' && body['error'] !== null) {
    const inner = body['error'] as Record<string, unknown>
    if (typeof inner['code'] === 'string') return inner['code'] // 레거시 mock 형상
  }
  if (typeof e['code'] === 'string') return e['code']
  return 'UNKNOWN'
}
