대시보드 (통합 AI 작업 목록)

포스터·썸네일·자막 등 전 AI 엔진의 작업(Job)을 단일 목록에서 조회·필터링하는 VAMS 홈 화면입니다. 서비스 타입 다중 필터(9종 — 개인화 포스터·개인화 하이라이트 분리)·상태칩(7종)·상태칩별 동적 정렬을 제공하고, 검색 조건은 vams:listQuery:dashboard 키로 localStorage에 영속되어 재방문 시 복원됩니다. 리스트 필터·툴바·테이블 셀·빈 상태·상세패널은 전 메뉴 공통 컴포넌트로 승격되었고, 목록·상세 조회 모두 실 BE 공통 시트(공통#1/#2/#3/#6/#7)로 전환된 상태입니다.

기능 개요

대시보드는 VAMS 로그인 후 처음 만나는 홈 화면으로, 포스터·썸네일·자막·개인화 포스터·개인화 하이라이트·구간마킹·얼굴인식(CI)·골라보기·하이라이트 9개 서비스 타입의 AI 작업을 하나의 목록으로 통합 조회합니다. 화면은 DashboardListPage.vue가 ContentListLayout 슬롯 합성으로 구성하며, 검색(SearchBox+최근검색)·상태칩 7종(전체/대기/검수필요/실패/검수중/검수완료/연동완료)·AI작업 다중 칩(전체 토글 + 9종)·조회기간 프리셋(1/5/15일/직접설정 달력)·긴급만 보기 스위치를 검색 조건으로 제공합니다. AI작업 9종 분화는 Flipbook Revision v0.9.30("LNB, AI작업칩: 개인화 포스터, 개인화 하이라이트 추가")로 개인화 칩이 SEGIMAGE·SEGHIGH 2코드로 나뉜 결과입니다. 상태칩 노출 옵션은 메뉴별 로컬 정의로 어긋나던 것을 domain/statusChip.ts의 statusChipOptions() 단일 소스로 통합했고, 페이지당 건수도 domain/pageSize.ts 공통 정책(10/20/50, 기본 20)을 따르며, 정렬 라벨도 3갈래로 갈렸던 표기를 domain/sortLabel.ts의 SORT_LABELS 단일 소스(최신입수순/오래된입수순/검수필요·실패 우선)로 정리했습니다.

리스트 페이지에 복붙돼 있던 필터·툴바 마크업은 이 화면을 파일럿으로 공통 컴포넌트에 이관됐습니다. 상태칩·AI작업 칩 행은 FilterBar+FilterField(범용 필터 슬롯) 조합 위에 상태칩 전용 StatusFilterField가 얹히고, ListToolbar가 Figma Header/Table 정본(타이틀 바 24h + 서브 바 32h)을 컨테이너로 제공하는 그 안에 카운트(ToolbarCount — 총 N건·선택 N건), 조회기간(DateRangeControl — 프리셋 박스 + 기간 표시 + 달력 팝오버), 정렬·페이지당 드롭다운(ToolbarBox)이 슬롯으로 주입됩니다. 이 v-model·핸들러 배선(datePreset·size·값라벨·달력 개폐) 자체도 10개 리스트 페이지가 동일하게 복붙하던 것을 useListToolbar 한 곳으로 모았습니다. 테이블 본문도 ID/명 2단 셀(IdNameCell)·행 CTA(TableActionButton — min-width 64 셀 규칙)·로딩(TableLoading)·빈 상태(ListEmptyState)로 공통화됐고, 상태 셀은 배지+원본변경 아이콘 마크업이 8개 메뉴에서 드리프트하던 것을 StatusChangedCell(StatusBadge dot + 16px 경고 아이콘, gap 6)로 일원화했습니다. 긴급 표식은 콘텐츠 셀 인라인에서 65px 전용 컬럼으로 분리됐고, 우측 상세패널 열림/닫힘 상태기계도 useListDetailPanel(닫기 트리거 3종 — ×·ESC·체크박스 선택 + 홈 전용 같은 행 재클릭 토글)로 공통화됐습니다. 컬럼 폭 모델도 패널 개폐 분기(panelOpen)로 두 벌을 손튜닝하던 방식을 버리고, 콘텐츠=흡수 주열(grow:1)·시리즈=양보 보조열(grow:0)·나머지=tier 고정폭이라는 §8 grow 관용구로 재선언해 컨테이너 폭만으로 전 상태가 재현됩니다.

검색 조건 상태는 공통 팩토리 createListQueryStore('dashboard')가 만든 Pinia 싱글톤 스토어가 담당합니다. 스토어는 @vueuse/core의 useStorage로 vams:listQuery:dashboard 키에 화이트리스트(상태칩·서비스타입·장르 2단·작업유형·조회기간 프리셋·정렬 등 — keyword·page는 제외)를 영속해, 다른 메뉴에 다녀와도 필터가 유지됩니다. 복원 시 size는 normalizePageSize()로, datePreset은 normalizeDatePreset()으로 각각 정본 집합에 정규화되고, dateRange는 restoreDateRange()가 프리셋(1/5/15일)이면 오늘 기준으로 재계산합니다 — 어제 저장한 절대 날짜를 그대로 복원하면 버튼 라벨은 "1일"인데 실제 조회는 어제 날짜로 나가던 문제(실측: startDt=endDt가 하루 전으로 굳어 0건)를 막기 위한 조치이며, 'custom'(직접설정)만 저장된 절대 범위를 유지합니다. 스토어는 hasActiveFilters computed 도 함께 노출하는데, 필터 필드(키워드·상태칩·서비스타입·장르 2단·작업유형·API명·조회기간·긴급) 중 하나라도 기본값과 다르면 참이 되어 0건 화면을 "조건에 맞는 작업이 없습니다"와 "등록된 작업이 없습니다"로 갈라 줍니다 — 정렬·페이지네이션은 결과를 0건으로 만드는 필터가 아니라 판정에서 제외합니다. 조회는 toListQuery()가 SearchData를 공통#1 계약 단일 소스인 api/contentListQuery.ts의 toContentListQuery()에 위임해 쿼리 파라미터로 변환하고, 그 출력이 TanStack Vue Query의 queryKey가 되어 필터를 바꾸면 자동 재조회됩니다. 응답 DTO는 api/adapters/dashboard.ts에서만 도메인 모델(DashboardJobRow)로 변환되어 화면은 DTO를 직접 만지지 않습니다.

행 단위 액션은 상태 기반 CTA로 결정됩니다. useDashboardActions().ctaFor()가 내부 상태코드 10종(P·I·F·S·R·V·W·T·E·L) 중 검수 가능 상태(S·V·L)와 연동실패(E)를 [검수]로 매핑하고(상태별 단건 액션 정책 v2 — 단건 [재처리요청]은 삭제되어 실패(F) 건은 툴바의 일괄 재처리요청으로만 처리, 연동실패도 [검수]로 통일), [검수]는 reviewRoute()가 domain/serviceRoute.ts의 단일 정본(serviceTypeRoute())에 위임해 서비스 타입별 상세 화면으로 라우팅합니다(개인화 하이라이트는 contentId 도 함께 실어 보냄). 일괄 연동/재처리 버튼의 활성 여부는 선택 행들의 상태 조합을 보는 useBulkActionEligibility가 판정하는데, 8개 메뉴가 같은 허용집합(연동=S·V·E / 재처리=F)을 복제하고 있던 것을 행 타입만 제네릭으로 받는 shared/composables 단일 구현으로 승격했습니다. 같은 정리로 조회기간 프리셋 datePresetOptions 9벌은 shared/lib/datePreset.ts로, 달력 팝오버 DateRangeCalendarPopover 9벌은 shared/components/composite/date-picker/로 합쳐졌습니다. 우측 상세 패널(DashboardDetailPanel)도 자체 <dl> 마크업을 공통 PanelInfoTable(행별 #label-*/#value-* 슬롯)로 바꾸고 장르 경로는 GenrePath, 긴급 표식은 UrgentBadge, 상태 카드 CTA는 PanelActionButton을 씁니다. 콘텐츠정보 섹션은 콘텐츠 유형·해상도 2필드가 추가돼 공통 정본 10필드(시리즈ID/명·콘텐츠ID·회차명·장르/세부장르·콘텐츠유형·해상도·원본URL·트랜스코드경로·입수일)로 완성됐고, 원본 URL 행에는 isChangedOriginPath가 참일 때 경고 아이콘+툴팁이 붙습니다. 작업이력 섹션의 엔진 버전 항목은 제거됐습니다 — GUI 정본에서 항목이 빠지고 API 리스트 v1.0.3 「작업이력 조회」가 enginVersion을 폐기 표시한 뒤 v1.0.4에서 공통#3 응답 필드가 실제로 삭제되어, 도메인 모델과 어댑터의 normalizeEngineVersion까지 8개 메뉴에서 함께 걷어냈습니다.

설계 포인트
기본 정렬은 "검수필요·실패 우선"(PRIORITY)이지만 상태칩이 all이 아니면 우선순위 정렬이 무의미하므로 toContentListQuery()가 LATEST로 강등하는 가드를 둡니다. 상태칩 변경 시에도 칩별 기본 정렬(SORT_BY_CHIP)로 자동 전환됩니다. 반응형 컬럼은 DataTable 내부의 useColumnLayout이 담당하는데, flexbox 결합 분배 알고리즘으로 폭을 계산해 px로 주입하되 활성 조건이 "grow>0 컬럼 1개 이상"이라, grow를 선언하지 않은 기존 화면은 레거시 고정폭 경로를 그대로 타 회귀가 없습니다(가상 스크롤 경로는 범위 밖). 홈은 2026-08-31에 전 경로가 실 BE 공통 시트로 이관됐습니다 — 목록은 공통#1(/api/content-info/list, serviceType 생략=전 메뉴 합집합), 상세는 합본 엔드포인트가 없어 공통#3(작업이력, contentId 확보) → 공통#2(콘텐츠정보) 순차 조인이며, 일괄 연동·재처리는 공통#6·#7입니다. dev 서버에서는 이 실경로들을 MSW가 인터셉트합니다. 2026-09-10에는 총건수 미제공 시 다음 페이지가 잠기던 결함이 13개 메뉴 공통으로 고쳐졌습니다 — 어댑터가 종전엔 응답에 총건수가 없으면 "받은 행 수"를 총건수로 대신 썼는데, 그러면 totalPages=ceil(total/size)가 현재 페이지에서 끊겨 조용히 마지막 페이지처럼 보였습니다. 지금은 표시값(총 N건)과 "뒤에 더 있다" 판정(hasMore)을 분리해, 총건수가 정확하면 그 값을 쓰고 서버가 last 플래그를 주면 그것을(Spring Page 축), 둘 다 없으면 꽉 찬 페이지 휴리스틱으로 shouldOpenNextPage 한 곳이 판정합니다.

2026-09-18 범위(9/11~9/18)에서는 상태 표시축이 다시 갈립니다. 상태칩(조회축) 7종은 그대로지만, 상태 셀·상세패널의 배지는 10종 내부 상태를 원본 그대로 표시하도록 뒤집혔습니다(domain/types.ts의 BadgeState·toBadgeState() 신설 — REQ-STATUS-005). 대시보드도 StatusChangedCell·DashboardDetailPanel이 toBadgeState(jobState)로 배지를 그리도록 바뀌었고, StatusBadge는 채움(pill) 변형이 정본에 없어 폐기되어 dot/panel 2종만 남았습니다. 어댑터의 parseJobState도 12개 메뉴 사본에서 domain/types.ts 단일 정본으로 승격됐고, 목록 행이 코드표 밖 상태를 받으면 종전엔 'P'(작업대기)로 접었지만 이제 null → 셀 '-' 표시로 바뀌었습니다 — 취소(C) 같은 실측 미지 코드를 "AI 큐 등록됨"으로 잘못 보여주지 않기 위함이며, 일괄연동·재처리·[검수] CTA는 원래도 허용목록 기반이라 동작은 바뀌지 않습니다. 이 밖에 페이지네이션은 totalPages <= 1이면 영역 자체가 사라지도록(Pagination.vue) 바뀌었고, 우측 상세패널의 같은 행 재클릭 닫기(toggleOnSameRow)는 대시보드 전용에서 전 리스트 화면 공통 기본값으로 승격됐습니다.

/**
 * SearchData(listQuery store) → 공통#1 쿼리파라미터.
 * 홈 고유값은 serviceType 이 가변이라는 것뿐이다.
 *   · AI작업 칩이 비었으면 → 키 자체를 싣지 않는다 = 전 메뉴 합집합(홈의 기본 상태)
 *   · 칩을 고르면 → 그 코드를 싣는다(BE 가 묶음코드를 실제코드로 확장해 준다).
 * PRIORITY 강등은 공용 기본값(LATEST)을 쓴다.
 */
export function toListQuery(s: SearchData): DashboardListQueryParams {
  return toContentListQuery(s, { serviceType: [...s.serviceTypes] })
}
src/api/contentListQuery.ts — 공통#1 파라미터 계약 단일 소스(13개 메뉴 공용)
export function toContentListQuery(
  s: SearchData,
  opts: ContentListQueryOptions,
): ContentListQueryParams {
  const demote = opts.demotePriority ?? (() => 'LATEST' as SortType)
  const sortType: SortType =
    s.sortType === 'PRIORITY' && s.statusChip !== 'all' ? demote(s.statusChip) : s.sortType

  // 날짜는 필수다(생략 시 VALIDATION_FAILED) → 스토어에 없으면 기본 범위(60일)를 만든다.
  const range = s.dateRange
    ? { from: toSpecDate(s.dateRange.from), to: toSpecDate(s.dateRange.to) }
    : defaultRange(opts.defaultRangeDays, opts.now)

  const params: ContentListQueryParams = {
    page: String(s.page), size: String(s.size), sortType,
    startDate: range.from, endDate: range.to,
  }

  // 빈 배열은 명시적 전체다 — 키를 싣지 않는다(빈 값을 실으면 BE 가 0건을 준다)
  const svc = opts.serviceType
  if (svc !== undefined && (!Array.isArray(svc) || svc.length > 0)) params.serviceType = svc
  if (s.keyword) params.searchWord = s.keyword

  // 칩이 묶는 상태를 전부 싣는다(다중 지원). '전체' 칩은 빈 배열이라 키가 빠진다.
  const states = CHIP_TO_STATES[s.statusChip]
  if (states.length > 0) params.progressState = [...states]
  if (s.urgentOnly) params.isUrgent = 'Y'
  return params
}
src/shared/stores/listQuery.ts — 검색 조건 영속 (vams:listQuery:<slug>)
export function createListQueryStore(slug: string) {
  return defineStore(`listQuery:${slug}`, () => {
    // useStorage 영속(화이트리스트) — 키 vams:listQuery:{slug}
    const persisted = useStorage<PersistedSearchData>(
      `vams:listQuery:${slug}`,
      pickPersisted(defaultSearchData()),
      localStorage,
      { mergeDefaults: true },
    )

    // searchData 초기값 = 기본값 + 영속 화이트리스트 머지.
    // size·datePreset 은 정본 집합으로 정규화 — 옵션 배열 변경 전 영속값이 남아 있으면
    // 드롭다운 라벨이 빈 문자열이 되거나(size) presetToDateRange 산술이 깨진다(datePreset).
    // dateRange 는 restoreDateRange() 가 프리셋(1/5/15)이면 "오늘 기준"으로 재계산한다 —
    // 어제 저장한 절대 날짜를 그대로 복원하면 라벨(1일)과 실제 조회 날짜가 어긋난다.
    const merged = { ...defaultSearchData(), ...persisted.value }
    const datePreset = normalizeDatePreset(merged.datePreset)
    const searchData = reactive<SearchData>({
      ...merged,
      datePreset,
      size: normalizePageSize(merged.size),
      dateRange: restoreDateRange(datePreset, merged.dateRange),
    })
    persisted.value = pickPersisted(searchData) // 정규화 결과 즉시 되쓰기(stale 값 정리)

    // searchData 변경 → 영속 화이트리스트 동기화
    watch(
      () => pickPersisted(searchData),
      (val) => { persisted.value = val },
      { deep: true },
    )

    // 활성 필터 존재 여부 — 필터 필드가 하나라도 기본값과 다르면 true.
    // 리스트 "빈 상태" 분기(필터 결과 없음 vs 데이터 없음)의 단일 정본. 전 메뉴 공용.
    // ⚠️ 필터만 포함 — sortType(정렬)·page·size(페이지네이션)는 결과를 0건으로 만드는 "필터"가 아니라 제외.
    const hasActiveFilters = computed<boolean>(() => {
      const d = defaultSearchData()
      return (
        searchData.keyword !== d.keyword ||
        searchData.statusChip !== d.statusChip ||
        searchData.serviceTypes.length > 0 ||
        searchData.genre !== d.genre ||
        ...
        searchData.urgentOnly !== d.urgentOnly
      )
    })

    return { searchData, patch, reset, hasActiveFilters }
  })()   // defineStore(...)() 즉시실행 — 싱글톤 인스턴스 반환
}

export function useDashboardColumns(): ComputedRef<ColumnDef<DashboardJobRow>[]> {
  const { t } = useI18n()
  // 뷰포트 tier — GUI "1280뷰포트"(LNB Fold) 경계. 1280 이하 = narrow.
  const isNarrow = useMediaQuery('(max-width: 1280px)')
  return computed(() => buildColumns(t, isNarrow.value))
}

function buildColumns(t: (key: string) => string, narrow: boolean): ColumnDef<DashboardJobRow>[] {
  // tier별 고정폭(px) — Figma 실측. narrow(1280) 에서 데이터 컬럼이 축소·고정.
  const serviceW = narrow ? 84 : 96
  // 콘텐츠 흡수 주열: basis=min(잉여 흡수). 시리즈 양보 보조열: 선호>min(부족 시만 양보).
  const contentMin = narrow ? 220 : 420
  const seriesW = narrow ? 260 : 400
  const seriesMin = narrow ? 260 : 317

  return [
    // 긴급 배지 전용 컬럼 — 헤더 텍스트 없음. 고정 65. #cell-urgent 슬롯.
    { key: 'urgent', header: '', width: 65 },
    // 잉여 폭 전량 흡수, min 밑으론 안 줄어듦
    { key: 'contentId', header: t('dashboard.field.contentIdName'),
      width: contentMin, grow: 1, minWidth: contentMin, truncate: true },
    // 선호폭 유지, 부족(패널 열림) 시 min 까지만 양보
    { key: 'seriesId', header: t('dashboard.field.seriesIdName'),
      width: seriesW, grow: 0, minWidth: seriesMin, truncate: true },
    { key: 'serviceType', header: t('dashboard.field.serviceType'), width: serviceW },
    ...
  ]
}

/**
 * 상태 → CTA 매핑 (cell-actions / DetailCta 공유). null 이면 버튼 없음.
 * - S·V·L·E → 검수(상세 이동, D2) / F → 버튼 없음(일괄 재처리요청만 제공)
 * - 대기·진행(P·W·I·T·R) → null
 * 근거: REQ-STATUS-003 v2 (Figma Flipbook Policy §2, 2026-07-13 —
 *   단건 [재처리요청]·[일괄연동] 삭제, 연동실패도 [검수]로 통일)
 */
function ctaFor(jobState: JobState): CtaConfig | null {
  switch (jobState) {
    case 'S':
    case 'V':
    case 'L':
    case 'E':
      return { labelKey: 'dashboard.action.review', action: 'review' }
    default:
      return null
  }
}
