대시보드 (통합 AI 작업 목록)

포스터·썸네일·자막 등 전 AI 엔진의 작업(Job)을 단일 목록에서 조회·필터링하는 VAMS 홈 화면입니다. 서비스 타입 다중 필터(8종)·상태칩(7종)·상태칩별 동적 정렬을 제공하고, 검색 조건은 vams:listQuery:dashboard 키로 localStorage에 영속되어 재방문 시 복원됩니다. 리스트 툴바·테이블 셀·빈 상태·상세패널은 전 메뉴 공통 컴포넌트로 승격되었고, 이 화면이 툴바 공통화의 정본 파일럿입니다.

기능 개요

대시보드는 VAMS 로그인 후 처음 만나는 홈 화면으로, 포스터·썸네일·자막·개인화·구간마킹·얼굴인식(CI)·골라보기·하이라이트 8개 서비스 타입의 AI 작업을 하나의 목록으로 통합 조회합니다. 화면은 DashboardListPage.vue가 ContentListLayout 슬롯 합성으로 구성하며, 검색(SearchBox+최근검색)·상태칩 7종(전체/대기/검수필요/실패/검수중/검수완료/연동완료)·AI작업 다중 칩·조회기간 프리셋(1/5/15일/직접설정 달력)·긴급만 보기 스위치를 검색 조건으로 제공합니다. 상태칩 노출 옵션은 메뉴별 로컬 정의로 어긋나던 것을 domain/statusChip.ts의 statusChipOptions() 단일 소스로 통합했고, 페이지당 건수도 domain/pageSize.ts 공통 정책(10/20/50, 기본 20)을 따릅니다.

10개 리스트 페이지에 복붙돼 있던 툴바 마크업은 이 화면을 파일럿으로 공통 컴포넌트 4종에 이관됐습니다. ListToolbar가 Figma Header/Table 정본(타이틀 바 24h + 서브 바 32h)을 컨테이너로 제공하고, 그 안에 카운트(ToolbarCount — 총 N건·선택 N건), 조회기간(DateRangeControl — 프리셋 박스 + 기간 표시 + 달력 팝오버), 정렬·페이지당 드롭다운(ToolbarBox)이 슬롯으로 주입됩니다. 테이블 본문도 ID/명 2단 셀(IdNameCell)·행 CTA(TableActionButton — min-width 64 셀 규칙)·로딩(TableLoading)·빈 상태(ListEmptyState)로 공통화됐고, 긴급 표식은 콘텐츠 셀 인라인에서 65px 전용 컬럼으로 분리됐습니다. 컬럼 폭 모델도 패널 개폐 분기(panelOpen)로 두 벌을 손튜닝하던 방식을 버리고, 콘텐츠=흡수 주열(grow:1)·시리즈=양보 보조열(grow:0)·나머지=tier 고정폭이라는 §8 grow 관용구로 재선언해 컨테이너 폭만으로 전 상태가 재현됩니다.

검색 조건 상태는 공통 팩토리 createListQueryStore('dashboard')가 만든 Pinia 싱글톤 스토어가 담당합니다. 스토어는 @vueuse/core의 useStorage로 vams:listQuery:dashboard 키에 화이트리스트(상태칩·서비스타입·장르 2단·작업유형·조회기간 프리셋·정렬 등 — keyword·page는 제외)를 영속해, 다른 메뉴에 다녀와도 필터가 유지됩니다. 복원 시 size는 normalizePageSize()로 정본 옵션(10/20/50)에 정규화되어, 옵션 배열 변경 전의 영속값(예: 100)이 남아 있어도 기본값으로 폴백합니다. 스토어는 hasActiveFilters computed 도 함께 노출하는데, 필터 필드(키워드·상태칩·서비스타입·장르 2단·작업유형·API명·조회기간·긴급) 중 하나라도 기본값과 다르면 참이 되어 0건 화면을 "조건에 맞는 작업이 없습니다"와 "등록된 작업이 없습니다"로 갈라 줍니다 — 정렬·페이지네이션은 결과를 0건으로 만드는 필터가 아니라 판정에서 제외합니다. 조회는 toListQuery()가 SearchData를 쿼리 파라미터로 변환(서비스타입 CSV, 상태칩→jobStates 코드 변환)해 TanStack Vue Query의 queryKey로 삼는 구조라, 필터를 바꾸면 자동 재조회됩니다. 응답 DTO는 api/adapters/dashboard.ts에서만 도메인 모델(DashboardJobRow)로 변환되어 화면은 DTO를 직접 만지지 않습니다.

행 단위 액션은 상태 기반 CTA로 결정됩니다. useDashboardActions().ctaFor()가 내부 상태코드 10종(P·I·F·S·R·V·W·T·E·L) 중 검수 가능 상태(S·V·L)와 연동실패(E)를 [검수]로 매핑하고(상태별 단건 액션 정책 v2 — 단건 [재처리요청]은 삭제되어 실패(F) 건은 툴바의 일괄 재처리요청으로만 처리, 연동실패도 [검수]로 통일), [검수]는 reviewRoute()로 서비스 타입별 상세 화면(/poster/:jobId 등)으로 라우팅합니다. 일괄 연동/재처리 버튼의 활성 여부는 선택 행들의 상태 조합을 보는 useBulkActionEligibility가 판정하는데, 8개 메뉴가 같은 허용집합(연동=S·V·E / 재처리=F)을 복제하고 있던 것을 행 타입만 제네릭으로 받는 shared/composables 단일 구현으로 승격했습니다. 같은 정리로 조회기간 프리셋 datePresetOptions 9벌은 shared/lib/datePreset.ts로, 달력 팝오버 DateRangeCalendarPopover 9벌은 shared/components/composite/date-picker/로 합쳐졌습니다. 우측 상세 패널(DashboardDetailPanel)도 자체 <dl> 마크업을 공통 PanelInfoTable(행별 #label-*/#value-* 슬롯)로 바꾸고 장르 경로는 GenrePath, 긴급 표식은 UrgentBadge, 상태 카드 CTA는 PanelActionButton을 씁니다. 이때 작업이력의 엔진 버전 항목은 제거됐습니다 — GUI 정본에서 항목이 빠지고 API 리스트 v1.0.3 「작업이력 조회」가 enginVersion을 폐기 표시한 뒤 v1.0.4에서 공통#3 응답 필드가 실제로 삭제되어, 도메인 모델과 어댑터의 normalizeEngineVersion까지 8개 메뉴에서 함께 걷어냈습니다.

설계 포인트
기본 정렬은 "검수필요·실패 우선"(PRIORITY)이지만 상태칩이 all이 아니면 우선순위 정렬이 무의미하므로 toListQuery()가 LATEST로 강등하는 가드를 둡니다. 상태칩 변경 시에도 칩별 기본 정렬(SORT_BY_CHIP)로 자동 전환됩니다. 반응형 컬럼은 DataTable 내부의 useColumnLayout이 담당하는데, flexbox 결합 분배 알고리즘으로 폭을 계산해 px로 주입하되 활성 조건이 "grow>0 컬럼 1개 이상"이라, grow를 선언하지 않은 기존 화면은 레거시 고정폭 경로를 그대로 타 회귀가 없습니다(가상 스크롤 경로는 범위 밖). 백엔드 미연동 개발 단계라 dev 서버에서는 MSW가 DASHBOARD_API 경로를 인터셉트해 fixtures를 반환합니다.

export function toListQuery(s: SearchData): DashboardListQueryParams {
  // PRIORITY 가드 — 상태칩이 all 이 아니면 LATEST 로 강등
  const sortType: SortType =
    s.sortType === 'PRIORITY' && s.statusChip !== 'all' ? 'LATEST' : s.sortType

  const base: DashboardListQueryParams = {
    page: String(s.page),
    size: String(s.size),
    sortType,
  }

  // AI작업 필터(다중) — 비었으면 전체
  if (s.serviceTypes.length > 0) {
    base.serviceTypes = s.serviceTypes.join(',')
  }

  if (s.keyword) {
    base.keyword = s.keyword
  }

  const states = CHIP_TO_STATES[s.statusChip]   // 상태칩 → 내부 상태코드 목록
  if (states.length > 0) {
    base.jobStates = states.join(',')
  }
  ...
  return base
}
src/shared/stores/listQuery.ts — 검색 조건 영속 (vams:listQuery:<slug>)
export function createListQueryStore(slug: string) {
  return defineStore(`listQuery:${slug}`, () => {
    // useStorage 영속(화이트리스트) — 키 vams:listQuery:{slug}
    const persisted = useStorage<PersistedSearchData>(
      `vams:listQuery:${slug}`,
      pickPersisted(defaultSearchData()),
      localStorage,
      { mergeDefaults: true },
    )

    // searchData 초기값 = 기본값 + 영속 화이트리스트 머지
    // size 는 정본 옵션(10/20/50)으로 정규화 — 옵션 배열 변경 전 영속값(예: 100)이 남아 있으면
    // 드롭다운 라벨이 빈 문자열이 되므로 기본값으로 폴백한다.
    const merged = { ...defaultSearchData(), ...persisted.value }
    const searchData = reactive<SearchData>({
      ...merged,
      size: normalizePageSize(merged.size),
    })

    // searchData 변경 → 영속 화이트리스트 동기화
    watch(
      () => pickPersisted(searchData),
      (val) => { persisted.value = val },
      { deep: true },
    )

    // 활성 필터 존재 여부 — 필터 필드가 하나라도 기본값과 다르면 true.
    // 리스트 "빈 상태" 분기(필터 결과 없음 vs 데이터 없음)의 단일 정본. 전 메뉴 공용.
    // ⚠️ 필터만 포함 — sortType(정렬)·page·size(페이지네이션)는 결과를 0건으로 만드는 "필터"가 아니라 제외.
    const hasActiveFilters = computed<boolean>(() => {
      const d = defaultSearchData()
      return (
        searchData.keyword !== d.keyword ||
        searchData.statusChip !== d.statusChip ||
        searchData.serviceTypes.length > 0 ||
        searchData.genre !== d.genre ||
        ...
        searchData.urgentOnly !== d.urgentOnly
      )
    })

    return { searchData, patch, reset, hasActiveFilters }
  })()   // defineStore(...)() 즉시실행 — 싱글톤 인스턴스 반환
}
src/features/dashboard/composables/useDashboardColumns.ts — §8 grow 컬럼 선언 (패널 개폐 분기 제거, 발췌)
export function useDashboardColumns(): ComputedRef<ColumnDef<DashboardJobRow>[]> {
  const { t } = useI18n()
  // 뷰포트 tier — GUI "1280뷰포트"(LNB Fold) 경계. 1280 이하 = narrow.
  const isNarrow = useMediaQuery('(max-width: 1280px)')
  return computed(() => buildColumns(t, isNarrow.value))
}

function buildColumns(t: (key: string) => string, narrow: boolean): ColumnDef<DashboardJobRow>[] {
  // tier별 고정폭(px) — Figma 실측. narrow(1280) 에서 데이터 컬럼이 축소·고정.
  const serviceW = narrow ? 84 : 96
  // 콘텐츠 흡수 주열: basis=min(잉여 흡수). 시리즈 양보 보조열: 선호>min(부족 시만 양보).
  const contentMin = narrow ? 220 : 420
  const seriesW = narrow ? 260 : 400
  const seriesMin = narrow ? 260 : 317

  return [
    // 긴급 배지 전용 컬럼 — 헤더 텍스트 없음. 고정 65. #cell-urgent 슬롯.

src/features/dashboard/composables/useDashboardActions.ts — 상태코드 → CTA 매핑
/**
 * 상태 → CTA 매핑 (cell-actions / DetailCta 공유). null 이면 버튼 없음.
 * - S·V·L·E → 검수(상세 이동, D2) / F → 버튼 없음(일괄 재처리요청만 제공)
 * - 대기·진행(P·W·I·T·R) → null
 * 근거: REQ-STATUS-003 v2 (Figma Flipbook Policy §2, 2026-07-13 —
 *   단건 [재처리요청]·[일괄연동] 삭제, 연동실패도 [검수]로 통일)
 */
function ctaFor(jobState: JobState): CtaConfig | null {
  switch (jobState) {
    case 'S':
    case 'V':
    case 'L':
    case 'E':
      return { labelKey: 'dashboard.action.review', action: 'review' }
    default:
      return null
  }
}
