구간마킹

씬서치(shot boundary) 샷 추출 결과를 기반으로 인트로·등급고지·엔딩 3종 구간을 확인·수정하는 화면입니다. 공통 리스트 패턴의 목록과 bare 풀스크린 상세(마킹 3카드 + 씬서치 그리드)로 구성되며, 씬 카드 클릭으로 START/END를 지정하는 편집 레이어와 시리즈 콘텐츠용 [시리즈 목록] 팝업(행 클릭 시 해당 회차 상세로 전환)을 갖춥니다. 목록·상세 모두 2026-08 공통 컴포넌트 정합(컬럼 폭 반응형·툴바·빈상태·상세패널)을 적용했습니다.

기능 개요

구간마킹은 AI 씬서치 엔진이 추출한 샷 경계(shot boundary) 결과를 근거로, 콘텐츠의 인트로(INTRO)·등급고지(RATING)·엔딩(ENDING) 3종 구간을 운영자가 확인하고 수정하는 메뉴입니다. 목록 화면(SegmentMarkingListPage)은 전 메뉴 공통 리스트 패턴(ContentListLayout + 검색·상태칩·페이지네이션)을 따르되, 구간마킹 고유의 완결여부 3택1 필터(feature-local ref로 머지, listQuery 스토어 미침범)와 마킹 구간 수(segmentCount) 컬럼을 추가합니다. 상태칩은 메뉴별 6칩/7칩 불일치를 정리한 공통 소스 statusChipOptions(domain/statusChip.ts)에서 정본 7종(전체/대기/검수필요/실패/검수중/검수완료/연동완료)을 받아 렌더합니다. 우측 SegmentMarkingDetailPanel로 행 요약을 확인하고, 상세는 AppShell 밖 bare 풀스크린 라우트(/segment-marking/:jobId)로 진입합니다.

2026-08 공통화 라운드에서 목록의 자체 구현 부분이 대거 공통 컴포넌트로 교체되었습니다. ID/명 2단 셀은 IdNameCell, 빈 상태는 3분기(로드실패 > 필터결과없음 > 데이터없음) 통합 컴포넌트 ListEmptyState, 로딩은 스켈레톤 대신 정본 스피너 TableLoading, 행 CTA는 TableActionButton이 담당하고, 긴급 깃발은 개별 SVG(flag.svg) 대신 공용 스프라이트 심볼(VIcon name="flag")로 일원화되었습니다. 조회기간 프리셋(datePresetOptions)·일괄액션 판정(useBulkActionEligibility)·달력 팝오버(DateRangeCalendarPopover)는 메뉴마다 복제돼 있던 것이 각각 shared/lib/datePreset·shared/composables/useBulkActionEligibility·shared/components/composite/date-picker/로 승격되어 이 페이지도 그 공통본을 import 합니다. 컬럼 정의(useSegmentMarkingColumns)도 "패널 열림 시 압축" 방식을 버리고, 뷰포트 tier(useMediaQuery('(max-width: 1280px)')) 고정폭 + DataTable의 grow 분배로 바뀌었습니다 — 콘텐츠 컬럼이 잉여 폭을 전량 흡수(grow:1)하고 시리즈 컬럼은 부족분을 minWidth까지 양보(grow:0)합니다. 한편 작업이력의 engineVersion 필드는 Flipbook 삭제 + API 리스트 v1.0.3 「작업이력 조회」 폐기에 따라 도메인 모델·어댑터에서 제거되었습니다.

상세 화면(SegmentMarkingDetailPage)은 헤더 + 마킹 3카드(프리뷰) + 리사이즈 스플리터 + 씬서치 썸네일 그리드(6열)의 3분할 구조입니다. 데이터는 useSegmentMarkingDetail이 2단계 조회로 가져옵니다 — 먼저 jobId로 콘텐츠 정보·작업이력을 조회하고, 확보한 contentId를 키로 씬 그리드(shot-boundary-detection-result)와 마킹 3종 구간(boundary-marking-result)을 병렬 조회합니다. 어댑터(toMarkingSegments)가 응답에 없는 구간 유형을 미지정(assigned=false)으로 채워 항상 길이 3의 고정 순서(INTRO→RATING→ENDING)를 보장하므로, 화면 코드는 결측 분기 없이 3카드를 그대로 렌더합니다. 시리즈 콘텐츠(seriesId 보유)에는 상세 헤더에 [시리즈 목록] 트리거가 노출되고, 팝업 SeriesListModal이 seriesQueries.fetchSeries(GET /series?seriesId)로 시리즈 소속 회차 목록과 회차별 마킹 대표 썸네일(toSeriesContentRow)을 페이지네이션(6행 고정) 조회합니다. 이 팝업은 더 이상 조회 전용이 아니어서, 행을 클릭하면 응답의 jobId로 segment-marking-detail 라우트를 push 해 해당 회차 상세로 전환합니다. 현재 열람 중인 콘텐츠 행 강조도 체크박스 다중선택(selected)이 아니라 DataTable의 activeKey(State=Selected — 틴트 + 1px 라인)로 바뀌었습니다.

상세 레이아웃도 Figma 실측에 맞춰 재정합되었습니다. 프리뷰 pane 높이는 고정 flexBasis 대신 clamp(352px, min(드래그값, 폭-자연높이), 484px)로 계산해, 스플리터 드래그값과 뷰포트 폭 기반 선형보간값(--preview-fit) 중 작은 쪽을 택합니다. 스플리터 grip은 알약 막대에서 Figma 원본 ↕ 이중 화살표 벡터로 교체되었고, 상세 헤더에는 공통 DetailHeader의 genre prop을 통해 장르칩(HeaderGenre)이 붙습니다. 씬서치 그리드도 6열 고정에서 폭 반응형(1920 6열 / 1280 4열)으로 바뀌어, CSS auto-fill이 정한 열 수를 ResizeObserver로 동일 공식(minmax(288px)·gap 16)으로 재산출해 하이라이트 밴드의 행 분해와 항상 일치시킵니다.

편집은 읽기전용 조회 위에 useMarkingSegmentEdit가 additive로 얹은 draft 레이어입니다. 카드 [편집]으로 editingKind를 활성화한 뒤 씬 카드의 [START]/[END]를 클릭하면 기획서 VAMS-MK-006의 5전이규칙(확장/축소·역전 시 구간 해제 등)에 따라 draft가 갱신되고, 그리드에는 구간이 행별 하이라이트 밴드로 실시간 표시됩니다. 저장은 완성(START·END 모두 지정) 구간만 추려 PUT boundary로 content 단위 전체 교체(replace)하며, dirty 상태에서는 이탈·새로고침 가드가 동작합니다. 그리드는 읽기 모드에서 구간 소속 씬 카드 hover 시 퀵메뉴(SceneQuickMenu)를 띄우는데, Figma 정본 재확인으로 내용이 타임코드에서 구간 씬 번호 범위(예 "1 - 4")로 바뀌고 세로 2줄에서 가로 1줄 배치가 되었습니다. 편집 모드에서는 타 구간 소속 씬을 잠금(dim·선택 불가) 처리해 구간 겹침을 차단하고(MK-005 §3), 하이라이트 밴드는 행별 조각마다 시작·끝 여부(isFirst/isLast)를 판정해 좌·우 캡(라운드 + 보더)만 그립니다. 검은 이미지 표시 토글을 꺼도 마킹 구간 안의 검은 씬은 예외로 항상 표시됩니다. 우측 상세패널(SegmentMarkingDetailPanel)도 자체 구현 표·긴급 점·복사 필드를 걷어내고 공통 PanelInfoTable·UrgentBadge·GenrePath·PanelActionButton 조합으로 재작성되었습니다.

참고 — 매니페스트 기술과의 차이
과제 개요 문서에는 이 기능이 "상세 본문 스텁 단계"로 기재되어 있으나, 현재 develop 소스에는 읽기전용 상세(3카드·씬 그리드·리사이즈)에 편집 레이어(Phase B — 씬 클릭 지정·저장·이탈가드)까지 구현되어 있습니다. 초기 골격이던 SegmentMarkingDetailStub.vue는 트리에 남아 있지만 라우트는 SegmentMarkingDetailPage.vue를 사용합니다.

src/api/adapters/marking.ts — 3종 구간을 항상 길이 3·고정 순서로 보장
const SEG_KIND: Record<BoundaryMarkingDto['type'], MarkingSegmentKind> = {
  opening: 'INTRO',
  notice: 'RATING',
  ending: 'ENDING',
}

const SEG_ORDER: MarkingSegmentKind[] = ['INTRO', 'RATING', 'ENDING']

/** 3종 구간 전체 — 항상 길이 3, 고정 순서 INTRO→RATING→ENDING.
 *  dto.data 에 없는 kind 는 미지정(assigned=false, 값 null)으로 채움. */
export function toMarkingSegments(dto: BoundaryMarkingResponseDto): MarkingSegment[] {
  const byKind = new Map<MarkingSegmentKind, MarkingSegment>()
  for (const item of dto.data) {
    byKind.set(SEG_KIND[item.type], toMarkingSegment(item))
  }
  return SEG_ORDER.map(
    (kind) =>
      byKind.get(kind) ?? {
        kind, assigned: false,
        startMs: null, endMs: null,
        startThumbUrl: null, endThumbUrl: null,
        startThumbIdx: null, endThumbIdx: null,
      },
  )
}
src/features/segment-marking/composables/useMarkingSegmentEdit.ts — START/END 지정 5전이규칙 (VAMS-MK-006)
// 1 START 재지정(END 이전)  → 확장/축소(정상)
// 2 END   재지정(START 이후) → 확장/축소(정상)
// 3 START 이전에 END 지정    → 구간 해제 → END만
// 4 END   이후에 START 지정   → 구간 해제 → START만
// 5 기존 START를 END로 / 기존 END를 START로 → 구간 해제 + 토스트
function designate(kind: MarkingSegmentKind, slot: 'start' | 'end', sceneIdx: number): void {
  const scene = sceneAt(sceneIdx)
  const seg = draftOf(kind)
  if (!scene || !seg) return

  if (slot === 'start') {
    const prevEnd = seg.endThumbIdx
    if (prevEnd === null || sceneIdx < prevEnd) {
      setStart(seg, scene)                  // 시작만 / 규칙1
    } else {
      setStart(seg, scene)                  // sceneIdx >= prevEnd
      clearEnd(seg)                         //   규칙4(>) 해제→START만 / 규칙5(==)
      if (sceneIdx === prevEnd) toast.info({ messageKey: RANGE_RESET_KEY })
    }
  } else {
    // END 슬롯 — 대칭 처리(규칙2·3·5)
  }
  syncAssigned(seg)                         // START·END 모두 지정 시 assigned=true
}
src/api/endpoints.ts · src/features/segment-marking/detailQueries.ts — contentId 키 상세 API와 저장(replace)
export const MARKING_API = {
  list: '/markings',
  detail: (jobId: string) => `/markings/${jobId}`,
  link: '/markings/link',
  reprocess: '/markings/reprocess',
  // 상세(읽기전용) — contentId 키. BE 실경로:
  //   scenes   = GET /db-api/shot-boundary-detection-result/contents/{contentId}
  //   boundary = GET /db-api/boundary-marking-result/content/{contentId}
  scenes: (contentId: string) => `/markings/contents/${contentId}/scenes`,
  boundary: (contentId: string) => `/markings/contents/${contentId}/boundary`,
  // 편집 저장(PUT) — GET boundary와 동일 경로, METHOD 분기(poster-result 선례).
  boundarySave: (contentId: string) => `/markings/contents/${contentId}/boundary`,
  // 시리즈 목록 조회 — seriesId는 쿼리 파라미터(BE 실경로: GET /db-api/series?seriesId&page&size)
  series: () => '/series',
} as const

/** 마킹 3종 구간 저장(편집 모드) — PUT editList(완성 구간만).
 *  content 단위 replace(M3): editList 로 boundary 전체 교체, 미완성은 미포함. */
export async function saveMarkingBoundary(
  contentId: string,
  editList: BoundaryMarkingEditDto[],
): Promise<void> {
  await httpPut<MarkingBoundarySaveDto, { code: string; message: string }>(
    MARKING_API.boundarySave(contentId),
    { editList },
  )
}

  const { t } = useI18n()
  // 뷰포트 tier — GUI "1280뷰포트"(LNB Fold) 경계. 1280 이하 = narrow.
  const isNarrow = useMediaQuery('(max-width: 1280px)')

  return computed(() => buildColumns(t, isNarrow.value))
}

function buildColumns(t: (key: string) => string, narrow: boolean): ColumnDef<MarkingJobRow>[] {
  const contentMin = narrow ? 220 : 420
  const seriesW = narrow ? 260 : 400
  return [
    // ...
    {
      // 콘텐츠ID / 콘텐츠명 — 흡수 주열(grow:1, basis=min). 잉여 전량 흡수, min 밑으론 안 줄어듦.
      key: 'contentId', width: contentMin, grow: 1, minWidth: contentMin, truncate: true,
      header: t('segmentMarking.field.contentIdName'),
    },
    {
      // 시리즈ID / 시리즈명 — 양보 보조열(grow:0). 선호폭 유지, 부족(패널열림) 시 min 까지만 양보.
      key: 'seriesId', width: seriesW, grow: 0, minWidth: 120, truncate: true,
      header: t('segmentMarking.field.seriesIdName'),
    },
    // 장르·완결여부·구간수·입수일시·상태·액션 = tier 고정폭(grow 미지정 → 폭 불변)
  ]
}
