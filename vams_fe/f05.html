구간마킹

씬서치(shot boundary) 샷 추출 결과를 기반으로 인트로·등급고지·엔딩 3종 구간을 확인·수정하는 화면입니다. 공통 리스트 패턴의 목록과 bare 풀스크린 상세(마킹 3카드 + 씬서치 그리드)로 구성되며, 씬 카드 클릭으로 START/END를 지정하는 편집 레이어를 갖춥니다.

기능 개요

구간마킹은 AI 씬서치 엔진이 추출한 샷 경계(shot boundary) 결과를 근거로, 콘텐츠의 인트로(INTRO)·등급고지(RATING)·엔딩(ENDING) 3종 구간을 운영자가 확인하고 수정하는 메뉴입니다. 목록 화면(SegmentMarkingListPage)은 전 메뉴 공통 리스트 패턴(ContentListLayout + 검색·상태칩·페이지네이션)을 따르되, 구간마킹 고유의 완결여부 3택1 필터(feature-local ref로 머지, listQuery 스토어 미침범)와 마킹 구간 수(segmentCount) 컬럼을 추가합니다. 우측 SegmentMarkingDetailPanel로 행 요약을 확인하고, 상세는 AppShell 밖 bare 풀스크린 라우트(/segment-marking/:jobId)로 진입합니다.

상세 화면(SegmentMarkingDetailPage)은 헤더 + 마킹 3카드(프리뷰) + 리사이즈 스플리터 + 씬서치 썸네일 그리드(6열)의 3분할 구조입니다. 데이터는 useSegmentMarkingDetail이 2단계 조회로 가져옵니다 — 먼저 jobId로 콘텐츠 정보·작업이력을 조회하고, 확보한 contentId를 키로 씬 그리드(shot-boundary-detection-result)와 마킹 3종 구간(boundary-marking-result)을 병렬 조회합니다. 어댑터(toMarkingSegments)가 응답에 없는 구간 유형을 미지정(assigned=false)으로 채워 항상 길이 3의 고정 순서(INTRO→RATING→ENDING)를 보장하므로, 화면 코드는 결측 분기 없이 3카드를 그대로 렌더합니다.

편집은 읽기전용 조회 위에 useMarkingSegmentEdit가 additive로 얹은 draft 레이어입니다. 카드 [편집]으로 editingKind를 활성화한 뒤 씬 카드의 [START]/[END]를 클릭하면 기획서 VAMS-MK-006의 5전이규칙(확장/축소·역전 시 구간 해제 등)에 따라 draft가 갱신되고, 그리드에는 구간이 행별 하이라이트 밴드로 실시간 표시됩니다. 저장은 완성(START·END 모두 지정) 구간만 추려 PUT boundary로 content 단위 전체 교체(replace)하며, dirty 상태에서는 이탈·새로고침 가드가 동작합니다.

참고 — 매니페스트 기술과의 차이
과제 개요 문서에는 이 기능이 "상세 본문 스텁 단계"로 기재되어 있으나, 현재 develop 소스에는 읽기전용 상세(3카드·씬 그리드·리사이즈)에 편집 레이어(Phase B — 씬 클릭 지정·저장·이탈가드)까지 구현되어 있습니다. 초기 골격이던 SegmentMarkingDetailStub.vue는 트리에 남아 있지만 라우트는 SegmentMarkingDetailPage.vue를 사용합니다.

핵심 코드

src/api/adapters/marking.ts — 3종 구간을 항상 길이 3·고정 순서로 보장
const SEG_KIND: Record<BoundaryMarkingDto['type'], MarkingSegmentKind> = {
  opening: 'INTRO',
  notice: 'RATING',
  ending: 'ENDING',
}

const SEG_ORDER: MarkingSegmentKind[] = ['INTRO', 'RATING', 'ENDING']

/** 3종 구간 전체 — 항상 길이 3, 고정 순서 INTRO→RATING→ENDING.
 *  dto.data 에 없는 kind 는 미지정(assigned=false, 값 null)으로 채움. */
export function toMarkingSegments(dto: BoundaryMarkingResponseDto): MarkingSegment[] {
  const byKind = new Map<MarkingSegmentKind, MarkingSegment>()
  for (const item of dto.data) {
    byKind.set(SEG_KIND[item.type], toMarkingSegment(item))
  }
  return SEG_ORDER.map(
    (kind) =>
      byKind.get(kind) ?? {
        kind, assigned: false,
        startMs: null, endMs: null,
        startThumbUrl: null, endThumbUrl: null,
        startThumbIdx: null, endThumbIdx: null,
      },
  )
}
src/features/segment-marking/composables/useMarkingSegmentEdit.ts — START/END 지정 5전이규칙 (VAMS-MK-006)
// 1 START 재지정(END 이전)  → 확장/축소(정상)
// 2 END   재지정(START 이후) → 확장/축소(정상)
// 3 START 이전에 END 지정    → 구간 해제 → END만
// 4 END   이후에 START 지정   → 구간 해제 → START만
// 5 기존 START를 END로 / 기존 END를 START로 → 구간 해제 + 토스트
function designate(kind: MarkingSegmentKind, slot: 'start' | 'end', sceneIdx: number): void {
  const scene = sceneAt(sceneIdx)
  const seg = draftOf(kind)
  if (!scene || !seg) return

  if (slot === 'start') {
    const prevEnd = seg.endThumbIdx
    if (prevEnd === null || sceneIdx < prevEnd) {
      setStart(seg, scene)                  // 시작만 / 규칙1
    } else {
      setStart(seg, scene)                  // sceneIdx >= prevEnd
      clearEnd(seg)                         //   규칙4(>) 해제→START만 / 규칙5(==)
      if (sceneIdx === prevEnd) toast.info({ messageKey: RANGE_RESET_KEY })
    }
  } else {
    // END 슬롯 — 대칭 처리(규칙2·3·5)
  }
  syncAssigned(seg)                         // START·END 모두 지정 시 assigned=true
}
src/api/endpoints.ts · src/features/segment-marking/detailQueries.ts — contentId 키 상세 API와 저장(replace)
// 구간마킹 — thumbnail 동형 추상경로(MSW 핸들러와 1:1)
export const MARKING_API = {
  list: '/markings',
  detail: (jobId: string) => `/markings/${jobId}`,
  // 상세 — contentId 키. BE 실경로:
  //   scenes   = GET /db-api/shot-boundary-detection-result/contents/{contentId}
  //   boundary = GET /db-api/boundary-marking-result/content/{contentId}
  scenes: (contentId: string) => `/markings/contents/${contentId}/scenes`,
  boundary: (contentId: string) => `/markings/contents/${contentId}/boundary`,
  boundarySave: (contentId: string) => `/markings/contents/${contentId}/boundary`, // PUT
} as const

/** 마킹 3종 구간 저장 — PUT editList(완성 구간만).
 *  content 단위 replace(M3): editList 로 boundary 전체 교체. */
export async function saveMarkingBoundary(
  contentId: string,
  editList: BoundaryMarkingEditDto[],
): Promise<void> {
  await httpPut<MarkingBoundarySaveDto, { code: string; message: string }>(
    MARKING_API.boundarySave(contentId),
    { editList },
  )
}
