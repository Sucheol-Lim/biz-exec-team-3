AI 썸네일 검수

구간 썸네일(SECTION)·10초 썸네일(GTV/GTM) 작업을 검수하는 워크플로입니다. 공통 리스트 패턴의 목록에서 bare 풀스크린 상세로 진입해, working copy 모델 위에서 대표 구간 지정·구간 썸네일 프레임 교체를 수행하고 저장·재생성·C-Cube 연동까지 이어집니다.

기능 개요

AI 썸네일 메뉴는 AI 엔진이 VOD 콘텐츠에서 자동 추출한 썸네일 작업을 검수하는 화면입니다. 작업유형은 두 가지로, thumbKind가 SECTION이면 구간 썸네일(콘텐츠의 구간별 대표 이미지, 편집 가능), GTV/GTM이면 10초 썸네일(읽기전용 정보 카드)로 분기합니다 — 이 판정은 domain/thumbnail.ts의 TEN_SEC_KINDS·isSectionKind/isTenSecKind 단일 소스를 공유합니다. 목록 화면 ThumbnailListPage는 전 메뉴 공통 리스트 패턴을 따르며 검색어·상태칩 7종(전체/대기/검수필요/실패/검수중/검수완료/연동완료 — domain/statusChip.ts 공통 SSOT)·장르/세부장르 2단 필터·작업유형 필터(전체/구간/10초, 10초 선택 시 thumbKinds='GTV,GTM')·조회기간·긴급만 보기를 제공하고, 정렬 옵션·기본값은 sortOrderFor(chip)가 선택 상태칩에 따라 동적으로 바꿉니다(전체=우선순위 PRIORITY 기본, 연동완료=최신입수순, 그 외=오래된입수순). 검색 조건은 createListQueryStore 기반 스토어로 영속되고(페이지당 건수는 공통 정책 10/20/50), 행 선택 시 우측 패널(ThumbnailDetailPanel)에서 AI 작업이력과 콘텐츠 정보를 확인합니다.

목록 화면의 껍데기는 8개 메뉴가 복제하던 마크업을 걷어내고 공통 컴포넌트로 교체됐습니다. 필터 행(상태칩·장르·작업유형)은 FilterBar/FilterField/StatusFilterField/GenreFilterField로, ID/명 2단 셀은 IdNameCell, 행 [검수] 버튼은 TableActionButton(Figma Cell Item 실측 min-width 64), 로딩은 TableLoading, 0건 화면은 ListEmptyState의 3-way 분기(로드실패 > 필터결과없음 > 데이터없음, store.hasActiveFilters 주입)를 씁니다. 상태 셀은 2026-08-26 공통화된 StatusChangedCell(StatusBadge dot + 원본변경 ⚠ 아이콘, F→workFailed/E→linkFailed 분리 표시)로, 상세패널 열림/닫힘은 useListDetailPanel로, 툴바 v-model 배선은 useListToolbar로, 정렬 라벨은 domain/sortLabel.ts의 SORT_LABELS로 각각 공통화됐습니다. 조회기간 프리셋(shared/lib/datePreset.ts)·달력 팝오버(shared/components/composite/date-picker/)·일괄액션 활성 판정(shared/composables/useBulkActionEligibility.ts)도 feature 로컬 복제본을 지우고 shared 단일 구현을 참조합니다. 컬럼 폭 모델은 패널 개폐로 두 벌을 손튜닝하던 방식(compact) 대신 §8 grow 관용구로 재선언됐습니다 — 콘텐츠는 잉여를 전량 흡수하는 주열(grow:1, basis=min), 시리즈는 부족할 때만 min까지 양보하는 보조열(grow:0), 긴급 65·장르·작업유형·입수일시·상태·액션은 뷰포트 tier(useMediaQuery('(max-width: 1280px)'))별 고정폭이라 컨테이너 폭만으로 패널 개폐 상태가 재현됩니다. 우측 패널도 공통 PanelInfoTable·GenrePath·UrgentBadge·PanelActionButton으로 바뀌었고, 작업이력의 엔진 버전 항목은 제거됐습니다(GUI 정본 삭제 + API 리스트 v1.0.3 폐기 표시 → v1.0.4 공통#3 응답 필드 실삭제). 상태 아이콘도 GUI 정본 실측에 맞춰 대기=빈 링(도넛), 검수완료=민트 전용 자산으로 교체됐습니다.

목록의 행을 열면 /thumbnail/:jobId?kind=… 라우트의 ThumbnailDetailPage(상세화면 S4)로 이동합니다. 이 라우트는 meta.layout:'bare' 풀스크린으로 LNB·앱 헤더 없이 렌더되며, 상단은 공통 DetailHeader+DetailHeaderActions(초기화·재생성·저장·연동)입니다. 2026-08-27 실경로 이관으로 상세 조회는 키 축이 둘로 갈립니다 — 구간(AI썸네일#1/#2)은 contentId 키, 10초(AI썸네일#3)는 jobId 키인데 라우트는 jobId만 실어 오므로, useThumbnailDetail이 먼저 공통#3(GET /api/job/{jobId})으로 contentId를 조달하고 그 값이 확정된 뒤에만(enabled) 구간 결과·공통#2 콘텐츠정보 쿼리를 켭니다. 작업명·세로형 판정은 상세 응답이 아니라 공통#2(episodeName·verticalVideoYn)에서 오고, 상태 배지는 공통#3의 progressState에서 옵니다 — 종전에 상세 응답 자체 필드를 읽던 것은 FE 창작값이었습니다. 구간 썸네일 상세(ThumbnailSegmentDetail)는 구간 카드 그리드(1920px 6열)를 보여주고, 카드에서 대표로 지정 버튼으로 콘텐츠 대표 구간을 바꾸거나, 카드를 클릭해 편집 모달(ThumbnailSegmentEditModal)에서 AI가 추출한 프레임 중 하나를 해당 구간의 썸네일로 교체합니다. 이전/다음 구간 이동으로 모달을 닫지 않고 연속 검수할 수 있습니다.

편집은 useThumbnailDetail 컴포저블의 working copy 모델로 동작합니다. 서버 응답을 깊은 복제(cloneSegments)한 로컬 사본 위에서만 대표 지정·프레임 교체가 일어나고(dirty 플래그 갱신), 저장은 PUT /api/ai-thumbnail-result/content/{contentId}(putSegmentEdits)로 일괄 커밋합니다. 이 저장 응답에는 갱신본이 없어({code,message}뿐) 저장 성공을 화면이 상상하지 않도록 재조회로 확정합니다(invalidateQueries → segmentQuery watch가 working copy를 다시 심음). 초기화는 진입 시점 데이터로 복귀하고, 미저장 상태로 뒤로가기를 누르면 3버튼 확인 다이얼로그(confirmChoice — [취소]/[저장하지 않고 종료]/[저장 후 종료], behavior VAMS-TH-003)가 뜨며 [저장 후 종료]는 저장 실패 시 이탈을 중단합니다. 재생성은 확인 후 공통#8(POST /api/job/{jobId}/reprocess, v1.0.8 신설)을 요청하고 목록으로 복귀하며, 거절 응답(JOB_NOT_REREQUESTABLE)도 HTTP 200으로 올 수 있어 res.ok가 아니라 envelope code로 성공을 판정합니다. 연동은 공통#6 일괄 mutation을 개인 jobId로 호출하고 결과 배열에서 내 id를 찾아 성공 여부를 판정합니다(개수만 세면 「어느 배열에도 없는 id」 누락이 성공으로 접힙니다). [연동] 활성 조건은 2026-09-14에 offerDate(연동이력) 유무 판정에서 공통#3 상태 허용목록(S·V·E) 기준으로 바뀌었습니다 — 종전 offerDate 판정은 재처리·저장 후에도 값이 남아 영구 잠기는 오류가 있었고, 지금은 연동하면 L, 재처리·저장하면 S/V로 풀리는 상태 전이로 표현됩니다(미저장 변경은 섞지 않고, 상태를 모르면 잠급니다).

설계 포인트
서버 상태(Vue Query 캐시)와 편집 상태(working copy)를 분리해 초기화·이탈 경고를 단순하게 만들었습니다. DTO는 api/adapters/thumbnail.ts에서만 도메인 모델로 변환되어 화면 코드는 도메인 타입만 다룹니다. 로딩·에러 상태는 구간의 경우 공통#3→결과 2단 조회 전체를 포함해야 합니다 — 앞단만 보면 contentId 조달 중 "작업을 찾을 수 없습니다"가 잠깐 보이고, 뒤단만 보면 공통#3 실패 시 구간 쿼리가 enabled=false로 멈춰 로딩이 영원히 끝나지 않습니다. 2026-09-10에는 목록 페이지네이션이 총건수 미제공 시 다음 페이지를 잠그던 결함(13개 메뉴 공통 shouldOpenNextPage)에서 벗어나 hasMore prop을 함께 받고, 날짜 셀 스타일도 raw CSS 대신 ColumnDef.tone='tertiary-sm' 토큰으로 옮겨졌습니다. 장르 옵션 소스도 인용키가 공통#12에서 공통#13으로 재확정된 /db-api/code/genres를 그대로 씁니다(경로 자체는 불변).

2026-09-11~18 범위에서는 세 갈래가 갱신됐습니다. ① parseJobState가 어댑터별 사본에서 domain/types.ts 단일 정본(toJobStateOrNull)으로 승격되면서, 코드표 밖 상태는 더 이상 'P'(작업대기)로 접지 않고 null → 셀 '-' 표시로 바뀌었습니다(취소 등 실측 미지 코드를 "AI 큐 등록됨"으로 잘못 보여주지 않기 위함). ② 상태 셀·상세 배지는 조회축 7칩과 분리된 10종 표시축(toBadgeState)을 그대로 노출하도록 바뀌어, 종전엔 목록·상세 5화면에서 실패(F)와 연동실패(E)가 똑같이 "실패"로만 보이던 것을 StatusChangedCell·상세패널 4곳이 toBadgeState 통일로 해소했습니다. ③ 리스트 장르 셀이 13px 공통 GenreCell·1280 tier 말줄임·Bold 화살표로 정본 정합됐습니다.

 * 공용 빌더에 옵션으로 넘긴다.
 *   ① serviceType — 작업유형 필터 축이 곧 serviceType 이다(THUMB_WORK_SERVICE).
 *      ⛔ 종전의 thumbKinds='GTV,GTM' 은 BE 에 없는 파라미터였다(실측 무시됨).
 *      전체=THUMBNAIL(묶음 33건) / 구간=AITHUMB(10건) / 10초=TENTHUMB(23건).
 *   ② PRIORITY 강등 규칙 — 칩이 'all' 이 아니면 LATEST.
 * 나머지(이름·날짜형식·필수값)는 api/contentListQuery.ts 소관.
 */
export function toListQuery(s: SearchData): ThumbnailListQueryParams {
  return toContentListQuery(s, {
    serviceType: THUMB_WORK_SERVICE[s.thumbKind],
    demotePriority: () => 'LATEST',
  })
}

function setSegmentThumb(segmentId: string, frameId: string): void {

async function goBack(): Promise<void> {

    // 이전 확인 3버튼(behavior VAMS-TH-003 1-1): [취소]/[저장하지 않고 종료]/[저장 후 종료]
    // GUI 4719:146816 실측 — 본문(왜 저장해야 하는가) + 빨간 캡션(저장하지 않으면…) 분리
    const choice = await confirmChoice({
      titleKey: 'thumbnail.confirm.leave.title',
      messageKey: 'thumbnail.confirm.leave.message',
      descAlign: 'center',
      captionKey: 'thumbnail.confirm.leave.caption',
      confirmKey: 'thumbnail.confirm.leave.saveExit',     // 저장 후 종료(primary)
      extraKey: 'thumbnail.confirm.leave.discardExit',    // 저장하지 않고 종료
    })
    if (choice === 'cancel') return
    if (choice === 'confirm') {
      await save()                  // 저장 후 종료
      if (dirty.value) return       // 저장 실패 시 이탈 중단
    }
    // 'extra'(저장하지 않고 종료) 또는 저장 성공 → 목록 이동
  }
  await router.push('/thumbnail')
}

/** 재생성 — 공통#8 POST /api/job/{jobId}/reprocess(v1.0.8). 거절({code:'JOB_NOT_REREQUESTABLE'})도
 *  HTTP 200 으로 올 수 있어 res.ok 가 아니라 envelope code 로 판정한다. */
export async function postRegenerate(jobId: string): Promise<{ ok: boolean }> {
  const res = await httpPost<undefined, { code?: string } | { ok?: boolean }>(
    THUMBNAIL_API.regenerate(jobId),
    undefined,
  )
  const code = (res as { code?: string } | null)?.code
  if (code !== undefined) return { ok: code === 'OK' }
  return { ok: (res as { ok?: boolean } | null)?.ok !== false } // mock 호환
}
