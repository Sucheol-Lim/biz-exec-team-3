개요

본 과제는 KT VOD 콘텐츠 운영에서 AI 엔진이 자동 생성한 멀티미디어 결과물(포스터·썸네일·자막·하이라이트·구간마킹·골라보기·Pick·얼굴인식 등)을 운영자·관리자가 검수 → 편집 → C-Cube 연동하는 관리자 웹앱을 Vue 3 기반으로 신규 구축(고도화)하는 프로젝트의 프론트엔드입니다. 기존에 외부 툴·메일·수기로 분산되어 있던 검수·편집·연동 동선을 단일 VAMS 콘솔로 통합합니다.

모든 메뉴가 콘텐츠 리스트 → 검색/필터 → 상세 → 편집 → 연동이라는 공통 워크플로를 공유하는 데이터 집약 관리자(admin) 성격에, 포스터 캔버스 편집기(Konva)·자막 파형 편집기(wavesurfer)·타임라인 구간 편집 같은 고난도 미디어 편집 위젯이 결합된 도메인입니다. 작업 단위(Job)는 대기→AI생성중→검수필요→검수중→검수완료→연동대기→연동중→연동완료(+실패/제외) 상태머신을 따르며, AI 정확도가 기준을 통과하면 자동 연동하고 미달이면 사람 검수로 분기하는 검수 게이트가 핵심 메커니즘입니다.

사업 맥락 (Confluence 근거)
발주는 KT — 콘텐츠(VOD) AI 운영 도메인이며 알티미디어가 수행(자막 엔진 등 일부 어뮤즈랩 협업)합니다. 상위 시스템 C-Cube가 콘텐츠 입수·로그인/권한 연계·최종 연동의 중심이고, VAMS는 그 사이의 운영 콘솔입니다. 마일스톤은 6월(포스터 엔진 배포·자막 프로토타입·썸네일 C-Cube 연동)과 10월(자막 상용 모델·10초 썸네일 통합)로 나뉩니다. Confluence 요약(2026-06-01 스냅샷)에는 11개 메뉴로 기재되어 있으나, 이후 Figma Flipbook v0.7에서 'AI 개인화'가 개인화 포스터·개인화 하이라이트로 2분할되고 얼굴인식이 분리되어 현재 소스(app/stores/menu.ts)의 LNB는 13개 메뉴입니다(소스 우선). Figma 자산의 권위 순서도 이 시기에 확정되어, UI 요소 정본은 Flipbook·아이콘 정본은 컴포넌트 라이브러리로 이원화되었습니다.

사용자 권한은 일반운영자/중간관리자/시스템관리자 3계층(useCan 컴포저블로 판정)이며, 상태칩 7종(전체/대기/검수필요/실패/검수중/검수완료/연동완료 — domain/statusChip.ts 공통 소스로 통합)과 조회기간 최대 60일 등 공통 정책이 전 메뉴에 적용됩니다. 현재 LNB 13개 메뉴 중 대시보드·AI 포스터·AI 썸네일·AI 자막·AI 하이라이트·AI 골라보기·AI Pick·구간마킹·얼굴인식·모니터링·설정 11개 도메인이 구현되어 있고, 개인화 포스터·개인화 하이라이트 2개만 메뉴 정의만 존재하는 구현 예정 상태입니다. 모니터링은 5개 탭 중 현황 대시보드(MN-001)와 로그 이력(MN-005) 2개가 구현되어 있고 나머지 3개 탭은 화면 개요를 담은 플레이스홀더(MonitoringTabPlaceholder)입니다.

주요 기능

대시보드 (통합 AI 작업 목록)
전 AI 엔진의 작업을 단일 목록에서 조회·필터링하는 홈 화면입니다. 서비스 타입 다중 필터, 상태칩, 검색 조건 영속(vams:listQuery:dashboard)을 지원합니다.
AI 포스터 검수·편집
포스터 작업 목록 → 결과 이미지 검수·대표 선택 상세 → Konva 캔버스 기반 이미지·타이틀 편집기로 이어지는 워크플로입니다. 크롭·마스킹·업스케일과 스냅샷 기반 undo/redo(최대 50단계)를 제공하며, 타이틀 편집은 N객체 모델 기반의 오려두기/제거·다중선택을 지원합니다.
AI 썸네일 검수
구간 썸네일·10초 썸네일 검수 워크플로입니다. 목록에서 풀스크린 상세로 진입해 후보 검수·대표 지정·재생성을 수행합니다.
AI 자막 편집기
자막 작업 목록에서 풀스크린 편집기로 진입합니다. wavesurfer 파형 타임라인, 편집 단축키, KRCC/KT 변환, 찾기/바꾸기, 동기화 시프트 등 20종 이상의 편집 다이얼로그를 갖춘 본 과제 최대 규모 기능입니다.
구간마킹
씬서치 샷 추출 결과 기반으로 인트로·등급고지·엔딩 구간을 확인·수정하는 화면입니다. 상세 편집(프리뷰 구간재생·씬 퀵메뉴·헤더 액션)과 시리즈 목록 팝업, 상태칩 7종까지 구현되어 있습니다.
설정 (관리자)
탭 기반 설정 화면으로 작업 설정(WorkConfig)·사용자 권한(UserRole)·연동(Integration) 3개 탭을 제공합니다. 권한 3계층 정책과 연동됩니다.
공통 컴포넌트·디자인 시스템
base 13종 + composite 20여 종 + layout 4종의 공통 컴포넌트 라이브러리와 dev 전용 카탈로그(/_catalog)입니다. Figma 실측 토큰(tokens.scss)과 Reka UI 헤드리스 래퍼 전략을 따릅니다.
Figma 연동·품질 게이트 파이프라인
Figma 덤프→화면 매핑→behavior 스펙 동기화 파이프라인(scripts/figma-mapping/)과 픽셀 게이트(check:pixel)·스택 핀 대조(check:pins)·CSS 변수 검사 등 자동 검증 도구 체계입니다.
얼굴인식 검수·편집
영상에서 검출한 인물 얼굴을 운영자가 검수하는 화면입니다. 검출 카드 그리드(FaceDetectionGrid)에서 인물별 역할(배역)을 매핑하고, 대표 이미지 영역을 드래그(useRepRegionDrag)로 지정합니다.
AI 골라보기 (Watch Pick)
인물 중심으로 장면을 골라 편집하는 시퀀스 타임라인 에디터입니다. 필름스트립(useFilmstrip)·트랜스포트 바·타임라인 뷰포트와 인물 배정 모달, 단축키 가이드를 제공합니다.
AI 하이라이트 편집
하이라이트 클립을 듀얼 타임라인(useDualTimeline)에서 구간 드래그로 편집하는 화면입니다. 실행취소·재실행(useHighlightUndoRedo), 플레이어 동기화, 원본 영상 업로드를 지원합니다.
AI Pick (씬 추출)
영상 파일을 업로드해 AI가 추출한 씬 목록을 확인하는 화면입니다. 업로드 시 영상 메타를 추출(useVideoFileMeta)하고, 목록 폴링(usePickListPolling)으로 처리 상태를 갱신합니다.
모니터링 (대시보드·로그 이력)
AI 엔진 운영 현황을 보는 모니터링 탭 화면입니다. 작업 현황·연동률·GPU 사용률 차트와 최근 로그 요약(RecentLogTable), 별도 로그 이력 목록을 제공합니다.

아키텍처 · 모듈 구조

Vue 3 SPA로, src/main.ts가 Pinia → Router → Vue Query → i18n 순으로 플러그인을 배선하고, src/app/router/index.ts가 앱 셸(LNB) 하위의 기능 라우트와 풀스크린(bare) 편집 화면을 분리합니다. 기능은 src/features/<도메인> 폴더 표준 구조(pages/components/composables)로 성장하며, 백엔드 DTO는 src/api/adapters에서만 도메인 모델로 변환되어 화면 코드는 도메인 모델만 다룹니다.

프레젠테이션(features/pages·shared/components) → 상태(Pinia 스토어·Vue Query 캐시) → 통신(http.ts·adapters) 계층으로 구성되며, 경계는 "BE 갭은 adapter·쿼리빌더·에러매핑 3지점에서만 흡수한다"는 설계 원칙(Confluence 공통 인프라 설계서)을 따릅니다. 외부 연동 대상은 C-Cube 통합 API(작업/연동), 자막 편집 서버(ALFA_API), 그리고 개발 단계에서는 MSW 목킹입니다. 이번 범위에서 endpoints.ts에 PICK_API·FACE_API·MONITORING_API 3개 그룹이 추가됐는데, 모니터링만 규격서 실경로를 그대로 쓰고 AI Pick·얼굴인식은 BE 확정 전 추정 경로라 주석에 근거·미확정 항목을 명시한 채 Mock을 유지합니다. 산출물은 정적 번들(dist)로 폐쇄망 내부 nginx에 배포하는 구조입니다.

핵심 동작 흐름

1. 앱 부트스트랩 · 인증

  1. 전역 스타일 · 앱 생성main.ts가 Figma 실측 토큰 기반 전역 스타일(styles/base.scss)을 로드하고 createApp(App)을 생성합니다.
  2. 플러그인 배선pinia(스토어 의존) → router → Vue Query → i18n 순서로 app.use를 호출합니다. dev 환경이면 mount 전에 MSW worker를 await로 기동해 모든 API를 목킹 하에 둡니다.
  3. 인증 부트스트랩첫 네비게이션에서 router.beforeEach가 authStore.bootstrapped를 확인하고 미완료면 bootstrap()을 1회 실행합니다. meta.layout==='bare' 화면은 면제됩니다.
  4. 셸 렌더AppShellContainer가 LNB(13개 메뉴, useMenuStore)와 콘텐츠 영역을 렌더하고, 권한(useCan)에 따라 메뉴 노출을 제어합니다.

2. 목록 조회 (대시보드 예시 — 전 메뉴 공통 패턴)

  1. 검색 상태 복원createListQueryStore('dashboard') 싱글톤 스토어가 vams:listQuery:dashboard 키에서 검색/필터 상태를 복원합니다.
  2. 쿼리 파라미터 생성useDashboardListParams()가 스토어 상태를 toListQuery()로 변환해 Vue Query의 queryKey 입력이 되는 computed 파라미터를 만듭니다.
  3. API 호출 · 목킹httpGet(DASHBOARD_API.list, params)를 호출하며, dev에서는 MSW 핸들러(mocks/handlers/dashboard.ts)가 인터셉트해 fixtures를 반환합니다.
  4. 어댑터 변환api/adapters/dashboard.ts가 DTO를 도메인 모델로 변환합니다(parseJobState로 상태머신 매핑, toStatusChip으로 상태칩 7종 매핑, maskActor로 개인정보 마스킹).
  5. 렌더뷰가 어댑터 출력만 사용해 DataTable·StatusBadge·Pagination 등 공통 컴포넌트로 렌더합니다.

3. 포스터 이미지 편집 (undo/redo)

  1. 편집기 진입포스터 상세에서 결과 이미지를 선택하면 bare 레이아웃의 PosterEditPage(/poster/:jobId/edit-image/:resultId)로 진입합니다.
  2. 도구 조작Konva 캔버스 위에서 크롭·마스킹·색보정·업스케일 등 도구를 조작합니다. 각 도구는 자신의 상태를 Snapshot(Record<string,unknown>)으로 정의합니다.
  3. 스냅샷 커밋조작 확정 시 usePosterEditorStore가 스냅샷을 스택에 쌓습니다(최대 50단계 FIFO). 스토어는 도구·Konva·fetch를 모르는 도구 불가지 구조입니다.
  4. undo/redo · 저장커서 이동으로 undo/redo를 수행하고, 저장 시 편집 결과를 업로드해 검수·연동 워크플로로 복귀합니다.

4. 얼굴인식 상세 검수 (로컬 스테이징 → 1회 flush)

  1. 상세 진입 · baseline 확정목록에서 jobId로 bare 라우트 /face-recognition/:jobId에 진입하고, 결과 조회 응답을 store.hydrate(jobId, result)로 넣어 되돌리기 기준(baseline)을 확정합니다.
  2. 로컬 편집대표/후보 전환·인물 재지정·대표 영역 지정은 edit/faceResultMutations.ts의 순수 함수가 다음 결과를 계산하고, 스토어 commit()이 히스토리에 쌓습니다(FACE_HISTORY_LIMIT 50단계 undo/redo). 이 단계에서 네트워크 호출은 없습니다.
  3. 분석 결과 모달FC-005 모달에서 검출 박스를 선택해 인물을 재지정하고 useRepRegionDrag로 대표 영역을 드래그 지정하면, 결과가 로컬 스테이징에 반영되고 저장은 헤더 [저장] 1경로에 편승합니다.
  4. 저장 · 초기화헤더 [저장]이 전체 스냅샷을 한 번에 보내고, 성공하면 applySaved()로 baseline을 승격하면서 vue-query 캐시도 함께 갱신합니다(캐시 미갱신 시 목록 복귀 후 재진입에서 편집이 사라지는 결함을 막습니다). [초기화]는 resetToBaseline()으로 되돌립니다.

5. 모니터링 현황 대시보드

  1. 탭 셸 진입/monitoring은 기본 진입 탭인 monitoring-dashboard로 리다이렉트되고, MonitoringPage 탭 셸이 자식 라우트를 렌더합니다. 라우트 name은 monitoring-<tab> 규약으로 탭 정의와 1:1 매핑됩니다.
  2. 위젯별 조회dashboard/queries.ts의 useSummaryCardsQuery·useWorkStatusQuery·useIntegrationStatusQuery·useIntegrationRateQuery·useGpuQuery·useRecentLogsQuery가 MONITORING_API 경로를 각각 호출합니다.
  3. 상태 fold · 렌더deriveWidgetState가 로딩·빈데이터·에러를 위젯 단위 단일 상태로 접고, ChartFrame/BaseChart가 스켈레톤·빈상태·차트를 그 상태에 따라 렌더합니다.
  4. 로그 이력으로 이동실시간 로그 위젯(RecentLogTable)의 [전체 로그 히스토리]가 monitoring-log-history 탭으로 이동하고, 목록에서 행을 선택하면 LogHistoryDetailPanel이 단건 상세를 조회해 표시합니다.
