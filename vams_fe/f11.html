AI 하이라이트 편집

AI가 뽑아낸 하이라이트 클립을 원본·결과 이중 타임라인에서 마크 인/아웃 드래그로 다듬는 bare 풀스크린 비디오 에디터입니다. 두 플레이어가 하나의 재생 시각(SSOT)을 공유하고, 클립 추가·분할·제외·순서변경은 메멘토 스택으로 50단계까지 되돌릴 수 있으며, 목록에서는 원본 영상 업로드로 작업을 생성합니다.

기능 개요

AI 하이라이트는 원본 영상에서 뽑아낸 짧은 구간(클립)들을 운영자가 검수·편집해 최종 하이라이트 영상을 확정하는 메뉴입니다. 목록(HighlightListPage)·우측 HighlightDetailPanel은 공통 리스트 패턴을 따르고, 다른 메뉴와 달리 원본 영상 업로드로 작업을 직접 생성하는 경로(VAMS-HL-003)가 있습니다. 업로드 팝업(HighlightUploadModal)의 상태기계는 empty → uploading → uploaded → creating인데, 확정 계약(02c)이 업로드 엔드포인트 하나만 제공하고 그 응답에 이미 jobId가 포함되므로 파일 선택 시점에 서버가 작업을 커밋합니다. 그래서 [생성] 단계는 추가 API 호출 없이 목록 invalidate와 토스트만 수행하고, [파일 제거]는 서버 취소 엔드포인트가 없어 로컬 draft만 리셋합니다(한계로 기록).

편집화면(HighlightEditPage)은 /highlight/:jobId bare 라우트로 열리며, 진입 시퀀스는 useHighlightEditSession이 오케스트레이션합니다. 상세(콘텐츠 정보)와 클립 컬렉션(H2)을 병렬 조회하되 클립 조회의 404는 에러가 아니라 빈 상태로 접어 클립이 0개인 세션으로 seed 합니다. 이 컴포저블은 헤더 액션([초기화]/[재생성]/[저장]/[연동])과 이탈 가드도 함께 담당하며, 스토어끼리 서로를 직접 참조하지 않도록 조정자 역할을 맡습니다.

상태는 데이터와 뷰로 명확히 갈라져 있습니다. highlightEditStore가 클립 배열·baseline·선택/편집 잠금·체크 선택·dirty·잡 상태를 소유하고, highlightPlaybackStore가 재생 시각(currentSec)·재생 여부·배속·줌·모니터 분할 비율 같은 뷰 상태를 소유합니다. 실행취소 스택은 데이터 스토어만 감시하며 재생 스토어는 절대 경유하지 않습니다 — 재생 위치 이동 같은 뷰 조작이 이력에 섞이지 않도록 한 규약(REQ-UNDO-002)입니다. 이력은 메멘토(before/after 클립 스냅샷 + action·batch 메타) 방식이며 50단계를 넘으면 가장 오래된 항목을 버리고 토스트로 알립니다.

이중 타임라인(useDualTimeline)은 원본 트랙과 결과 트랙이 playback.currentSec이라는 단일 진리원을 공유하되 좌표계만 다르게 씁니다. 원본 트랙은 시각을 그대로 표시하고, 결과 트랙은 선택 클립의 markIn~markOut 상대 좌표로 매핑합니다. 비디오 엘리먼트와의 동기화는 usePlayerSync를 팩토리로 두 인스턴스(origin·result) 생성해 처리하고, activeSource와 일치하는 인스턴스만 스토어→엘리먼트 시킹을 반영합니다. 결과 플레이어는 markOut 도달을 rAF로 감시해 다음 클립으로 연속 재생합니다. 구간 수정(useClipSegmentDrag)은 드래그 중에는 라이브 프리뷰(재생 스토어)만 갱신하고, 클립 데이터와 undo 이력은 pointerup 1회에서만 커밋해 중간값이 이력을 오염시키지 않게 합니다. 모니터 영역 높이 리사이즈(useMonitorResize)는 핸들 컴포넌트와 레이아웃이 같은 값을 봐야 해서 모듈 스코프 싱글턴으로 두었습니다(기본 416 / 260~660px, localStorage 영속).

설계 포인트 — API 경계 격리
상세/편집의 서버 접점은 editQueries.ts 한 파일 뒤로 전부 격리되어 있습니다. 조회(H2)만 확정 계약이고 저장(H3 확장)·재생성·다운로드는 아직 가설이라, 계약이 확정되면 이 파일만 고치고 스토어·컴포저블·컴포넌트는 손대지 않는 구조입니다. 다운로드는 공통 httpGetBlob을 쓰며, 이번 갱신에서 Content-Disposition의 RFC 5987 filename*을 우선 해석해 한글 파일명이 깨지지 않도록 공통 인프라가 보강되었습니다.

src/features/highlight/edit/composables/useDualTimeline.ts — 좌표계가 다른 두 트랙의 단일 SSOT 매핑
// 두 타임라인은 playback.currentSec 단일 SSOT를 공유하되 좌표계가 다름:
//  - origin 트랙: currentSec을 원본좌표로 직접 표시
//  - result 트랙: selectedClip 내 상대좌표(markIn~markOut)로 매핑
function secToPx(sec: number, kind: TimelineKind, trackWidthPx: number): number {
  const total = kind === 'origin' ? originTotalSec.value : resultTotalSec.value
  const rel = kind === 'origin' ? sec : sec - (editStore.selectedClip?.markInSec ?? 0)
  const ratio = Math.min(1, Math.max(0, rel / total))
  return ratio * trackWidthPx * playback.zoom
}

/** 타임라인 클릭 — 뷰 액션(이력 X). 해당 source로 seek + activeSource 전환 */
function onTimelineClick(sec: number, kind: TimelineKind): void {
  playback.setActiveSource(kind)
  playback.seek(sec, 'timeline')
}
src/features/highlight/edit/composables/useHighlightUndoRedo.ts — 메멘토 스택 50단계
/** REQ-UNDO-003 verbatim — 최대 단계 */
export const HL_MAX_HISTORY = 50

// ⚠️ 이 스택은 highlightEditStore(데이터)만 감시 — playback(뷰) store는 절대 경유하지 않는다.
function push(
  entry: Omit<HighlightUndoEntry, 'before' | 'after'> & {
    before: HighlightClip[]
    after: HighlightClip[]
  },
): void {
  undoStack.value.push({
    action: entry.action,
    batch: entry.batch,
    before: cloneClips(entry.before),
    after: cloneClips(entry.after),
  })
  redoStack.value = []                              // 새 분기 발생 — redo 스택 초기화
  if (undoStack.value.length > HL_MAX_HISTORY) {
    undoStack.value.shift()                         // 초과 시 가장 오래된 이력부터 제거
  }
}
src/features/highlight/edit/composables/useHighlightClips.ts — 구간수정은 드롭 시 1회만 커밋
/**
 * 구간수정(마크 인/아웃) 커밋 — drop(pointerup) 시 1회만 호출(중간값 미기록).
 * markInSec < markOutSec 불변식. originStartSec/originEndSec은 마크IO와 별개로 유지.
 */
function trimClip(id: string, markInSec: number, markOutSec: number): void {
  if (markOutSec <= markInSec) return
  const before = cloneClips(store.clips)
  const idx = before.findIndex((c) => c.id === id)
  if (idx === -1) return
  const next = before.map((c) =>
    c.id === id ? { ...c, markInSec, markOutSec, durationSec: markOutSec - markInSec } : c,
  )
  store.applyClipMutation(next, { action: 'trim', batch: false, before, after: next })
}

/** 다른 카드 편집 중 잠금 가드 — true면 액션 차단(토스트 발화) */
function guardEditingLock(targetId?: string): boolean {
  if (store.editingClipId !== null && store.editingClipId !== targetId) {
    toast.warning({ messageKey: 'highlight.edit.toast.editingLocked' })
    return true
  }
  return false
}
src/features/highlight/edit/composables/useHighlightEditSession.ts — 404를 빈 상태로 접는 진입 시퀀스
/** 진입 시퀀스 — H2 조회(+상세 콘텐츠정보) → seed. 404(VAMS-HLT-002)는 empty로 처리 */
async function init(entryState?: JobState): Promise<void> {
  loadStatus.value = 'loading'
  try {
    const [detail, clipCollection] = await Promise.all([
      fetchHighlightDetail(jobId.value),
      fetchHighlightClips(jobId.value).catch((err: unknown) => {
        const status = (err as { status?: number })?.status
        if (status === 404) return null
        throw err
      }),
    ])
    contentInfo.value = detail.contentInfo
    originVideoUrl.value = detail.contentInfo.originUrlPath
    // clipCollection 이 null 이면 클립 0개로 seed → 빈 상태 화면
  } catch (e) {
    loadStatus.value = 'error'
  }
}
