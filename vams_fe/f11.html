AI 하이라이트 편집

AI가 뽑아낸 하이라이트 클립을 원본·결과 이중 타임라인에서 마크 인/아웃 드래그로 다듬는 bare 풀스크린 비디오 에디터입니다. 두 플레이어가 하나의 재생 시각(SSOT)을 공유하고, 클립 추가·분할·제외·순서변경은 메멘토 스택으로 50단계까지 되돌릴 수 있으며, 목록에서는 원본 영상 업로드로 작업을 생성합니다.

기능 개요

AI 하이라이트는 원본 영상에서 뽑아낸 짧은 구간(클립)들을 운영자가 검수·편집해 최종 하이라이트 영상을 확정하는 메뉴입니다. 목록(HighlightListPage)·우측 HighlightDetailPanel은 공통 리스트 패턴을 따르고, 다른 메뉴와 달리 원본 영상 업로드로 작업을 직접 생성하는 경로(VAMS-HL-003)가 있습니다. [업로드] 버튼은 GUI 정본 위치인 페이지 헤더 타이틀 우측으로 Teleport되어 있고, 업로드 팝업(HighlightUploadModal)의 상태기계는 empty → uploading → uploaded → creating인데, 확정 계약(02c)이 업로드 엔드포인트 하나만 제공하고 그 응답에 이미 jobId가 포함되므로 파일 선택 시점에 서버가 작업을 커밋합니다. 그래서 [생성] 단계는 추가 API 호출 없이 목록 invalidate와 토스트만 수행하고, [파일 제거]는 서버 취소 엔드포인트가 없어 로컬 draft만 리셋합니다(한계로 기록).

편집화면(HighlightEditPage)은 /highlight/:jobId bare 라우트로 열리며, 진입 시퀀스는 useHighlightEditSession이 오케스트레이션합니다. 상세와 클립 컬렉션(H2)은 병렬이 아니라 순차 조회입니다 — 결과 조회 경로가 /api/highlight-result/content/{contentId}라 contentId를 먼저 알아야 하는데 라우트는 jobId만 갖고 있어, 상세 응답에서 contentId를 얻은 뒤에야 클립을 조회할 수 있습니다(계약 구조상의 순차 의존). 클립 조회의 404는 에러가 아니라 빈 상태로 접어 클립이 0개인 세션으로 seed 합니다. 이 컴포저블은 헤더 액션([초기화]/[재생성]/[저장]/[연동])과 이탈 가드도 함께 담당하며, 스토어끼리 서로를 직접 참조하지 않도록 조정자 역할을 맡습니다.

상태는 데이터와 뷰로 명확히 갈라져 있습니다. highlightEditStore가 클립 배열·baseline·선택/편집 잠금·체크 선택·dirty·잡 상태를 소유하고, highlightPlaybackStore가 재생 시각(currentMs — 도메인 전역 ms로 통일)·재생 여부·배속·J/L 셔틀 배속·모니터 분할 비율 같은 뷰 상태를 소유합니다. 실행취소 스택은 데이터 스토어만 감시하며 재생 스토어는 절대 경유하지 않습니다 — 재생 위치 이동 같은 뷰 조작이 이력에 섞이지 않도록 한 규약(REQ-UNDO-002)입니다. 이력은 메멘토(before/after 클립 스냅샷 + action·batch 메타) 방식이며 50단계를 넘으면 가장 오래된 항목을 버리고 토스트로 알립니다. [저장] 직전에는 정본(3495:42873) 6케이스(역전·0초·최소 5초 미만·최대 200초 초과·원본범위 이탈·겹침)를 validateClips로 검증해 위반이 있으면 첫 건만 토스트로 안내하고 해당 카드를 선택시킨 뒤 저장을 막습니다.

저장(saveHighlightClips, POST /api/highlight-result/content/{contentId} 전체 스냅샷)은 응답이 {code, message}뿐이라 신규 클립의 서버 ID를 알 방법이 없어, 저장 성공 후 재조회 1회(reconcileAfterSave)로 (1) 임시 ID(tmp- 접두)를 (originStartMs, originEndMs) 매칭으로 서버 ID에 매핑하고 (2) 직전 조회 시점 서버 ID 집합과 대조해 제외·삭제한 구간이 그대로 남아있는 "조용한 유실"을 감지해 콘솔에 경고합니다. 저장 실패는 응답 유무·HTTP 상태로 classifySaveError가 network/session/server 3분류로 나눠 각각 토스트·토스트·화면에 남는 오류 배너(SaveErrorBanner)로 다르게 안내합니다. [재생성](regenerateHighlight)도 실 BE 엔드포인트로, 거절 응답(JOB_NOT_REREQUESTABLE)이 HTTP 200으로 오므로 res.ok가 아니라 envelope의 code로 성공을 판정합니다. 배경 필름스트립은 더 이상 BE 계약을 시도하지 않습니다 — 2026-09 초 BE …/filmstrip 경로를 전량 삭제하고 클라이언트 추출을 유일한 경로로 확정했습니다(src/shared/media-edit/ — WebCodecs+HLS(fMP4) 고속 경로, 미지원 시 <video> seek+canvas 폴백, Web Worker 오프로드, IndexedDB 누적 캐시, 뷰포트 우선 큐 + 재생 양보). 이 진입 흐름은 골라보기(f10)와 완전히 같은 코드를 두 화면에 배선하던 것을 2026-09-10 useSessionFilmstrip 하나로 승격해, 하이라이트는 정책값(시작 지연·초기 우선 구간)만 다르게 주입합니다.

이중 타임라인(useDualTimeline)은 원본 트랙과 결과 트랙이 playback.currentMs라는 단일 진리원(ms)을 공유하되 좌표계만 다르게 씁니다 — 두 플레이어가 같은 원본 영상을 소스로 쓰므로 결과 트랙도 원본 절대좌표이고, 선택 클립의 originStartMs를 뺀 상대 좌표로만 매핑합니다(과거엔 결과 축인 markIn을 빼 좌표가 어긋났던 버그 H-2를 이렇게 해소했습니다). 좌표 변환·뷰포트(줌/팬)는 자체 secToPx/pxToSec를 폐기하고 골라보기(f10)와 공용인 src/shared/media-edit/(useTimelineViewport + timeline/scale.ts의 msToX/xToMs)로 옮겨 탔습니다 — 다만 배경 필름스트립 타일과 클립 블록(ClipBlock)만은 하이라이트 GUI가 실측 기준이라 이 화면 쪽 구현이 공용화의 정본이 되었습니다. 비디오 엘리먼트와의 동기화는 usePlayerSync를 팩토리로 두 인스턴스(origin·result) 생성해 처리하고, activeSource와 일치하는 인스턴스만 스토어→엘리먼트 시킹을 반영합니다. 결과 플레이어는 markOut 도달을 rAF로 감시해 다음 클립으로 연속 재생합니다. 구간 수정(useClipSegmentDrag)은 마크 핸들 드래그(길이 변경)와 블록 본체 드래그(moveClip, 길이 유지 이동)를 함께 처리하며 드래그 중에는 라이브 프리뷰(재생 스토어)만 갱신하고 클립 데이터와 undo 이력은 pointerup 1회에서만 커밋합니다. ⚠️ 카드를 손으로 끌어 순서를 바꾸는 reorderClips는 폐기했습니다 — BE 질의 결론(Q-1)이 저장 editList에 orderNo가 없고 서버가 시간순으로 재부여하는 것으로 확정되어, 순서를 바꾸려면 moveClip으로 구간 시간 자체를 옮기는 것만 유효합니다. 모니터 영역 높이 리사이즈는 골라보기·구간마킹과 동일하게 공용 useSplitResize로 승격되어 하이라이트 쪽엔 Figma 실측 상수(기본 416 / 260~660px)만 남았습니다.

설계 포인트 — API 경계 격리
상세/편집의 서버 접점은 editQueries.ts 한 파일 뒤로 전부 격리되어 있습니다. 조회(H2)·저장·재생성은 실 계약이고, 다운로드는 [추정] 계약([추정] 신설, 실 v1.0.2 「하이라이트」 시트에 없음)으로 남아 있습니다. 필름스트립은 더 이상 계약 대기 상태가 아닙니다 — BE 경로 자체가 삭제되고 클라이언트 추출(shared/media-edit/)로 완전히 대체돼, 계약 확정을 기다릴 필요가 없어졌습니다. 다운로드는 공통 httpGetBlob을 쓰며, Content-Disposition의 RFC 5987 filename*을 우선 해석해 한글 파일명이 깨지지 않도록 공통 인프라가 보강되었습니다.

src/features/highlight/edit/composables/useDualTimeline.ts — 원본 절대좌표로 통일한 두 트랙 매핑(H-2)
// 두 타임라인은 playback.currentMs 단일 SSOT(ms)를 공유하되 좌표계가 다름:
//  - origin 트랙: currentMs를 원본좌표로 직접 표시
//  - result 트랙: selectedClip 내 상대좌표(originStart~originEnd)로 매핑.
//    ⚠ 두 플레이어가 같은 원본 영상을 쓰므로 currentMs 도 원본 절대 좌표다 — 클립 시작을
//    빼서 상대화한다. 예전엔 result 축(markIn)을 뺐는데, 축이 달라 위치가 어긋났다(H-2).
// M3: 배율 zoom 기반 msToPx/pxToMs 는 공용 뷰포트(shared/media-edit)로 대체돼 제거했다.
const resultPointerRatio = computed(() => {
  const clip = editStore.selectedClip
  if (!clip) return 0
  return Math.min(1, Math.max(0, (playback.currentMs - clip.originStartMs) / resultTotalMs.value))
})

/** 타임라인 클릭 — 뷰 액션(이력 X). 해당 source로 seek + activeSource 전환 */
function onTimelineClick(ms: number, kind: TimelineKind): void {
  playback.setActiveSource(kind)
  playback.seek(ms, 'timeline')
}

// ⚠️ 이 스택은 highlightEditStore(데이터)만 감시 — playback(뷰) store는 절대 경유하지 않는다.
function push(
  entry: Omit<HighlightUndoEntry, 'before' | 'after'> & {
    before: HighlightClip[]
    after: HighlightClip[]
  },
): void {
  undoStack.value.push({
    action: entry.action,
    batch: entry.batch,
    before: cloneClips(entry.before),
    after: cloneClips(entry.after),
  })
  redoStack.value = []                              // 새 분기 발생 — redo 스택 초기화
  if (undoStack.value.length > HL_MAX_HISTORY) {
    undoStack.value.shift()                         // 초과 시 가장 오래된 이력부터 제거
  }
}
src/features/highlight/edit/composables/useHighlightClips.ts — 구간수정(trim)과 블록이동(move)의 역할 분리
/** 구간수정(마크 인/아웃) — drop(pointerup) 시 1회만 커밋(중간값 미기록, REQ-UNDO-003). */
function trimClip(id: string, originStartMs: number, originEndMs: number): void {
  if (originEndMs <= originStartMs) return
  store.setEditing(id) // 구간을 조정한 순간부터 '편집 중' — [클립 저장] 시 AI→EDITED 배지 전이 조건
  const before = cloneClips(store.clips)
  const idx = before.findIndex((c) => c.id === id)
  if (idx === -1) return
  // 시작 시간이 바뀌면 카드 순서도 바뀐다(orderNo 는 시간 순서의 표현) → renumber 경유
  const next = renumber(
    before.map((c) =>
      c.id === id
        ? { ...c, originStartMs, originEndMs, durationMs: originEndMs - originStartMs }
        : c,
    ),
  )
  store.applyClipMutation(next, { action: 'trim', batch: false, before, after: next })
}

/**
 * 블록 이동(타임라인 DND) — 길이를 유지한 채 시작/종료를 함께 옮긴다(trim 과 달리 durationMs 불변).
 * ⚠️ 겹침을 드래그 중에는 허용한다 — 헤더 [저장] 시 clipValidation 이 걸러낸다.
 * ⛔ reorderClips(카드 드래그로 순서만 바꾸기)는 폐기했다 — BE 확정(Q-1): 저장 editList 에
 *    orderNo 가 없고 서버가 시간순으로 재부여한다. 순서를 바꾸려면 구간 시간을 옮기는 것뿐이다.
 */
function moveClip(id: string, newStartMs: number): void {
  if (guardEditingLock(id)) return
  const before = cloneClips(store.clips)
  const target = before.find((c) => c.id === id)
  if (!target) return
  const durationMs = target.originEndMs - target.originStartMs
  if (durationMs <= 0) return
  const totalMs = playback.originDurationMs
  const maxStartMs = totalMs > 0 ? Math.max(0, totalMs - durationMs) : Number.POSITIVE_INFINITY
  const originStartMs = Math.max(0, Math.min(newStartMs, maxStartMs))
  if (originStartMs === target.originStartMs) return // 제자리면 이력 오염 방지
  store.setEditing(id)
  const next = renumber(
    before.map((c) =>
      c.id === id ? { ...c, originStartMs, originEndMs: originStartMs + durationMs } : c,
    ),
  )
  store.applyClipMutation(next, { action: 'move', batch: false, before, after: next })
}
src/features/highlight/edit/clipValidation.ts — 저장 차단 6케이스(정본 3495:42873)
export const MIN_CLIP_MS = 5_000   // 최소 길이(5초)
export const MAX_CLIP_MS = 200_000 // 최대 길이(200초)

/** 저장 전 전량 검증 — 위반을 전부 돌려주고, 무엇을 보여줄지는 호출측이 정한다(현재는 첫 건만 토스트). */
export function validateClips(clips: HighlightClip[], totalDurationMs: number): ClipViolation[] {
  const targets = clips.filter((c) => !c.excluded) // 제외된 클립은 최종 결과에 안 들어가 검증 제외
  const out: ClipViolation[] = []
  for (const c of targets) {
    const lengthMs = c.originEndMs - c.originStartMs
    if (lengthMs < 0) out.push({ code: 'inverted', clipId: c.id, orderNo: c.orderNo })
    else if (lengthMs === 0) out.push({ code: 'zeroLength', clipId: c.id, orderNo: c.orderNo })
    else if (lengthMs < MIN_CLIP_MS) out.push({ code: 'tooShort', clipId: c.id, orderNo: c.orderNo })
    else if (lengthMs > MAX_CLIP_MS) out.push({ code: 'tooLong', clipId: c.id, orderNo: c.orderNo })
    if (totalDurationMs > 0 && (c.originStartMs < 0 || c.originEndMs > totalDurationMs)) {
      out.push({ code: 'outOfRange', clipId: c.id, orderNo: c.orderNo })
    }
  }
  // 겹침은 전 쌍을 본다(클립 수가 수십 단위라 비용 문제없음) — 생략(전체 로직은 소스 참조)
  return out
}

/**
 * 저장 직후 재조회 1회로 두 가지를 한다: ① 신규 클립의 임시 id(tmp-)를 서버 sectionId로 확정

 * 구간이 서버 결과에 그대로 남아있는 "조용한 유실"을 콘솔 경고로 잡는다.
 * ⚠️ clips 를 서버 응답으로 덮어쓰지 않는다 — workBadge 는 로컬 마킹이라 덮으면 배지가 사라진다.
 */
async function reconcileAfterSave(contentId: string, sentClips: HighlightClip[]): Promise<void> {
  try {
    const after = await fetchHighlightClips(contentId)
    const mapping = mapTempIdsToServer(sentClips, after.clips)
    store.applyServerIds(mapping, after.clips)
    const violations = diffSaveContract(sentClips, lastKnownServerIds.value, after.clips)
    lastKnownServerIds.value = after.clips.map((c) => c.id)
    for (const v of violations) {
      console.warn('[highlight] 저장 계약 위배 의심 — 제외/삭제한 구간이 서버 결과에 남아있다.', v)
    }
  } catch {
    // 검증용 조회 실패는 저장 결과에 영향을 주지 않는다
  }
}

/** 응답 유무·HTTP 상태로 네트워크/세션/서버 저장실패를 가른다 — 각각 다른 UI 액션(정본 _07 §3) */
export function classifySaveError(err: unknown): SaveFailureKind {
  const status = (err as { status?: number } | null)?.status
  if (typeof status !== 'number') return 'network'   // fetch 자체 실패(오프라인/DNS/CORS)
  if (status === 401) return 'session'
  return 'server'                                      // → saveErrorBanner(화면에 남는 배너)
}
