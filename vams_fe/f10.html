AI 골라보기 (Watch Pick)

장면·인물·비식별 그룹 축으로 묶인 클립을 타임라인에서 편집하는 bare 풀스크린 에디터입니다. 구간 타임라인과 시퀀스 타임라인 2개의 독립 뷰포트, BE 프레임 기반 필름스트립, 클립 추가·제외·분할과 50단계 undo/redo를 갖추며 모든 편집은 로컬 스테이징 후 [저장] 1회로만 서버에 반영됩니다.

기능 개요

AI 골라보기는 시청자가 특정 인물·장면만 골라 볼 수 있도록 AI가 뽑아낸 클립 구간을 운영자가 검수·편집하는 메뉴입니다. 목록(WatchPickListPage)과 우측 WatchPickDetailPanel은 다른 메뉴와 동일한 공통 리스트 패턴을 따르고, [검수]로 AppShell 밖 bare 풀스크린 편집화면 WatchPickEditPage에 진입합니다. 편집화면은 상단 정보바(ClipInfoBar)와 툴바, 가운데 플레이어(WatchPickEditPlayer)·재생 박스, 하단 구간 타임라인(WatchPickRangeTimeline)과 시퀀스 타임라인(WatchPickSequenceTimeline), 그리고 클립 카드 그리드(ClipCardGrid)로 구성됩니다.

편집 데이터는 2단계 조회로 조립됩니다. 먼저 목록과 같은 fetchWatchPickDetail로 콘텐츠 정보를 얻고, 편집 결과는 fetchWatchPickResult가 실 계약 4종(C1 flat 행 · C3 행동코드 · C4 인물 · C5 비식별 그룹)을 병렬 호출해 어댑터에서 조인합니다. 이 중 필수는 C1뿐입니다 — 나머지 셋은 표시명 조인 소스라 Promise.allSettled로 개별 실패를 빈 배열로 degrade 해 코드·ID 폴백으로 화면을 띄웁니다. 여기에 셰이프 드리프트 방어가 있습니다. API 스펙 v1.0.4에서 C4 응답이 data[]에서 data.personList[]로 한 겹 깊어졌는데, 셰이프가 어긋나면 거부가 아니라 undefined로 이행하고 allSettled는 그것을 성공으로 보기 때문에 degrade가 걸리지 않고 어댑터의 persons.map에서 터져 편집 화면 전체가 뜨지 않았습니다. 지금은 fetch 지점과 settled() 두 곳에서 배열 여부를 확인해 degrade 경로로 되돌립니다. 이 조회에 앞서 키 축 변환이 한 단계 더 있습니다 — 라우트 파라미터는 jobId지만 C1~C5 편집 API는 전부 contentId 축입니다(실측: jobId 6290 ↔ contentId 4138, 서로 다른 값). resolveWatchPickContentId가 공통#3(GET /api/job/{jobId})으로 정본 contentId를 먼저 얻은 뒤에야 C1~C5·저장(C2)을 부릅니다 — jobId를 그대로 실으면 200으로 "클립 없음"이거나 다른 콘텐츠에 저장되는 조용한 오염이 발생하기 때문입니다.

상태 소유권은 vue-query가 아니라 Pinia watchPickEdit 스토어에 있습니다. result 쿼리는 staleTime: Infinity 로더 전용이고 성공 시 hydrate()가 1회 이관하며, 이후 렌더 소스는 store.result뿐입니다. 클립 저장·추가·제외·분할은 전부 resultMutations.ts의 순수 불변 transform을 스토어 액션으로 감싼 로컬 커밋(네트워크 0)이고, BE 쓰기는 saveWatchPickResult(C2 PATCH, editList 전체 스냅샷) 하나뿐입니다. dirty는 3종으로 분리해 isClipDirty(선택 클립 draft 3필드)·isJobDirty(result !== baselineResult 참조 비교)·isAnyDirty로 나누며, 실행취소는 커서 + 스냅샷 배열 방식으로 50단계(MAX_HISTORY_STEPS)까지 보관합니다. 신규 클립은 임시 ID로 발급하고 저장 응답의 idMap(응답에 확정 매핑이 없어 위치 기반 buildIdMapFallback으로 복원)으로 재매핑합니다. 재생 자체는 스토어가 아니라 페이지 스코프 컴포저블 useWatchPickPlayer가 소유합니다 — 단일 <video>의 재생상태 단일 소유자로, 재생 중엔 rAF 루프로 currentMs를 매 프레임 갱신하고(타임코드 표시용 timeupdate만으로는 포인터가 끊깁니다), seekMs·stepFrame·setPlaybackRate를 제공합니다.

타임라인은 DOM에 의존하지 않는 순수 ms 뷰포트(useTimelineViewport)로 구현했습니다. 자막 편집기의 WaveSurfer 위임 로직(setViewWindow·zoomCenter·휠 팬·플레이헤드 추종·조작 후 FOLLOW_RESUME_MS 유예)을 DOM 없이 재구현한 것으로, viewStartMs/viewEndMs 두 ref가 진리원이고 나머지는 전부 파생입니다. 구간·시퀀스 타임라인은 이 뷰포트를 각자 1개씩 갖습니다(공유 금지). 좌표 변환은 timeline/scale.ts의 순수 함수(msToX·xToMs·getMsAtClientX·snapToFrame)가 담당합니다. 배경 필름스트립은 화면 고정 72×48 그리드입니다 — 타일 위치는 줌·팬에 불변이고 각 타일의 프레임 이미지 내용만 뷰 창에 따라 바뀌며, 임의 시각의 최근접 프레임은 이진탐색(frameUrlAt, O(log n))으로 찾습니다. 이 타임라인 인프라(뷰포트·좌표 유틸·필름스트립·눈금·스크롤바)는 골라보기 전용에서 AI 하이라이트 편집(f11)과의 공용 계층 src/shared/media-edit/로 승격됐습니다 — 두 화면이 같은 Figma 컴포넌트 트리(Video Task Panel/Timeline Structure)를 쓰던 약 1,500줄 중복을 해소한 것으로, 골라보기 로컬 edit/timeline/·useTimelineViewport.ts·useFilmstrip.ts는 폐기되고 두 화면 모두 공용 모듈을 import합니다(Card List·TransportBar 등 나머지 컴포넌트는 도메인별 기능 차이가 커 각 feature에 유지). 프리뷰 높이는 드래그 리사이즈(기본 248 / 최소 92 / 최대 492px)로 조절되며 localStorage에 영속됩니다.

[저장] 직전에는 C7 구간 썸네일 추출(ensureClipThumbnails)이 한 번 돕니다. 클립을 추가·분할하거나 시작 시각을 바꾸면 그 클립은 자기 썸네일(thumbPath)이 없는데, 종전에는 이웃 클립의 값을 그대로 써서 남의 썸네일을 자기 것으로 저장했습니다. 지금은 needsThumbnailExtraction으로 대상을 골라 클립의 시작 시각 프레임을 C7(POST /api/thumbnail)로 순차 추출합니다. C7은 BE가 NAS에 파일을 쓰는 쓰기라서 편집 조작마다 부르지 않고 [저장] 직전 한 번만 부릅니다 — 이 화면엔 undo/redo가 있어 그때마다 불렀다면 되돌려진 편집 몫의 고아 파일이 쌓이기 때문입니다. 실패하면 빈 thumbPath가 저장되지 않도록 저장 자체를 중단합니다.

설계 포인트 — 인물 재지정은 전량 로컬
비식별 그룹을 실제 인물로 지정하는 C6(PUT)은 personId를 body·path·query 중 어디로 넘기는지 BE 미확답(WP-C2)이라 배선하지 않았습니다. 인물 재지정 모달(WatchPickPersonAssignModal)은 assignUnknownLocal/excludeUnknownLocal로 전량 로컬 스테이징하고, 결과는 [저장]의 editList 전체 스냅샷에 실려 나갑니다. 엔드포인트는 주석 seam으로만 남겨 두었습니다.

핵심 코드

src/features/watch-pick/edit/queries.ts — jobId→contentId 축 변환(공통#3) + C4 v1.0.4 셰이프 드리프트 방어
// 라우트는 jobId, 편집 API(C1/C2/C4/C5)는 전부 contentId 축이다 — 실 BE 에서는 두 값이 다르다
// (실측: jobId 6290 ↔ contentId 4138). jobId 를 그대로 실으면 200 인데 "클립 없음"이거나
// 400 이거나, 최악의 경우 **다른 콘텐츠에 저장**된다 — 무엇도 "잘못된 키"라고 말해주지 않는다.
/** jobId → contentId(공통#3). 캐시하지 않는다 — 편집 세션당 2회(로드·저장)뿐인 작은 GET. */
export async function resolveWatchPickContentId(jobId: string): Promise<string> {
  const dto = await httpGet<ContentEnvelope<{ contentId?: number | string }>>(CONTENT_API.job(jobId))
  const contentId = unwrapContentEnvelope(dto).contentId
  if (contentId == null || String(contentId) === '') {
    throw new Error(`공통#3 응답에 contentId 가 없다(jobId=${jobId}) — 편집 API 를 부를 수 없다`)
  }
  return String(contentId)
}

// C4 응답은 v1.0.4 에서 `data[]` → `data.personList[]` 로 한 겹 깊어졌다.
// ⚠️ 셰이프가 어긋나면 거부가 아니라 undefined 로 이행한다 — allSettled 는 그걸 성공으로
// 보므로 빈 배열 degrade 가 안 걸리고 어댑터의 `persons.map` 에서 터진다.
function fetchPersons(contentId: string) {
  return httpGet<WatchPickPersonListResponseDto>(WATCHPICK_API.persons(contentId)).then((r) => {
    const list = r?.data?.personList
    if (!Array.isArray(list)) return []       // degrade 경로로 되돌린다
    return list
  })
}

export async function fetchWatchPickResult(jobId: string): Promise<WatchPickResult> {
  const contentId = await resolveWatchPickContentId(jobId) // 키 축 변환이 먼저 — 실패 시 그대로 throw
  const rows = await fetchResultRows(contentId)             // 필수 — 실패 시 그대로 throw
  const [actionsR, personsR, groupsR] = await Promise.allSettled([
    fetchActionCodes(), fetchPersons(contentId), fetchUnknownGroups(contentId),
  ])
  // fulfilled 라도 값이 배열이 아니면 어댑터에서 터지므로 함께 막는다.
  const settled = <T>(r: PromiseSettledResult<T[]>): T[] =>
    r.status === 'fulfilled' && Array.isArray(r.value) ? r.value : []
  return toWatchPickResult(jobId, rows, settled(actionsR), settled(personsR), settled(groupsR))
}
src/features/watch-pick/edit/composables/useWatchPickEdit.ts — 저장 직전 C7 썸네일 추출(빠진 클립만)
/**
 * 대상은 thumbPath 가 없는 클립(추가 · 분할 우측 · 시작 시각 편집). 종전에는 이웃 클립 값을
 * 승계해 남의 썸네일을 자기 것으로 저장했다.
 * ⚠️ C7 은 쓰기다(BE 가 NAS 에 파일을 만든다) — undo 로 사라질 편집 때문에 고아 파일을 남기지
 *    않으려고 편집 조작마다 부르지 않고 [저장] 직전 한 번만 부른다. 실패하면 저장 자체를 중단한다.
 */
async function ensureClipThumbnails(r: WatchPickResult): Promise<WatchPickResult> {
  const targets = [...r.scenes, ...r.persons, ...r.unknowns]
    .flatMap((g) => g.clips)
    .filter(needsThumbnailExtraction)
  if (targets.length === 0) return r

  const filePath = contentInfo.value?.transcodeFilePath ?? '' // 공통#2 transcodeFile(m3u8)
  if (!filePath) throw new Error('C7 썸네일 추출 불가 — 콘텐츠 정보(transcodeFile)가 없다')

  const extracted = new Map<string, { thumbPath: string; fileSizeByte: number }>()
  for (const c of targets) {
    extracted.set(c.clipId, await extractClipThumbnail(filePath, toExtractTimestamp(c.startMs)))
  }
  return mapAllGroups(r, (clips) =>
    clips.map((c) => (extracted.has(c.clipId) ? { ...c, ...extracted.get(c.clipId) } : c)),
  )
}
src/shared/media-edit/useFilmstrip.ts — 최근접 프레임 이진탐색(AI 하이라이트 편집 f11과 공용)
const TILE_W = 72 // GUI 실측 — 배경 필름스트립 타일 폭(고정, 줌/팬에 불변)

/** 임의 시각(ms)에 가장 가까운 BE 프레임 URL. frames는 어댑터가 timeMs 오름차순 정렬 보장. */
function frameUrlAt(ms: number): string | null {
  const frames = opts.filmstrip.value?.frames
  if (!frames || frames.length === 0) return null
  let lo = 0
  let hi = frames.length - 1
  while (lo < hi) {
    const mid = (lo + hi) >> 1
    if (frames[mid]!.timeMs < ms) lo = mid + 1
    else hi = mid
  }
  if (lo > 0) {
    const prev = frames[lo - 1]!
    const cur = frames[lo]!
    if (Math.abs(prev.timeMs - ms) <= Math.abs(cur.timeMs - ms)) return prev.url
  }
  return frames[lo]!.url
}
src/shared/media-edit/timeline/scale.ts — DOM 무결합 좌표 변환(AI 하이라이트 편집 f11과 공용)
/** ms → 트랙 내 x좌표(px). 선형 매핑. */
export function msToX(ms: number, viewStartMs: number, viewEndMs: number, trackW: number): number {
  const span = viewEndMs - viewStartMs
  if (span <= 0) return 0
  return ((ms - viewStartMs) / span) * trackW
}

/** el 기준 clientX → ms. rect 기반, clamp[viewStartMs, viewEndMs]. */
export function getMsAtClientX(
  el: HTMLElement,
  clientX: number,
  viewStartMs: number,
  viewEndMs: number,
): number {
  const rect = el.getBoundingClientRect()
  const ratio = rect.width > 0 ? (clientX - rect.left) / rect.width : 0
  const clampedRatio = Math.max(0, Math.min(1, ratio))
  return viewStartMs + clampedRatio * (viewEndMs - viewStartMs)
}
