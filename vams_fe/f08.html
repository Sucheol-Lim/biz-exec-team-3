Figma 연동·품질 게이트 파이프라인

Figma 공식 릴리즈 3파일을 PAT(REST)로 덤프해 화면 매핑 정본(design/screen-map.json)과 behavior 스펙을 동기화하는 파이프라인(scripts/figma-mapping/, Python)과, 픽셀 게이트(check:pixel)·스택 버전 핀 대조(check:pins)·미정의 CSS 변수 검사(check:cssvars) 등 "추측 구현·조용한 회귀"를 기계로 차단하는 자동 검증 도구 체계입니다.

기능 개요

이 기능은 화면이 아니라 개발 프로세스 자체를 코드로 만든 인프라입니다. 첫째 축은 Figma 매핑 파이프라인(scripts/figma-mapping/, Python·PAT REST 전용·MCP 불사용)입니다. check-versions.py가 디자인팀 공식 릴리즈 3파일(UI 시나리오 Flipbook · GUI · 공통 컴포넌트 GUI)의 version/lastModified를 스냅샷(design/json_raw/.versions.json)과 대조해 변경 여부를 exit code(0=변경 없음/1=변경/2=404/3=판단 불가)로 알려주고, 변경 시 dump-sources.py가 Flipbook 페이지별 JSON과 GUI depth-2 인벤토리를 design/json_raw/에 저장합니다 — --page 옵션으로 특정 메뉴 페이지만 선택 덤프할 수 있고(파일 전체 version만 제공되는 Figma API 특성상 페이지 델타 감지는 불가능해 사람이 지정), 429 응답은 check-versions와 동일한 쿼터 소진 방어(Retry-After 60초 초과 시 즉시 중단)를 갖췄습니다. 이어서 build-screen-map.py가 Flipbook(시나리오) ↔ GUI 화면 매칭 정본 design/screen-map.json을 생성하는데, 사람 판정(수동 매칭·컴포넌트 참조·정책 재분류)은 overrides.json으로 분리·머지되어 재생성해도 큐레이션이 보존됩니다. 화면마다 renderKind 축(기본 assembly=공통 컴포넌트 조립 / bespoke=에디터·타임라인·캔버스류)이 기록되며, bespoke 의심 화면은 이름 사전으로 경고만 하고 확정은 overrides의 사람 판정에 맡깁니다. SECTION 안에 화면처럼 섞인 메뉴 스코프 정책 프레임(menuPolicyFrames)도 화면 버킷에서 분리됩니다.

매핑 정본 위에서 extract-behaviors.py가 시나리오 프레임의 description 표를 구조화해 메뉴별 behavior 스펙(design/behavior/{NN}-{menu}.json)을 뽑고, extract-policy-common.py(00-policy/00-common)와 link-policy-refs.py(behavior ↔ 공통 정책 상호참조 링킹)가 뒤따릅니다. 추출기는 v3/v4로 보강되어 각 row에 Figma 노드ID·그룹 앵커(row-title)를 부착하고 /guide 콜아웃 마커를 화면 요소와 z-order 히트테스트로 매핑한 anchor를 답니다 — Flipbook을 요구사항 지식그래프로 직렬화하는 scripts/kg-extract/ 파이프라인의 REQ↔UI 요소 provenance 근거입니다. 분리된 메뉴 정책 프레임은 신설 extract-menu-policy.py가 {NN}-{menu}-policy.json으로 별도 추출합니다(link-policy-refs는 이 파일을 링킹 대상에서 제외). gen-pixel-manifest.py는 screen-map에서 GUI 노드를 조회해 픽셀 게이트 manifest 뼈대와 레퍼런스 PNG(REST 이미지 렌더)를 만들어 두 축을 연결하는데, renderKind로 분기합니다 — assembly는 프레임 PNG + 오버레이 중심이고, bespoke는 신설 extract-elements.py(GUI 노드 depth-8 심층조회 → 내부 element 실측 구조화)의 산출물이 없으면 즉시 FAIL하며, 있으면 manifest elements[]에 figmaNode·크기·색·radius·폰트 기대값을 자동 기입하고 렌더 DOM selector만 사람 몫으로 남깁니다(프레임 레벨 눈대중 재현이 만든 HL-004 드리프트 사고 재발 방지).

둘째 축은 npm 스크립트로 실행하는 결정론적 품질 게이트(scripts/*.mjs, Node)입니다. check:pixel(L4)은 Playwright로 렌더 DOM의 크기·색·여백·radius·폰트를 실측해 Figma 실측 manifest와 1:1 대조하고 스크린샷·레퍼런스 PNG 오버레이 diff까지 수행합니다 — manifest나 레퍼런스가 없으면 "조용한 PASS" 없이 즉시 FAIL(exit 1)입니다(2026-06-18 썸네일 상세 추측 구현 사고 재발 방지). check:pins(L3)는 package.json 핵심 의존성 메이저 버전을 ADR 확정 핀과 대조해 임의 다운그레이드를 잡고(2026-06-05 TS6→5.9 거짓 다운그레이드 사고 재발 방지), check:cssvars(L3)는 fallback 없는 미정의 var(--x) 사용(토큰 리네임 낙오 회귀)을, check:ownership은 feature 브랜치의 담당 범위 침범을 검출합니다. figma:tokens는 tokens.scss와 Figma 변수의 드리프트를 리포트합니다(게이트 아님, 항상 exit 0).

설계 포인트
파이프라인 산출물(design/json_raw/·design/screen-map.json·design/behavior/)은 gitignore된 로컬 전용이라 팀원 각자 실행해 생성하며, 저장소에는 스크립트·overrides.json·픽셀 게이트 manifest(design/pixel-gate/)만 커밋됩니다. 전 과정은 PAT(REST) 전용으로 Figma MCP 없이 동작하고, 429 응답의 Retry-After가 60초를 넘으면 플랜 쿼터 소진으로 판단해 무한 대기하지 않습니다.

관계. Python 파이프라인(좌측 계열)이 Figma 원본을 덤프·매핑·추출해 산출물을 만들고, 그 산출물을 Node 게이트(우측 계열)가 소비합니다. 게이트는 L3(결정론적 정적 검사 — 버전 핀·CSS 변수)와 L4(런타임 픽셀 실측)로 층위가 나뉩니다.
