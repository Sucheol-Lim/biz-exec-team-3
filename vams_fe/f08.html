Figma 연동·품질 게이트 파이프라인

Figma 공식 릴리즈 3파일을 PAT(REST)로 덤프해 화면 매핑 정본(design/screen-map.json)과 behavior 스펙을 동기화하는 파이프라인(scripts/figma-mapping/, Python)과, 픽셀 게이트(check:pixel)·스택 버전 핀 대조(check:pins)·미정의 CSS 변수 검사(check:cssvars) 등 "추측 구현·조용한 회귀"를 기계로 차단하는 자동 검증 도구 체계입니다. 2026-08에는 BE API 명세 엑셀 추출기(spec:api)·Figma 섹션 버전 diff(figma:diff)·아이콘 스프라이트 동기화(icons:sync)가 더해져, 디자인뿐 아니라 BE 계약과 아이콘 자산까지 기계 대조 대상이 되었습니다.

기능 개요

이 기능은 화면이 아니라 개발 프로세스 자체를 코드로 만든 인프라입니다. 첫째 축은 Figma 매핑 파이프라인(scripts/figma-mapping/, Python·PAT REST 전용·MCP 불사용)입니다. check-versions.py가 디자인팀 공식 릴리즈 3파일(UI 시나리오 Flipbook · GUI · 공통 컴포넌트 GUI)의 version/lastModified를 스냅샷(design/json_raw/.versions.json)과 대조해 변경 여부를 exit code(0=변경 없음/1=변경/2=404/3=판단 불가)로 알려주고, 변경 시 dump-sources.py가 Flipbook 페이지별 JSON과 GUI depth-2 인벤토리를 design/json_raw/에 저장합니다 — --page 옵션으로 특정 메뉴 페이지만 선택 덤프할 수 있고(파일 전체 version만 제공되는 Figma API 특성상 페이지 델타 감지는 불가능해 사람이 지정), 429 응답은 check-versions와 동일한 쿼터 소진 방어(Retry-After 60초 초과 시 즉시 중단)를 갖췄습니다. 이어서 build-screen-map.py가 Flipbook(시나리오) ↔ GUI 화면 매칭 정본 design/screen-map.json을 생성하는데, 사람 판정(수동 매칭·컴포넌트 참조·정책 재분류)은 overrides.json으로 분리·머지되어 재생성해도 큐레이션이 보존됩니다. 화면마다 renderKind 축(기본 assembly=공통 컴포넌트 조립 / bespoke=에디터·타임라인·캔버스류)이 기록되며, bespoke 의심 화면은 이름 사전으로 경고만 하고 확정은 overrides의 사람 판정에 맡깁니다. SECTION 안에 화면처럼 섞인 메뉴 스코프 정책 프레임(menuPolicyFrames)도 화면 버킷에서 분리됩니다.

매핑 정본 위에서 extract-behaviors.py가 시나리오 프레임의 description 표를 구조화해 메뉴별 behavior 스펙(design/behavior/{NN}-{menu}.json)을 뽑고, extract-policy-common.py(00-policy/00-common)와 link-policy-refs.py(behavior ↔ 공통 정책 상호참조 링킹)가 뒤따릅니다. 추출기는 v3/v4로 보강되어 각 row에 Figma 노드ID·그룹 앵커(row-title)를 부착하고 /guide 콜아웃 마커를 화면 요소와 z-order 히트테스트로 매핑한 anchor를 답니다 — Flipbook을 요구사항 지식그래프로 직렬화하는 scripts/kg-extract/ 파이프라인의 REQ↔UI 요소 provenance 근거입니다. 분리된 메뉴 정책 프레임은 신설 extract-menu-policy.py가 {NN}-{menu}-policy.json으로 별도 추출합니다(link-policy-refs는 이 파일을 링킹 대상에서 제외). gen-pixel-manifest.py는 screen-map에서 GUI 노드를 조회해 픽셀 게이트 manifest 뼈대와 레퍼런스 PNG(REST 이미지 렌더)를 만들어 두 축을 연결하는데, renderKind로 분기합니다 — assembly는 프레임 PNG + 오버레이 중심이고, bespoke는 신설 extract-elements.py(GUI 노드 depth-8 심층조회 → 내부 element 실측 구조화)의 산출물이 없으면 즉시 FAIL하며, 있으면 manifest elements[]에 figmaNode·크기·색·radius·폰트 기대값을 자동 기입하고 렌더 DOM selector만 사람 몫으로 남깁니다(프레임 레벨 눈대중 재현이 만든 HL-004 드리프트 사고 재발 방지). extract-elements.py는 이후 visible=false 서브트리를 전면 제외하도록 보강되었습니다 — 숨김 노드는 렌더 DOM에 없어 픽셀 게이트에서 영구 FAIL하는 유령 element가 되기 때문입니다(해당 메뉴가 쓰지 않는 조회기간·검색·토글 등 GUI 리스트 템플릿 잔재, 2026-07-30 PK-001 실측에서 발견).

둘째 축은 npm 스크립트로 실행하는 결정론적 품질 게이트(scripts/*.mjs, Node)입니다. check:pixel(L4)은 Playwright로 렌더 DOM의 크기·색·여백·radius·폰트를 실측해 Figma 실측 manifest와 1:1 대조하고 스크린샷·레퍼런스 PNG 오버레이 diff까지 수행합니다 — manifest나 레퍼런스가 없으면 "조용한 PASS" 없이 즉시 FAIL(exit 1)입니다(2026-06-18 썸네일 상세 추측 구현 사고 재발 방지). check:pins(L3)는 package.json 핵심 의존성 메이저 버전을 ADR 확정 핀과 대조해 임의 다운그레이드를 잡고(2026-06-05 TS6→5.9 거짓 다운그레이드 사고 재발 방지), check:cssvars(L3)는 fallback 없는 미정의 var(--x) 사용(토큰 리네임 낙오 회귀)을, check:ownership은 feature 브랜치의 담당 범위 침범을 검출합니다. figma:tokens는 tokens.scss와 Figma 변수의 드리프트를 리포트합니다(게이트 아님, 항상 exit 0). 2026-08 갱신으로 픽셀 게이트에 fill:<selector>=<text> setup 액션이 추가되어 "입력이 있어야 도달하는 상태"(예: 얼굴인식 인물 검색 결과)도 촬영할 수 있고(셀렉터에 =가 흔해 마지막 =로 가릅니다), check:ownership의 표준 슬러그는 개인화 2분할·얼굴인식 분리를 반영해 13종으로 갱신되면서 face 계열 브랜치 별칭이 추가되었습니다 — 구 personalization 토큰은 어느 쪽인지 알 수 없어 의도적으로 미매핑으로 남겨 오판 대신 --own 명시를 요구합니다.

2026-08에 세 번째 축이 붙었습니다. 첫째, extract-api-spec.py(npm run spec:api)는 BE가 배포하는 「VAMS API 리스트」 엑셀을 외부 의존성 없이 stdlib(zipfile + xml.etree)로 파싱해 Ref-docs/claude/api-spec/<version>.json 정본으로 만듭니다 — 원본 엑셀이 레포에 없고 design/은 gitignore라 이 JSON이 BE 계약의 유일한 추적 기록입니다. --diff 옵션은 직전 버전과 엔드포인트 추가·삭제·시그니처 변경·필드 변경·폐기 전환을 대조해 리포트하며, 이번 라운드에서 v1.0.4 정본과 diff-v1.0.3-v1.0.4.md가 생성되어 골라보기 인물 리스트 계약 변경 같은 항목이 조기에 잡혔습니다. 임기응변 파싱 시절 「얼굴인식」 시트를 "없다"고 오판해 추정 경로 위에 구현한 사고가 이 스크립트의 배경입니다.

둘째, figma-section-diff.py(figma:diff)는 Figma 섹션의 "이전 버전 ↔ 현재" 차이를 REST로 뽑습니다. Figma MCP 읽기 도구와 Plugin API 모두 읽기용 version 파라미터가 없어 버전 diff는 REST 전용이며, versions/bisect/fetch/diff/hash 서브커맨드로 섹션 직속 COMPONENT의 추가·삭제·개명·지오메트리·크기 변경을 이분 탐색합니다(fills·strokes·토큰 바인딩 변경은 감지 대상이 아님을 명시). 셋째, sync-icons.py(icons:sync)는 아이콘 스프라이트 src/assets/icons.svg를 컴포넌트 라이브러리 Icons 섹션 마스터에서 재생성합니다 — 매핑 정본 scripts/icon-map.json(68 슬러그, 좌표 Jaccard·래스터 IoU로 tier 판정)이 무엇을 갱신·보존·삭제할지 규정하고, GUI 화면 파일 대신 마스터를 직접 받아 mask 해체·타이트 크롭·instance-swap 누락 문제를 원천 회피합니다. 스프라이트를 placeholder로 덮어써 위험했던 구 build-icons.mjs는 삭제되고 icons:build는 안내 후 exit 1 하는 폐기 스텁으로 남았습니다.

설계 포인트
파이프라인 산출물(design/json_raw/·design/screen-map.json·design/behavior/)은 gitignore된 로컬 전용이라 팀원 각자 실행해 생성하며, 저장소에는 스크립트·overrides.json·픽셀 게이트 manifest(design/pixel-gate/)만 커밋됩니다. 전 과정은 PAT(REST) 전용으로 Figma MCP 없이 동작하고, 429 응답의 Retry-After가 60초를 넘으면 플랜 쿼터 소진으로 판단해 무한 대기하지 않습니다.
