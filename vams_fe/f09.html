얼굴인식 검수·편집

AI 얼굴인식 엔진이 영상에서 검출한 인물 얼굴을 운영자가 검수하는 화면입니다. 공통 리스트 패턴 목록(FC-001)과 우측 상세패널(FC-002), 배역 인식 목록 모달(FC-003)을 거쳐 bare 풀스크린 상세(FC-004)에서 배역 칩·검출 썸네일 그리드·대표 이미지 아코디언을 다루고, 상세 분석 결과 모달(FC-005)에서 인물 재지정과 대표 영역 드래그 지정을 수행합니다.

기능 개요

얼굴인식은 콘텐츠 영상에서 검출된 인물 얼굴을 배역(인물)별로 정리하고, AI가 잘못 묶은 얼굴을 운영자가 바로잡는 메뉴입니다. 목록(FaceRecognitionListPage)은 2026-08-28 실 BE 경로로 이관되어 공통#1(GET /api/content-info/list?serviceType=CI)을 직접 쓰고, 완결여부 3택1 필터를 feature-local ref로 유지해 공용 listQuery 스토어를 침범하지 않습니다(completedYn은 페이지에서 머지). 정렬은 상태칩이 all이 아닐 때 PRIORITY를 LATEST로 강등하는 공통 가드를 그대로 씁니다. 우측 FaceRecognitionDetailPanel이 행 요약을 보여주고(작업이력=공통#3 + 콘텐츠정보=공통#2 순차 조인, 후자가 실패해도 패널 상단은 살립니다), [검수] CTA가 AppShell 밖 bare 풀스크린 라우트 /face-recognition/:jobId로 진입시킵니다. 목록 상단에서는 콘텐츠를 횡단하는 전역 배역 조회 모달(FaceRoleListModal, FC-003)을 열 수 있으며, 실계약(얼굴인식#1 /api/person-meta)은 검색어가 없으면 건수 제한 없이 전량(실측 421건)을 주므로 "최근 등록 배역" 3건은 클라이언트에서 RECENT_ROLE_LIMIT로 잘라 보여줍니다.

상세 화면(FaceRecognitionDetailPage)의 본문 3개 섹션(배역 칩 행 · 검출 썸네일 그리드 · 대표 이미지 아코디언)은 2026-08-27 실계약 정합으로 두 API 조인이 되었습니다 — 라우트가 가진 건 jobId뿐이라 먼저 resolveFaceContentId(공통#3)로 contentId를 얻은 뒤, 얼굴인식#3(/api/face-result/contents/{contentId}, 검출 그리드)과 얼굴인식#4(/api/content-person-mapp/content/{contentId}, 칩·대표이미지쌍)를 병렬로 불러 조인합니다. 한쪽이 실패해도 화면 전체를 죽이지 않고 그 섹션만 비웁니다. 이 조인 결과는 최초 fetch 로더 전용으로만 쓰입니다 — staleTime: Infinity + refetchOnMount/WindowFocus: false로 두고, 성공하면 store.hydrate()가 결과를 Pinia 스토어로 1회 이관합니다. 이후 렌더 소스는 오직 store.result이며, 대표/후보 토글·인물 재지정·대표 영역 지정은 전부 로컬 스테이징(네트워크 0)으로 처리하고 BE 쓰기는 헤더 [저장] 한 경로로 모읍니다. 썸네일 제어(FaceSizeControl)로 검출 얼굴 크기를 조절하거나 "결과만 보기"를 토글할 수 있습니다. 헤더의 [재생성](공통#8 단건)·[연동](공통#6, jobId 하나로 일괄 API를 호출) 버튼도 2026-08-28에 실제로 배선되었습니다 — 그 전까지는 눌러도 아무 반응이 없는 버튼이었습니다. [이전]으로 나갈 때 dirty 상태면 [취소]/[저장 후 종료]/[저장하지 않고 종료] 3버튼 확인 팝업이 뜨는 것도 2026-08-31에 배선되었습니다(저장 실패 시에는 이탈하지 않습니다) — 포스터·썸네일·구간마킹·하이라이트·개인화 포스터 5개 메뉴가 이미 쓰던 공용 ConfirmDialog 패턴에 얼굴인식만 배선이 빠져 있던 것입니다.

편집 상태는 faceRecognitionEdit 스토어가 shallowRef로 소유합니다. 결과 그래프가 불변(immutable)이라 deep reactivity가 필요 없고, 루트 참조만 갈아끼우면 파생 computed가 전부 갱신되기 때문입니다. 그래서 isDirty는 result !== baselineResult 참조 비교 O(1)로 판정되고, 이 판정이 성립하려면 faceResultMutations.ts의 모든 transform이 불변이면서 no-op일 때 인자를 그대로 반환해야 합니다(위반 시 헛 dirty). 실행취소·재실행은 이 불변성 덕에 루트 참조 스냅샷 스택으로 충분해 클론 없이 O(1) push/pop이며, 상한은 50단계(FACE_HISTORY_LIMIT)로 초과분은 가장 오래된 이력부터 버립니다. 모든 편집은 commit() 단일 관문을 지나므로 필터칩·스크롤·모달 열기 같은 보기 상태는 구조적으로 이력에 기록되지 않습니다. FaceBox는 실계약 확인 후 축이 둘로 나뉘었습니다 — 검출 박스(faceBox·otherFaces)는 실계약 그대로 절대 px인 반면 대표 영역 드래그(repRegion)는 여전히 정규화 0~1이라, FaceAnalysisModal이 <img>의 naturalWidth/naturalHeight로 나눠 px를 비율로 환산하는 지점(toRatioBox)을 화면 쪽에 하나 두어 렌더·라벨 배치가 여전히 비율 축으로만 동작하게 합니다.

설계 포인트 — 저장 후 캐시 승격
저장 성공 시 store.applySaved(r)로 baseline을 승격하는 것만으로는 부족합니다. result 쿼리가 staleTime: Infinity이고 언마운트 시 스토어가 리셋되므로, qc.setQueryData로 캐시까지 함께 승격하지 않으면 저장 → 목록 복귀 → gcTime 내 재진입 시 저장 이전 스냅샷으로 다시 hydrate되어 편집이 사라진 것처럼 보입니다. 실제로 리뷰에서 MAJOR로 잡혀 수정된 결함입니다.
참고 — 계약 상태(2026-08-27/28 실계약 정합 완료)
종전 FACE_API의 경로는 전부 [추정]이었고 저장은 Mock 로컬 반영 수준이었으나, 목록(공통#1)·상세 패널(공통#2+#3)·본문 결과(얼굴인식#3+#4 조인)·저장(얼굴인식#10 인물 재지정 PUT + 얼굴인식#8 대표이미지 POST, 순차 호출)·연동(공통#6)·재생성(공통#8)까지 전부 실 BE 경로로 전환되었습니다. 대표 영역 지정(얼굴인식#9 POST /api/image-crop, 절대 px)만 되읽는 응답 경로가 없어(FC-C10) 이번 전환 범위 밖으로 남아 있습니다. 저장 응답은 HTTP 200이면서 {code:'JOB_NOT_REREQUESTABLE'}류로 거절될 수 있어, assertSaved가 엔벨로프 code를 직접 확인합니다(HTTP 상태만 보면 거절이 성공 토스트로 보입니다).

src/features/face-recognition/edit/stores/faceRecognitionEdit.ts — 편집 커밋 단일 관문과 50단계 이력
/** 이력 최대 단계 — 정본 §6 "기본 50단계". 초과 시 가장 오래된 이력부터 제거. */
export const FACE_HISTORY_LIMIT = 50

/** dirty — 참조 비교 O(1). */
const isDirty = computed<boolean>(() => result.value !== baselineResult.value)

/**
 * 편집 커밋 단일 관문 — result 교체 + 이력 기록을 한 곳에 모은다.
 * no-op(next === 현재)이면 result 참조도 이력도 건드리지 않는다(헛 dirty·헛 이력 방지).
 */
function commit(next: FaceRecognitionResult): void {
  const r = result.value
  if (!r || next === r) return
  const prev = undoStack.value
  // §6 초과 처리: 가장 오래된 이력부터 제거(신규 1칸 확보).
  undoStack.value =
    prev.length >= FACE_HISTORY_LIMIT
      ? [...prev.slice(prev.length - FACE_HISTORY_LIMIT + 1), r]
      : [...prev, r]
  redoStack.value = []
  result.value = next
}
src/features/face-recognition/edit/faceResultMutations.ts — no-op이면 인자를 그대로 반환하는 불변 transform
/** idx 위치의 detection만 교체한 새 배열(불변) — 다른 항목은 참조 그대로 유지. */
function replaceAt(detections: FaceDetection[], idx: number, next: FaceDetection): FaceDetection[] {
  const out = [...detections]
  out[idx] = next
  return out
}

export function setRepresentative(
  result: FaceRecognitionResult,
  detectionId: string,
): FaceRecognitionResult {
  const idx = findIndex(result, detectionId)
  if (idx === -1) return result                      // no-op(없는 detectionId)
  const d = result.detections[idx]!
  if (d.cardState === 'representative') return result // no-op(이미 대표)
  return {
    ...result,
    detections: replaceAt(result.detections, idx, { ...d, cardState: 'representative' }),
  }
}
src/features/face-recognition/composables/useRepRegionDrag.ts — 종횡비 보정된 정사각 영역 계산
/** 최소 영역 크기(정규화) — 이보다 작으면 "클릭 오조작"으로 보고 그리기를 폐기한다. */
export const MIN_REGION_SIZE = 0.05

/**
 * 정규화 좌표에서 w === h 는 컨테이너가 정사각일 때만 시각적 정사각이다.
 * 장면 이미지는 658×370(≈16:9)이므로 변의 길이를 x-정규화 단위로 계산하고
 * 높이는 size × aspect 로 환산한다. aspect = 1 이면 기존 동작으로 축퇴한다.
 */
export function squareFromAnchor(anchor: Point, point: Point, aspect = 1): FaceBox {
  const dx = point.x - anchor.x
  const dy = point.y - anchor.y
  const towardRight = dx >= 0
  const towardBottom = dy >= 0
  // 진행 방향으로 남은 여유 — y축 여유도 x-정규화 단위로 환산해 비교한다.
  const roomX = towardRight ? 1 - anchor.x : anchor.x
  const roomY = (towardBottom ? 1 - anchor.y : anchor.y) / aspect
  const size = Math.min(Math.max(Math.abs(dx), Math.abs(dy) / aspect), roomX, roomY)
  const height = size * aspect
  return {
    x: towardRight ? anchor.x : anchor.x - size,
    y: towardBottom ? anchor.y : anchor.y - height,
    w: size,
    h: height,
  }
}
src/features/face-recognition/pages/FaceRecognitionDetailPage.vue — 저장 후 baseline·캐시 동시 승격 (실계약 2종 순차 호출, 2026-08-27)
async function onSave(): Promise<void> {
  if (!store.isDirty || savePending.value) return
  const r = store.result
  if (!r) return
  savePending.value = true
  try {
    // 페이로드 변환은 queries 가 맡는다 — 실계약이 두 갈래(#10 재지정 · #8 대표이미지)라
    // 화면이 어느 쪽을 부를지 알 필요가 없다. baseline 을 함께 넘긴다 — 재지정 해제
    // (인물 → 미지정)는 진입 스냅샷과 비교해야만 판별된다. 안 넘기면 해제가 서버에 반영되지 않는다.
    await saveFaceRecognitionResult(jobId.value, r, store.baselineResult)
    store.applySaved(r)   // 응답이 {code,message}뿐 — 저장 직전 로컬 result를 baseline으로 승격
    // ⚠️ 캐시도 함께 승격해야 한다. result 쿼리는 staleTime: Infinity + refetchOnMount: false 라
    // 이 줄이 없으면 저장 → 목록 복귀 → (gcTime 내) 재진입 시 저장 이전 스냅샷으로 다시 hydrate 된다.
    qc.setQueryData(faceRecognitionKeys.result(jobId.value), r)
    toast.success({ messageKey: 'faceRecognition.detail.toast.saveOk' })
  } catch (e) {
    toast.error({ messageKey: 'faceRecognition.detail.toast.saveFail' })
  } finally {
    savePending.value = false
  }
}
src/features/face-recognition/queries.ts — 실계약 2종 순차 저장 + 엔벨로프 거절 검사
/**
 * 상세 결과 저장 — 실계약 2종을 순차 호출한다.
 *   #10 PUT  /api/face-result/contents/{contentId}       — 인물 재지정
 *   #8  POST /api/person-crop-result/{contentId}/save    — 대표이미지
 * 보낼 것이 없으면 호출하지 않는다. 순차로 부른다(병렬 아님) — 재지정이 먼저 반영돼야
 * 대표이미지의 personId 가 유효하다.
 */
export async function saveFaceRecognitionResult(
  jobId: string,
  result: FaceRecognitionResult,
  baseline?: FaceRecognitionResult | null,
): Promise<void> {
  const assign = toFaceAssignSave(result, baseline)
  const rep = toFaceRepImageSave(result)
  if (assign.editList.length === 0 && rep.editList.length === 0) return

  const contentId = await resolveFaceContentId(jobId) // 조회와 같은 축으로 저장
  if (assign.editList.length > 0) {
    assertSaved(await httpPut(FACE_API.saveAssign(contentId), assign), '얼굴인식#10(인물 재지정 저장)')
  }
  if (rep.editList.length > 0) {
    assertSaved(await httpPost(FACE_API.saveRepImage(contentId), rep), '얼굴인식#8(대표이미지 저장)')
  }
}

// 🔴 2026-08-31 신설 — 이 계열 BE 는 거절을 HTTP 200 + {code:'…'} 로 준다
// (재생성 JOB_NOT_REREQUESTABLE 이 실측 사례). HTTP 상태만 보면 거절이 성공 토스트로 보인다.
function assertSaved(res: ContentEnvelope<unknown> | null | undefined, what: string): void {
  const code = res?.code
  if (code === undefined || code === null) return       // 형상 없는 mock 은 성공으로 본다
  if (isContentEnvelopeSuccess(code)) return
  throw Object.assign(new Error(`${what} 거절: ${code} ${res?.message ?? ''}`), { code })
}
src/features/face-recognition/faceBoxLabel.ts — 검출 박스 라벨 2축 독립 배치
/**
 * 라벨 배치 판정. 기본은 좌하단이며, 넘칠 때만 반대편으로 뒤집는다("라벨이 잘리면 안됨").
 *  - 하단 넘침: box.bottom + labelH > containerH → above
 *  - 우측 넘침: box.left  + labelW > containerW → right
 * 컨테이너/라벨 실측이 0(미렌더·측정 전)이면 판정을 보류하고 기본값을 돌려준다.
 */
export function resolveFaceLabelPlacement(input: FaceLabelPlacementInput): FaceLabelPlacement {
  const { box, containerWidth, containerHeight, labelWidth, labelHeight } = input
  const placement: FaceLabelPlacement = { vertical: 'below', horizontal: 'left' }
  if (containerWidth <= 0 || containerHeight <= 0) return placement

  if (labelHeight > 0 && (box.y + box.h) * containerHeight + labelHeight > containerHeight) {
    placement.vertical = 'above'
  }
  if (labelWidth > 0 && box.x * containerWidth + labelWidth > containerWidth) {
    placement.horizontal = 'right'
  }
  return placement
}
