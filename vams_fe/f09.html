얼굴인식 검수·편집

AI 얼굴인식 엔진이 영상에서 검출한 인물 얼굴을 운영자가 검수하는 화면입니다. 공통 리스트 패턴 목록(FC-001)과 우측 상세패널(FC-002), 배역 인식 목록 모달(FC-003)을 거쳐 bare 풀스크린 상세(FC-004)에서 배역 칩·검출 썸네일 그리드·대표 이미지 아코디언을 다루고, 상세 분석 결과 모달(FC-005)에서 인물 재지정과 대표 영역 드래그 지정을 수행합니다.

기능 개요

얼굴인식은 콘텐츠 영상에서 검출된 인물 얼굴을 배역(인물)별로 정리하고, AI가 잘못 묶은 얼굴을 운영자가 바로잡는 메뉴입니다. 목록(FaceRecognitionListPage)은 전 메뉴 공통 리스트 패턴을 따르되 serviceType: 'CI'를 고정 주입하고, 완결여부 3택1 필터를 feature-local ref로 유지해 공용 listQuery 스토어를 침범하지 않습니다(completedYn은 페이지에서 머지). 정렬은 상태칩이 all이 아닐 때 PRIORITY를 LATEST로 강등하는 공통 가드를 그대로 씁니다. 우측 FaceRecognitionDetailPanel이 행 요약을 보여주고, [검수] CTA가 AppShell 밖 bare 풀스크린 라우트 /face-recognition/:jobId로 진입시킵니다. 목록 상단에서는 콘텐츠를 횡단하는 전역 배역 조회 모달(FaceRoleListModal, FC-003)을 열 수 있으며, 이 모달은 keyword에만 의존하는 별도 쿼리 축(faceRecognitionKeys.roles)을 씁니다.

상세 화면(FaceRecognitionDetailPage)은 두 축의 쿼리로 구성됩니다. 헤더 breadcrumb(장르·콘텐츠명)용 fetchFaceRecognitionDetail과, 화면 본문 3개 섹션(배역 칩 행 · 검출 썸네일 그리드 · 대표 이미지 아코디언)의 단일 소스인 fetchFaceRecognitionResult입니다. 후자는 최초 fetch 로더 전용으로만 쓰입니다 — staleTime: Infinity + refetchOnMount/WindowFocus: false로 두고, 성공하면 store.hydrate()가 결과를 Pinia 스토어로 1회 이관합니다. 이후 렌더 소스는 오직 store.result이며, 대표/후보 토글·인물 재지정·대표 영역 지정은 전부 로컬 스테이징(네트워크 0)으로 처리하고 BE 쓰기는 헤더 [저장] 한 경로로 모읍니다. 썸네일 제어(FaceSizeControl)로 검출 얼굴 크기를 조절하거나 "결과만 보기"를 토글할 수 있습니다.

편집 상태는 faceRecognitionEdit 스토어가 shallowRef로 소유합니다. 결과 그래프가 불변(immutable)이라 deep reactivity가 필요 없고, 루트 참조만 갈아끼우면 파생 computed가 전부 갱신되기 때문입니다. 그래서 isDirty는 result !== baselineResult 참조 비교 O(1)로 판정되고, 이 판정이 성립하려면 faceResultMutations.ts의 모든 transform이 불변이면서 no-op일 때 인자를 그대로 반환해야 합니다(위반 시 헛 dirty). 실행취소·재실행은 이 불변성 덕에 루트 참조 스냅샷 스택으로 충분해 클론 없이 O(1) push/pop이며, 상한은 50단계(FACE_HISTORY_LIMIT)로 초과분은 가장 오래된 이력부터 버립니다. 모든 편집은 commit() 단일 관문을 지나므로 필터칩·스크롤·모달 열기 같은 보기 상태는 구조적으로 이력에 기록되지 않습니다.

설계 포인트 — 저장 후 캐시 승격
저장 성공 시 store.applySaved(r)로 baseline을 승격하는 것만으로는 부족합니다. result 쿼리가 staleTime: Infinity이고 언마운트 시 스토어가 리셋되므로, qc.setQueryData로 캐시까지 함께 승격하지 않으면 저장 → 목록 복귀 → gcTime 내 재진입 시 저장 이전 스냅샷으로 다시 hydrate되어 편집이 사라진 것처럼 보입니다. 실제로 리뷰에서 MAJOR로 잡혀 수정된 결함입니다.
참고 — 계약 상태
FACE_API의 경로는 아직 전부 [추정]입니다. API 리스트 v1.0.3에서 얼굴인식 시트가 4종 → 11종으로 확장되며 교체 블로커 2건이 해소됐고 상세 결과 저장(FC-9 PATCH)은 여전히 API 부재(FC-I4)로 표시되어, 저장은 Mock 로컬 반영 수준입니다. 실 계약 확정 시 endpoints.ts와 어댑터 2지점만 교체하도록 격리해 두었습니다.

핵심 코드

src/features/face-recognition/edit/stores/faceRecognitionEdit.ts — 편집 커밋 단일 관문과 50단계 이력
/** 이력 최대 단계 — 정본 §6 "기본 50단계". 초과 시 가장 오래된 이력부터 제거. */
export const FACE_HISTORY_LIMIT = 50

/** dirty — 참조 비교 O(1). */
const isDirty = computed<boolean>(() => result.value !== baselineResult.value)

/**
 * 편집 커밋 단일 관문 — result 교체 + 이력 기록을 한 곳에 모은다.
 * no-op(next === 현재)이면 result 참조도 이력도 건드리지 않는다(헛 dirty·헛 이력 방지).
 */
function commit(next: FaceRecognitionResult): void {
  const r = result.value
  if (!r || next === r) return
  const prev = undoStack.value
  // §6 초과 처리: 가장 오래된 이력부터 제거(신규 1칸 확보).
  undoStack.value =
    prev.length >= FACE_HISTORY_LIMIT
      ? [...prev.slice(prev.length - FACE_HISTORY_LIMIT + 1), r]
      : [...prev, r]
  redoStack.value = []
  result.value = next
}
src/features/face-recognition/edit/faceResultMutations.ts — no-op이면 인자를 그대로 반환하는 불변 transform
/** idx 위치의 detection만 교체한 새 배열(불변) — 다른 항목은 참조 그대로 유지. */
function replaceAt(detections: FaceDetection[], idx: number, next: FaceDetection): FaceDetection[] {
  const out = [...detections]
  out[idx] = next
  return out
}

export function setRepresentative(
  result: FaceRecognitionResult,
  detectionId: string,
): FaceRecognitionResult {
  const idx = findIndex(result, detectionId)
  if (idx === -1) return result                      // no-op(없는 detectionId)
  const d = result.detections[idx]!
  if (d.cardState === 'representative') return result // no-op(이미 대표)
  return {
    ...result,
    detections: replaceAt(result.detections, idx, { ...d, cardState: 'representative' }),
  }
}
src/features/face-recognition/composables/useRepRegionDrag.ts — 종횡비 보정된 정사각 영역 계산
/** 최소 영역 크기(정규화) — 이보다 작으면 "클릭 오조작"으로 보고 그리기를 폐기한다. */
export const MIN_REGION_SIZE = 0.05

/**
 * 정규화 좌표에서 w === h 는 컨테이너가 정사각일 때만 시각적 정사각이다.
 * 장면 이미지는 658×370(≈16:9)이므로 변의 길이를 x-정규화 단위로 계산하고
 * 높이는 size × aspect 로 환산한다. aspect = 1 이면 기존 동작으로 축퇴한다.
 */
export function squareFromAnchor(anchor: Point, point: Point, aspect = 1): FaceBox {
  const dx = point.x - anchor.x
  const dy = point.y - anchor.y
  const towardRight = dx >= 0
  const towardBottom = dy >= 0
  // 진행 방향으로 남은 여유 — y축 여유도 x-정규화 단위로 환산해 비교한다.
  const roomX = towardRight ? 1 - anchor.x : anchor.x
  const roomY = (towardBottom ? 1 - anchor.y : anchor.y) / aspect
  const size = Math.min(Math.max(Math.abs(dx), Math.abs(dy) / aspect), roomX, roomY)
  const height = size * aspect
  return {
    x: towardRight ? anchor.x : anchor.x - size,
    y: towardBottom ? anchor.y : anchor.y - height,
    w: size,
    h: height,
  }
}
src/features/face-recognition/pages/FaceRecognitionDetailPage.vue — 저장 후 baseline·캐시 동시 승격
async function onSave(): Promise<void> {
  if (!store.isDirty || savePending.value) return
  const r = store.result
  if (!r) return
  savePending.value = true
  try {
    const payload = toFaceRecognitionResultSave(r)
    await saveFaceRecognitionResult(jobId.value, payload)
    store.applySaved(r)   // 응답이 {code,message}뿐 — 저장 직전 로컬 result를 baseline으로 승격
    // ⚠️ 캐시도 함께 승격해야 한다. result 쿼리는 staleTime: Infinity + refetchOnMount: false 라
    // 이 줄이 없으면 저장 → 목록 복귀 → (gcTime 내) 재진입 시 저장 이전 스냅샷으로 다시 hydrate 된다.
    qc.setQueryData(faceRecognitionKeys.result(jobId.value), r)
    toast.success({ messageKey: 'faceRecognition.detail.toast.saveOk' })
  } catch (e) {
    toast.error({ messageKey: 'faceRecognition.detail.toast.saveFail' })
  } finally {
    savePending.value = false
  }
}
src/features/face-recognition/faceBoxLabel.ts — 검출 박스 라벨 2축 독립 배치
/**
 * 라벨 배치 판정. 기본은 좌하단이며, 넘칠 때만 반대편으로 뒤집는다("라벨이 잘리면 안됨").
 *  - 하단 넘침: box.bottom + labelH > containerH → above
 *  - 우측 넘침: box.left  + labelW > containerW → right
 * 컨테이너/라벨 실측이 0(미렌더·측정 전)이면 판정을 보류하고 기본값을 돌려준다.
 */
export function resolveFaceLabelPlacement(input: FaceLabelPlacementInput): FaceLabelPlacement {
  const { box, containerWidth, containerHeight, labelWidth, labelHeight } = input
  const placement: FaceLabelPlacement = { vertical: 'below', horizontal: 'left' }
  if (containerWidth <= 0 || containerHeight <= 0) return placement

  if (labelHeight > 0 && (box.y + box.h) * containerHeight + labelHeight > containerHeight) {
    placement.vertical = 'above'
  }
  if (labelWidth > 0 && box.x * containerWidth + labelWidth > containerWidth) {
    placement.horizontal = 'right'
  }
  return placement
}
