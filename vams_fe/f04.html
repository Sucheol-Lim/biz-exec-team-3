AI 자막 편집기

자막 작업 목록에서 bare 풀스크린 편집기(SubtitleEditPage)로 진입해, wavesurfer 파형 타임라인·편집 단축키(S/D/A/F/Q/W)·KRCC/KT 변환·찾기/바꾸기·동기화 시프트와 20종 이상의 편집 다이얼로그로 AI 생성 자막을 검수·편집하고 SMI로 최종 저장(연동)하는 본 과제 최대 규모 기능입니다.

기능 개요

AI 자막 엔진(어뮤즈랩 협업 alfaeditor)이 생성한 자막을 운영자가 사람 검수로 다듬는 화면입니다. 자막 작업 목록(SubtitleListPage, LNB 하위 /subtitle)에서 행을 선택하면 meta.layout:'bare' 풀스크린 라우트 /subtitle/:jobId/edit의 SubtitleEditPage로 진입합니다. 화면은 헤더 / 자막 리스트 + 영상·편집 패인 / 하단 전폭 파형 타임라인 3구역으로 구성되며, Pinia setup 스토어 subtitleEditor가 currentTimeMs·selectedLineId·playing을 단일 진실로 삼아 리스트·영상·파형 3자를 동기화합니다. 모든 seek/선택은 SyncSource(list/video/waveform/find/keyboard 등) 소스 태그를 달아 무한 이벤트 루프를 차단합니다.

진입 시 스토어 init()은 메타 → E7 점유 확인 → E4 임시저장 복구 순으로 호출합니다(2026-08 순서 정정 — 인터페이스 정의서 API0001~0003 기준). 종전엔 메타 조회에 alfaeditor 내부 엔드포인트(E1 GET /alti/content)를 썼는데 그 조회 자체가 락 획득 부작용이 있어(이미 점유 중이면 200+빈 body) 점유 확인보다 먼저 부를 수 없었습니다. 지금은 메타를 VAMS 신규 API(fetchReviewTarget, GET /api/subtitle-result/contents/{contentId}, v1.0.5)로 조회하는데 이 호출엔 부작용이 없어 점유 확인(API0003 GET /alti/status)보다 먼저 부르고, 그 응답에서 확정된 ccContentsId·language를 점유 확인 호출에 넘깁니다 — 정의서 키축은 ccContentsId인데 alfaeditor 내부(/temporary·/peaks)는 contentId 축이라 두 값을 함께 들고 다닙니다. 타인이 편집 중(RUNNING)이면 sessionState='denied'로 차단합니다. 편집 락은 WebSocket 세션(useSubtitleSocket, WS /alti/socket) 자체가 담당하며, 서버의 temporary_storage 메시지(5분 주기)가 자동 임시저장(E5)을 트리거합니다. 파형은 useWaveform이 wavesurfer.js + Regions 플러그인으로 라인 ↔ region을 양방향 동기화하고, 빈 구간 드래그로 새 자막 라인을 삽입할 수 있습니다. 편집 트랜잭션(텍스트 적용·타임코드 변경·분할/병합 등)은 useEditHistory 메멘토 스택(최대 100단계)에 적재되어 Ctrl+Z / Ctrl+Shift+Z로 undo/redo 됩니다.

편집 도구는 Subtitle Edit 기반 단축키(useSubtitleShortcuts — S 시작시간, D 종료시간, A/F 다음·이전 줄, Q/W 이전·다음 병합, Ctrl+R 자동 줄바꿈)와 찾기/이동·찾아 바꾸기·다중 바꾸기·선택해서 바꾸기·오류 일괄수정·간격 채우기·동기화 시프트·타임코드·색상/글꼴·다운로드(검수 전 SRT / 완료 SMI) 등 다이얼로그 18종 + 컨텍스트 메뉴·팝업으로 제공됩니다. KRCC 바꾸기/KT 포맷 변환(useSubtitleTransform)은 서버 왕복 없는 FE 정규식 연산이며 비가역(history 미적재) 정책입니다 — KT 변환은 서식 태그(<b> 등)·<br>·공백을 lookahead 로 건너뛴 실질 문장 끝의 마침표·느낌표만 제거하고, 실행 확인·완료 팝업은 GUI 정본 SubtitleAlertModal(440px 가운데 정렬)로 띄우며 확인 팝업의 [자세히 보기] 링크가 변환 규칙 팝업(KtRuleDialog)을 겹쳐 열고 완료 팝업에 변경된 자막 개수를 표시합니다. 2026-09-14 재배선으로 저장과 연동이 분리되었습니다 — 헤더 [저장](saveFinal)이 buildSmi()로 완성 SMI 문자열을 만들어 E6 확정 저장 + 공통#11 검수자 마킹(V)까지 하고, 헤더 [연동](requestLink)은 dirty 여부와 무관하게 항상 saveFinal()을 먼저 호출한 뒤(실패하면 연동 자체를 중단) 다른 12개 메뉴와 같은 공통#6 send-result만 요청합니다 — temporary만 있던 진입에서도 확정본을 만들어 두는 선택지입니다. jobId가 없는 진입(직접 URL·C-Cube 진입)은 send-result를 한 건도 못 보내는 'skipped'로 구분해 성공으로 잘못 표시하지 않습니다.

편집기 앞단인 자막 작업 목록(SubtitleListPage)은 전 메뉴 공통 컴포넌트로 정리됐습니다. ID/명 2단 셀은 IdNameCell, 행 [검수] CTA는 TableActionButton, 로딩은 TableLoading, 0건 화면은 ListEmptyState의 3-way 분기를 쓰는데, 자막은 자막언어·CC자막 필터가 공통 SearchData 밖의 로컬 상태라 store.hasActiveFilters || subtitleLang !== LANG_ALL || ccFilter !== CC_ALL로 "필터 결과 없음" 판정을 보강합니다. 검색줄 우측에는 Flipbook ST-001 #10 「현재 설정 엔진 / [엔진변경]」이 신설되어(AI자막#3 조회·#4 변경) 현재 엔진명을 라벨로 보여주고 [엔진변경] 클릭 시 드롭다운 팝업으로 전환합니다 — 공용 헤더에 tail 슬롯이 없어 얼굴인식 [배역 인식] 버튼 선례를 따라 검색줄에 배치한 의도된 GUI 편차입니다. 조회기간 프리셋·달력 팝오버·일괄액션 활성 판정도 로컬 복제본을 지우고 shared/ 단일 구현을 참조합니다. 컬럼은 §8 grow 관용구로 재선언되면서 구 코드의 result(결과) 합본 240px 컬럼이 1055 와이어 잔재로 판정돼 다른 메뉴와 동일하게 상태(120)+액션(84) 두 컬럼으로 분리됐고, 긴급 84→65·장르 162→154·입수일시 140→120으로 폭이 교정됐습니다. 우측 상세패널도 공통 PanelInfoTable·GenrePath·UrgentBadge·PanelActionButton으로 바뀌면서 작업이력의 엔진 버전 항목이 제거됐습니다(GUI 정본 삭제 + API 리스트 v1.0.3 폐기 표시 → v1.0.4 공통#3 응답 필드 실삭제).

편집기 쪽 이번 정합은 국소적입니다. 다중 바꾸기 팝업의 [적용]이 팝업을 닫지 않는 연속 적용형이라는 점이 GUI 정본 3컷 대조로 확정돼(적용 후 닫힘 상태가 어디에도 없음) 결과는 토스트+상태바로만 알리고 팝업은 X·백드롭으로만 닫도록 근거가 코드에 명문화됐습니다. 편집 리스트 테이블은 공통 DataTable 기본값(medium 헤더 36px)이 적용되지 않도록 --v-table-head-h: 48px를 핀으로 고정했고, 오류 일괄수정·선택해서 바꾸기 다이얼로그는 래퍼가 이미 radius 8을 주므로 헤더셀 radius를 0으로 꺼 이중 라운드를 없앴습니다. 자산 쪽에서는 src/assets/icons/subtitle-*.svg 10개가 참조 0곳으로 확인돼 삭제되고 스프라이트 심볼(i-subtitle-*) 단일 배달 경로로 일원화됐습니다.

2026-09 초 자막 API가 전량 실 배선으로 전환됐습니다(AI자막#1·#3·#4 + alfaeditor 5종 + WS 프록시) — 목록·메타·임시저장·최종저장·소켓까지 라이브 라우팅 대상입니다. 편집 진입 키도 이 축으로 재정합됐는데, 실 BE는 jobId≠contentId≠ccContentsId 셋이 전부 달라 fetchReviewTarget이 라우트의 jobId를 contentId로 먼저 환산한 뒤 그 응답에서 확정된 ccContentsId로 점유 확인(E7)을 호출합니다. 전체화면 미리보기의 인라인 서식(굵게·기울임·밑줄·취소선·색·글꼴)도 재작업됐습니다 — 종전엔 "VTT가 인라인 서식을 못 싣는다"고 보고 태그를 전부 지웠는데, 실제 렌더로 확인한 결과 <b><i><u>는 WebVTT 표준 큐 태그라 그대로 통과하고 취소선·색·글꼴도 <c.클래스> + ::cue(.클래스)로 표현할 수 있어, 서식을 버리지 않고 subtitleVtt.ts가 트랙에 실제 쓰인 값만 모아 <style>을 런타임 생성합니다 — <font color>/face는 업로드 파일에서 온 사용자 데이터라 CSS 규칙 탈출을 막도록 값을 화이트리스트(hex/영문 색상명, 안전 문자)로 제한합니다. 이탈 가드는 페이지 컴포넌트에 섞여 있던 것을 useSubtitleLeaveGuard 단일 컴포저블로 뽑아냈고, 파형 리전 색상 판정도 waveformBarColors.ts로 분리해 3구간 색·선택/생성 상태를 순수 함수로 테스트합니다.

설계 포인트 — 대량 트랙 성능
700줄 이상 트랙에서 편집 1회마다 reactive 배열 deep watch가 CPU를 크게 점유하는 문제를, in-place 편집은 linesRevision 카운터로 얕게 트리거하고 삭제/삽입은 raw 배열에서 renumber 후 배열 참조를 1회만 재할당(reactive write n+1 → 1)하는 방식으로 해결했습니다. 또한 문자키 단축키는 e.key 대신 물리 키코드 e.code로 판정해 한국어 IME 상태에서도 동작합니다.

2026-09-11~17 범위에서는 진입·편집·저장 세 축이 함께 갱신됐습니다. 진입 등록 — VAMS BE가 구 흐름(편집기 URL 발급)에서만 POST /alti/content(API0001)로 콘텐츠를 등록하고 AI자막#1 진입은 등록을 부르지 않아 미등록 콘텐츠가 생기는 것이 실측 확인되어(E1 진단 400), REGISTER_ON_ENTRY 플래그로 편집 진입마다 FE가 직접 등록하도록 바뀌었습니다(덮어쓰기라 중복 무해). 등록 실패는 이후 연동 통보 본문이 전부 null로 나가는 조용한 데이터 사고로 이어질 수 있어 contentRegisterFailed로 표면화합니다. 편집 단축키 — Ctrl+C/Ctrl+V로 선택 줄을 다음 번호에 팝업 없이 복사·삽입할 수 있고, Ctrl+X "컬럼 붙여넣기" 팝업(Flipbook 11038:1117)이 신설되어 임시 겹침 붙여넣기 구현을 대체했습니다(무변화 붙여넣기는 no-op, 팝업 포커스 중 단일 키 차단). dirty 판정 — 실행취소로 라인을 모두 원상복구하면 isDirty와 검수(R) 상태 전이가 함께 풀리도록, 마지막 저장 스냅샷이 아니라 진입 시 clean 스냅샷과의 내용 비교로 재정의됐습니다. 그 밖에 콘텐츠ID/시리즈ID 표시축이 다른 12개 메뉴와 같은 externalContentId/externalSeriesId로 통일됐고, 상태 배지는 조회축 7칩과 분리된 10종 표시축(toBadgeState)을 그대로 보여줍니다.

src/features/subtitle/edit/composables/useSubtitleTransform.ts — KT 포맷 변환 순수함수 (서식 태그 대응 lookahead)
/**
 * applyKtFormatToLines: 각 라인 텍스트의 문장 끝 마침표·느낌표 일괄 제거.
 * 와이어 ST-007 §2 변환 규칙. 비가역 — history push 없음(아키 §4.4 정책).
 *
 * "문장 끝" = 뒤따르는 서식 닫힘태그(</b> 등)·<br>·공백을 건너뛴 실질 문장의 끝.
 * 단순 `$`(물리적 줄 끝)로는 `<b>문장.</b>`의 마침표를 놓친다. lookahead 로
 * 닫는 태그·공백을 소비하지 않고 그 앞의 [.!]만 제거한다. 물음표(?)는 보존.
 */
export function applyKtFormatToLines(lines: SubtitleLine[]): {
  lines: SubtitleLine[]
  changedCount: number
} {
  // 다중행(m) 각 줄에서 실질 문장 끝의 연속 [.!] 제거. 뒤의 (공백|<br>|닫힘태그)*는 유지.
  const re = /[.!]+(?=(?:\s|<br\s*\/?>|<\/[^>]+>)*$)/gm
  let changedCount = 0
  const nextLines = lines.map((l) => {
    const next = l.text.replace(re, '')
    if (next === l.text) return { ...l }
    changedCount++
    return { ...l, text: next }
  })
  return { lines: nextLines, changedCount }
}
