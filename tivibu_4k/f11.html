EAS · MES 알림

MesService가 MesRepository의 WebSocket 푸시 메시지를 수신해 알림 팝업(MesNotificationPopup)과 시스템 알림 웹뷰(MesWebViewPopup)를 띄우고, 동시접속 제한·핑거프린트 갱신·강제 재시작 등 서버 명령을 처리합니다.

기능 개요

MES(Message Service)는 백엔드가 단말로 실시간 메시지를 밀어넣는 서버 푸시 채널입니다. MesService(@Singleton)가 부팅 초기화 단계에서 initialize()로 MesRepository.connect()를 호출하면, MesRepositoryImpl이 단말 접속 정보(getWsInfo())를 조회한 뒤 WebSocket을 열고(MesWebSocketManager), 터미널 등록(terminalregistreq)과 주기적 하트비트(terminalheartreq)로 세션을 유지합니다. 수신 메시지는 messageEvents(RxJava PublishSubject)로 흘러나와 MesService.handleMesMessage()가 메인 스레드에서 처리합니다.

handleMesMessage()는 메시지의 MsgServType·MsgShowType·MsgType 조합으로 분기합니다. 사용자 안내성 메시지는 MesNotificationPopup(텍스트 팝업) 또는 MesWebViewPopup(시스템 알림 웹뷰, StayTime만큼 자동 숨김)으로 표출하고, 시스템 알림(MsgServType=2)은 ServiceType에 따라 프로필 선택·디버그 로그 캡처 토글·패키지 정지/변경 후 재시작(restartApp)·핑거프린트 포맷 갱신을 수행합니다. 프로비전 명령(msgcode=9000)은 공장 초기화(factoryReset())로, 동시 시청 제한(msgcode=8000)은 고화질 채널 시청 중단(openChannelConcurrencyStop())으로 이어집니다.

웹뷰 알림의 액션 버튼은 handleNotificationAction()이 액션 타입 상수("0" 프로그램 상세 ~ "8" 캠페인 이동)로 분기해 VOD 상세·채널 튜닝·녹화 추가·홈 메뉴 진입 등으로 연결하고, 각 동작을 DataCollectRepository.logNotification()으로 집계합니다. 대기(standby) 상태에서 도착한 메시지는 storedMessage에 보관했다가 액티브 모드 복귀 시 runActiveMode()로 재처리합니다.

명칭 주의 — EAS는 긴급경보가 아닌 프로비전/인증 API
카드 설명의 "EAS"는 코드상 EasApi/EasRepository를 가리키는데, 이 저장소에서 Eas*는 EPG App Server의 프로비전·SSO 로그인·토큰 발급 API(provision, queryAccountList, mobileGetUserToken 등)이며 별도의 긴급경보(Emergency Alert) 구현은 없습니다. 인증/프로비전 흐름은 로그인·프로비저닝 문서를 참고하세요. 본 문서는 실시간 알림의 실구현인 MES를 중심으로 설명합니다.

시퀀스 다이어그램

sequenceDiagram autonumber participant SVC as MesService participant REPO as MesRepositoryImpl participant WS as MesWebSocketManager participant SRV as MES 서버 participant POP as MesNotification / WebViewPopup SVC->>REPO: initialize() then connect() REPO->>SRV: getWsInfo() (TERMINAL_ACCESS) SRV-->>REPO: MesWebSocketInfo REPO->>WS: connect(wsInfo) WS-->>REPO: onOpen REPO->>SRV: terminalregistreq + 하트비트 시작 loop 메시지 수신 SRV-->>WS: sendmessagereq (푸시) WS-->>REPO: onMessage REPO->>SRV: sendmessagersp (수신 응답) REPO-->>SVC: messageEvents.onNext(map) SVC->>SVC: handleMesMessage() 분기 alt 안내/시스템 알림 SVC->>POP: 팝업 또는 웹뷰 표출 else 명령(재시작/초기화/동시접속) SVC->>SVC: restartApp / factoryReset / 채널 중단 end end

흐름. MesService가 연결을 트리거하면 MesRepositoryImpl이 WebSocket 세션을 확립하고, 서버 푸시는 수신 응답을 보낸 뒤 messageEvents로 올라와 handleMesMessage()가 팝업 표출 또는 시스템 명령으로 분기합니다.

클래스 다이어그램

관계. MesService는 MesRepository의 messageEvents를 구독하는 표출/명령 처리 계층이고, MesRepositoryImpl은 MesWebSocketManager로 실제 WebSocket 세션을 관리하는 데이터 계층입니다.

핵심 코드

app/core/service/MesService.kt — 연결 + 메시지 이벤트 구독
fun initialize() {
    mesRepository.initialize()
        .andThen(mesRepository.connect())
        .toSingle { InitializerResult.SUCCESS }
        .onErrorReturnItem(InitializerResult.FAILURE)
        .subscribe().addTo(disposables)

    mesRepository.messageEvents
        .observeOn(AndroidSchedulers.mainThread())
        .subscribe { message -> handleMesMessage(message) }
        .let { disposables.add(it) }
}
app/core/service/MesService.kt — 메시지 타입 분기(표출 vs. 시스템 명령)
if (messageServType == "1") {
    if (msgShowType == "1") {                 // 상품 복원 등 안내
        showNotificationPopup(false, msgInfo = info)
    } else if (infoMsgType == "0" && !fileUrl.isNullOrBlank()) {
        showMesWebViewPopup(/* epgUrl, fileUrl, stayTime ... */)   // 시스템 알림 웹뷰
        startAutoHideTimer(scope, durationSec = stayTime) { /* deactivate */ }
    }
} else if (messageServType == "2") {          // 시스템 알림
    when (serviceType) {
        "1", "2" -> showNotificationPopup { restartApp() }  // 패키지 정지/변경
        "17"     -> startLogTimer(...)                      // 디버그 로그 캡처
        "26"     -> fingerPrintRepository.updateFormatData(...) // 핑거프린트 갱신
    }
} else if (msgType == "1") {
    if (msgCode == "9000") showNotificationPopup(true) { factoryReset() } // 프로비전
    else if (msgCode == "8000") mesRepository.openChannelConcurrencyStop() // 동시 시청 제한
}
data/repository/mes/MesRepositoryImpl.kt — 수신 메시지 → 응답 후 이벤트 방출
private fun handleIncomingMessage(message: String, baseMap: Map<*, *>) {
    val transactionId = baseMap["TransactionID"] as? String
    if (transactionId != null) {
        sendMessageResponse(transactionId)        // sendmessagersp 회신
            .subscribeOn(Schedulers.io()).subscribe().let { disposables.add(it) }
    }
    messageEventsSubject.onNext(baseMap)           // MesService 로 전달
}
