기능 개요

프로비저닝/로그인은 부팅 초기화 파이프라인의 한 단계(ActivityInitializer)인 ProvisionInitializer가 담당합니다. 첫 생성(isFirstCreated) 시 OTT 계정 전환 여부를 점검(checkOttAccountSwitch)한 뒤 tryLogin()으로 로그인 시도를 시작합니다. 플랫폼(IPTV / Tivibu Go / Smart TV OTT)과 게스트/계정 로그인 여부에 따라 guestLogin()·ottLogin() 등 경로가 분기됩니다.

실제 네트워크 호출은 EasRepository가 EasApi(Retrofit)로 수행합니다. 단말 프로비전(provision(provisionId, devMac, deviceId)), SSO 계정 조회·인증(queryAccountList), 토큰 발급 등을 통해 단말을 등록하고 사용자 세션을 확립합니다. CAS 인증 단말(isCasAuth)은 로그인을 생략하고 곧바로 FailSafe 모드로 동작합니다.

로그인 실패 또는 예외가 발생하면 onErrorReturn으로 InitializerResult.FAILURE_SAFE를 반환하고, FailSafe 모니터(FailSafeMonitorRepository)를 가동한 뒤 채널 목록을 FailSafe 파라미터로 초기화해 최소 기능으로 부팅을 이어갑니다. 사용자 입력이 필요한 경우 ProvisionPopup(프로비전 ID 입력 등)과 ProvisionErrorPopup(오류 안내)을 띄웁니다.

설계 포인트
인증을 "막느냐/통과시키느냐"의 이분법이 아니라, 실패해도 FailSafe 모드로 부팅을 완주시키는 폴백을 1차 시민으로 둡니다. 로그인 단계가 전체 부팅을 막지 않도록 RxJava 체인(onErrorReturn → flatMap)으로 결과를 다음 초기화로 전달합니다.

흐름. 부팅 초기화에서 ProvisionInitializer가 EAS 경로로 프로비전·로그인을 수행하고, 실패 시 FailSafe 모니터를 켜고 FailSafe 채널 초기화로 폴백하면서 결과를 다음 초기화로 넘깁니다.

관계. ProvisionInitializer는 초기화 인터페이스 구현체로, EasRepository→EasApi로 단말 등록·인증을 수행하고 실패 시 FailSafeMonitorRepository로 폴백하며 입력/오류 팝업을 띄웁니다.

핵심 코드

app/core/initializer/ProvisionInitializer.kt — 로그인 시도 + FailSafe 폴백
return if (isFirstCreated) {
    checkOttAccountSwitch()
    tryLogin()
        .onErrorReturn {
            Log.d(TAG, "initialize|onErrorReturn, failsafe mode")
            InitializerResult.FAILURE_SAFE
        }
        .flatMap { initResult ->
            if (initResult == InitializerResult.FAILURE_SAFE) {
                if (!failSafeMonitorRepository.isMonitorRunning()) {
                    failSafeMonitorRepository.startMonitor()
                }
                channelRepository.initialize(params = TTInitChannelListParams.FailSafe)
                    .map { initResult }
            } else {
                Single.just(initResult)
            }
        }
} else Single.just(InitializerResult.SUCCESS)
