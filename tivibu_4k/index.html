개요

이 프로젝트는 터키 통신사 Türk Telekom의 IPTV/OTT 브랜드인 Tivibu를 위한 Android 기반 TV 클라이언트 애플리케이션입니다. 4K STB(셋톱박스)를 비롯한 TV 단말에서 실행되는 런처(launcher) 형태의 앱으로, 라이브 TV 시청, VOD 재생, 채널 편성표(TV Guide), 녹화(nPVR), 구매·결제, 설정 등 IPTV/OTT 서비스의 핵심 기능을 한 곳에서 제공합니다. Confluence 기준 사업 프로젝트 코드는 C2001732 [BIZ] Turktelekom Android 4K Project이며, 기존 Linux+Web 기반 Tivibu 서비스를 Android STB+Launcher 형태로 전환하는 과제입니다.

역할 분담은 UI/GUI는 TTG, STB 하드웨어와 백엔드는 ZTE, Android 미들웨어와 런처(앱)는 Altimedia가 담당합니다. 본 저장소는 그중 Altimedia가 개발하는 런처/애플리케이션 영역입니다.

하나의 코드베이스에서 Gradle product flavor로 4개의 단말/배포 형태를 분기하여 빌드합니다. tivibuEv(IPTV STB 런처, applicationId tivibu.android.stb, 기본 flavor), tivibuGo(OTT 런처, tivibu.android.stb.ott), stvOtt(Smart TV용 OTT 앱, com.ttnet.tivibutv, 이 flavor에만 staging 빌드 타입 활성), zteAosp(ZTE AOSP 단말용, com.zte.aosp)입니다.

대상 플랫폼과 입력 모델
대상 플랫폼은 Android TV / Leanback 환경이며, 리모컨 키 입력 기반 포커스/클릭 처리를 전제로 설계되어 있습니다. 코딩 컨벤션상 클릭 리스너 대신 onKeyDown의 DCA key 및 KEY_OK를 사용해 동작을 추적하기 쉽게 만듭니다. minSdk 23, targetSdk 35, compileSdk 35이며, 매니페스트의 단일 진입 액티비티는 singleInstance 런치 모드로 동작합니다.

주요 기능

라이브 TV 시청
채널 튜닝과 실시간 방송 재생을 담당합니다. OSD, 미니 가이드, 채널 리스트, 5채널 보기 등 라이브 시청 화면 요소를 호스팅합니다.
TV 가이드(편성표)
홈 영역의 TV Guide에서 채널별 편성 정보를 탐색하고, 예약/리마인더와 연동된 시청 진입을 제공합니다.
VOD 재생
Media3/ExoPlayer 기반으로 VOD를 재생합니다. 플레이바, 해상도/자막/배속 선택, 썸네일 미리보기, 스타트오버 등을 지원합니다.
녹화(nPVR)
네트워크 녹화(nPVR) 도메인과 API를 통해 녹화 예약·재생 흐름을 제공합니다(NPvrApi, npvr repository).
구매·결제
상품 구매, 쿠폰, OTT 상품, 프로모션 처리를 지원합니다. PIN 팝업과 구매 완료 로딩 팝업, 중복 요청 방지 로직이 포함됩니다.
채널 필터·즐겨찾기·잠금
채널 필터(필터 아이콘 red dot 표시), 즐겨찾기 채널, 채널 잠금(Channel Lock)을 설정 화면에서 관리합니다.
PIP · 모자이크
라이브 화면 위에 PIP(Picture-in-Picture) 뷰와 모자이크(MosaicView) 채널 보기를 오버레이로 제공합니다.
핑거프린트 오버레이
콘텐츠 보호를 위한 핑거프린트(FingerPrintView, VMX CAS 연동 VmxFingerPrintView)를 라이브 재생 위에 표시합니다.
검색
콘텐츠 검색 도메인/API(SearchApi)를 제공하며, 검색 언어 처리 작업이 별도 스프린트 브랜치로 진행되었습니다.
로그인·프로비저닝
로그인 입력 화면과 프로비저닝(ProvisionPopup/ProvisionErrorPopup)을 통해 단말 등록·인증 흐름을 처리합니다.
EAS · MES 알림
긴급경보(EAS, EasApi)와 메시지 서비스(MES) 알림(MesNotificationPopup/MesWebViewPopup)을 처리합니다.
재생 품질 모니터링(Conviva)
Conviva SDK로 재생 품질을 모니터링합니다. 최근 스프린트에서 Conviva 상태 기반 로그 전송 로직이 다수 반영되었습니다.
설정 · 프로필
설정 화면과 프로필 도메인을 제공하며, OTA 업데이트 팝업·전역 에러 팝업·FailSafe 복구 팝업 등 시스템 운영 UI를 포함합니다.
멀티 단말 분기 빌드
tivibuEv/tivibuGo/stvOtt/zteAosp 4개 flavor를 단일 코드베이스에서 분기 빌드하며, 플랫폼 종속 구현은 flavor별로 주입합니다.

아키텍처 · 모듈 구조

멀티 모듈 구조이며, 의존성은 대체로 app → domain → core 방향으로 흐릅니다. 플랫폼 종속 구현(player, si, dependency/platform)은 인터페이스/추상화와 구현을 분리하여 flavor별로 주입합니다. Confluence 구조 문서 기준으로 data는 캐시·네트워크 통신, domain은 비즈니스 로직, si/player는 각 프로젝트가 구현해야 할 인터페이스 집합체(공통 모듈)와 그 구현체로 나뉩니다.

핵심 동작 흐름

부팅 · 초기화 시퀀스

  1. Application 진입TivibuApplication(@HiltAndroidApp)이 시작되어 Hilt DI 그래프를 구성하고 라이프사이클 관찰을 시작합니다.
  2. 단계별 초기화 파이프라인 실행RxJava 기반 InitializerList가 ApplicationInitializer → ActivityInitializer 순으로 초기화를 수행하고, AppStateManager가 InitializeState를 관리합니다.
  3. 부팅 화면 표시BootScreen/BootViewModel이 진행 카운트·다운로드 진행률·에러 코드를 관찰하며 스플래시·프로비저닝 진행을 표시합니다.
  4. 프로비저닝 / 로그인단말 등록·인증을 처리하고, 실패 시 ProvisionErrorPopup 또는 FailSafeInitializer/FailSafeRecoveryPopup으로 폴백 복구를 시도합니다.
  5. 홈 진입초기화가 완료되면 MainActivity가 홈(HomeScreen)을 띄워 메뉴·TV 가이드·라이브 TV 진입점을 제공합니다.

라이브 TV · 재생 흐름

  1. 채널 선택 / 튜닝리모컨 키 입력으로 채널을 선택하면 SI(impl-tt4k)가 채널/편성 정보를 제공하고 채널 튜닝을 시작합니다.
  2. 플레이어 구동PlayOrchestrator가 재생을 조율하고, player/impl-tt4k(ExoPlayer 코어 기반)가 스트림을 재생합니다.
  3. 오버레이 표시OSD·미니 가이드와 함께 콘텐츠 보호용 핑거프린트(VMX CAS 연동), 필요 시 PIP·모자이크 뷰를 라이브 화면 위에 오버레이합니다.
  4. 품질 모니터링Conviva SDK가 재생 세션 품질을 측정하고, Conviva 상태에 따라 로그를 전송합니다.

구매 · 결제 흐름

  1. 상품 선택VOD/OTT 상품 또는 쿠폰을 선택하면 구매 팝업(popup/purchase, popup/ott)이 열립니다.
  2. PIN 인증PasswordPopup에서 PIN을 입력합니다. 직접 키코드 입력을 지원하고, 중복 API 요청을 방지합니다.
  3. 구매 처리 · 완료구매 API 호출 후 로딩 팝업을 거쳐 완료 처리하며, 프로모션 데이터 잔존 등 예외 상황을 보정합니다.

빌드 · 실행

namespace는 com.tivibu.play이며, 빌드 시 반드시 product flavor(TivibuEv/TivibuGo/StvOtt/ZteAosp)와 빌드 타입(Debug/Release, stvOtt 한정 StagingDebug/StagingRelease)을 조합합니다.

# 클린
./gradlew clean

# flavor별 전체 빌드 (디버그 + 릴리스)
./gradlew assembleTivibuEv      # Tivibu Ev (IPTV)
./gradlew assembleTivibuGo      # Tivibu Go (OTT)
./gradlew assembleStvOtt        # Smart TV OTT
./gradlew assembleZteAosp       # ZTE AOSP

# 특정 변형만 빌드
./gradlew assembleTivibuEvDebug
./gradlew assembleTivibuEvRelease

# stvOtt 전용 staging 변형
./gradlew assembleStvOttStagingRelease

빌드 산출물(APK)은 app/build/outputs/ 아래에 생성되며, 파일명은 tt-play_<versionName>_<yyyyMMdd>_<buildType>.apk 형식입니다(app/build.gradle.kts의 outputFileName 규칙).

버전명/버전코드는 version.properties와 auto-version-*.gradle에서 자동 산출됩니다. 버전명 규칙은 a.b.c.d[.e] 형태로, a=클라이언트 타입(IPTV=4, STV=3), b=연도 끝 2자리, c=서브타입(EV=0, GO=1), d=스프린트 월, e=hotfix 옵션입니다(예. IPTV 26년 빌드 4.26.0.x, Smart TV 3.26.x.x).

릴리스 빌드는 ProGuard/R8 minify + resource shrink가 적용되며(proguard-rules.pro, proguard-retrofit.pro, proguard-okhttp3.pro, proguard-conviva.pro), keystore/tivibu.keystore.jks로 서명됩니다. 로컬 빌드에는 Android SDK와 local.properties(SDK 경로) 설정이 필요합니다.

CI 파이프라인
Bitbucket Pipelines는 alvrme/alpine-android:android-34-jdk17 이미지에서 ./gradlew clean 후 flavor별 assembleTivibuEv·assembleTivibuGo·assembleStvOtt·assembleZteAosp를 순차 실행(OOM 방지)하고, 산출 APK를 Tivibu_EV/Tivibu_GO/SmartTV_OTT 등 flavor별 폴더로 분류해 FTP(atlassian/ftp-deploy 파이프)로 배포합니다.
