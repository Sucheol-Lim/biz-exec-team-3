기능 개요

녹화는 단말 로컬이 아니라 네트워크 녹화(nPVR) 방식입니다. 라이브 TV(LiveTvScreen의 onRecord/onRecordCancel/onRecordRemove) 또는 편성표에서 녹화를 요청하면 LiveTvViewModel이 위임받은 RecordCoordinator를 통해 도메인 흐름으로 들어갑니다. RecordCoordinator는 데이터 가공과 네비게이션(예약 결과/에러 팝업)을 함께 담당합니다.

실제 서버 호출은 NPvrRepository 구현이 NPvrApi(Retrofit 인터페이스)를 통해 수행합니다. 단편 녹화 추가(addNPvr), 시리즈 녹화 추가(addNPvrSeries), 삭제(delNPvr/delNPvrSeries), 자동 삭제 갱신(updateNPvr), 녹화 제한 확인(limitNPvr), 잔여 녹화 시간(getNPvrTime), 녹화 상태 조회(checkNPvrStatus), 사용자/시리즈 녹화 목록(getUserNPvrList/getUserSeriesNPvrList)을 제공합니다.

녹화된 콘텐츠의 재생은 VOD 재생 파이프라인을 재사용합니다. PlayOrchestrator의 핸들러 딕셔너리에서 VodType.RECORD(와 VodType.PPV)가 NPVRPlayHandler에 매핑되어 녹화물을 일반 VOD처럼 재생합니다. 재생 상태 관찰(observePlayStates) 중 시청을 중단(STOPPED)하면 addBookmarkUseCase로 이어보기 북마크를 저장하고, 끝까지 시청(FINISHED)하면 completeBookmark()가 VodRepository.addComplete()로 시청 완료를 보고한 뒤 기존 북마크를 삭제(delBookmark)합니다. 재생 종료 처리(terminate())는 AppStateProvider의 포그라운드 상태(currentIsActive)를 먼저 확인해, 앱이 백그라운드로 내려간 상태에서는 플레이바 닫기·라이브 튜닝 등 종료 동작을 수행하지 않습니다.

설계 포인트
각 NPvrApi 메서드 주석에 서버 인터페이스 번호(예. 3.18.1. Addition of NPVR (Non-Series) Recording)가 명시되어 있어 Türk Telekom 백엔드 스펙과 1:1로 추적됩니다. 시리즈 녹화 추가 시 prevueCode를 의도적으로 생략하는 등 웹(QueryManager.js) 동작과 정합을 맞춘 흔적이 코드 주석에 남아 있습니다.

관계. RecordCoordinator가 도메인 NPvrRepository를 호출하고, 구현은 Retrofit NPvrApi로 서버에 도달합니다. 녹화물 재생은 PlayOrchestrator의 NPVRPlayHandler(VodType.RECORD/PPV)가 담당하며, 재생 완료 시 VodRepository로 시청 완료(addComplete)를 보고하고 북마크를 정리하며, 종료 처리(terminate()) 전에 AppStateProvider로 앱 포그라운드 여부를 확인합니다.

핵심 코드

data/remote/api/NPvrApi.kt — nPVR Retrofit 인터페이스(서버 스펙 번호 매핑)
interface NPvrApi {
    // 3.18.1. Addition of NPVR (Non-Series) Recording
    @GET(DataConfig.API_ADD_NPVR)
    fun addNPvr(
        @Query("channelcode") channelCode: String,
        @Query("seriesheadid") seriesHeadId: String,
        @Query("prevuecode") prevueCode: String,
    ): Single<BaseResponseDto>

    // 3.18.5. Addition of NPVR (Series) Recording
    @GET(DataConfig.API_ADD_NPVR_SERIES)
    fun addNPvrSeries(
        @Query("channelcode") channelCode: String,
        @Query("seriesheadid") seriesHeadId: String,
        // prevueCode 생략: Web QueryManager.js - addNPvrSeries 참조
        @Query("istotalseason") isTotalSeason: String? = "1",
    ): Single<BaseResponseDto>

    // 4.2.2. User Recording Restriction Notification Interface
    @GET(DataConfig.API_LIMIT_NPVR)
    fun limitNPvr(...): Single<NPvrLimitDto>
}
ui/play/handler/NPVRPlayHandler.kt — 재생 완료(FINISHED) 시 시청 완료 보고 + 북마크 정리
// observePlayStates(): PlayerState.FINISHED 분기에서 호출
private fun completeBookmark(playInfo: PlayInfo.Channel) {
    Timber.d("completeBookmark() addComplete")
    bookmarkDisposable?.dispose()
    bookmarkDisposable = vodRepository.addComplete(
        contentCode = playInfo.program.prevueCode,
        contentType = (playInfo.bookmarkType ?: DomainConfig.BookmarkType.TVOD).value,
        beginTime = playInfo.program.startTime.getTimeString("yyyy.MM.dd HH:mm:ss")
    )
        .flatMap {
            Timber.d("completeBookmark() delBookmark")
            vodRepository.delBookmark(DomainConfig.BookmarkType.TVOD.value, playInfo.program.prevueCode)
        }
        .subscribe(/* 성공/실패 모두 bookmarkDisposable 해제 */)
}

기존에는 FINISHED 시에도 addBookmark()(이어보기 북마크 저장)만 호출되어 시청 완료 보고(addComplete)가 누락되는 문제가 있었습니다. sprint/LS0626_release의 수정(VLTRANLAND-1897)으로 FINISHED 분기가 completeBookmark()로 교체되어, addComplete 호출 후 기존 북마크를 삭제합니다. 이를 위해 PlayOrchestrator가 RECORD/PPV 핸들러 생성 시 vodRepository를 추가로 주입합니다.

ui/play/handler/NPVRPlayHandler.kt — 백그라운드 전환 시 종료 동작 생략(terminate 가드)
private fun terminate() {
    val isAppActive = appStateProvider.currentIsActive
    Timber.d("terminate() in Main Dispatchers, isAppActive: $isAppActive")
    if (!isAppActive) {
        return
    }

    clear()

    CoroutineScope(Dispatchers.Main).launch { // player stop must be requested in MAIN Thread
        // Close ChannelPlayBarScreen
        navigator.hideChannelPlayBarScreen()
        /* TV Guide 표시 중이면 라이브 튜닝, 재생 중이면 vodAdapter.stop() */
    }
}

앱이 백그라운드로 전환되며 재생이 끝날 때 플레이바 화면이 닫히는 문제를 막기 위한 수정입니다. terminate()가 AppStateProvider.currentIsActive를 확인해 백그라운드 상태에서는 종료 처리를 건너뛰며, 이를 위해 PlayOrchestrator가 모든 재생 핸들러 생성 시 appStateProvider를 함께 주입합니다.
