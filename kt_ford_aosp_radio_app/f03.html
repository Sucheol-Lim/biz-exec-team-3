사업자 API 기반 스트림 URL 획득

MBC·SBS 채널은 채널의 API URL로 온에어 정보를 한 번 더 조회해 실제 재생 URL을 받아옵니다. SBS는 응답의 mediaurl이 암호화되어 있어 AES 복호화가 필요합니다.

기능 개요

MBC·SBS는 채널 데이터에 들어 있는 URL이 곧바로 재생 가능한 스트림이 아니라 "온에어 정보를 알려주는 API 엔드포인트"입니다. 따라서 RadioPlayerHelper.playChannel()이 채널명을 보고 MBC면 playMBCChannel(), SBS면 playSBSChannel()로 분기해, 재생 직전에 Retrofit으로 해당 API를 한 번 더 호출합니다.

MBC는 sminiplay.imbc.com의 응답(MbcChannel)에서 play_url 필드를 그대로 받아 HLS 재생 URL로 사용합니다. SBS는 apis.sbs.co.kr의 응답(SbsOnAir → onair.source.mediaurl)을 파싱하지만 mediaurl 값이 암호화되어 있어, Base64Decoder.Decrypt()로 복호화한 뒤에야 재생 가능한 URL이 됩니다. 두 호출 모두 비동기(enqueue)로 처리되고, 응답이 도착하면 playFromUri()로 MediaPlayer에 전달됩니다.

설계 포인트
Retrofit 인터페이스 RadioApiService는 고정 path 없이 @Url로 호출 URL을 동적 지정합니다. 채널마다 baseUrl(MBC/SBS)만 다르고 실제 경로는 MediaItem의 mediaUri가 그대로 들어가므로, 채널 추가 시 인터페이스 변경이 필요 없습니다.

흐름. 채널명으로 MBC/SBS를 구분해 사업자 API를 호출하고, MBC는 play_url을 그대로, SBS는 복호화 후 MediaPlayer로 넘깁니다.

핵심 코드

media/RadioPlayerHelper.java — 채널명 기반 분기
public void playChannel(MediaMetadataCompat metadata) {
    String name = metadata.getDescription().getMediaId();
    if (name != null) {
        if (name.contains("MBC"))      playMBCChannel(metadata);
        else if (name.contains("SBS")) playSBSChannel(metadata);
        else                           playOtherChannel(metadata);
    }
}
media/RadioPlayerHelper.java — MBC 온에어 API 호출
Call<MbcChannel> getData = service.getMbcChannelSSL(
        metadata.getDescription().getMediaUri().toString());
getData.enqueue(new Callback<MbcChannel>() {
    public void onResponse(Call<MbcChannel> call, Response<MbcChannel> response) {
        MbcChannel channel = response.body();
        String url = channel.getPlayUrl();      // play_url 그대로 재생
        playFromUri(metadata, Uri.parse(url));
    }
    public void onFailure(Call<MbcChannel> call, Throwable t) { }
});
