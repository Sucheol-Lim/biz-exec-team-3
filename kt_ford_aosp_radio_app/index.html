개요

이 프로젝트는 KT가 Ford 차량용으로 공급하는 AOSP 기반 모빌리티 인포테인먼트 단말에 탑재되는 라디오 앱입니다. 운전자·탑승자가 차량 화면에서 MBC·SBS·TBS·아리랑·불교방송(BBS)·극동방송(FEBC)·CTS·국악방송 등 국내 라디오 채널을 실시간으로 청취할 수 있도록 합니다. 앱 패키지명은 com.altimedia.automotive.kt.service.radio이며, 단말에 표시되는 이름은 한국어 로케일에서 라디오, 영문 로케일에서 Radio입니다.

대상 플랫폼은 Android 7.0(API 24, minSdk 24) 이상의 AOSP / Android Automotive 환경입니다(compileSdk / targetSdk 30). 단일 Activity가 차량 런처(com.kt.automotive.service.launcher)와 브로드캐스트로 연동되며, 런처가 보내는 앱 시작·정지·뒤로·종료, 다음/이전 채널, "지금 듣고 있는 채널" TTS 요청에 반응하고, 재생 상태를 다시 런처로 통지합니다.

차량용 멀티윈도우 환경을 고려해 다중 해상도와 세로(Portrait)·가로(Landscape) 방향을 모두 지원하며, 동일 레이아웃에 대해 해상도(dpi)별 스타일을 분기 적용하는 방식으로 개발되었습니다. Confluence 사양에 따르면 Aviator(1280×800)·Navigator/Nautilus/Corsair(2348×1080)·Expedition·Ranger·Bronco·Mustang 등 Ford 차종별 디스플레이 해상도를 지원 대상으로 합니다. KT Ford 향은 Freedom·PIP 모드는 사용하지 않고 시스템에서 half 사이즈로 고정된 split screen 모드를 사용합니다.

설계상의 핵심 특징

재생 코어는 MediaBrowserService + MediaSession 기반의 포그라운드 서비스로 구성되어, 화면(Activity)이 백그라운드로 가도 재생이 유지됩니다. 채널 목록은 서버 조회 없이 앱 내부에 12개 채널로 하드코딩되어 있으며(KBS는 판권 문제로 제외), MBC·SBS는 재생 직전 사업자 API를 한 번 더 호출해 실제 스트림 URL을 받아오고 그 외 채널은 HLS(.m3u8)를 직접 재생합니다.

주요 기능

국내 라디오 12개 채널 실시간 청취
MBC 표준 FM·FM4U, SBS 파워 FM·러브 FM, TBS FM·eFM, 아리랑 FM, BBS 불교방송, FEBC 극동방송, CTS 라디오·라디오 JOY, 국악방송을 제공합니다. 채널 목록은 ChannelListItems에 하드코딩되어 있습니다.
백그라운드 지속 재생
MediaBrowserServiceCompat + MediaSessionCompat 기반 포그라운드 서비스로 동작해, 화면을 닫거나 다른 앱으로 전환해도 라디오 재생이 끊기지 않고 유지됩니다.
사업자 API 기반 스트림 URL 획득
MBC·SBS는 채널의 API URL로 온에어 정보를 한 번 더 조회해 실제 재생 URL을 받아옵니다. SBS는 응답의 mediaurl이 암호화되어 있어 AES 복호화가 필요합니다.
SBS 스트림 AES 복호화
Base64Decoder가 assets/encryption.txt의 2줄(암호화된 키 + 시크릿)에서 세션키를 복원한 뒤 AES/ECB/PKCS5Padding으로 SBS 스트림 URL을 복호화합니다. 보안성 검사 대응으로 키 하드코딩이 제거되었습니다.
HLS 직접 재생
TBS·아리랑·BBS·FEBC·CTS·국악방송 등은 채널 데이터의 .m3u8 URL을 MediaPlayer로 그대로 재생합니다.
차량 런처 연동 (브로드캐스트)
RadioReceiver가 radio.play, kas.action.app.start, kas.action.app.clear를 수신해 서비스를 기동/제어합니다. 정지·뒤로·종료·셧다운 등 KT 런처 인터페이스(kas.action.app.*)에 대응합니다.
음성(TTS) "지금 듣고 있는 채널" 응답
런처의 radio.nowPlaying 요청을 받아 현재 재생 채널 정보를 kas.action.app.tts 인터페이스로 런처에 회신합니다(기가지니 음성 명령 시나리오).
다음/이전 채널 전환
skipToNext / skipToPrevious 세션 콜백과 radio.playNextChannel / radio.playPrevChannel 브로드캐스트로 채널을 순환 전환합니다.
오디오 포커스 관리
AudioManager / AudioFocusRequest로 오디오 포커스를 요청·감시합니다. 포커스 상실 시 mute/pause, 복귀 시 unmute로 회복하는 정책을 구현합니다.
마지막 청취 채널 복원
RadioPreferenceManager(SharedPreferences)가 마지막 청취 위치(LCW)를 저장·복원해, 재실행 시 직전에 듣던 채널로 이어집니다.
미디어 알림 / 포그라운드 유지
RadioNotification이 재생 상태에 따라 미디어 알림을 갱신해 포그라운드 서비스 상태를 유지합니다.
적응형 멀티윈도우 UI
해상도별·세로/가로 방향별 레이아웃·드로어블 리소스를 분기하고, half/full split screen 멀티윈도우 환경에 맞춰 화면을 구성합니다. 구성 변경 시 Fragment 재생성과 화면 방향 보정을 처리합니다.
주·야간 테마
drawable-night / values-night 리소스 분기로 단말 uiMode(주간·야간)에 따라 테마가 전환됩니다.
다국어 리소스 (한/영)
기본(한국어) 문자열과 values-en-rUS 영문 리소스를 제공해 로케일에 따라 앱 이름·문구가 전환됩니다(v1.0.7에서 영문 리소스 추가).

핵심 동작 흐름

1) 런처 명령으로 라디오 재생 시작

  1. 브로드캐스트 수신런처가 radio.play(또는 kas.action.app.start)를 보내면 RadioReceiver가 수신합니다. radio.play의 extras에 metadata(예: {"Channel":"SBS 파워 FM"})가 있으면 채널명을 파싱해 인텐트에 담습니다.
  2. 포그라운드 서비스 기동startForegroundService()로 RadioBrowserService를 시작합니다(Android O 이상). 서비스는 MediaSession·RadioPlayerHelper·RadioNotification을 초기화합니다.
  3. 채널 결정 및 세션 콜백 호출지정된 채널(또는 마지막 청취 채널 LCW)을 선택해 MediaMetadata를 구성하고 RadioSessionCallback.onPlay()를 통해 RadioPlayerHelper.playChannel()을 호출합니다.
  4. 채널 유형별 스트림 획득채널명이 MBC면 imbc 온에어 API로 play_url(HLS)을 받아오고, SBS면 SBS API 응답의 mediaurl을 Base64Decoder로 AES 복호화합니다. 그 외 채널은 데이터에 있는 .m3u8 URL을 그대로 사용합니다.
  5. 재생 및 알림 갱신오디오 포커스를 획득한 뒤 MediaPlayer로 스트림을 재생하고, RadioNotification이 알림을 갱신해 포그라운드 상태를 유지합니다. 재생 상태(playType)는 런처로 통지됩니다.

2) "지금 듣고 있는 채널" 음성(TTS) 응답

  1. 조회 요청 수신기가지니 음성 명령이 들어오면 런처가 radio.nowPlaying 브로드캐스트를 보내고, 서비스가 등록한 인텐트 필터가 이를 수신합니다.
  2. 현재 재생 정보 구성현재 MediaMetadata에서 채널명을 읽어 안내 문구(text)를 만듭니다.
  3. 런처로 TTS 회신kas.action.app.tts 액션으로 안내 문구를 런처에 전달하면 런처가 음성으로 안내합니다.

3) 사용자 채널 목록 선택 및 전환

  1. 채널 목록 진입RadioFragment(메인 재생 화면)에서 목록 진입 시 Navigation으로 ChannelListFragment로 전환되고, RadioClient가 구독한 MediaItem 목록이 RecyclerView로 표시됩니다.
  2. 채널 선택사용자가 항목을 선택하면 해당 mediaId로 MediaController.transportControls.playFromMediaId()가 호출됩니다.
  3. 재생 전환 및 상태 반영서비스가 새 채널을 재생하고, 재생 상태·메타데이터 변경 콜백이 RadioViewModel로 반영되어 현재 채널 인덱스·재생 아이콘 등 UI가 갱신됩니다.

빌드 · 실행

표준 Android Gradle 프로젝트로, 프로젝트 루트의 Wrapper(Gradle 7.2)를 사용해 빌드합니다. 릴리스 빌드 타입은 버전 자동 증가 단위(major/minor/patch)에 따라 태스크가 분리되어 있습니다.

# 디버그 빌드 (versionNameSuffix "-debug", BuildConfig.DEBUG=true)
./gradlew assembleDebug

# 릴리스 빌드 — 버전 자동 증가 단위별 태스크 (version.properties가 갱신·저장됨)
./gradlew assembleRelease_patch   # patch 증가
./gradlew assembleRelease_minor   # minor 증가
./gradlew assembleRelease_major   # major 증가

# 클린 / 테스트
./gradlew clean
./gradlew test
./gradlew connectedAndroidTest

환경 설정·산출물 관련 사항입니다.

  • 버전 정보는 app/version.properties(VERSION_MAJOR/MINOR/PATCH, 현재 1.0.8)에 저장되며, versionCode는 major*100 + minor*10 + patch + 9900 규칙으로 계산됩니다(현재 10008).
  • release_* 및 debug 빌드 타입 모두 signingConfigs.release(app/keystore/release.keystore.jks, keyAlias kt.ford.radio)로 서명합니다. 키스토어 비밀번호는 app/build.gradle에 평문으로 기재되어 있습니다.
  • APK 파일명은 kt_ford_radio_v.<major>.<minor>.<patch>{-debug|-release}_<빌드날짜>.apk 형태로 생성됩니다.
  • SBS 채널 재생을 위해서는 app/src/main/assets/encryption.txt 키 파일이 있어야 정상 복호화됩니다.
  • minifyEnabled false이며, 모든 빌드 타입이 proguard-rules.pro를 참조하고 lint-baseline.xml 기준선을 사용합니다.
참고 — 분기 작업 흔적

원격에 develop-aaos, develop-aaos-exoplayer, kotlin_version 등의 브랜치가 존재해 ExoPlayer 전환 및 Kotlin 마이그레이션 시도가 별도 브랜치에서 진행된 흔적이 있습니다. 다만 분석 기준 develop 브랜치는 MediaPlayer 기반 + 전부 Java 구성이며, 다른 브랜치의 작업 내용은 미확인입니다(브랜치명에 근거한 추정).
