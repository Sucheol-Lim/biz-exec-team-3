기능 개요

이 기능은 두 화면으로 구성됩니다. 하나는 시스템 상태 화면(dashboardSystem)으로, RMS 서버 인프라 메트릭을 자체 차트로 그리는 대신 REACT_APP_RMS_GRAFANA_URL이 가리키는 Grafana(node-exporter) 대시보드를 iframe으로 임베드합니다. 컴포넌트 자체는 매우 얇아서, 메트릭 수집·시각화 책임을 Grafana에 위임하고 RMS UI는 메뉴 안에서 그 화면을 보여주는 역할만 합니다.

다른 하나는 Quick Operation 화면입니다. 라우트 진입점은 quickOperationMain으로, IBC 타깃(modulePermissions.anomalyDetect)에서는 이상 감지 화면(anomalyDetect)을, 그 외 타깃에서는 기존 quickOperation(현재 component/ 하위로 이동)을 렌더합니다. URL 파라미터 detectId가 있으면 해당 단말 이름으로 검색을 프리필합니다. 운영자가 단말 목록에서 여러 행을 체크해 선택(selectedRows)한 뒤 전원/제어 명령을 내리면, DevicesApiManager.commandDevices()가 선택 단말 ID 배열과 명령 코드를 묶어 /api/v1/multi-device-commands/devices로 POST 합니다. 메시지 명령은 제목·본문 외에 표시 위치(position) 필드를, 잠금(LOCK) 명령은 잠금 사유(lockScreenReason) 필드를 함께 보낼 수 있습니다. 잠금 사유는 공통 컴포넌트 LockReasonRadioGroup에서 Illegal·Unactive·Suspended·IP Range·Model·ETC 중 선택하며, XLSmart 타깃에서는 Illegal 항목이 제외됩니다. 명령 진행 상태와 배포 현황은 getQuickOperationStatus·getQuickOperationDistribution로 폴링하며, 내가 보낸 명령 이력은 MyCommandHistoryModal로 확인합니다. 모달 관리(최소화·복원)는 useTask 컨텍스트가 담당합니다.

단말 연결 선행 조건
Quick Operation에서 일부 명령은 단말이 CONNECTED 상태일 때만 의미가 있습니다. 화면은 단말 섹션 상태를 확인해 연결되지 않은 경우 createDeviceConnection으로 connection을 먼저 시도한 뒤 명령을 전송하는 흐름을 가집니다.

시퀀스 다이어그램

sequenceDiagram autonumber participant OP as 운영자 (Browser) participant QO as component/quickOperation.tsx participant DM as DevicesApiManager (_api/Devices) participant BE as RMS BE 서버 participant DEV as 대상 단말들 OP->>QO: 단말 목록 조회 QO->>DM: getQuickOperationList(page, size, search) DM->>BE: GET /quick/operation BE-->>QO: 단말 목록 OP->>QO: 여러 단말 체크 (selectedRows) OP->>QO: 명령 실행 (예: REBOOT) QO->>DM: commandDevices(ids, command) DM->>BE: POST /multi-device-commands/devices BE->>DEV: 명령 전파 loop 진행 상태 폴링 QO->>DM: getQuickOperationStatus() DM->>BE: GET 상태 BE-->>QO: currSectionStatus / 진행률 end OP->>QO: My Command History 열기 QO->>QO: MyCommandHistoryModal 표시

흐름. 단말 목록을 받아 여러 행을 선택하고 명령을 실행하면 commandDevices가 ID 배열·명령을 묶어 일괄 POST 합니다. 진행 상태는 주기적으로 폴링하고 이력은 모달로 확인합니다. (시스템 모니터링은 Grafana iframe 임베드로 별도 호출 없음.)

클래스 다이어그램

classDiagram class MonitoringDashboardSystem { +render() iframe(GRAFANA_URL) } class QuickOperationMain { +render() 타깃별 분기 } class AnomalyDetect { -detectId 검색 프리필 } class QuickOperation { -selectedRows -openMyCommandHistory +updateQuickOperationHeader() +handleSort(id, sort) +handleFilter(id, list) } class DevicesApiManager { +getQuickOperationList(cb, page, size, search) +getQuickOperationStatus(cb) +getQuickOperationDistribution(cb, type) +commandDevices(CommandType) +createDeviceConnection(cb, id) } class TaskContext { +openModal(ModalProps) +minimize(ModalProps) +handleRestore(idx) } class MyCommandHistoryModal { +open +setOpen() } QuickOperationMain --> QuickOperation : 기본 타깃 렌더 QuickOperationMain --> AnomalyDetect : IBC(anomalyDetect 권한) QuickOperation --> DevicesApiManager : 명령/상태 호출 QuickOperation --> TaskContext : useTask 모달 관리 QuickOperation o-- MyCommandHistoryModal : 이력 모달

관계. 라우트 진입점 QuickOperationMain이 타깃 권한에 따라 QuickOperation 또는 AnomalyDetect를 렌더하고, QuickOperation이 DevicesApiManager로 일괄 명령과 상태 폴링을 수행하며, useTask(TaskContext)로 모달 생명주기를 관리합니다. 시스템 화면은 Grafana iframe만 렌더하는 독립 컴포넌트입니다.

핵심 코드

pages/monitoring/dashboardSystem.tsx — Grafana 대시보드 iframe 임베드
<iframe
  title="dashboard-system"
  src={process.env.REACT_APP_RMS_GRAFANA_URL}
  style={{ display: 'block', border: 'none', width: '100%', height: '80vh' }}
  frameBorder={0}
/>
_api/Devices.tsx — 선택 단말에 명령을 묶어 일괄 전송
commandDevices: ({ callback, ids, command, packageIds, subject, message, position, ..., lockScreenReason }: CommandType) => {
  const data = {
    ids,
    command,
    ...(packageIds && packageIds.length > 0 ? { packageIds } : {}),
    ...(message != null && message !== '' ? { message } : {}),
    ...(position != null && position !== '' ? { position } : {}),
    ...(lockScreenReason != null && lockScreenReason !== '' ? { lockScreenReason } : {})
    // ...type / autoClose / screenSize / firmwareId / imageUrl / url 등 조건부 병합
  };
  request('post', `/api/v1/multi-device-commands/devices`, callback, data);
}
