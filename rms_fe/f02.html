시스템 모니터링 · Quick Operation

dashboardSystem이 Grafana(node-exporter) 대시보드를 iframe으로 임베드해 RMS 서버 메트릭을 보여주고, quickOperation은 여러 단말을 선택해 commandDevices로 명령을 일괄 적용합니다. IBC 타깃에서는 같은 메뉴가 이상 감지 기반 AI Quick Operation(anomalyDetect/)으로 분기해 이슈별 추천 조치를 발송·중지합니다.

기능 개요

이 기능은 두 화면으로 구성됩니다. 하나는 시스템 상태 화면(dashboardSystem)으로, RMS 서버 인프라 메트릭을 자체 차트로 그리는 대신 REACT_APP_RMS_GRAFANA_URL이 가리키는 Grafana(node-exporter) 대시보드를 iframe으로 임베드합니다. 컴포넌트 자체는 매우 얇아서, 메트릭 수집·시각화 책임을 Grafana에 위임하고 RMS UI는 메뉴 안에서 그 화면을 보여주는 역할만 합니다.

다른 하나는 Quick Operation 화면입니다. 라우트 진입점은 quickOperationMain으로, IBC 타깃(modulePermissions.anomalyDetect)에서는 AI Quick Operation(이상 감지) 화면을, 그 외 타깃에서는 기존 quickOperation(component/ 하위)을 렌더합니다. 이상 감지 화면은 아래에서 따로 다루고, 기존 quickOperation 화면은 종전 흐름을 유지합니다. 운영자가 단말 목록에서 여러 행을 체크해 선택(selectedRows)한 뒤 전원/제어 명령을 내리면, DevicesApiManager.commandDevices()가 선택 단말 ID 배열과 명령 코드를 묶어 /api/v1/multi-device-commands/devices로 POST 합니다. 메시지 명령은 제목·본문 외에 표시 위치(position) 필드를, 잠금(LOCK) 명령은 잠금 사유(lockScreenReason) 필드를 함께 보낼 수 있습니다. 잠금 사유는 공통 컴포넌트 LockReasonRadioGroup에서 Illegal·Unactive·Suspended·IP Range·Model·ETC 중 선택하며, XLSmart 타깃에서는 Illegal 항목이 제외됩니다. 명령 진행 상태와 배포 현황은 getQuickOperationStatus·getQuickOperationDistribution로 폴링하며, 내가 보낸 명령 이력은 MyCommandHistoryModal로 확인합니다. 모달 관리(최소화·복원)는 useTask 컨텍스트가 담당하며, IBC 타깃(modulePermissions.chatbot)에서는 TaskContext의 openDeviceDetailModal/closeDeviceDetailModal/minimize가 ChatContext.sendToChatbot으로 DEVICE_MODAL_STATUS(OPEN/CLOSE) 이벤트를 보내 챗봇과 디바이스 모달 상태를 공유합니다. 단말 행 클릭 시의 재연결 대기도 화면에서 DEVICE_CONNECTION_TIME_LEFT만큼 로딩을 걸던 방식에서, 명령 직후 isCommandSent: true로 상세 모달을 먼저 열고 모달 본체(detailWrapper)가 폴링을 이어받는 방식으로 바뀌었습니다.

IBC 타깃의 AI Quick Operation(이상 감지)은 이번 변경의 핵심입니다. 단일 파일(component/anomalyDetect.tsx)이던 화면이 anomalyDetect/ 디렉토리 모듈로 재편되어, 진입점 index.tsx가 All/CPU/Memory/Network/Crash 탭과 상단 헤더를, TopRecurringIssues가 반복 이슈 Top 3를, IssueList+AnomalyAccordionList가 이슈 목록 아코디언을 담당합니다. 탭 키는 typeKeyMap(TU_CPU·TU_MEMORY·TU_NETWORK·TU_APP_CRASH)으로 서버의 thresholdType과 매핑되며, 탭별 건수는 목록 응답의 allCount·tabCounts에서 실제 값으로 채워집니다. 헤더의 AI Analyze 버튼은 dispathAnomalyDetections()(POST /api/v1/anomaly-detections/dispatch)로 분석을 요청한 뒤 getAnomalyDetectionsRunsLastest()(GET /api/v1/anomaly-detections/runs/latest)를 5초 주기로 폴링합니다. 상태가 ENQUEUED/ANALYZING인 동안 버튼 배경에 그라디언트 애니메이션이 돌고, 분석이 끝나면 refreshKey를 올려 TopRecurringIssues·IssueList를 key 교체로 리마운트하고 getQuickOperationIssuesStatus()(/api/v1/quick-operation-issues/stats)로 최신 갱신 시각을 다시 읽습니다. 위젯 상세 팝업에서 넘어올 때 붙는 ?deviceId= 딥링크는 IssueSearch에 자동 입력되고 목록의 첫 이슈가 자동으로 펼쳐지며, Refresh를 누르면 isDeepLinkActive가 꺼져 딥링크 필터가 해제됩니다.

이슈 아코디언은 한 건의 이슈를 타임라인으로 풀어 보여줍니다. Detected(최초/최종 탐지 시각, 그룹이면 대상 대수) → AI Cause(aiCause) → Recommended Action(recommendations[0].message) 순으로 쌓이고, 상태 칩은 issueStatus가 UNRESOLVED인지에 따라 Unresolved/In Progress로 표시됩니다. Unresolved 상태에서는 그룹 이슈(deviceCount > 1)면 Apply to N devices와 Select Devices & Apply 두 버튼이, 단일 단말이면 Send Command 버튼 하나가 뜹니다. 어느 쪽이든 확인 모달 SendCommandModal을 거쳐 sendCommandAiQuickOperation(issueId, [recommendationCode], deviceIds?)(POST /api/v1/quick-operation-issues/{id}/commands)로 명령이 나가고, SelectDevicesApplyModal에서 고른 단말만 deviceIds로 실려 부분 적용이 됩니다. In Progress + 그룹 이슈에는 Result · Group Monitoring 행이 추가되어 회복 건수/적용 건수 진행률(LinearProgress), Pause·Resume(pauseCommand/resumeCommand), Stop(stopCommand + StopCommandModal 확인), View Devices 버튼을 제공하며, 아코디언이 펼쳐져 있는 동안 getAiQuickOperationDetail(id)를 5초 주기로 재조회해 수치를 갱신합니다. 아코디언을 펼치는 순간에는 챗봇 권한이 있는 사이트에 한해 sendToChatbot으로 ISSUE_INFO 이벤트가 전달됩니다.

대상 단말 모달 두 개는 같은 getAiQuickOperationDevices(issueId, …)(GET /api/v1/quick-operation-issues/{id}/devices)를 씁니다. SelectDevicesApplyModal은 체크박스로 적용 대상을 고르고(선택 상태는 checkedIds Set으로 페이지 이동·검색과 무관하게 유지), ViewDevicesModal은 명령 발송/회복/대기·실패 건수를 InfoBox 세 개로 요약한 뒤 단말별 진행 상태를 보여주고 모달 안에서 바로 Pause/Stop을 실행합니다. 두 모달 모두 Device ID·Model·Device Group(·Issue State) 검색과 detectedAt 정렬을 지원합니다. 아코디언·모달에 흩어져 있던 인라인 요약 박스와 라벨-값 행은 anomalyDetect/components/InfoBox.tsx·InfoRow.tsx 공통 컴포넌트로 분리되었습니다. 내가 보낸 명령 이력 모달(MyCommandHistoryModal)은 from="AI" prop을 받으면 컬럼·검색 옵션·조회 API를 각각 getAiMyCommandHisotryColumns·getAiQuickOperationSearchOptionList·getAiQuickOperationHistory(/api/v1/quick-operation-issues/my-command-history)로 바꿔 이슈 기준 이력(Issue·Issue Date·Executed Date·Issue State)을 보여줍니다.

단말 연결 선행 조건
Quick Operation에서 일부 명령은 단말이 CONNECTED 상태일 때만 의미가 있습니다. 화면은 단말 섹션 상태를 확인해 연결되지 않은 경우 createDeviceConnection으로 connection을 먼저 시도한 뒤 명령을 전송하는 흐름을 가집니다. 다만 재연결 대기 책임이 옮겨져, 화면에서 utils/constants.ts의 DEVICE_CONNECTION_TIME_LEFT(30초)·DEVICE_CONNECTION_COUNTDOWN_INTERVAL(1초)로 로딩을 걸던 코드는 quickOperation·devices·lockDevices 등에서 모두 제거되었고(상수 자체는 utils/constants.ts에 남아 있으나 현재 참조처가 없습니다), 지금은 isCommandSent 플래그를 받은 상세 모달(detailWrapper)이 1초 간격·최대 20회 폴링으로 대신 처리합니다.

흐름(AI Quick Operation). 진입 시 이슈 통계와 직전 분석 실행 상태를 확인하고, 탭에 맞는 thresholdType으로 이슈 목록을 조회합니다. AI Analyze는 분석을 요청한 뒤 5초 주기로 실행 상태를 폴링하다가 끝나면 목록을 리마운트합니다. 아코디언에서 고른 이슈는 대상 단말 조회 → 확인 모달 → commands POST 순으로 명령이 나가고, 진행 중인 롤아웃은 pause/resume/stop으로 제어합니다. 기존(비 IBC) Quick Operation은 getQuickOperationList로 단말을 받아 commandDevices로 일괄 명령하고 getQuickOperationStatus로 진행률을 폴링하는 종전 흐름을 유지하며, 시스템 모니터링은 Grafana iframe 임베드로 별도 호출이 없습니다.

관계. 라우트 진입점 QuickOperationMain이 타깃 권한에 따라 QuickOperation 또는 AnomalyDetect를 렌더합니다. 이상 감지 쪽은 AnomalyDetect가 탭·AI 분석 상태를 쥐고 TopRecurringIssues·IssueList를 소유하며, 이슈 단위 조치(명령 발송·일시중지·중지·대상 단말 조회)는 AnomalyAccordionList와 세 모달이 DevicesApiManager의 quick-operation-issues 계열 API로 처리합니다. 기존 QuickOperation은 종전대로 일괄 명령·상태 폴링을 수행하고, IBC 타깃에서는 모달 상태와 이슈 정보가 ChatContext.sendToChatbot으로 챗봇에 통지됩니다. 시스템 화면은 Grafana iframe만 렌더하는 독립 컴포넌트입니다.

_api/Devices.tsx — 선택 단말에 명령을 묶어 일괄 전송
commandDevices: ({ callback, ids, command, packageIds, subject, message, position, ..., lockScreenReason }: CommandType) => {
  const data = {
    ids,
    command,
    ...(packageIds && packageIds.length > 0 ? { packageIds } : {}),
    ...(message != null && message !== '' ? { message } : {}),
    ...(position != null && position !== '' ? { position } : {}),
    ...(lockScreenReason != null && lockScreenReason !== '' ? { lockScreenReason } : {})
    // ...type / autoClose / screenSize / firmwareId / imageUrl / url 등 조건부 병합
  };
  request('post', `/api/v1/multi-device-commands/devices`, callback, data);
}

const startPolling = () => {
  if (pollingRef.current !== null) return;
  pollingRef.current = setInterval(() => {
    DevicesApiManager.getAnomalyDetectionsRunsLastest((result, data) => {
      if (result && (data?.status === 'ENQUEUED' || data?.status === 'ANALYZING')) return;
      setIsAnalizing(false);
      stopPolling();
      setRefreshKey((k) => k + 1);            // TopRecurringIssues·IssueList 리마운트
      updateQuickOperationHeader();
    });
  }, 5000);
};
