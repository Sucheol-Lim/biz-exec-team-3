단말(Device) 관리

기능 개요

단말 관리(Management)는 RMS 운영의 기반이 되는 영역입니다. managementDevices/devicelist가 DevicesApiManager.getList()(/api/v1/devices)로 단말 목록을 조회하고, deviceDetailInfo/deviceEdit가 getDetail·update(/api/v1/devices/:id/update)로 상세 조회와 편집을 처리합니다. 그룹은 groups/groupEdit가 getGroupList·changeGroup·moveDevices 등으로 단말을 그룹 단위로 묶어 운영하고, 단말 정책은 devicePolicy가 getPolicyList(/api/v1/device-policies)로 STB Policy를 다루며, 정책 목록에 재부팅 자동화(standbyRebootEnabled, Reboot Automation) 컬럼이 추가되고 검색 옵션이 management.searchOption.ts의 getDevicePolicySearchOptionList로 분리되어 임계치·자동 실행과 함께 재부팅 자동화 On/Off 검색을 지원합니다. 단말 관리 탭 컨테이너(managementDevices.tsx)에는 Locked Devices 탭이 추가되어 Device List · Locked Devices · Command History · (OBE/TTG 한정) Advance Search 구성이 되었고, 같은 탭을 다시 클릭하면 refreshKey를 증가시켜 하위 컴포넌트의 key를 바꿔 리마운트하는 방식으로 목록을 새로고침합니다. Locked Devices 탭(lockDevices.tsx)은 getLockedDeviceList가 lockScreenEnable: true 파라미터로 /api/v1/devices를 조회해 화면 잠금된 단말만 보여주고, 선택 단말 일괄 삭제(deleteBulk)와 잠금 단말 Excel 일괄 등록을 지원합니다. Device List와 마찬가지로 잠금 단말 목록도 등록일(createdAt) 내림차순이 기본 정렬로 지정되어 최근 등록 단말부터 표시됩니다. 단말 행을 클릭했을 때의 재연결 대기 처리는 목록 화면에서 걷어냈습니다. devices.tsx·lockDevices.tsx 모두 DEVICE_CONNECTION 명령을 보낸 뒤 30초 카운트다운과 getDetail 폴링을 돌리던 블록이 삭제되고, 대신 isCommandSent: true를 실은 모달 정보를 useTask().openDeviceDetailModal()(구 openModal)에 넘겨 상세 모달을 먼저 엽니다. 이후 폴링·연결 생성과 "다른 사용자가 연결 중" 안내는 모달 본체(pages/device/detailWrapper.tsx)가 담당하며, 조작 가능 여부도 호출부가 계산하던 isMine 대신 모달이 lastConnectUserId와 로그인 사용자를 비교한 isConnectedByMe로 판정합니다.

단말 목록의 컬럼 설정도 개편되었습니다. 컬럼 선택 모달(components/ColumnModal.tsx)이 항목을 하드코딩 배열로 들고 있던 방식을 버리고 getDevicesColumns()가 정의한 컬럼 중 isColumnModalItem이 붙은 것만 골라 목록을 만들며, 표시 순서는 현재 적용된 컬럼 순서를 먼저 따르고 미체크 항목을 뒤에 이어 붙입니다. 테이블은 ModalTable에서 react-dnd 기반 SortableModalTable로 교체되어 행을 끌어 순서를 바꿀 수 있고, isDefault 컬럼은 disabled로 내려가 dim 처리되어 해제·이동이 막힙니다. 저장된 컬럼 ID 배열은 devices.tsx의 buildOrderedColumns()가 읽어 체크박스·번호 같은 구조 컬럼을 앞에 두고 나머지를 저장 순서대로 재배열합니다(종전 updateChecked는 체크 여부만 반영했습니다). 컬럼 정의에서는 MAC 주소 컬럼이 등록일 뒤로 자리를 옮겼습니다.

단말 편집 화면(deviceEdit.tsx)의 그룹 지정 UI도 바뀌었습니다. 전체 그룹을 getGroupListAll로 한 번에 내려받아 긴 체크박스 표를 그리던 방식에서, getGroupList(0, 10000, name)로 검색어 기준 조회를 하고 상단에 검색창·새로고침 버튼을 두는 방식으로 정리되었습니다. 검색 결과가 바뀌어도 선택이 사라지지 않도록 화면에 보이는 selectedRows와 별개로 checkedGroups가 세션 동안의 선택 전체를 유지하며, 선택한 그룹은 components/SelectedChipsDropdown.tsx 칩 드롭다운에 모여 개별 삭제할 수 있습니다. 저장 시 groupIds도 checkedGroups에서 만들어집니다. 아울러 타깃 분기가 훅(hooks/useTarget.ts, 삭제됨)에서 utils/env.ts의 IS_KT/isTarget과 components/TargetGuard.tsx로 일원화되어, KT 전용 SAID 입력이나 TTG 전용 MAC 입력은 <TargetGuard only="KT"> 형태로 감싸 노출을 제어합니다. 그룹 상세 조회(_api/deviceGroupApi.ts의 fetchGroupDetail)는 응답 코드가 200000이 아니면 예외를 던져 실패를 실제 에러로 다루도록 보강되었습니다.

대량 등록은 Excel import로 이뤄집니다. deviceImportDialog가 downloadExcel('/api/v1/devices/download-upload-template', ...)로 템플릿을 내려주고, 운영자가 작성한 파일을 FormData에 담아 uploadDeviceExcelFileResult로 multipart/form-data 전송합니다. 이렇게 서버에 단말 정보가 등록되면, 단말 부팅 시 RMS Client가 해당 정보로 인증하고 목록/상세에 연동 단말로 나타납니다. 잠금 단말 등록 시에는 같은 다이얼로그가 type="lock"으로 열려 공용 컴포넌트 LockReasonRadioGroup에서 고른 잠금 사유를 lockScreenReason으로 FormData에 함께 첨부합니다. 단말·그룹 일괄 명령 API(commandDevices·commandDevicesAll·commandDeviceGroups 등)의 CommandType에는 잠금 사유(lockScreenReason) 필드가 있어, LOCK 명령 시 명령 모달에서 선택한 사유(Illegal·Unactive·Suspended·IP Range·Model·ETC, XLSmart 타깃은 Illegal 제외)가 함께 전송됩니다. 메시지 명령 입력(components/MessageInput.tsx)에서는 유튜브 타입(YOUTUBE)을 고르면 메시지 크기·표시 위치·자동 닫힘 항목이 화면에서 감춰지고 CommandModal의 전송 payload에서도 sizeMsg·position·autoClose가 빠지며, 영상(VIDEO) 타입 파일 업로드에는 권장 해상도 안내 문구(addSubDesc)가 덧붙습니다. 또한 연결 단말 실시간 제어 명령 controlCommand(/api/v1/device-connections/:id/commands/control)에 DELETE_BLUETOOTH 명령 타입이 추가되어, OBE 단말 상세의 블루투스 삭제 버튼(device/comp/bluetoothBox.tsx)이 삭제할 기기 address를 함께 전송합니다.

사이트별 식별자 필드
utils/env.ts의 ID_FIELD는 KT 타깃이면 deviceSiteId, 그 외에는 deviceId로 분기됩니다(useRegionalId). 같은 단말 화면도 KT에서는 지역 식별자 기준으로 표시·검색됩니다.

흐름. Excel 템플릿을 받아 작성·업로드하면 FormData로 일괄 등록되고, 단말이 부팅·인증하면 목록에 나타납니다. 목록 컬럼은 드래그로 정렬한 순서가 저장되어 buildOrderedColumns()로 복원되고, 편집 화면의 그룹 지정은 검색 기반 조회 + checkedGroups 누적 선택으로 이뤄져 update에 groupIds로 실려 저장됩니다.

_api/Devices.tsx — 단말 목록/상세/수정·제어 명령 엔드포인트
getList: (callback, page, size, searchItems?) => {
  request('get', `/api/v1/devices`, callback, data);
},
getLockedDeviceList: (callback, page, size, searchItems?) => {
  const data = { lockScreenEnable: true, page, size, ...searchItems };
  request('get', `/api/v1/devices`, callback, data);
},
getDetail: (callback, id) => {
  request('get', `/api/v1/devices/${id}`, callback);
},
update: (callback, data) => {
  request('post', `/api/v1/devices/${data.id}/update`, callback, data);
},
controlCommand: (callback, id, commandType, params?) => {
  const data = {
    commandType,
    ...(commandType === 'SET_VOLUME' && params?.volume && { volume: params.volume }),
    ...(commandType === 'INPUT_KEYEVENT' && params?.inputKeyEvent && { inputKeyEvent: params.inputKeyEvent }),
    ...(commandType === 'DELETE_BLUETOOTH' && params?.address && { address: params.address })  // OBE 블루투스 삭제
  };
  request('post', `/api/v1/device-connections/${id}/commands/control`, callback, data);
}

const buildOrderedColumns = (columns: DeviceColumn[], ids: string[]): DeviceColumn[] => {
  const structuralDefaults = columns.filter((col) => col.isDefault && !col.isColumnModalItem);
  const columnMap = new Map(columns.map((col) => [col.id, col]));
  const orderedModalItems = ids
    .map((id) => columnMap.get(id))
    .filter((col): col is DeviceColumn => Boolean(col))
    .map((col) => ({ ...col, checked: true }));

  return [...structuralDefaults, ...orderedModalItems];
};
