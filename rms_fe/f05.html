단말(Device) 관리

Management 메뉴가 단말 목록/상세/편집·그룹·단말 정책(STB Policy)·잠금 단말(Locked Devices)을 다루며, deviceImportDialog가 Excel 파일을 multipart/form-data로 업로드해 단말을 일괄 등록하고 DevicesApiManager가 그룹 단위 운영을 지원합니다.

기능 개요

단말 관리(Management)는 RMS 운영의 기반이 되는 영역입니다. managementDevices/devicelist가 DevicesApiManager.getList()(/api/v1/devices)로 단말 목록을 조회하고, deviceDetailInfo/deviceEdit가 getDetail·update(/api/v1/devices/:id/update)로 상세 조회와 편집을 처리합니다. 그룹은 groups/groupEdit가 getGroupList·changeGroup·moveDevices 등으로 단말을 그룹 단위로 묶어 운영하고, 단말 정책은 devicePolicy가 getPolicyList(/api/v1/device-policies)로 STB Policy를 다루며, 정책 목록에 재부팅 자동화(standbyRebootEnabled, Reboot Automation) 컬럼이 추가되고 검색 옵션이 management.searchOption.ts의 getDevicePolicySearchOptionList로 분리되어 임계치·자동 실행과 함께 재부팅 자동화 On/Off 검색을 지원합니다. 단말 관리 탭 컨테이너(managementDevices.tsx)에는 Locked Devices 탭이 추가되어 Device List · Locked Devices · Command History · (OBE/TTG 한정) Advance Search 구성이 되었고, 같은 탭을 다시 클릭하면 refreshKey를 증가시켜 하위 컴포넌트의 key를 바꿔 리마운트하는 방식으로 목록을 새로고침합니다. Locked Devices 탭(lockDevices.tsx)은 getLockedDeviceList가 lockScreenEnable: true 파라미터로 /api/v1/devices를 조회해 화면 잠금된 단말만 보여주고, 선택 단말 일괄 삭제(deleteBulk)와 잠금 단말 Excel 일괄 등록을 지원합니다. 여기에 잠금 해제가 붙어, roleLevel이 Level3이거나 userInfo.commands에 UNLOCK이 있는 계정에만 Unlock 아이콘 버튼이 노출되고, 누르면 types/devicePageList.ts의 UNLOCK 명령 정의로 공용 CommandModal을 열어 선택 단말(또는 검색 조건 전체)에 commandDevices·commandAllDevicesSearch로 해제 명령을 보냅니다. 잠금 단말 Excel도 일반 단말과 분리되어, 템플릿은 /api/v1/devices/lock-import/template, 업로드는 uploadLockDeviceExcelFileResult(POST /api/v1/devices/lock-import)를 씁니다. Device List와 마찬가지로 잠금 단말 목록도 등록일(createdAt) 내림차순이 기본 정렬로 지정되어 최근 등록 단말부터 표시됩니다. 단말 행을 클릭했을 때의 재연결 대기 처리는 목록 화면에서 걷어냈습니다. devices.tsx·lockDevices.tsx 모두 DEVICE_CONNECTION 명령을 보낸 뒤 30초 카운트다운과 getDetail 폴링을 돌리던 블록이 삭제되고, 대신 isCommandSent: true를 실은 모달 정보를 useTask().openDeviceDetailModal()(구 openModal)에 넘겨 상세 모달을 먼저 엽니다. 이후 폴링·연결 생성과 "다른 사용자가 연결 중" 안내는 모달 본체(pages/device/detailWrapper.tsx)가 담당하며, 조작 가능 여부도 호출부가 계산하던 isMine 대신 모달이 lastConnectUserId와 로그인 사용자를 비교한 isConnectedByMe로 판정합니다.

단말 목록의 컬럼 설정도 개편되었습니다. 컬럼 선택 모달(components/ColumnModal.tsx)이 항목을 하드코딩 배열로 들고 있던 방식을 버리고 getDevicesColumns()가 정의한 컬럼 중 isColumnModalItem이 붙은 것만 골라 목록을 만들며, 표시 순서는 현재 적용된 컬럼 순서를 먼저 따르고 미체크 항목을 뒤에 이어 붙입니다. 테이블은 ModalTable에서 react-dnd 기반 SortableModalTable로 교체되어 행을 끌어 순서를 바꿀 수 있고, isDefault 컬럼은 disabled로 내려가 dim 처리되어 해제·이동이 막힙니다. 저장된 컬럼 ID 배열은 devices.tsx의 buildOrderedColumns()가 읽어 체크박스·번호 같은 구조 컬럼을 앞에 두고 나머지를 저장 순서대로 재배열합니다(종전 updateChecked는 체크 여부만 반영했습니다). 컬럼 정의 자체도 다시 정리되어, deviceId/deviceSiteId를 hidden으로 갈라 두던 식별자 컬럼이 사이트 대표 식별자 DEV_MAIN_KEY 한 컬럼으로 합쳐지고 그 뒤에 MAC 주소 컬럼이 오며(구 serial 컬럼 자리), 등록일 컬럼은 기본 노출로 올라오고 세션 상태(status) 컬럼은 주석 처리되어 빠졌습니다. Edit 컬럼은 isDefault로 승격되어 컬럼 모달에서도 항상 체크·비활성 상태이며, 저장된 순서와 무관하게 buildOrderedColumns()가 언제나 마지막에 붙입니다. 같은 함수가 isDefault인 모달 컬럼은 정의 순서를, 나머지는 저장 순서를 따르도록 두 단계로 나뉘었고, 초기 상태도 checked 필터 결과가 아니라 buildOrderedColumns()를 거쳐 만들어집니다. 검색 옵션(getDevicesSearchOptionList)은 현재 화면의 컬럼 목록을 인자로 받아 같은 id의 컬럼 라벨로 옵션 라벨을 덮어써 테이블 헤더와 검색 이름이 어긋나지 않게 하고, MAC 검색 id는 mac에서 macAddress로, 등록일 검색·정렬 키는 importDate에서 createdAt으로 맞춰졌습니다.

단말 편집 화면(deviceEdit.tsx)의 그룹 지정 UI도 바뀌었습니다. 전체 그룹을 getGroupListAll로 한 번에 내려받아 긴 체크박스 표를 그리던 방식에서, getGroupList(0, 10000, name)로 검색어 기준 조회를 하고 상단에 검색창·새로고침 버튼을 두는 방식으로 정리되었습니다. 검색 결과가 바뀌어도 선택이 사라지지 않도록 화면에 보이는 selectedRows와 별개로 checkedGroups가 세션 동안의 선택 전체를 유지하며, 선택한 그룹은 components/SelectedChipsDropdown.tsx 칩 드롭다운에 모여 개별 삭제할 수 있습니다. 저장 시 groupIds도 checkedGroups에서 만들어집니다. 검색창은 별도 새로고침 아이콘 버튼 대신 Search 컴포넌트의 onReload·hasBorder 옵션으로 합쳐졌고, 그룹 표는 폭 505px·페이지당 4행의 테두리 있는 목록으로 바뀌었습니다. 입력 항목도 대표 식별자 체계에 맞춰 재구성되어, 상시 노출되던 Device ID 입력이 빠지고 대신 대표 키가 serial인 사이트(XLSmart)에서는 필수 S/N 입력이, 그 외에는 MAC 주소 입력이 필수로 표시됩니다. MAC 입력은 항상 노출되며 utils/common.tsx의 formatMAC()으로 두 자리마다 콜론을 넣어 자동 정형화하고, 대표 키가 macAddress인 사이트에서는 수정이 막힙니다. 저장 payload도 대표 키에 맞는 필드(serial/macAddress)만 담고, DevicesApiManager.update는 데이터에 섞여 있던 id를 별도 인자로 받도록 시그니처가 update(callback, id, data)로 바뀌었습니다. 아울러 타깃 분기가 훅(hooks/useTarget.ts, 삭제됨)에서 utils/env.ts의 IS_KT/isTarget·DEV_MAIN_KEY와 components/TargetGuard.tsx로 일원화되어, KT 전용 SAID 입력은 <TargetGuard only="KT"> 형태로 감싸 노출을 제어합니다. 그룹 상세 조회(_api/deviceGroupApi.ts의 fetchGroupDetail)는 응답 코드가 200000이 아니면 예외를 던져 실패를 실제 에러로 다루도록 보강되었습니다.

대량 등록은 Excel import로 이뤄집니다. deviceImportDialog가 downloadExcel('/api/v1/devices/download-upload-template', ...)로 템플릿을 내려주고, 운영자가 작성한 파일을 FormData에 담아 uploadDeviceExcelFileResult로 multipart/form-data 전송합니다. 이렇게 서버에 단말 정보가 등록되면, 단말 부팅 시 RMS Client가 해당 정보로 인증하고 목록/상세에 연동 단말로 나타납니다. 등록 결과에 실패 건이 있으면 뜨는 실패 목록 다운로드 버튼(list_fail.xlsx)도 개별 fetch+logger.debug 구현을 걷어내고 같은 downloadExcel()을 쓰도록 통일되었습니다. 잠금 단말 등록 시에는 같은 다이얼로그가 type="lock"으로 열려 공용 컴포넌트 LockReasonRadioGroup에서 고른 잠금 사유를 lockScreenReason으로 FormData에 함께 첨부하고, 템플릿 URL과 업로드 API도 잠금 전용(/api/v1/devices/lock-import/template·/api/v1/devices/lock-import)으로 갈라졌으며 완료 모달 제목도 등록 유형에 따라 분기됩니다. 단말·그룹 일괄 명령 API(commandDevices·commandDevicesAll·commandDeviceGroups 등)의 CommandType에는 잠금 사유(lockScreenReason) 필드가 있어, LOCK 명령 시 명령 모달에서 선택한 사유(Illegal·Unactive·Suspended·IP Range·Model·ETC, XLSmart 타깃은 Illegal 제외)가 함께 전송됩니다. 메시지 명령 입력(components/MessageInput.tsx)에서는 유튜브 타입(YOUTUBE)을 고르면 메시지 크기·표시 위치·자동 닫힘 항목이 화면에서 감춰지고 CommandModal의 전송 payload에서도 sizeMsg·position·autoClose가 빠지며, 영상(VIDEO) 타입 파일 업로드에는 권장 해상도 안내 문구(addSubDesc)가 덧붙습니다. 또한 연결 단말 실시간 제어 명령 controlCommand(/api/v1/device-connections/:id/commands/control)에 DELETE_BLUETOOTH 명령 타입이 추가되어, OBE 단말 상세의 블루투스 삭제 버튼(device/comp/bluetoothBox.tsx)이 삭제할 기기 address를 함께 전송합니다.

가장 최근 범위(~868b6160)는 XLSmart 운영 이관 과정에서 드러난 버그 픽스가 중심입니다. 단말 목록·잠금 단말(devices.tsx·lockDevices.tsx)이 클릭한 단말이 "내가 연결한 단말"인지 판정하던 기준이 getLastConnection 응답의 modifiedBy(계정명)와 sessionStorage.clientId 비교에서, sessionStorage.user를 파싱한 로그인 사용자 id와 응답의 agentId 비교로 바뀌었고, 목록 삭제 버튼의 노출 조건도 isPermission.isDelete에서 isPermission.isEdit으로(권한 모델 전체의 isDelete 폐지에 맞춰) 정리되었습니다. 단말 상세의 Command Transaction 탭(transactionTab.tsx) 검색 필터 목록은 실제 서버가 쓰는 최신 명령 코드(TURN_ON_RMS_APP/TURN_OFF_RMS_APP·DELETE_BLUETOOTH·TERMINAL_COMMAND·PACKET_CAPTURE·SURVEY·FIRM_OTA_UPDATE_STOP/PAUSE/RESUME 등)로 다시 맞춰지고, TTG 전용 HIDDEN_WIFI/SHOW_WIFI가 추가되었으며, 폐지된 SCREEN_OFF·WIPE·FCM_RESET·DIAGNOSTIC 등 검색해도 결과가 없던 항목은 제거되었습니다(과거 필터에 있던 코드가 실제 서버 이력과 맞지 않아 검색이 비어 보이던 문제를 바로잡음). 그룹 편집(deviceGroupEdit.tsx)의 대기 등록 단말 행·정렬 키도 deviceId/deviceSiteId 이중 처리 대신 DEV_MAIN_KEY.id 하나로 단순화되었고, 일괄 명령 이력(getCommandHistoryColumns)의 Target 컬럼은 대표 식별자가 serial/macAddress인 사이트에서 해당 단말 필드 배열(serials/macAddresses)을 보여주도록 고쳐져, XLSmart에서 Target 값이 비거나 엉뚱하게 나오던 문제가 해소되었습니다. 이 화면들을 포함해 컬럼 드롭다운(DevicesSearch.tsx 등)에 남아 있던 구 CustomDropDown도 이번 범위에서 공용 CustomSelect로 모두 교체되었습니다.

사이트별 식별자 필드
단말 화면의 식별자 분기는 두 값이 함께 쓰입니다. 목록 행에서 상세 모달로 넘길 값을 고르는 utils/env.ts의 ID_FIELD는 종전대로 KT면 deviceSiteId, 그 외에는 deviceId입니다. 여기에 컬럼·검색·편집 화면 전반을 관장하는 DEV_MAIN_KEY가 추가되어 KT는 deviceSiteId(SAID), XLSmart는 serial(S/N), 그 외에는 deviceId를 대표 식별자로 삼고 라벨까지 함께 내려줍니다. 덕분에 화면마다 hidden: IS_KT/hidden: IS_NOT_KT로 컬럼을 두 벌 정의하던 코드가 대부분 사라졌고, 목록 행 클릭 시에는 serial·macAddress도 함께 상세 모달로 전달됩니다.

const buildOrderedColumns = (columns: DeviceColumn[], ids: string[]): DeviceColumn[] => {
  // 체크박스/no 처럼 컬럼 모달에 노출되지 않는 고정 컬럼
  const structuralDefaults = columns.filter((col) => col.isDefault && !col.isColumnModalItem);
  const columnMap = new Map(columns.map((col) => [col.id, col]));
  // isDefault 모달 컬럼: 저장 순서와 무관하게 getDevicesColumns 정의 순서 유지
  const modalDefaults = columns
    .filter((col) => col.isDefault && col.isColumnModalItem && col.id !== 'edit')
    .map((col) => ({ ...col, checked: true }));
  // 나머지 모달 컬럼: 드래그로 저장한 순서 유지
  const nonDefaultModalItems = ids
    .map((id) => columnMap.get(id))
    .filter((col): col is DeviceColumn => Boolean(col) && !col!.isDefault)
    .map((col) => ({ ...col, checked: true }));
  // edit 컬럼은 항상 마지막
  const editColumn = columnMap.get('edit');

  return [...structuralDefaults, ...modalDefaults, ...nonDefaultModalItems, ...(editColumn ? [{ ...editColumn, checked: true }] : [])];
};
