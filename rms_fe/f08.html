관리자 · 역할(Role) 관리

administratorList/rolelist가 UserApiManager로 관리자 계정과 역할(Role) 기반 권한을 관리하고, mailreport 경로는 사이트 공통으로 AlertSetting(알림 설정)을 렌더합니다. 알림 탭은 단말 상태·OTT 버전(KT 전용)·네트워크 오프라인으로 구성됩니다.

기능 개요

관리자 영역은 RMS 운영자 계정과 권한 체계를 다룹니다. administratorList는 UserApiManager.getList()(/api/v1/users)로 관리자 목록을 조회하고, 등록/상세/수정은 create·getDetail·update로 처리합니다. 비밀번호 초기화(resetUserPassword)와 사용자명/이메일 중복 검사(checkUserName/checkEmail)도 같은 매니저에 있습니다. KT 타깃 대응으로 사용자 등록 신청 흐름이 추가되어, 로그인 화면의 User Registration 팝업(UserRegistrationModal)이 registLdap(/api/v1/auth/ldap/register/verify, KT User ID + LDAP Password 검증)과 submitLdap(/api/v1/auth/ldap/register/submit)으로 신청을 제출하고, 관리자는 getRegistrationList(/api/v1/registration-users)로 신청 목록을 조회해 approveUser(roleId 지정 승인)/rejectUser(거절)로 처리합니다.

역할(Role)은 rolelist가 getRoleList(/api/v1/roles)·createRole·updateRole로 관리합니다. 여기서 정의한 역할이 PermissionContext+PermissionGuard를 통해 화면 접근 권한으로 적용됩니다. 운영 이력 화면(operationHistory.tsx)은 라우트에서 분리되어, 현재 operationHistory 경로는 임시로 설문 설정 화면(SurveySetting)을 렌더하며 별도의 surveySetting(목록)·surveySetting/register(SurveyCreate) 경로도 추가되었습니다([XL Smart] survey setting, 메뉴 임시 처리). 알림 설정은 라우트 정의(MainRoutes.tsx)에서 mailreport 경로가 사이트 구분 없이 <AlertSetting />을 렌더하도록 통합되었고(기존 IS_KT ? AlertSetting : MailReport 분기 제거), 대신 탭 단에서 OTT 버전(OTT_VER) 탭만 IS_KT일 때 노출됩니다.

알림 설정 통합 + 네트워크 오프라인 탭 (XLSmart Alert setting 반영)
AlertSetting은 단말 상태(DeviceAlert)·OTT 버전(OttVersion, KT 전용)·네트워크 오프라인(NetworkOffline) 세 탭으로 구성됩니다. 네트워크 오프라인 알림은 모니터링 윈도우/오프라인 비율/수신자 목록을 관리하며, 편집은 networkoffline/:id 경로의 NetworkOfflineEdit 화면이 담당합니다.

시퀀스 다이어그램

sequenceDiagram autonumber participant OP as 운영자 (Browser) participant AL as administratorList / rolelist participant UM as UserApiManager (_api/User) participant BE as RMS BE 서버 participant PC as PermissionContext / Guard OP->>AL: 관리자 목록 조회 AL->>UM: getList(data) UM->>BE: GET /api/v1/users BE-->>AL: 관리자 목록 OP->>AL: 역할 생성/수정 AL->>UM: createRole / updateRole(data) UM->>BE: POST /api/v1/roles ... Note over PC: 정의된 Role 이 화면 접근 권한으로 적용 OP->>PC: 메뉴 진입 PC->>PC: PermissionGuard 권한 검사 Note over AL: mailreport 경로는 AlertSetting (OTT_VER 탭은 IS_KT 전용)

흐름. 관리자/역할을 UserApiManager로 CRUD 하고, 정의된 Role이 PermissionGuard를 통해 접근 통제에 반영됩니다. 메일 리포트 메뉴는 사이트 공통으로 알림 설정 화면을 렌더하고, OTT 버전 탭만 KT 전용으로 노출됩니다.

클래스 다이어그램

classDiagram class AdministratorList { +getList() } class RoleList { +getRoleList() +createRole() } class SurveySetting { +searchFinished() +refresh() } class UserRegistrationModal { +handleNext() +handleSubmit() } class AlertSetting { +DeviceAlert +OttVersion +NetworkOffline } class NetworkOfflineEdit { +render() } class UserApiManager { +getList(cb, data) +create(cb, data) +update(cb, data) +getRoleList(cb, page, size, name) +createRole(cb, data) +resetUserPassword(cb, userID) +getRegistrationList(cb, data) +approveUser(cb, id, roleId) +rejectUser(cb, id) +registLdap(cb, userId, password) +submitLdap(cb) } class MainRoutes { +mailreport: AlertSetting +networkoffline: NetworkOfflineEdit +operationHistory: SurveySetting +surveySetting: SurveyCreate } AdministratorList --> UserApiManager : 계정 CRUD RoleList --> UserApiManager : 역할 CRUD UserRegistrationModal --> UserApiManager : LDAP 검증·신청 제출 MainRoutes ..> AlertSetting : mailreport 경로 MainRoutes ..> NetworkOfflineEdit : networkoffline 편집 라우트 MainRoutes ..> SurveySetting : operationHistory·surveySetting 경로

관계. 계정·역할 화면과 KT 사용자 등록 팝업(UserRegistrationModal)이 UserApiManager를 공유하고, MainRoutes의 mailreport 경로는 항상 AlertSetting을 렌더합니다. AlertSetting 안에서 OTT 버전 탭은 IS_KT일 때만 노출되고, 네트워크 오프라인 알림 편집은 NetworkOfflineEdit로 이동합니다. operationHistory·surveySetting 경로는 현재 설문 설정 화면(SurveySetting/SurveyCreate)을 렌더합니다.

핵심 코드

_api/User.tsx — 관리자와 역할(Role) 엔드포인트
getList: (callback, data) => { request('get', '/api/v1/users', callback, data); },
create: (callback, data) => { request('post', '/api/v1/users', callback, data); },
// Roles
getRoleList: (callback, page, size, name?) => { request('get', `/api/v1/roles`, callback, data); },
createRole: (callback, data) => { request('post', '/api/v1/roles', callback, data); },
// KT 사용자 등록 신청 (registration-users)
getRegistrationList: (callback, data) => { request('get', '/api/v1/registration-users', callback, data); },
approveUser: (callback, id, roleId) => { request('post', `/api/v1/registration-users/${id}/approve`, callback, { roleId }); },
rejectUser: (callback, id) => { request('post', `/api/v1/registration-users/${id}/reject`, callback); },
// LDAP — KT User ID / LDAP Password 검증 후 신청 제출
registLdap: async (callback, userId, password) =>
  request('post', '/api/v1/auth/ldap/register/verify', callback, { ktUserId: userId, ldapPassword: password }),
submitLdap: async (callback) => request('post', '/api/v1/auth/ldap/register/submit', callback)
routes/MainRoutes.tsx — mailreport 경로의 AlertSetting 통합과 networkoffline 편집 라우트
{
  path: 'mailreport',
  children: [
    { path: '', element: <AlertSetting /> }   // 기존 IS_KT ? AlertSetting : MailReport 분기 제거
    // :id → MailEdit, ottVer/:id → OttAlertEdit ...
  ]
},
{
  path: 'networkoffline',
  children: [
    { path: ':id', element: <NetworkOfflineEdit /> }
  ]
},
{ path: 'operationHistory', element: <SurveySetting /> },   // 임시: 설문 설정 렌더
{
  path: 'surveySetting',
  children: [
    { path: '', element: <SurveySetting /> },
    { path: 'register', element: <SurveyCreate /> }
  ]
}
pages/administrator/alertSetting.tsx — OTT 버전 탭 KT 전용 + 네트워크 오프라인 탭
<Tab label={t('ms:alert_setting.tab.device_status')} value={'DEVICE_STATUS'} />
{IS_KT && <Tab label={t('ms:alert_setting.tab.ott_ver')} value={'OTT_VER'} />}
<Tab label={t('ms:alert_setting.tab.network_offline')} value={'NETWORK_OFFLINE'} />
// ...
{tabState === 'DEVICE_STATUS' && <DeviceAlert />}
{tabState === 'OTT_VER' && <OttVersion />}
{tabState === 'NETWORK_OFFLINE' && <NetworkOffline />}
