관리자 · 역할(Role) 관리

administratorList는 Admin List·Access History·Pending Approval(KT 전용) 탭으로 관리자 계정·접속 이력·등록 신청 승인을, rolelist는 역할(Role) 기반 권한을 UserApiManager로 관리합니다. 개인정보 마스킹은 MaskingProvider가 전역 상태로 들고 프로필 메뉴의 Data Masking 스위치로 전환하며, mailreport 경로는 사이트 공통으로 AlertSetting(단말 상태·OTT 버전(KT 전용)·네트워크 오프라인 탭)을 렌더합니다.

기능 개요

관리자 영역은 RMS 운영자 계정과 권한 체계를 다룹니다. administratorList는 Admin List·Access History·Pending Approval 세 탭을 가진 컨테이너로, Admin List 탭(administer/adminList.tsx)이 UserApiManager.getList()(/api/v1/users)로 관리자 목록(역할명·Role Level 포함)을 조회하고, 등록/상세/수정은 create·getDetail·update로 처리합니다. 관리자 목록에서는 전화번호(phoneNumber) 컬럼과 전화번호 검색 옵션이 제거되고 이름·Role Level·Division 컬럼 폭이 재조정되었습니다. 비밀번호 초기화(resetUserPassword)와 사용자명/이메일 중복 검사(checkUserName/checkEmail)도 같은 매니저에 있습니다. KT 사용자 등록 신청 흐름은 로그인 화면의 User Registration 팝업(UserRegistrationModal)이 registLdap(/api/v1/auth/ldap/register/verify, KT User ID + LDAP Password 검증)과 submitLdap(/api/v1/auth/ldap/register/submit)으로 신청을 제출하면, 관리자가 Pending Approval 탭(administer/pendingApprovalList.tsx, adminPermissions.pendingApprovalTab — KT 타깃 전용)에서 getRegistrationList(/api/v1/registration-users)로 신청 목록을 확인하고, 신청 행을 눌러 진입한 상세 화면(administer/adminDetail.tsx)에서 approveUser(roleId 지정 승인)/rejectUser(거절)로 처리합니다.

역할(Role)은 rolelist가 getRoleList(/api/v1/roles)·createRole·updateRole로 관리하며, 목록·상세에 Role Level(Level1~Level3)이 뱃지 형태로 표시되고 권한 편집 UI는 공용 컴포넌트(administer/components/permissionShared.tsx)로 정리되었습니다. 여기서 정의한 역할이 PermissionContext+PermissionGuard를 통해 화면 접근 권한으로 적용됩니다. 운영 이력 화면(operationHistory.tsx)은 라우트에 다시 연결되어 operationHistory 경로가 DevicesApiManager.getOperationHistory 기반의 운영 이력 화면을 렌더하고, 설문 설정은 surveySetting(목록)·surveySetting/register(SurveyCreate)에 상세/수정 경로 surveySetting/:id(SurveyDetail)가 추가되었습니다. 설문 상세 화면(administer/surveyDetail.tsx)은 대상 그룹명·설문 문항·응답 옵션 텍스트가 표시 영역을 넘으면 여러 줄로 줄바꿈(flexWrap·wordBreak, 고정 높이 대신 minHeight)해 보여주고, 응답 비율/건수 표기는 nowrap으로 한 줄을 유지하도록 다듬어졌습니다. 알림 설정은 라우트 정의(MainRoutes.tsx)에서 mailreport 경로가 사이트 구분 없이 <AlertSetting />을 렌더하고, 탭 단에서 OTT 버전(OTT_VER) 탭만 IS_KT일 때 노출됩니다. 역할 레벨별 기본 권한/명령 매핑(administer/rolePermission.tsx의 LEVEL_PERMISSIONS·LEVEL_COMMAND)은 process.env.REACT_APP_TARGET 직접 비교 대신 공통 유틸 isTarget()(utils/env.ts)로 정리되어, TTG 전용 LAUNCHER_RESET 같은 사이트 분기를 한 곳에서 판정합니다.

새로 추가된 Access History 탭(administer/historyList.tsx)은 운영자 접속 이력을 조회합니다. UserApiManager.getLoginHistories(/api/v1/login-histories)로 페이지·검색 조건을 넘겨 목록을 받고, 컬럼(getHistoryListColumns)은 번호·계정 식별자·이름·Role Level·Account Type·Event·Detail·일시(loginAt, relativeDate 타입)로 구성되며, 계정 식별자 컬럼은 KT 타깃에서 ID, 그 외 사이트에서 ID/E-mail 라벨로 갈립니다. 검색 옵션(getHistoryListSearchOptionList)도 KT는 ID·E-mail을 따로, 그 외 사이트는 ID/E-mail 하나로 노출하며, 여기에 이름 텍스트 검색과 Account Type(LOCAL/SSO)·Event(LOGIN/LOGOUT)·Detail(SUCCESS/FAILURE/LOGOUT/SESSION_EXPIRED/SESSION_KICKED) select가 더해집니다. 목록에서 체크한 행은 DownloadExcelModal이 /api/v1/login-histories/download-excel?ids=…로 엑셀 내보내기를 수행합니다. 새로고침 버튼은 페이지·페이지 크기·검색 조건을 초기값으로 되돌린 뒤 다시 조회합니다.

개인정보 마스킹 — 전역 컨텍스트 + 요청 헤더
MaskingProvider(contexts/MaskingContext.tsx)가 MainLayout 전체를 감싸고, sessionStorage의 roleLevel이 Level3인 계정에만 마스킹 권한(hasMaskingPermission)을 부여합니다. 진입 시 getMaskingStatus(/api/v1/masking/status)로 현재 상태를 읽고, 프로필 메뉴(Header/HeaderContent/Profile)의 Data Masking 스위치를 조작하면 setMasking(/api/v1/masking/{on|off} + reason)을 호출한 뒤 sessionStorage.masking을 갱신하고 화면을 리로드해 모든 목록을 다시 그립니다. 실제 마스킹 적용은 _api/AxiosRequest.tsx의 요청 인터셉터가 모든 API 호출에 masking 헤더를 실어 서버가 판단하며, 마스킹 상태 API는 returnFullData 옵션으로 응답 전체를 그대로 받습니다. 마스킹 전환 이력은 getMaskingHistories(/api/v1/masking-histories)로 조회할 수 있습니다.
네트워크 오프라인 알림 — 전용 API 연동 (XLsmart Network Offline api 반영)
AlertSetting은 단말 상태(DeviceAlert)·OTT 버전(OttVersion, KT 전용)·네트워크 오프라인(NetworkOffline) 세 탭으로 구성됩니다. 네트워크 오프라인 알림은 MailApiManager의 전용 엔드포인트 /api/v1/network-offline-alert/policy(목록/생성/상세/수정/삭제)와 템플릿 API(/api/v1/network-offline-alert/template)로 연동되었으며, 편집은 networkoffline/:id 경로의 NetworkOfflineEdit 화면이 담당합니다.

흐름. 관리자 화면이 Admin List·Access History·Pending Approval 탭으로 계정 조회, 로그인/로그아웃 이력 조회·엑셀 내보내기, KT 등록 신청 승인/거절을 한 화면에서 처리하고, rolelist에서 정의한 Role이 PermissionGuard를 통해 접근 통제에 반영됩니다. Data Masking 전환은 상태 API 호출 후 세션 값을 갱신하고 화면을 리로드해 전 목록에 반영됩니다.

관계. 관리자 화면(AdministratorList)이 Admin List·Access History·Pending Approval 탭 컨테이너로서 하위 목록 컴포넌트와 상세(AdminDetail)가 UserApiManager를 공유하고, 마스킹 전역 상태(MaskingProvider)도 같은 매니저의 masking API를 사용하며, KT 사용자 등록 팝업(UserRegistrationModal)도 같은 매니저로 신청을 제출합니다. MainRoutes의 mailreport 경로는 항상 AlertSetting을 렌더하며(OTT 버전 탭은 IS_KT 전용), 네트워크 오프라인 탭은 MailApiManager의 network-offline-alert API를 사용하고 편집은 networkoffline/:id의 NetworkOfflineEdit가 담당합니다. operationHistory 경로는 운영 이력 화면으로 복구되었고, surveySetting 경로는 목록·등록(SurveyCreate)·상세(SurveyDetail)를 렌더합니다.

contexts/MaskingContext.tsx · _api/AxiosRequest.tsx — 마스킹 전역 상태와 요청 헤더
// MaskingContext — Level3 계정만 마스킹 전환 권한
const hasMaskingPermission = sessionStorage.getItem('roleLevel') === 'Level3';
const [masking, setMaskingState] = useState<boolean>(sessionStorage.getItem('masking') === 'on');

const updateMasking = (checked: boolean, reason: string = 'reason') => {
  UserApiManager.setMasking((result, data) => {
    if (result) {
      const isMasked = !!data?.isMasked;
      sessionStorage.setItem('masking', isMasked ? 'on' : 'off');
      setMaskingState(isMasked);
      window.location.reload();          // 마스킹 변경 후 화면 전체 재조회
    }
  }, checked ? 'on' : 'off', reason);
};

// AxiosRequest — 모든 요청에 masking 헤더 첨부 (토큰은 인터셉터에서 주입)
config.headers.masking = `${sessionStorage.getItem('masking') === 'off' ? false : true} `;
