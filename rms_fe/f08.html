관리자 · 역할(Role) 관리

administratorList/rolelist가 UserApiManager로 관리자 계정과 역할(Role) 기반 권한을 관리하고, 메일 리포트 화면은 라우트 단에서 KT 타깃이면 AlertSetting(알림 설정)으로 분기됩니다.

기능 개요

관리자 영역은 RMS 운영자 계정과 권한 체계를 다룹니다. administratorList는 UserApiManager.getList()(/api/v1/users)로 관리자 목록을 조회하고, 등록/상세/수정은 create·getDetail·update로 처리합니다. 비밀번호 초기화(resetUserPassword)와 사용자명/이메일 중복 검사(checkUserName/checkEmail)도 같은 매니저에 있습니다.

역할(Role)은 rolelist가 getRoleList(/api/v1/roles)·createRole·updateRole로 관리합니다. 여기서 정의한 역할이 PermissionContext+PermissionGuard를 통해 화면 접근 권한으로 적용됩니다. 운영 이력은 operationHistory가 DevicesApiManager.getOperationHistory()로 운영자 작업 기록을 보여줍니다. 메일 리포트/알림 설정은 사이트별로 갈리는데, 라우트 정의(MainRoutes.tsx)에서 mailreport 경로가 IS_KT이면 <AlertSetting />, 아니면 <MailReport />로 분기됩니다.

KT의 메일 리포트 → 알림 설정 분기
KT 타깃에서는 메일 리포트 대신 단말 상태/OTT 버전 알림을 설정하는 AlertSetting 화면이 노출됩니다. 동일한 메뉴 경로(mailreport)지만 IS_KT 플래그로 렌더 컴포넌트가 바뀌어, 사이트별 운영 요구에 맞춥니다.

시퀀스 다이어그램

sequenceDiagram autonumber participant OP as 운영자 (Browser) participant AL as administratorList / rolelist participant UM as UserApiManager (_api/User) participant BE as RMS BE 서버 participant PC as PermissionContext / Guard OP->>AL: 관리자 목록 조회 AL->>UM: getList(data) UM->>BE: GET /api/v1/users BE-->>AL: 관리자 목록 OP->>AL: 역할 생성/수정 AL->>UM: createRole / updateRole(data) UM->>BE: POST /api/v1/roles ... Note over PC: 정의된 Role 이 화면 접근 권한으로 적용 OP->>PC: 메뉴 진입 PC->>PC: PermissionGuard 권한 검사 Note over AL: mailreport 경로는 IS_KT ? AlertSetting : MailReport

흐름. 관리자/역할을 UserApiManager로 CRUD 하고, 정의된 Role이 PermissionGuard를 통해 접근 통제에 반영됩니다. 메일 리포트 메뉴는 KT 여부로 알림 설정 화면으로 분기됩니다.

클래스 다이어그램

classDiagram class AdministratorList { +getList() } class RoleList { +getRoleList() +createRole() } class OperationHistory { +getOperationHistory() } class MailReport { +render() } class AlertSetting { +DeviceAlert +OttVersion } class UserApiManager { +getList(cb, data) +create(cb, data) +update(cb, data) +getRoleList(cb, page, size, name) +createRole(cb, data) +resetUserPassword(cb, userID) } class MainRoutes { +mailreport: IS_KT ? AlertSetting : MailReport } AdministratorList --> UserApiManager : 계정 CRUD RoleList --> UserApiManager : 역할 CRUD MainRoutes ..> AlertSetting : KT 분기 MainRoutes ..> MailReport : 비-KT 기본

관계. 계정·역할 화면이 UserApiManager를 공유하고, 메일 리포트 메뉴는 MainRoutes에서 IS_KT 플래그에 따라 AlertSetting/MailReport 중 하나로 렌더됩니다.

핵심 코드

_api/User.tsx — 관리자와 역할(Role) 엔드포인트
getList: (callback, data) => { request('get', '/api/v1/users', callback, data); },
create: (callback, data) => { request('post', '/api/v1/users', callback, data); },
// Roles
getRoleList: (callback, page, size, name?) => { request('get', `/api/v1/roles`, callback, data); },
createRole: (callback, data) => { request('post', '/api/v1/roles', callback, data); }
routes/MainRoutes.tsx — KT 타깃에서 메일 리포트를 알림 설정으로 분기
import { IS_KT } from 'utils/env';
// ...
{
  path: 'mailreport',
  children: [
    { path: '', element: IS_KT ? <AlertSetting /> : <MailReport /> }
  ]
}
