배치 리포트

batchReport가 Log/Report/Failure 탭으로 배치 집계 결과를 나누어 보여주고, batchReportDetail로 상세를 조회합니다. 각 행의 결과 파일은 공용 유틸 downloadExcel()(utils/common.tsx)이 /api/v1/files/download를 axios(beAxios)로 받아 Blob으로 내려받습니다.

기능 개요

배치 리포트 화면(batchReport.tsx)은 MUI Tabs로 LOG·DEVICE(report)·FAIL(failure) 세 탭을 제공합니다. LOG 탭은 tabs/Log.tsx(LogReport), 나머지 두 탭은 tabs/Etc.tsx(EtcReport)가 렌더링합니다. 데이터는 ParameterApiManager를 통해 조회하는데, LOG 탭은 getFileMetaLast(/api/v1/file-metas), Report/Failure 탭은 getReportHistory(/api/v1/report-historys)를 호출합니다.

각 리포트 행에는 결과 파일이 첨부되어 있어, 운영자가 다운로드를 누르면 REACT_APP_RMS_BE_SERVER_URL + /api/v1/files/download?objectName=... URL을 downloadExcel()(utils/common.tsx)에 넘겨 Blob으로 저장합니다. LOG·Report·Failure 세 탭이 각자 갖고 있던 Authorization 헤더 수동 첨부 + fetch + 실패 시 toast('download error') 구현은 중복 제거되어 이 공용 함수로 통일되었고, 실패 시에는 토스트 대신 401 응답이면 세션을 지우고 로그인 만료 화면으로 보내는 방식으로 바뀌었습니다. Report/Failure 탭(Etc.tsx)에서는 파일명 텍스트 링크 대신 다운로드 아이콘 버튼(customFileComponet + DownloadIcon)으로 내려받으며, 테이블의 리포트 주기 컬럼 라벨도 items.report_cycle로 정리되었습니다. 컬럼 정의는 reportColumns/failureColumns로 분리되어, Failure 탭(tabState === 'FAIL')에서는 실패 유형(thresholdType, 라벨 items.failure_type) 컬럼이 추가로 표시됩니다. 데이터가 없을 때의 빈 목록 문구도 탭별로 분기되어 Report 탭은 empty.no_report_data, Failure 탭은 empty.no_failure_data, LOG 탭은 empty.log 메시지를 보여줍니다. 상세 보기는 batchReportDetail이 getBatchReport(/api/v1/batch-reports)로 단건 데이터를 받아 표시하고, 뒤로가기 시 navigate('/monitoring/batch')로 목록으로 복귀합니다. 최근 변경분에서 배치 리포트 로직 자체는 그대로이고, 라우팅에서 빠져 있던 구버전 화면 batchReport_old.tsx와 그 테이블 타입 정의(types/dashboardDetail/table_old.tsx)에 이어 react-table/react-csv 기반 공용 래퍼 components/third-party/ReactTable.tsx도 dead code로 정리·삭제되었습니다. 세 탭 모두 공용 CustomTable만 사용하므로 화면에서의 CSV 내보내기 진입점은 남아 있지 않고(react-csv는 package.json에만 남은 미사용 의존성입니다), 리포트 반출은 행 단위 파일 다운로드로만 이뤄집니다.

LOG 탭의 테이블·검색 정의도 사이트 대표 식별자 체계로 옮겨졌습니다. monitoring.columns.ts의 getLogColumns가 deviceId/deviceSiteId를 hidden으로 갈라 두 벌 두던 컬럼을 DEV_MAIN_KEY(KT deviceSiteId · XLSmart serial · 그 외 deviceId) 한 컬럼으로 합치고, 그 뒤에 MAC 주소 컬럼을 추가했습니다(대표 식별자가 이미 macAddress인 사이트에서는 숨김). 검색 옵션(getLogSearchOptionList)도 같은 방식으로 DEV_MAIN_KEY 한 항목만 노출합니다.

조회와 다운로드의 분리
목록 조회는 콜백 스타일 request 헬퍼(axios)로, 파일 다운로드는 공용 downloadExcel()이 beAxios로 Blob을 받아 처리합니다. 둘의 책임이 분리되어 있어 대용량 리포트 파일도 테이블 렌더와 무관하게 받아지고, 다운로드 쪽만 401 세션 만료를 별도로 처리합니다.

흐름. 탭에 따라 file-metas 또는 report-historys를 조회하고, 행 단위 파일은 files/download를 fetch해 Blob으로 저장합니다.

관계. BatchReport가 탭에 따라 LogReport/EtcReport를 소유하고, 각각 ParameterApiManager의 서로 다른 엔드포인트를 호출합니다. LOG 탭의 컬럼·검색 정의는 monitoring.columns.ts/monitoring.searchOption.ts에서 DEV_MAIN_KEY 기준으로 내려받습니다. 상세는 BatchReportDetail이 getBatchReport로 처리합니다.

핵심 코드

pages/monitoring/batchReport.tsx — 탭에 따라 LogReport/EtcReport 분기
{tabState === 'LOG' && <LogReport tabState={tabState}></LogReport>}
{tabState !== 'LOG' && <EtcReport tabState={tabState}></EtcReport>}
pages/monitoring/tabs/Log.tsx — 리포트 파일 다운로드 URL 구성 후 공용 downloadExcel 호출
import { downloadExcel } from 'utils/common';

const donwloadUrl =
  `${process.env.REACT_APP_RMS_BE_SERVER_URL}/api/v1/files/download?objectName=${row.filePath}`;
downloadExcel(donwloadUrl, fileName);   // beAxios GET(blob) → a.download 저장, 401 시 로그인 만료 이동
ParameterApiManager.getFileMetaLast((result, data) => { /* 목록 렌더 */ });
pages/monitoring/tabs/Etc.tsx — Report/Failure 행 다운로드 아이콘 버튼 (공용 downloadExcel)
import { downloadExcel } from 'utils/common';

const customFileComponet = (row: any) => {
  if (row.fileName) {
    const donwloadUrl = `${process.env.REACT_APP_RMS_BE_SERVER_URL}/api/v1/files/download?objectName=${row.filePath}`;
    return (
      <IconButton onClick={(evt) => { evt.stopPropagation(); evt.preventDefault(); downloadExcel(donwloadUrl, row.fileName); }}>
        <DownloadIcon />
      </IconButton>
    );
  }
};

// utils/common.tsx — downloadExcel: 실패 시 401이면 세션 클리어 후 로그인 만료로 이동
.catch((error) => {
  logger.error(error);
  if (error.response && error.response.status === 401) {
    sessionStorage.clear();
    window.location.href = `${process.env.REACT_APP_PUBLIC_URL}/login/expire`;
  }
});
pages/monitoring/tabs/Etc.tsx — Failure 탭 전용 컬럼 분기 (fail type 컬럼 추가)
<CustomTable
  dataSource={tabState === 'FAIL' ? failureColumns : reportColumns}
  rows={rows}
  setRows={setRows}
  selectedRows={selectedRows}
  ...
/>
// failureColumns: no / reportTime / reportPeriodType / thresholdType(items.failure_type) / count / filePath
// reportColumns:  no / reportTime / reportPeriodType / count / filePath
