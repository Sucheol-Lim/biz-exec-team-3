기능 개요

모니터링 대시보드는 운영자가 RMS에 로그인하면 처음 마주하는 화면으로, 현장에 배포된 단말의 온라인 수·모델별 분포·임계치 초과 추이 등을 위젯 단위로 보여줍니다. 화면 본체인 dashboardRms.tsx는 react-grid-layout의 Responsive를 WidthProvider로 감싼 ResponsiveGridLayout을 렌더링하며, 각 칸이 하나의 DashboardItem 위젯이 됩니다. 레이아웃 컬럼 수는 widgetPermissions.widgetCols로 분기되어 XLSmart 타깃은 20, 그 외는 16 컬럼을 사용합니다. XLSmart에서 KPI 위젯을 5개(KPIWidgetCount) 나란히 표시하기 위한 확장으로, IBC 타깃은 이 확장 대상에서 제외되어 기본 16컬럼·KPI 4개를 사용합니다.

위젯 데이터는 서버 상태로 관리되며, 레이아웃/메타 조회와 실제 데이터 조회가 두 단계로 분리되어 있습니다. 마운트 시 initialize()가 getLayout()·getWidget()·getOnlineDevice()를 Promise.all로 병렬 실행하는데, getWidget()은 loadWidget()으로 위젯 목록(/api/v1/dashboard-config/widgets)만 받아 각 위젯의 data를 null로 채운 채 즉시 반환합니다. 이어서 모듈 레벨 헬퍼 buildLayouts()가 서버 레이아웃(/api/v1/dashboard-config/layouts)과 위젯 메타를 결합해 그리드부터 그리고, 새로 추가된 loadWidgetDataProgressively()가 위젯별로 getWidgetDetailInfos(t)에 정의된 API를 각각 독립적으로 호출해 응답이 도착하는 대로 해당 위젯의 data만 setWidgets로 채워 넣습니다. 예전에는 Promise.allSettled로 모든 위젯 API를 한 번에 기다렸다가 한꺼번에 그렸지만, 지금은 위젯이 각자 로딩되므로 응답이 느린 위젯 하나 때문에 나머지 위젯까지 늦게 뜨는 일이 없습니다. data가 아직 null인 위젯 자리는 DashboardItem이 이중 CircularProgress(바깥쪽 고정 원 + 안쪽 회전 원) 로딩 스피너로 채우며, 크기는 맨 위 KPI 카드류(typoVariation)는 28px, 그 외 위젯은 56px입니다. 운영자가 편집 모드에서 위젯을 드래그하면 onLayoutChange가 상태를 갱신하며 sessionStorage에 임시 저장하고(재진입 시 복원 확인 모달), 저장 시 saveLayout()·saveWidget()이 변경된 레이아웃과 위젯 구성을 서버에 POST 합니다.

XLSmart 타깃 대응으로 위젯이 확장되었습니다. KPI 위젯 Illegal Devices(/api/v3/dashboard/illegal-device)가 widgetPermissions.illegalDevices 조건(XLSmart 전용)으로 초기 위젯 목록(types/dashboard/init.ts)에 추가되고, 차트 위젯 Top Installed Apps(install-app)·Top Deleted Apps(delete-app)·HDMI Connection Status(hdmi-connection)가 widgetDetailInfos(types/dashboard/data.ts)에 정의되었습니다. 각 위젯에는 topInstall·topDelete·hdmi 전용 아이콘도 부여되었습니다. 지도 위젯(DashboardItem/map/Map.tsx)에는 단말 상태(All/Active/Crash App/Warning/Illegal)를 고르는 CustomSelect 셀렉트가 지도 우상단 position: absolute 오버레이(top 48px·폰트 13px·높이 32px, 총계 문구 아래로 위치 조정)로 표시되며, 선택한 상태는 onMapChange를 거쳐 getDeviceStatusParam()(components/CustomizedMap.tsx)으로 변환되어 지도 데이터 조회 파라미터에 실제 반영됩니다. 지도 마커에는 hoverEnabled prop이 추가되어, 마커 선택이 불가능한(isSelectable이 아닌) 대시보드 위젯에서도 마우스를 올리면 해당 마커가 강조됩니다(선택 스타일은 그대로 제외). 베이스맵 타일 URL도 REACT_APP_CARTO_MAP_KEY를 쿼리로 붙인 CARTO 유료 키 방식으로 바뀌었습니다(components/CustomizedMap.tsx). 위젯 상세 모달(dashboardDetailModal.tsx)도 isShowDeviceStatus 플래그로 같은 상태 필터를 노출하며, Illegal Devices 위젯의 테마 컬러는 #93ACFF로 조정되고 위젯 툴팁 문구(tooltipLabel)가 추가되었습니다(types/dashboard/data.ts).

위젯 상세(2depth) 화면도 강화되었습니다. widgetDetailInfos의 각 위젯에 기본 정렬 옵션 defaultSortTarget·defaultSortType이 추가되어 상세 테이블이 위젯 성격에 맞는 컬럼(threshold 계열은 cpuUsage/memoryUsage/networkUsage, 단말 목록 계열은 대표 식별자 DEV_MAIN_KEY.id)으로 정렬된 채 열립니다. 종전의 IS_KT ? 'deviceSiteId' : 'deviceId' 3항식과 검색 옵션의 deviceId/deviceSiteId 이중 정의는 모두 utils/env.ts의 DEV_MAIN_KEY 한 곳으로 모였고, 상세 검색 목록(createSortedSearchList)도 DEV_MAIN_KEY.name·DEV_MAIN_KEY.id 한 항목만 노출합니다. Top Installed / Top Deleted Apps 위젯의 검색 API 경로도 info/installed-app/{unit}·info/deleted-app/{unit}으로 정정되었습니다. App Crash·CPU/Memory/Network Threshold 위젯에는 isAiCause: modulePermissions.anomalyDetect 플래그가 붙어 IBC 타깃에서 이상 감지(AI 원인 분석) 기능과 연동됩니다. 또한 별도 팝업으로 뜨는 위젯 상세(components/DashboardItemDetail)에서 Device Details를 클릭하면 window.opener.openDeviceDetailModal(deviceId)로 부모 대시보드에 등록된 콜백이 호출되고, dashboardRms가 DevicesApiManager.getList()로 단말을 조회한 뒤 단말 관리 화면(devices.tsx)의 행 클릭과 동일한 연결 상태 분기를 수행합니다.

단말 연결 대기 처리는 모달을 띄우기 전에서 띄운 뒤로 옮겨졌습니다. 예전에는 DISCONNECTED+ONLINE 단말에 DEVICE_CONNECTION 명령을 보낸 뒤 dashboardRms가 BackdropLoading을 띄운 채 DEVICE_CONNECTION_TIME_LEFT(30초) 동안 세션 상태를 폴링했지만, 지금은 명령을 보내자마자 isCommandSent: true를 실은 모달 정보를 useTask().openDeviceDetailModal()에 넘겨 device_info 모달을 먼저 엽니다. 실제 재연결 확인은 모달 본체인 pages/device/detailWrapper.tsx가 맡아 1초 간격·최대 20회로 getDetail을 폴링하다가 STANDBY가 되면 createDeviceConnection으로 연결을 만들고 updateCurrDeviceDetailModalConnectionId(connectionId)로 이미 열려 있는 모달의 connectionId를 갱신합니다. 이 개편으로 TaskContext의 API 이름도 디바이스 상세 전용임이 드러나게 openModal→openDeviceDetailModal, currModal→currDeviceDetailModal로 정리되었고, ModalProps에서는 호출부가 계산하던 isMine이 빠지고 isCommandSent가 추가되었습니다. 조작 권한(Controllable/View Only)은 상세 모달이 getDeviceInfo 응답의 lastConnectUserId와 로그인 사용자 userInfo.id를 비교한 isConnectedByMe로 직접 판단합니다.

위젯 상세(2depth) 팝업의 이슈 이력 모달(IssueHistoryModal)은 목업 배열을 걷어내고 dashboardAxios로 /api/v1/quick-operation-issues/device-history를 조회해 실제 이슈 타임라인을 그립니다. 응답의 days·totalCount로 "최근 N일 M건" 배지를 표시하고, 그 아래에 cpuCount·memoryCount·networkCount·appCount 중 0이 아닌 항목만 CPU·Memory·Network·App 건수 배지로 나열합니다. 각 이슈는 RESOLVED·AUTO_RECOVERED·UNRESOLVED 상태별 아이콘과 색으로 구분되며 actionsTaken·recoveredInMinutes·scope를 조합해 설명 문구를 만들고, 탐지 시각은 YYYY-MM-DD(굵게)와 HH:mm:ss 두 줄 값으로 분리되어 표시됩니다. 타임라인 영역은 maxHeight 560의 자체 스크롤 박스로 감싸져 이력이 길어져도 모달 높이가 늘어나지 않습니다. 응답의 quickOperationAvailable이 참일 때만 Quick Operation 이동 버튼이 노출되는데, 넘기는 값이 단말이 아니라 이슈로 바뀌어 callbackFc('Q', deviceInfo.quickOperationIssueId)가 부모 창을 /monitoring/quickOperation?issueId=…&size=20으로 보냅니다. 이 issueId 쿼리는 이상 감지 화면에서 해당 이슈를 직접 펼치는 딥링크 조건으로 쓰입니다. 상세 테이블의 AI Cause 버튼도 row.quickOperationIssueId가 null이면 렌더링되지 않습니다. 차트 쪽에서는 BarChart의 x축 tick 클릭이 막대 클릭과 같은 handleClickX() 경로로 합쳐져 날짜 레이블을 눌러도 onClickDate가 호출되고, Y축 스케일이 자릿수 기반 올림에서 Math.max(50, Math.ceil(max / 50) * 50)으로 바뀌어 최소 50 단위로 정돈됩니다. 눈금 라벨은 buildChartTickValues(6개)로, 배경 그리드는 새 헬퍼 buildChartGridValues(11개)로 나뉘어 그려지고, Y축 폭은 최댓값이 아니라 실제 눈금 라벨 중 가장 긴 문자열 길이로 계산됩니다. 툴팁 분기에도 위젯이 추가되어 topInstalledApps·topDeletedApps가 topAppUsed와 같은 비율 표시·Other Apps 후순위 정렬을 따르고, hdmiConnectionStatus는 networkInterface처럼 share 비율을 함께 보여줍니다.

편집 모드 자체도 손봤습니다. 위젯을 연달아 추가할 때 setWidgets·setLayouts의 비동기 반영 때문에 직전 추가분이 누락되던 문제를 widgetsRef·layoutsRef로 항상 최신값을 읽도록 바꿔 해결했고, 새 위젯을 놓을 자리는 layouts.lg의 마지막 원소가 아니라 y·x 내림차순으로 정렬한 실제 최하단 위젯을 기준으로 계산합니다. 그리드 컬럼 수 상태도 초기값 0 대신 COLS.lg로 시작해 첫 렌더에서 폭이 어긋나지 않습니다. 임시 저장 복원 확인 모달은 버튼 역할이 뒤바뀌어, 기본(OK) 버튼이 임시 저장분을 버리고 다시 불러오는 onTempClose(Go back), 보조 버튼이 이어서 편집하는 onTempSave(Continue editing)가 되었습니다.

가장 최근 범위(~868b6160)에서는 지도 위젯의 기반 기술이 바뀌었습니다. components/CustomizedMap.tsx가 react-leaflet의 래스터 TileLayer(CARTO PNG)를 걷어내고 @maplibre/maplibre-gl-leaflet로 CARTO Voyager 벡터 스타일(basemaps.cartocdn.com/gl/voyager-gl-style/style.json)을 그리는 VectorBasemapLayer로 교체되었습니다. CRA(webpack)가 maplibre-gl이 import.meta.url로 계산하는 워커 스크립트 경로를 번들링하지 못해 벡터 타일이 뜨지 않는 문제는 public/maplibre-gl-worker.mjs를 직접 배치하고 setWorkerUrl()로 그 경로를 지정해 우회했으며(infra/helm/nginx/nginx.conf에 .mjs MIME 매핑 추가), 지도 경계(bounds)에도 경도 40도의 여유 패딩이 더해졌습니다. 차트 쪽에서는 BarChart가 위젯별 지정 날짜 포맷(widgetInfo.dateFormat)을 X축·툴팁에 그대로 쓰도록 바뀌고 마지막 막대의 종료 시각 계산이 to 값 유효성·역전 여부·:59 보정을 따지도록 보강되었습니다. LineChart의 활성 단말 대비 비율("N% of active device")은 상위에서 내려주던 exceedPct prop 대신 시리즈 데이터의 activeDevice 값으로 화면이 직접 계산하도록 고쳐졌고, PieChart 툴팁은 topInstalledApps/topDeletedApps 항목에서 Devices 대신 각각 Installed/Deleted 라벨을 보여줍니다. utils/chartParsing.ts의 parseDetailLineChartCustom은 합계를 device + app/transferred + created로 재계산하던 방식 대신 응답의 total 필드를 우선 쓰고 Total Devices(totalDevices) 위젯에서는 삭제 단말 수(deleted)를 빼도록 고쳐져, 1depth 대시보드의 표시 정책 오류가 해소되었습니다. 위젯 상세(2depth) 기본 조회 기간(DateRange.tsx)도 "오늘 포함 8일"에서 "어제까지 7일"로 조정되었습니다.

가장 최근 범위(~0406bc7a)의 핵심은 앞서 설명한 위젯별 순차 로딩(loadWidgetDataProgressively + 로딩 스피너) 도입이고, 그 외에 PieChart가 데이터 0건일 때를 위한 isEmpty 분기를 갖게 되었습니다. data.length === 0이면 도넛 색을 #D9D9D9 단색으로, 범례 영역은 항목 목록 대신 t('common.no_data')(레전드가 없는 좁은 폭에서는 t('cm:no_data')) 문구로 채우고 isInteractive를 꺼 hover 강조도 비활성화합니다. 대시보드 API 호출도 더 안전해졌습니다. dashboardAxios의 응답 인터셉터에 실패 핸들러가 새로 붙어 401 응답이면 세션을 지우고 로그인 만료 화면(/login/expire)으로 이동시키되, 이동이 실제로 끝나기 전까지 호출부의 await/catch가 이어서 실행되지 않도록 new Promise(() => {})로 영구 대기시켜 화면이 어중간한 상태로 남지 않게 합니다. 세션 타임아웃 자체도 JWTContext가 navigate() 대신 window.location.href 전체 새로고침으로 처리하도록 바뀌어, 대시보드가 떠 있는 동안 세션이 끊겨도 진행 중이던 위젯 폴링·요청이 새로고침으로 확실히 정리됩니다.

사이트별 위젯 분기
utils/env.ts의 widgetPermissions에 따라 단말 위치 지도(deviceLocationMap)·브랜드 모델·네트워크 인터페이스 위젯은 OBE/TTG/XLSmart/IBC 타깃에서 숨겨지고, KT 타깃은 disableEditMode로 편집 자체가 비활성화됩니다. XLSmart에서는 illegalDevices 위젯이 켜지고 KPIWidgetCount 5·widgetCols 20이 적용됩니다. IBC는 위젯 확장 대상에서 빠지는 대신 modulePermissions에서 anomalyDetect·chatbot·terminal이 켜지는 별도 프로파일로 정리되었습니다. 여기에 단말 대표 식별자 DEV_MAIN_KEY가 더해져 KT는 deviceSiteId(SAID), XLSmart는 serial(S/N), 그 외는 deviceId를 대표 키로 쓰며, modulePermissions에도 installFw(TTG 제외)·ssoLogin(XLSmart)이 추가되고 terminal에 XLSmart가 포함되었습니다. 즉 같은 코드가 사이트에 따라 다른 위젯 구성과 다른 대표 식별자를 노출합니다.
