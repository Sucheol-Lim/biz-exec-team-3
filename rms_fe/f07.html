OTA(펌웨어) 관리

fwList가 펌웨어 이미지를 등록·관리하고, fwInstall이 FirmwareApiManager.install()로 대상 단말 그룹에 펌웨어 OTA 업데이트를 예약·전파합니다. 설치 상세 모달에서는 상태별 집계·진행률 바와 함께 Retry·Pause/Resume·Stop으로 진행 중인 배포를 제어합니다.

기능 개요

OTA(펌웨어) 관리는 단말 펌웨어 이미지를 등록하고 무선으로(Over-The-Air) 업데이트를 배포합니다. fwList는 FirmwareApiManager.getList()(/api/v1/firmwares)로 등록된 펌웨어 목록을 보여주고, 등록은 앱 패키지와 같은 업로드 모달(appmanagement/modal/UploadModal.tsx, type='FW')을 재사용합니다. 모달은 checkName으로 이름/버전 중복을 먼저 확인한 뒤 펌웨어 이미지를 multipart/form-data로 /api/v1/firmwares에 업로드하며 진행률을 표시합니다.

실제 OTA 배포는 fwInstall 화면이 담당합니다. 운영자가 펌웨어·대상 그룹·설치 시각·모드를 지정하면 install()(/api/v1/firmware-installs)에 firmware·mode·installTime·deviceGroupIds(필요 시 rescueId)를 묶어 POST 합니다. 설치 시각은 formatToIsoDateTime(utils/dateFormat)이 사이트 정책(useIsoTimestamp — XLSmart·IBC)에 따라 ISO 8601 문자열 또는 YYYYMMDDHHmmss로 변환해 보냅니다. 설치 모드 목록(MODE_LIST — Force·Normal·Optional)도 모달 안에 중복 정의돼 있던 것을 types/package.ts의 공용 정의로 바꿔 앱 설치 모달과 공유합니다. 배포 후에는 getInstallList로 설치 작업 목록을, getInstallDetailHistroy로 단말별 설치 진행/결과 이력을 추적합니다. 설치 작업 행에는 대상 그룹이 사람이 읽기 쉬운 텍스트로 요약 표시되고 목록에 OS 컬럼이 있으며, 예약 시각(installTime)은 문자열을 직접 자르던 getTimeText(삭제됨) 대신 테이블 컬럼의 type: 'date'·dateFormat 지정으로 서버 값 그대로 받아 포맷합니다(XLSmart ISO 타임스탬프 대응).

설치 상세 모달의 단말 이력 테이블(getFwInstallModalDeviceColumns)에는 이번 범위에서 두 컬럼이 함께 고쳐졌습니다. 재시도 횟수(retryCount) 컬럼은 실제로는 단말 상태(statusComponent(row.status))를 그대로 렌더링하는 복사·붙여넣기 버그가 있어 재시도 횟수 대신 상태 텍스트가 표시되고 있었는데, 지금은 type: 'text'로 바뀌어 row.retryCount 값을 그대로 보여줍니다. 바로 아래 최근 설치 시각 컬럼도 같은 버그로 상태 텍스트를 보여주고 있었고, 컬럼 id도 실제 데이터 필드와 다른 lastInstallTime으로 정의돼 있었습니다. 이번 수정으로 id가 실제 필드명인 lastModifiedAt으로 바뀌고, App 관리(appmanagement.columns.ts)와 같은 범용 파서 convertReceiveDate(row.lastModifiedAt, 'YYYY-MM-DD HH:mm')로 값을 표시하도록 정정되었습니다("FW 송출건이 최신순으로 정렬되지 않는" 부분은 같은 티켓의 서버 응답 정렬 문제로, 프론트엔드 쪽에는 별도 정렬 로직 변경이 없습니다).

설치 상세 모달(FwInstallModal)은 getInstallDetailHistroyStatus(/firmware-install-historys/status/{id})로 단말 설치 상태를 Init·In_Progress·Success·Fail 4단계로 집계해 진행률 바(installProgress)와 함께 보여주고, 이 집계가 제어 버튼 활성화 조건이 됩니다. handleRetry는 getInstallRetry(/firmware-installs/{id}/retry)로 실패 단말 재시도를 요청하고(Fail 단말이 있을 때 활성화), handlePauseToggle은 getInstallPause/getInstallRestart(/pause·/resume)로 배포 일시정지/재개를 토글하며(진행 중 단말이 있을 때 활성화), 재개 버튼 문구는 Restart에서 Resume(items.resume)으로 정리되었습니다. Stop은 확인 다이얼로그를 거쳐 getInstallStop(/stop)을 호출하며, STOP 상태가 되면 버튼 대신 Stopped 배지와 중지 시각이 표시됩니다. 단말 이력 테이블에는 재시도 횟수(retryCount)·최근 설치 시각(lastInstallTime) 컬럼이 추가되었고, 모달을 닫으면 설치 목록을 다시 조회(reload)합니다. 같은 모달이 신규 설치 폼으로도 쓰이므로, 상세 조회(fetchInstallDetail)와 상태 집계(fetchInstallStatus)는 신규 설치 모드(isInstall)에서는 호출하지 않도록 가드되어 불필요한 API 호출과 콘솔 경고가 제거되었습니다. 단말 이력 테이블의 식별자 컬럼(getFwInstallModalDeviceColumns)도 IS_KT/IS_NOT_KT로 두 컬럼을 감추던 방식 대신 사이트 대표 식별자 DEV_MAIN_KEY(KT는 deviceSiteId, XLSmart는 serial, 그 외는 deviceId) 하나로 통합되었습니다.

단말 한 대를 대상으로 하는 펌웨어 업데이트는 디바이스 상세 모달의 명령 패널에서 실행합니다. pages/device/modal/fwInstallModal.tsx는 펌웨어 목록에 더해 설치 모드 드롭다운(MODE_LIST)을 받아 connectionCommand(..., 'firmware-ota-update', { commandType: 'FIRM_OTA_UPDATE', firmwareId, mode })로 명령을 보내며, 펌웨어와 모드를 모두 고르기 전에는 적용 버튼이 dim 처리됩니다. 이 Install FW 명령 자체의 노출 여부는 utils/env.ts의 modulePermissions.installFw(TTG 사이트 제외)로 갈리며, 같은 플래그가 역할(Role) 권한 편집 화면의 명령 목록에도 적용됩니다.

그룹 단위 OTA
펌웨어 OTA는 개별 단말이 아니라 단말 그룹(deviceGroupIds) 단위로 배포 대상을 지정합니다. 즉 단말 관리에서 만든 그룹이 펌웨어 배포의 단위가 되어, 모델·지역별 단계적 롤아웃이 가능합니다.

흐름. 펌웨어를 검증·등록한 뒤 대상 그룹·시각·모드로 install을 호출해 OTA를 배포하고, 설치 히스토리로 단말별 결과를 추적합니다. 설치 상세 모달에서는 상태 집계 API로 진행률을 표시하고 retry/pause/resume/stop 엔드포인트로 진행 중인 배포를 제어합니다.

핵심 코드

_api/Firmware.tsx — 펌웨어 등록(FormData)·그룹 단위 OTA 설치·배포 제어
create: (callback, data: FormData) => {
  request('post', `/api/v1/firmwares`, callback, data, true);  // isForm = multipart
},
install: (callback, firmware, mode, installTime, deviceGroupIds, rescueId) => {
  const data = { firmware, mode, installTime, deviceGroupIds,
    ...(rescueId != null && rescueId !== '' ? { rescueId } : {}) };
  request('post', `/api/v1/firmware-installs`, callback, data);
},
getInstallDetailHistroyStatus: (callback, id: number) => {
  request('get', `/api/v1/firmware-install-historys/status/${id}`, callback);
},
getInstallRetry: (callback, id: number) => {
  request('post', `/api/v1/firmware-installs/${id}/retry`, callback);
},
getInstallRestart: (callback, id: number) => {
  request('post', `/api/v1/firmware-installs/${id}/resume`, callback);
},
getInstallPause: (callback, id: number) => {
  request('post', `/api/v1/firmware-installs/${id}/pause`, callback);
},
getInstallStop: (callback, id: number) => {
  request('post', `/api/v1/firmware-installs/${id}/stop`, callback);
}
pages/ota/fwInstall.tsx — 설치 목록 조회 후 대상 그룹 텍스트 요약
FirmwareApiManager.getInstallList((result, data) => {

const getDeviceText = (deviceGroups) =>
  deviceGroups[0].name + (deviceGroups.length > 1 ? ` + ${deviceGroups.length - 1}` : '');
pages/ota/FwInstallModal.tsx — 배포 일시정지/재개(Resume) 토글 + 상태 재조회
const fetchInstallStatus = (onDone?: () => void) => {
  if (!isInstall) {                       // 신규 설치 모드에서는 상태 조회 생략 (콘솔 경고 수정)
    apiManager.getInstallDetailHistroyStatus((result, data) => {
      // INIT/SENDED/PENDING → Init, IN_PROGRESS, SUCCESS, FAILED 집계
      onDone?.();
    }, reqId);
  }
};

const handlePauseToggle = () => {
  if (isProcessing) return;
  setIsProcessing(true);
  if (paused) {
    apiManager.getInstallRestart((result) => {   // POST .../resume
      if (result) {
        setPaused(false);
        getDeviceList();
        fetchInstallStatus(() => setIsProcessing(false));  // Init/In_Progress/Success/Fail 재집계
      } else {
        setIsProcessing(false);
      }
    }, reqId);
  } else {
    apiManager.getInstallPause((result) => {     // POST .../pause
      if (result) setPaused(true);
      getDeviceList();
      setIsProcessing(false);
    }, reqId);
  }
};
