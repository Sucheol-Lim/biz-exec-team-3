앱(App) 관리

packageList/packageInstall/defaultPackage/appPolicy가 AppApiManager로 APK 패키지 업로드·설치(중지/재시도 포함)·기본 패키지·앱 정책(App Exception 정책 포함)을 다루며, 목록에는 getAppPackageName 유틸로 앱 이름(appName(패키지명)) 형식을 표시합니다.

기능 개요

앱 관리는 단말에 배포할 APK 패키지의 등록부터 설치, 정책 적용까지를 다룹니다. packageList는 AppApiManager.getList()(/api/v1/app-packages)로 패키지 목록을 조회하고, 업로드는 create(FormData + isForm=true)로 APK를 multipart/form-data 전송하며 사전에 getApkInfo(analyze-apk)로 APK 메타를 분석합니다. 실제 단말 설치는 packageInstall이 install()(/api/v1/app-package-installs)에 packageIds·mode·installTime·대상 deviceGroupIds를 넘겨 예약/즉시 배포합니다. 진행 상태는 getInstallDetailHistroyStatus로 추적하고, 진행 중인 배포는 설치 상세 모달(PkgInstallModal)에서 getInstallStop(/app-package-installs/{id}/stop)으로 중지하거나 getInstallRetry로 재시도할 수 있습니다. 설치 목록은 건당 단일 패키지(appPackage) 기준으로 표시됩니다.

defaultPackage는 단말 초기 구성에 들어갈 기본 패키지(/api/v1/default-packages)와 관리 앱(managed-app) XML 업로드를 다루고, appPolicy는 Threshold(임계치)·App Exception·화이트리스트/블랙리스트·managed-app 탭을 묶는 컨테이너로 하위 목록은 whiteList.tsx가 공용 처리합니다. 새로 추가된 App Exception 탭(appExceiptionList.tsx)은 getExceptionPolicies(/api/v1/app-exception-policies)로 앱 예외 정책 목록을 조회해 예외 코드별 Enable/Disable 상태를 보여주고, 편집 모달(ExceptionEditModal)에서 체크한 항목들을 editExceptionPolicies(/api/v1/app-exception-policies/bulk/update)로 일괄 저장합니다(XLSmart admin-api 변경 반영). 화이트/블랙리스트 편집 모달(PolicyAppListEditModal)은 getDefaultGroupedPkg(/default-packages/grouped)로 같은 이름의 패키지를 묶어 버전을 select로 고르게 합니다. 목록 컬럼은 getAppPackageName 유틸이 앱 이름이 있으면 appName(패키지명) 형식으로 표시합니다(appmanagement.columns.ts).

설치 중지·앱 이름 표시 정비
최근 작업으로 앱 설치 중지 API(/app-package-installs/{id}/stop) 반영과 설치 목록 단일 패키지 표시 수정(개발 이력 55313374), 화이트/블랙리스트 버전 select(863f6b65)가 추가되었고, KT UI 검수를 거치며 패키지명 표시가 사이트 공통 유틸 getAppPackageName으로 통일되었습니다(53f8ace7, ae080c36). 이후 XLSmart 대응으로 App Exception 정책 탭이 신설되어 app-exception-policies API 연동과 일괄(bulk) 수정이 반영되었습니다(e4723487, f02fabdb, edaba4ff). 최근 범위에서는 앱 관리 화면 자체의 기능 변경 없이, 정책 앱 목록 편집 모달의 콘솔 로그가 공통 로거(log.debug)로 정리되고(cbf079cb) 업로드 영역(UploadFile)의 드롭존 높이가 전달받은 height를 따르도록, 보조 안내문(addSubDesc) 표기가 작은 글씨로 조정되었습니다.

흐름. APK를 분석·업로드한 뒤 대상 그룹·시각·모드를 지정해 install로 배포하고, 설치 히스토리 상태를 폴링해 단말별 결과를 확인합니다. 진행 중인 배포는 설치 상세 모달(PkgInstallModal)에서 중지(stop)·재시도(retry)할 수 있습니다.

관계. 앱 관리 하위 화면들이 AppApiManager 하나를 공유해 패키지 CRUD·설치(중지 포함)·정책을 처리합니다. APK 업로드와 managed-app XML은 FormData(isForm)로 전송되고, 정책 편집 모달은 getDefaultGroupedPkg로 이름별 버전 목록을 받아 select로 제공합니다. App Exception 탭(AppExceiptionList)은 예외 정책을 조회해 편집 모달의 체크 결과를 bulk update로 저장합니다.

핵심 코드

_api/App.tsx — APK 업로드(FormData)·그룹 단위 설치·설치 중지
create: (callback, data: FormData) => {
  request('post', `/api/v1/app-packages`, callback, data, true);  // isForm = multipart
},
install: (callback, packageIds, mode, installTime, deviceGroupIds: number[]) => {
  request('post', `/api/v1/app-package-installs`, callback,
    { packageIds, mode, installTime, deviceGroupIds });
},
getInstallStop: (callback, id: number) => {
  request('post', `/api/v1/app-package-installs/${id}/stop`, callback);
},
// App Exception 정책 (XLSmart admin-api)
getExceptionPolicies: (callback) => {
  request('get', `/api/v1/app-exception-policies`, callback);
},
editExceptionPolicies: (callback, data) => {
  request('post', `/api/v1/app-exception-policies/bulk/update`, callback, { policies: data });
}
utils/common.tsx · appmanagement.columns.ts — 앱 이름(appName) 표시 유틸과 목록 컬럼
// utils/common.tsx — 앱 이름이 있으면 "appName(패키지명)" 형식으로 표시
export const getAppPackageName = (app: { name: string; appName?: string }): string => {
  return app.appName ? `${app.appName}(${app.name})` : `${app.name}`;
};

// appmanagement.columns.ts — 패키지 목록의 App Name 컬럼
{
  id: 'appName',
  label: t('cm:items.app_name'),
  type: 'custom',
  component: (data: any, row: any, rows: any[]) => {
    return getAppPackageName(row);
  }
}
