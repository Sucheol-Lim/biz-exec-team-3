앱(App) 관리

packageList/packageInstall/defaultPackage/appPolicy가 AppApiManager로 APK 패키지 업로드·설치(중지/재시도 포함)·기본 패키지·앱 정책(App Exception 정책 포함)을 다루며, 목록에는 getAppPackageName 유틸로 앱 이름(appName(패키지명)) 형식을 표시합니다.

기능 개요

앱 관리는 단말에 배포할 APK 패키지의 등록부터 설치, 정책 적용까지를 다룹니다. packageList는 AppApiManager.getList()(/api/v1/app-packages)로 패키지 목록을 조회하고, 업로드는 목록 화면이 띄우는 업로드 모달(modal/UploadModal.tsx)이 담당합니다. APK 파일을 고르면 모달이 /api/v1/app-packages/analyze-apk2로 파일을 보내 App Name·패키지명·버전·설명을 자동으로 채우고, checkName으로 이름·버전 중복을 확인한 뒤 multipart/form-data로 /api/v1/app-packages에 업로드하며 업로드 진행률을 표시합니다. 같은 모달이 type 프로퍼티로 펌웨어 업로드(/api/v1/firmwares)도 겸하며, 별도 화면이던 packageFileUpload는 제거되었습니다. 실제 단말 설치는 packageInstall이 install()(/api/v1/app-package-installs)에 packageIds·mode·installTime·대상 deviceGroupIds를 넘겨 예약/즉시 배포합니다. 설치 예약 시각은 formatToIsoDateTime(utils/dateFormat)을 거쳐 useIsoTimestamp 사이트(XLSmart·IBC)에서는 ISO 8601 문자열로, 그 외에는 YYYYMMDDHHmmss 형식으로 전송됩니다. 진행 상태는 getInstallDetailHistroyStatus로 추적하고, 진행 중인 배포는 설치 상세 모달(PkgInstallModal)에서 getInstallStop(/app-package-installs/{id}/stop)으로 중지하거나 getInstallRetry로 재시도할 수 있습니다. 설치 목록은 건당 단일 패키지(appPackage) 기준으로 표시됩니다.

설치 모드 목록(MODE_LIST — Force·Normal·Optional)과 Mode 타입은 PkgInstallModal 안에 중복 정의돼 있던 것을 types/package.ts로 옮겨, 앱 설치 모달·펌웨어 설치 모달·디바이스 상세의 설치 명령이 같은 정의를 공유합니다. 설치 상세 모달의 단말 테이블(getPkgInstallModalDeviceColumns)과 설치 단말 목록(InstalledPkgModal)도 IS_KT/IS_NOT_KT로 deviceId·deviceSiteId 컬럼을 감추던 방식 대신, 사이트 대표 식별자 DEV_MAIN_KEY(KT는 deviceSiteId, XLSmart는 serial, 그 외는 deviceId) 컬럼 하나로 정리되었습니다. InstalledPkgModal은 대표 식별자가 macAddress인 사이트에서 MAC 컬럼을 중복 노출하지 않고, 제목도 appName(V버전)(패키지명) 형식으로 바뀌었습니다. 이 모달은 이번 범위에서 한 번 더 정리되어, 사이트와 무관하게 하드코딩돼 있던 serial 컬럼이 제거되고 검색 라벨·검색 조건도 items.device_id 고정 문구 대신 DEV_MAIN_KEY.name/DEV_MAIN_KEY.id로 통일되었습니다(XLSmart에서 S/N 컬럼이 두 번 보이던 문제 해소).

defaultPackage는 단말 초기 구성에 들어갈 기본 패키지(/api/v1/default-packages)와 관리 앱(managed-app) XML 업로드를 다루고, appPolicy는 Threshold(임계치)·App Exception·화이트리스트/블랙리스트·managed-app 탭을 묶는 컨테이너로 하위 목록은 whiteList.tsx가 공용 처리합니다. 새로 추가된 App Exception 탭(appExceiptionList.tsx)은 getExceptionPolicies(/api/v1/app-exception-policies)로 앱 예외 정책 목록을 조회해 예외 코드별 Enable/Disable 상태를 보여주고, 편집 모달(ExceptionEditModal)에서 체크한 항목들을 editExceptionPolicies(/api/v1/app-exception-policies/bulk/update)로 일괄 저장합니다(XLSmart admin-api 변경 반영). 화이트/블랙리스트 편집 모달(PolicyAppListEditModal)은 getDefaultGroupedPkg(/default-packages/grouped)로 같은 이름의 패키지를 묶어 버전을 select로 고르게 합니다. 목록 컬럼은 getAppPackageName 유틸이 앱 이름이 있으면 appName(패키지명) 형식으로 표시합니다(appmanagement.columns.ts). 기본 패키지·화이트/블랙리스트 목록은 행에서 appName까지 함께 들고 있다가 설치 단말 모달로 넘겨 제목에 앱 이름을 표시하고, 정책 앱 직접 등록 모달(PackageRegistModal)에는 Package Name 입력이 추가되어 App Name(appName)과 패키지 식별자(name)를 나눠 받습니다. Package Name을 비우면 App Name을 식별자로 쓰고, 필수 입력은 App Name·Version 둘뿐이며 Description은 선택 항목이 되었습니다.

사이트 대표 식별자(DEV_MAIN_KEY)로의 정리
앱 설치 중지 API(/app-package-installs/{id}/stop)와 설치 목록 단일 패키지 표시, 화이트/블랙리스트 버전 select, 패키지명 표시의 getAppPackageName 통일, XLSmart 대응 App Exception 정책 탭(app-exception-policies 조회·bulk update)이 앞선 작업으로 반영되었습니다. 이번 범위에서는 XLSmart 대응이 이어져, 단말 식별자를 화면마다 IS_KT로 분기하던 코드가 utils/env.ts의 DEV_MAIN_KEY 한 곳으로 모였고(XLSmart는 serial을 대표 식별자로 사용), 설치 예약 시각이 사이트별 타임스탬프 형식(formatToIsoDateTime)을 따르도록 바뀌었으며, APK 업로드 화면(packageFileUpload)이 업로드 모달로 일원화되면서 삭제되었습니다.

흐름. 업로드 모달이 APK를 분석해 입력값을 채우고 이름·버전 중복 검사를 거쳐 업로드한 뒤, 대상 그룹·시각·모드를 지정해 install로 배포하고 설치 히스토리 상태를 폴링해 단말별 결과를 확인합니다. 설치 시각은 사이트별 타임스탬프 형식으로 변환해 보내며, 진행 중인 배포는 설치 상세 모달(PkgInstallModal)에서 중지(stop)·재시도(retry)할 수 있습니다.

관계. 앱 관리 하위 화면들이 AppApiManager 하나를 공유해 패키지 CRUD·설치(중지 포함)·정책을 처리합니다. APK 업로드는 UploadModal이 분석(analyze-apk2)·중복 검사·multipart/form-data 전송을 맡고 managed-app XML은 FormData(isForm)로 전송되며, 설치 예약 모달은 사이트별 타임스탬프 변환과 공용 MODE_LIST·DEV_MAIN_KEY 컬럼을 사용합니다. 정책 편집 모달은 getDefaultGroupedPkg로 이름별 버전 목록을 받아 select로 제공합니다. App Exception 탭(AppExceiptionList)은 예외 정책을 조회해 편집 모달의 체크 결과를 bulk update로 저장합니다.

pages/appmanagement/modal/UploadModal.tsx — APK 분석 → 중복 검사 → multipart 업로드
// 1) 파일을 고르면 APK 를 분석해 입력값을 자동으로 채운다
beAxios.post('/api/v1/app-packages/analyze-apk2', analyzeFormData, {
  headers: { 'Content-Type': 'multipart/form-data' }
}).then((response) => {
  const responseData = response.data.data;
  formik.setFieldValue('name', responseData.name);
  isPKG && formik.setFieldValue('appName', responseData.appName);
  formik.setFieldValue('version', responseData.version);
  formik.setFieldValue('description', responseData.description);
});

// 2) 업로드 시 이름·버전 중복을 먼저 확인한다 (ApiManager = App 또는 Firmware)
onSubmit: (values, { setSubmitting }) => {
  ApiManager.checkName((result, data) => {
    if (result && data.available) {
      if (!fileData.filepath) fileUpload();     // multipart 업로드 (진행률 표시)
      else filePathUpload();                    // 서버가 이미 받은 파일 경로로 등록
    } else {
      setInvalidModalOpen(true);
    }
  }, values.name, values.version);
}

// 3) createApi = isPKG ? '/api/v1/app-packages' : '/api/v1/firmwares'
formData.append('content', formik.values.file);
formData.append('name', formik.values.name);
isPKG && formData.append('appName', formik.values.appName);
await beAxios.post(createApi, formData, { headers: { 'Content-Type': 'multipart/form-data' }, onUploadProgress });
_api/App.tsx — 그룹 단위 설치·설치 중지·App Exception 정책
install: (callback, packageIds, mode, installTime, deviceGroupIds: number[]) => {
  request('post', `/api/v1/app-package-installs`, callback,
    { packageIds, mode, installTime, deviceGroupIds });
},
getInstallStop: (callback, id: number) => {
  request('post', `/api/v1/app-package-installs/${id}/stop`, callback);
},
// App Exception 정책 (XLSmart admin-api)
getExceptionPolicies: (callback) => {
  request('get', `/api/v1/app-exception-policies`, callback);
},
editExceptionPolicies: (callback, data) => {
  request('post', `/api/v1/app-exception-policies/bulk/update`, callback, { policies: data });
}
utils/common.tsx · appmanagement.columns.ts — 앱 이름(appName) 표시 유틸과 목록 컬럼
// utils/common.tsx — 앱 이름이 있으면 "appName(패키지명)" 형식으로 표시
export const getAppPackageName = (app: { name: string; appName?: string }): string => {
  return app.appName ? `${app.appName}(${app.name})` : `${app.name}`;
};

// appmanagement.columns.ts — 패키지 목록의 App Name 컬럼
{
  id: 'appName',
  label: t('cm:items.app_name'),
  type: 'custom',
  component: (data: any, row: any, rows: any[]) => {
    return getAppPackageName(row);
  }
}
