웹 터미널

기능 개요

웹 터미널은 운영자가 브라우저에서 단말에 원격 셸을 붙이는 기능으로, utils/env.ts의 modulePermissions.terminal이 OBE·TTG·XLSmart·IBC 타깃일 때만 활성화됩니다(IBC는 이상감지 모듈 도입과 함께, XLSmart는 그 뒤에 추가). 같은 값이 commands.tsx의 명령 목록과 역할 권한 화면(CommandPermission.tsx)의 TERMINAL_COMMAND 항목 노출도 함께 결정합니다. 구현은 두 갈래입니다. 첫째, 독립 페이지 pages/terminal/terminal.tsx는 URL 쿼리의 address를 읽어 REACT_APP_WEB_TERMINAL(wetty) 주소를 iframe으로 임베드합니다. 즉 셸 세션 자체는 wetty 서버가 제공하고 RMS UI는 그 화면을 감싸기만 합니다.

둘째, 디바이스 상세 모달 안의 terminalModal.tsx는 @xterm/xterm + @xterm/addon-fit으로 터미널 에뮬레이터를 직접 그립니다. 사용자가 한 줄을 입력해 엔터를 치면 sendTerminal()이 DevicesApiManager.specialCommands(..., 'TERMINAL_COMMAND', { terminalCommand })로 명령을 전송하고 transactionId를 받습니다. 명령 실행 결과는 useSSEController가 구독한 /api/v1/notifications/subscribe SSE의 NOTIFICATION 이벤트로 도착해 xterm에 출력됩니다. 응답이 지연되면 로딩 애니메이션을 돌리고, REACT_APP_RMS_SSE_TIMEOUT 초가 지나면 타임아웃 메시지를 표시합니다. 여기에 선택적 issueId prop이 더해져, Quick Operation 이슈에서 열린 터미널이면 명령 전송이 성공한 시점에 DevicesApiManager.inprogressQuickOperation(cb, issueId, connectionId)(POST /api/v1/quick/operation/{id}/inprogress)를 함께 호출해 그 이슈를 진행 중 상태로 올립니다. issueId는 다른 명령 모달과 동일하게 pages/device/commands.tsx가 내려 줍니다.

명령 전송과 결과 수신의 분리
xterm 터미널은 입력을 specialCommands(REST)로 보내고, 출력은 SSE(NOTIFICATION)로 비동기 수신하는 요청/이벤트 분리 구조입니다. 단말이 결과를 올릴 때까지 모달은 SSE 구독을 유지하며(connect(true)), 입력은 로컬 에코로 즉시 화면에 반영합니다.

핵심 코드

pages/device/modal/terminalModal.tsx — xterm 입력을 명령으로 전송
import { Terminal } from '@xterm/xterm';
import { FitAddon } from '@xterm/addon-fit';

const sendTerminal = (request: string) => {
  DevicesApiManager.specialCommands((result, data, code, message) => {
    if (result && message === 'OK' && data?.transactionId) {
      if (issueId) {
        // Quick Operation 이슈에서 열린 터미널이면 그 이슈를 진행 중으로 표시
        DevicesApiManager.inprogressQuickOperation(() => {}, issueId, connectionId);
      }
      setTransactionId(data?.transactionId);
      startSafeTimer();   // SSE_TIMEOUT 까지 결과 대기
    }
  }, connectionId, 'TERMINAL_COMMAND', { terminalCommand: request });
};
