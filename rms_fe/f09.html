Master 정책 설정

Master 화면이 STB·App 디바이스 정책을 탭으로 나눠 보여주고, devicePolicyStbRegister가 DevicesApiManager.createPolicy()로 사이트 공통 정책(/api/v1/device-policies)을 등록·수정합니다. 등록/수정 4개 화면의 폼 본문은 policy/components/* 공통 섹션 컴포넌트로 분리되어 있습니다.

기능 개요

Master 정책은 사이트 전체에 공통으로 적용되는 디바이스 정책을 정의하는 영역입니다. devicePolicyList가 STB 탭(devicePolicyTabStb)과 App 탭(devicePolicyTabApp)으로 나뉘어 정책 목록을 보여주고, DevicesApiManager.getPolicyList()(/api/v1/device-policies)로 조회합니다. STB 정책은 단말 정보 업데이트 주기(period)·CPU/온도/네트워크 사용량 임계 등 모니터링 항목을, App 정책은 앱 디바이스 관련 항목을 다룹니다. App 탭 검색은 패키지명 대신 앱 이름(fullName) 기준으로 바뀌었고 앱 크래시·메모리/CPU/네트워크/HDD 임계·정책 상태 필터를 제공합니다(기존 셋톱 재시작 stbReboot 필터는 제거).

정책 등록은 policy/devicePolicyStbRegister(및 App/Edit 화면)가 Formik 폼으로 처리합니다. 저장 시 checkPolicyName(type, name)으로 정책명 중복을 검사한 뒤, 즉시 적용/예약 여부(immediately)에 따라 createPolicy()로 /api/v1/device-policies에 POST 합니다. 수정은 updatePolicy(/device-policies/:id/update)를 사용합니다. STB 정책에는 부팅 시 자동 실행(autoLaunchOnBoot) 항목이 추가되어(XLSmart 대응) Switch로 On/Off 하고, PackageListModal에서 대상 앱을 선택해 autoLaunchOnBootPackageName/autoLaunchOnBootAppName을 지정합니다. App 정책 등록도 같은 모달에서 앱 이름과 패키지명을 분리해 받아(getPackageName(name, pkgName)) 정책 name에는 패키지명을 저장합니다. STB 정책의 정보 업데이트 주기 같은 항목은 사이트 정책 주기 기본값(stpPolicyPeriodMin)과 연계됩니다.

STB 정책에는 대기(standby) 상태 자동 재부팅(Reboot Automation, standbyReboot*) 항목이 추가되었습니다(OBE 대응). Switch(standbyRebootEnabled)를 켜면 TimeAutocomplete로 From/To 시간대를 30분 단위 옵션에서 고르고(readOnly·disableClearable로 수동 입력 방지), 재확인 주기(standbyRebootIntervalMinute)는 5/10/15/20분 중에서 선택합니다. From이 To보다 빠르지 않으면 validateTimeRange(dayjs)가 timeError를 세워 검증 모달을 띄우고, standbyRebootEnabled가 켜진 채 시간 오류가 남아 있으면 저장이 중단됩니다. 저장 시 standbyRebootFromHour/Minute·standbyRebootToHour/Minute·standbyRebootIntervalMinute 6개 필드가 createPolicy/updatePolicy 파라미터에 포함됩니다.

정책 등록·수정 화면 4개(STB 등록/수정, App 등록/수정)에 중복돼 있던 폼 본문은 pages/master/policy/components/ 아래 공통 섹션 컴포넌트로 분리되었습니다. StbConditionSection(메모리·CPU·CPU 온도·네트워크·HDD 임계), PolicyActionSection(types/devicePolicy의 actions 체크박스 묶음 — 이번 범위부터 utils/env.ts의 policyActionPermissions로 항목 자체가 필터링되어, TTG 타깃은 Restart App·Close Background Apps 두 액션이 목록에서 아예 빠집니다), StbPeriodSection(단말 정보 업데이트 주기), StbAutoLaunchSection(부팅 시 자동 실행 + 앱 선택 모달 열기), StbRebootSection(Reboot Automation From/To·재확인 주기) 다섯 개가 각각 formik을 프로퍼티로 받아 렌더하고, STB 등록/수정 화면은 이 순서 그대로 조립만 합니다. 화면별 차이는 프로퍼티로 흡수되어, 수정 화면은 dynamicSwitchType으로 값이 0보다 큰 항목만 스위치를 켠 상태로 시작하고 App 등록 화면은 PolicyActionSection에 커스텀 체크박스 아이콘(CheckOff/CheckOn)과 spacing을 주입합니다. 이 분리로 devicePolicyStbEdit·devicePolicyStbRegister는 각각 400줄 가까이 줄었습니다.

수정 화면에서는 Reboot Automation 시간 검증 초기값도 보정되었습니다. timeError가 기본 true로 시작하기 때문에, 이미 대기 재부팅이 켜진 정책을 수정할 때 시간을 다시 건드리지 않으면 저장이 막히는 문제가 있었습니다. devicePolicyStbEdit는 마운트 시 state.standbyRebootEnabled이면 setTimeError(false)로 초기화해(OBE 대응) 기존 값 그대로 저장할 수 있게 했습니다. 함께 정책 화면 전반의 console.log도 공통 로거(log.debug)로 정리되었습니다.

사이트별 정책 주기 기본값
utils/env.ts의 stpPolicyPeriodMin은 KT 타깃이면 10분, 그 외에는 5분으로 분기됩니다. 같은 정책 화면이라도 사이트에 따라 단말 정보 업데이트 주기의 기준값이 달라집니다.

흐름. STB/App 탭으로 정책 목록을 조회하고, 등록 폼에서 자동 실행 대상 앱을 PackageListModal로 선택하고 Reboot Automation 시간대를 dayjs로 검증(From < To)한 뒤, 정책명 중복 검사를 거쳐 createPolicy로 사이트 공통 정책을 저장합니다.

관계. DevicePolicyList가 STB/App 탭을 소유하고, 등록·수정 화면은 DevicesApiManager의 정책 엔드포인트를 호출하면서 폼 본문은 다섯 개 공통 섹션 컴포넌트를 조립해 구성합니다. 앱 선택 모달과 시간 선택 컴포넌트는 각각 StbAutoLaunchSection·StbRebootSection이 소유하고, 정책 주기 기본값은 env.ts에서 분기됩니다. App 정책 등록/수정도 같은 PolicyActionSection을 씁니다.

const validateTimeRange = (fTime: string, tTime: string) => {
  const from = dayjs(`${fTime}`, 'HH:mm');
  const to = dayjs(`${tTime}`, 'HH:mm');
  if (!from.isBefore(to)) {
    setTimeError(true);
    setValidateModal({ open: true, content: 7 });   // 유효하지 않은 시간대
  } else {
    setTimeError(false);
  }
};

const [timeError, setTimeError] = useState<boolean>(true);

useEffect(() => {
  state.standbyRebootEnabled && setTimeError(false);   // 기존에 켜져 있던 정책은 오류 없음으로 시작
}, []);

const validCondition = async () => {

    setValidateModal({ open: true, content: 7 });   // 유효하지 않은 시간대
    return false;
  }
  // ...period 검사
};
