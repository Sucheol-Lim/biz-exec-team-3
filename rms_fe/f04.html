기능 개요

VoC(Voice of Customer) 영역은 상담원이 자신의 응대 현황과 이력을 한 화면에서 확인하도록 돕습니다. 핵심 화면 agentDevicelist.tsx 상단 My VOC Overview 카드는 일/월 기간을 선택해 VocApiManager.getVOCAgentOverview()(/api/v2/voc/agent/overview)로 응대 요약을 받아, 총 처리 건수·평균 해결 시간·세션당 평균 명령 수를 AgentDevicelistInfoButton 위젯으로, 상위 이슈 유형(topIssueTypes)을 CustomizedBarchart로, 처리 현황(resolutionStatus)을 ActiveDeviceDonutChart로 시각화합니다.

하단 My VOC History 카드는 getVOCHistory()(/api/v2/voc/history, agent=로그인 clientId 필수)로 응대 이력 테이블을 채웁니다. Overview와 같은 일/월 기간 선택이 from/to 파라미터로 함께 전달되어 이력도 기간으로 필터링되며(일 모드는 YYYYMMDD, 월 모드는 월초~월말로 변환), 기간·모드를 바꾸면 페이지를 0으로 리셋한 뒤 재조회합니다. 검색 조건을 이슈 유형으로 바꾸면 getIssueList()로 선택 목록을 불러오며, 선택값이 All이면 해당 조건을 아예 파라미터에서 빼 전체 조회가 되도록 고쳤습니다(종전에는 issue=All이 그대로 실려 결과가 비었습니다). 이력 행 데이터에는 serial·macAddress가 함께 매핑되어 단말 상세 모달로 전달됩니다. 테이블 컬럼과 검색 옵션(voc.columns.ts·voc.searchOption.ts)도 deviceId/deviceSiteId 두 벌 정의를 걷어내고 사이트 대표 식별자 DEV_MAIN_KEY(KT deviceSiteId · XLSmart serial · 그 외 deviceId) 한 항목으로 통합했으며, 그 자리에 MAC 주소 컬럼이 추가되었습니다(대표 식별자가 이미 macAddress인 사이트에서는 숨김). 이력 행을 클릭하면 ConnectIssueReportViewModal로 해당 연결의 이슈 리포트를 조회·수정하고, Initiate VOC Session 버튼으로 InitiatedVOCSessionModal을 열어 단말을 검색해 VoC 세션을 개시합니다. 세션 모달의 인터페이스는 setOpen 상태 setter를 넘기던 방식에서 onClose 콜백 하나로 정리되어, 모달을 닫으면 agentDevicelist가 searchFinished()로 이력을 다시 조회한 뒤 닫습니다. 세션 모달의 단말 검색도 값이 All인 조건은 쿼리에서 제외하고, 결과가 있을 때 모달 최대 높이를 810px로 늘려 목록이 잘리지 않게 했습니다. 그 외 VoC 대시보드 영역은 VocApiManager의 voc-overview/voc-connection-status 계열 엔드포인트로 활성 단말 수, 모델/OS 분포, 연결 사유 통계 등을 집계합니다.

세션 개시 시의 단말 재연결 처리도 바뀌었습니다. 예전에는 InitiatedVOCSessionModal이 DEVICE_CONNECTION 명령을 보낸 뒤 DEVICE_CONNECTION_TIME_LEFT(30초)·DEVICE_CONNECTION_COUNTDOWN_INTERVAL(1초) 상수로 자체 폴링을 돌렸지만, 지금은 명령 직후 isCommandSent: true를 실어 useTask().openDeviceDetailModal()로 단말 상세 모달을 먼저 열고 폴링은 모달 본체(pages/device/detailWrapper.tsx)가 이어받습니다. 모달을 닫을 때 실행되는 callback도 시그니처가 (connId, status)로 바뀌어, TaskContext.closeDeviceDetailModal이 넘겨준 connectionId와 세션 상태를 보고 이슈 리포트 모달을 띄울지 결정합니다. 이슈 리포트 모달(recentConnectIssueReportModal)은 기존 리포트 조회 조건이 type === MODIFY에서 id 존재 여부로 완화되었고, 연결 단말 요약에 표시하는 보조 식별자는 공용 TargetGuard 컴포넌트로 분기되어 KT 타깃은 macAddress, 그 외 타깃은 serial을 보여줍니다. 상세 모달로 넘기는 ModalProps에도 serial·macAddress가 추가되어, 대표 식별자가 사이트마다 달라도 모달이 같은 값으로 단말을 표시합니다.

단말 한 대의 VoC 이력을 따로 읽는 getVocHistory(deviceId)(GET /api/v2/voc/devices/{deviceId}/history)도 VocApiManager에 추가되었습니다. 단말 상세 모달의 Info 탭(pages/device/infoTab.tsx)이 roleLevel이 Level1일 때만 이 API를 호출해, 상담원 권한 계정에서 해당 단말의 과거 VoC 응대 이력을 상세 화면 안에서 바로 확인하도록 합니다.

agent 파라미터
VoC agent 화면에서는 이력 조회(getVOCHistory) 시 상담원(agent)을 필수 파라미터로 추가하고(소스 주석 명시), 조회 기간(from/to)도 함께 전달합니다. 즉 같은 이력 조회 API라도 VoC agent 컨텍스트에서는 "누가, 어느 기간에 응대했는가"를 함께 식별합니다.

흐름. 화면 진입 시 상담원 응대 요약과 이력(agent 필수·기간 from/to 포함)을 조회해 위젯·차트·테이블로 표시하고, 이력 행에서 이슈 리포트를 확인하거나 InitiatedVOCSessionModal로 응대 세션을 시작합니다. 세션 개시는 재연결 명령 직후 단말 상세 모달을 열고, 모달이 닫힐 때 받은 connId·status로 이슈 리포트 작성 여부를 판단합니다.

관계. AgentDevicelist가 VocApiManager로 응대 통계·이력을 받아 요약 위젯과 도넛/바 차트로 그리고, 이력 행 클릭 시 이슈 리포트 모달을, 응대 시작 시 InitiatedVOCSessionModal을 소유합니다. 세션 모달은 단말 상세 모달의 생명주기를 TaskContext에 위임하고, 모달 종료 콜백으로 받은 연결 정보로 이슈 리포트 작성 여부를 정합니다.

핵심 코드

_api/Voc.tsx — VoC 이력·상담원 응대 요약 조회 (v2 엔드포인트)
getVOCHistory: (callback: CallbackFunction, data: any) => {
  // queryParam = deviceId, agent, issue
  // voc agent 에서는 agent를 필수로 추가
  request('get', `/api/v2/voc/history`, callback, data);
},
getVOCAgentOverview: (callback: CallbackFunction, from: string, to: string) => {
  const data = { from, to };
  request('get', `/api/v2/voc/agent/overview`, callback, data);
},
pages/voc/agentDevicelist.tsx — agent·기간(from/to) 이력 조회와 VoC 세션 모달 트리거
const request = {
  page: page,
  size: rowsPerPage,
  agent: user?.clientId,
  from: convertDateFormat2(startDate, dateMode === 'date' ? 'YYYYMMDD' : 'YYYYMM01'),
  to: convertDateFormat2(endDate, dateMode === 'date' ? 'YYYYMMDD' : 'YYYYMM' + getLastDayOfMonth(endDate)),
  ...(searchItem?.id && searchItem?.searchValue && { [searchItem.id]: searchItem.searchValue })
};
VocApiManager.getVOCHistory((result, data) => { /* 응대 이력 테이블 */ }, request);
// ...
VocApiManager.getVOCAgentOverview((result, data) => { /* 요약 위젯·차트 */ }, from, to);
// ...
{openVOCSession && (
  <InitiateVOCSessioModal
    open={openVOCSession}
    onClose={() => { searchFinished(); setOpenVOCSession(false); }}   // 닫으면 이력 재조회
  />
)}
pages/management/components/InitiatedVOCSessionModal.tsx — 재연결 대기를 상세 모달에 위임하고, 종료 콜백으로 이슈 리포트 오픈 판단
const modalInfo: ModalProps = {
  id: data.id,
  deviceId: data.deviceId,
  path: VOC,
  isConnected,
  callback: (connId, status) => {              // 모달 종료 시 TaskContext가 전달
    connectionId.current = connId;
    onSearch();
    connId !== 0 && setOpenIssueReportModal(status === 'CONNECTED');
  },
  key: data.deviceId,
  modalType: 'device_info',
  connectionId: data.connectionId,
  isCommandSent: data.isCommandSent               // 구 isMine 제거
};
openDeviceDetailModal(modalInfo);

// DISCONNECTED + ONLINE 이면 DEVICE_CONNECTION 명령 직후 곧바로 goDetail({ ..., isCommandSent: true })
