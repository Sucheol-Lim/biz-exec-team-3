개요

RMS FrontEnd(rms_fe)는 Altimedia RMS(Remote Management System)의 관리자용 웹 UI입니다. 운영자가 브라우저로 접속해 현장에 배포된 다수의 Android 기반 셋톱박스(STB)/OTT 단말을 원격으로 모니터링하고 제어하는 단일 페이지 애플리케이션(SPA)입니다. 빌드 산출물은 정적 자원으로 패키징되어 /rms-ui 경로 하위에 배포되며, 사내 접속 URL은 https://rms.altimedia.com/rms-ui/index.html입니다.

대상 사용자는 운영자 PC의 데스크톱 브라우저이며, 관리 대상은 Android STB/OTT 디바이스입니다. 화면은 모니터링 대시보드, VoC(고객 응대), 단말(Device) 관리, 앱(App) 관리, OTA(펌웨어) 관리, 관리자(Administrator) 설정, Master 정책, Workflow, 웹 터미널, AI 챗봇 등 운영자가 단말 생애주기 전반을 다룰 수 있도록 구성되어 있습니다.

이 프론트엔드는 단일 코드베이스를 여러 사이트에 공통 배포하는 멀티 타깃 구조입니다. .env.* 파일과 src/utils/env.ts의 REACT_APP_TARGET 값으로 사이트를 구분하며, 확인된 타깃은 KT, OBE, TTG, XLSmart, IBC, GLOBAL(기본값)입니다. 타깃별로 웹 터미널, 고급 메시지, 런처 리셋, WiFi 메뉴 노출, 위치 지도/네트워크 위젯, 챗봇 노출, 단말 식별자 필드(KT는 deviceSiteId, 그 외 deviceId) 등이 분기되며, XLSmart는 Illegal Devices 위젯과 KPI 위젯 5개(대시보드 cols 20) 레이아웃을 추가로 사용합니다. IBC 타깃에는 이상 감지(anomalyDetect) 모듈·AI 챗봇·웹 터미널 분기가 활성화되어 있습니다.

단말 연동 기본 흐름
운영자가 Management 메뉴의 Excel import로 단말 정보를 서버에 등록한 뒤 단말을 부팅하면, 단말의 RMS Client가 등록 정보를 바탕으로 인증하고 상태/정보를 서버에 올립니다. Screen Share·Terminal 같은 실시간 기능은 단말이 accessToken을 받아 connection 된 상태에서만 동작합니다(Confluence "RMS FE 단말 연동 방법").

주요 기능

모니터링 대시보드
단말 상태를 실시간 집계해 보여주는 RMS 대시보드입니다. react-grid-layout 기반 드래그 가능한 위젯 그리드로 구성되며, ApexCharts/Nivo 차트로 지표를 시각화합니다.
시스템 모니터링 · Quick Operation
시스템 상태 화면(dashboardSystem)과 다수 단말에 명령을 일괄 적용하는 Quick Operation 화면을 제공합니다. Grafana(node-exporter) 모니터링과도 연계됩니다.
배치 리포트
배치로 집계된 리포트 목록과 상세(batchReport/batchReportDetail)를 조회하고, react-csv로 결과를 내보낼 수 있습니다.
VoC 고객 응대
VoC 대시보드와 에이전트별 단말 조회 화면(agentDevicelist)을 제공해 상담원이 특정 가입자 단말의 상태를 빠르게 확인하도록 지원합니다.
단말(Device) 관리
단말 목록/상세, 단말 편집, 그룹 관리, 단말 정책(STB Policy)을 다룹니다. Excel import로 단말을 등록하고 그룹 단위 일괄 운영이 가능하며, Locked Devices 탭에서 잠금 단말과 잠금 사유(lockReason)를 관리합니다.
앱(App) 관리
패키지 목록·설치, 기본 패키지(DefaultPackage), 앱 정책(AppPolicy) 등록/수정을 지원합니다. OBE 사이트에서는 패키지명 대신 앱 이름(appName)으로 표시합니다.
OTA(펌웨어) 관리
펌웨어 목록(fwList)과 펌웨어 설치(fwInstall) 화면으로 단말 펌웨어 OTA 업데이트를 운영합니다.
관리자 · 역할(Role) 관리
관리자 계정 등록/상세, 역할(Role) 기반 권한, 알림 설정(AlertSetting, 메일/OTT/Network Offline 알림 편집), 운영 이력(OperationHistory)을 관리합니다. 로그인·마스킹 접속 이력을 보는 History 탭과 Level3 계정용 개인정보 마스킹 전환 스위치가 추가되었습니다. KT 타깃은 LDAP 기반 가입 신청 승인/거절(Pending Approval) 탭을 별도 제공합니다.
Master 정책 설정
단말(STB)·앱 디바이스 정책을 등록·수정하는 Master 화면(devicePolicyStb*/devicePolicyApp*)으로 사이트 공통 정책을 정의합니다.
실시간 원격 제어 · 화면 공유
WebSocket 시그널 서버와 SSE로 단말 상태/이벤트를 수신하며 Screen Share, 원격 명령, 디바이스 모달 폴링(10초) 등 실시간 제어를 수행합니다.
웹 터미널
@xterm/xterm 기반 웹 터미널(pages/terminal)로 단말에 원격 셸을 연결합니다(wetty 연동). OBE·TTG·IBC 타깃에서만 활성화됩니다.
AI 챗봇
사내 패키지 @altimedia/rms-chatbot-ui를 연동한 챗봇 팝업입니다. 디바이스/사용자 정보 요청과 화면 공유·앱 설치·펌웨어 OTA 등으로의 네비게이션을 처리하며 IBC 타깃에서만 노출됩니다.
국제화(i18n)
i18next/react-i18next로 다국어를 지원합니다. 로케일은 en·fr·tr·du가 포함되어 글로벌 사이트 대응이 가능합니다.
사이트별 기능 분기
REACT_APP_TARGET에 따라 모듈 권한·위젯 권한·정책 주기·식별자 필드를 분기해 KT/OBE/TTG/XLSmart/IBC/GLOBAL을 한 코드베이스로 운영합니다.

아키텍처 · 모듈 구조

Create React App(react-scripts)을 react-app-rewired + config-overrides.js로 확장한 React SPA입니다. 전역 상태는 Redux Toolkit, 서버 상태는 react-query가 담당하며 라우팅은 react-router-dom으로 코드 스플리팅(lazy + Loadable)됩니다. 인증/권한은 React Context(JWTContext, PermissionContext)로 처리하고, 백엔드 통신은 src/_api의 axios 인스턴스(beAxios)와 WebSocket/SSE로 이뤄집니다.

계층 · 외부 연동

UI 계층은 MUI(Material UI)/antd 기반 Mantis 테마를 사용하며, 좌측 Navigation 메뉴와 공용 테이블·차트·Leaflet 지도·드래그 그리드를 components/sections로 제공합니다. 백엔드(RMS ADM 서버)와는 REST(axios), 실시간 이벤트는 WebSocket 시그널 서버와 SSE로 연결됩니다. 단말과의 원격 셸은 wetty(REACT_APP_WEB_TERMINAL), 시스템 메트릭은 Grafana(REACT_APP_RMS_GRAFANA_URL)와 연계됩니다. 배포는 Docker(node:20.11.1 빌드 후 serve) 또는 Kubernetes/Helm(infra/helm — 구 eks/에서 이전, XLSmart AWS용 rms-ui-app 차트·buildspec 포함)에서 nginx로 /rms-ui를 서빙합니다.

핵심 동작 흐름

운영자 로그인 · 권한 진입

  1. 로그인 화면 진입LoginRoutes로 진입해 운영자 계정/비밀번호를 입력합니다. JWTContext가 /api/v1/auth로 인증 요청을 보냅니다(이때 authorization 헤더는 비움).
  2. 토큰 발급·보관발급된 accessToken을 sessionStorage에 저장합니다. 이후 모든 요청은 axios 인터셉터가 토큰과 Time-Zone 헤더를 자동 주입합니다.
  3. AuthGuard · PermissionGuard메인 라우트는 AuthGuard로 로그인 여부를, PermissionGuard로 역할(Role) 기반 메뉴 접근 권한을 검사합니다. 통과하면 MainLayout과 좌측 Navigation이 렌더링됩니다.
  4. 사이트 분기 적용REACT_APP_TARGET에 따라 modulePermissions/widgetPermissions가 평가되어 터미널·챗봇·WiFi 메뉴·위젯 노출과 단말 식별자 필드가 결정됩니다.

단말 등록 · 연동

  1. Excel 템플릿 작성Management 메뉴에서 단말 등록용 Excel 템플릿을 내려받아 4개 항목을 기입합니다(Confluence "RMS FE 단말 연동 방법").
  2. Excel import작성한 파일을 import 하면 단말 정보가 서버에 등록됩니다. 프론트엔드는 multipart/form-data 폼으로 파일을 전송합니다.
  3. 단말 부팅·인증단말을 부팅하면 RMS Client가 등록 정보로 인증하고 상태/기타 정보를 서버에 올립니다. 목록·상세 화면에서 연동 단말을 확인할 수 있습니다.
  4. 실시간 connection단말에서 RMS Client가 accessToken을 받거나 Management의 Connection Device 명령을 내리면 connection 되어, Screen Share·Terminal 등 실시간 기능을 사용할 수 있습니다.

이상 감지 이슈 확인 · 명령 발송 (IBC)

  1. AI 분석 실행 · 상태 폴링AI Analyze 버튼이 /api/v1/anomaly-detections/dispatch로 분석을 요청하고, anomaly-detections/runs/latest를 주기적으로 폴링해 분석 진행 상태를 버튼에 표시합니다.
  2. 이슈 목록 조회all/cpu/memory/network/crash 탭이 thresholdType으로 /api/v1/quick-operation-issues를 조회하고, /stats로 탭별 건수를, /recurring으로 Top Recurring Issues를 채웁니다. ?deviceId=로 진입하면 해당 단말이 검색 조건에 자동 입력됩니다.
  3. 대상 단말 확인ViewDevicesModal·SelectDevicesApplyModal이 /api/v1/quick-operation-issues/{issueId}/devices로 이슈에 속한 단말을 페이지 단위로 조회합니다. commandSent 조건으로 명령이 이미 발송된 단말을 걸러 볼 수 있습니다.
  4. 명령 발송SendCommandModal에서 commandTypes를 고르고 POST /api/v1/quick-operation-issues/{issueId}/commands로 전송합니다. 이슈 단위 일괄 발송과 선택 단말(deviceIds) 지정 발송을 모두 지원합니다.
  5. 진행 제어 · 이력 확인발송 후에는 commands/pause·resume·stop으로 롤아웃을 일시정지·재개·중지하고, My Command History 모달이 /api/v1/quick-operation-issues/my-command-history로 본인 발송 이력을 조회합니다.

AI 챗봇을 통한 원격 작업

  1. 챗봇 채널 등록ChatPopup이 useChat의 registOnChatbot(receiveMsg)로 챗봇 통신 채널을 등록합니다(챗봇은 IBC 타깃에서만 노출).
  2. 정보/네비게이션 요청sendToFrontend로 ChatRequestType(type=REQ_INFO/REQ_NAV, nav, target)을 전달합니다. nav 값으로 화면 공유·앱 설치·캐시 삭제·네트워크 점검·패킷 캡쳐·펌웨어 OTA·터미널·메시지 등으로 분기합니다.
  3. 응답 처리FE는 ChatResponseType(result, message, ChatResponseData)로 디바이스 연결 여부·소유 여부·accessToken·사용자/권한 정보를 회신하고, 해당 기능 화면으로 네비게이션합니다.

빌드 · 실행

Node 20.x(Dockerfile 기준 node:20.11.1)와 Yarn을 권장합니다. tsconfig.json의 baseUrl: src로 절대 경로 import를 사용합니다.

의존성 설치 · 로컬 개발 서버

yarn            # 또는 npm install

# 로컬 개발 서버 (HTTPS + PORT 8080, OS별 인증서 경로)
yarn mac-start    # macOS  (/Users/rms/cert)
yarn linux-start  # Linux  (/home/rms/cert)
yarn start        # Windows (set 명령으로 동일 환경변수)
로컬 접속 주의
브라우저 접속 후 URL을 https://rms2.altimedia.com:8080/rms-ui로 변경해야 정상 동작하며, hosts 파일에 127.0.0.1 rms2.altimedia.com 매핑이 필요합니다. 인증서는 SSL_CRT_FILE/SSL_KEY_FILE 경로에 배치합니다.

사이트별 빌드 (build.js)

# 인자 형식 (--target은 dev|prod, prod일 때 --domain 필수)
yarn build --version={버전} --target={dev|prod} --compressType={tar|zip} \
           --protocol={http|https} --domain={FE 도메인} --be={BE 도메인} --name={압축파일명}

# 사이트 빌드 예시
yarn build --target=prod --compressType=tar --domain=rms-cloud-obe.altimedia.com --name=OBE          # OBE
yarn build --target=prod --compressType=tar --domain=rms-cloud-xl.altimedia.com  --name=XL           # XL
yarn build --target=prod --compressType=tar --name=TTG --domain=172.28.12.11:8081 \
           --protocol=http --be=172.28.12.11:8080                                                    # TTG
--version 사용 시 git 커밋·푸시
--version을 주면 .env.<target>*의 REACT_APP_VERSION/REACT_APP_BUILD_TIME을 갱신하고 git add/commit/push까지 자동 수행하므로 주의가 필요합니다. --compressType 지정 시 dist/ 하위에 {name}_RMS_FE_{version}.{tar|zip} 압축본을 생성합니다.

그 외 빌드 · 테스트

yarn buildProd --target=ttg      # buildProd.js, target에 맞는 .env 파일 필요
yarn buildProd --target=xl_prod  # XLSmart 운영 (구 rmsai_one)
yarn build:dev                # dotenv -e .env.dev react-app-rewired build
yarn build:ttg / build:aws    # .env.ttg/.env.aws + postbuild compress.js
yarn test                     # react-scripts test (CRA Jest)

산출물은 정적 자원(build/)으로 빌드되어 /rms-ui 경로에 배포됩니다. 컨테이너 배포는 docker build -t rms-ui .(빌드 후 serve로 8080 서빙)이며, Kubernetes는 infra/helm의 차트와 infra/helm/nginx/nginx.conf로 서빙합니다(XLSmart AWS 배포는 infra/helm/xlsmart/rms-ui-app 차트·buildspec 사용, 빌드 타깃은 xl_prod이고 호스트는 xlsmart.rmsai.one입니다). 환경 설정은 .env.local / .env.kt / .env.obe / .env.ttg / .env.ttg.aws / .env.ttg_staging / .env.demo / .env.eu / .env.alti / .env.ai / .env.xl / .env.xl_prod 등 사이트별 파일로 분리됩니다.
