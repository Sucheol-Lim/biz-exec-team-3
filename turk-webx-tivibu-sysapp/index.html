개요

본 프로젝트는 터키 통신사 Türk Telekom의 IPTV 서비스인 Tivibu를 위한 셋톱박스(STB) 시스템 애플리케이션입니다. STB의 기본 사용자 환경을 구성하는 EPG(전자 프로그램 가이드)와 Live TV 시청, 미니가이드, 채널 리스트, 검색, VOD/시리즈 상세, 녹화(Recording), 예약·리마인더, 부모 잠금(Parental Lock), 결제(PPV/구매), 프로필, 설정 등 STB의 핵심 화면과 기능을 하나의 웹 애플리케이션으로 제공합니다. 사내에서는 이 과제를 SYSAPP으로 부릅니다.

대상 단말은 WebX 플랫폼 기반 STB입니다. WebX는 OIPF/HbbTV 계열의 브라우저 기반 STB 미들웨어로, 앱은 이 미들웨어가 제공하는 브라우저(WebKit 계열) 위에서 동작합니다. 라이브 방송 영상은 OIPF의 oipfObjectFactory.createVideoBroadcastObject()로 생성한 Video Broadcast Object(VBO)를 통해 출력하며, VOD 등 OTT 재생에는 HTML5 <video> 요소를 병행합니다. 기준 레이아웃 해상도는 1280×720(720p)이며, AppConfig.PC_BROWSER 플래그로 PC 브라우저에서의 개발·디버깅 모드도 지원합니다.

실제 운영 환경에서 STB은 ZTE의 클라우드 EPG 서버에 올라간 클라이언트를 부팅 시 내려받아 실행합니다. STB이 켜지면 미들웨어가 localApp을 구동해 환경을 점검하고, ZTE의 EAS 서버(개통/로그인 페이지)가 단말의 개통 여부를 판단한 뒤 EPG 서버로 리다이렉트합니다. 배포되는 앱과 API는 frameXXXX 형태의 framecode(ZTE 클라우드 저장소 ID)로 구분됩니다. 본 SYSAPP은 그 EPG 서버에 송출되는 클라이언트 측 애플리케이션입니다.

UI는 TAL(TV Application Layer, antie 네임스페이스) 프레임워크를 기반으로 작성되어 있으며, 다국어 리소스로 터키어(tr.json)와 영어(en.json)를 포함합니다. 빌드 산출물은 일반(default) 버전과, 애니메이션을 비활성화한 구형 단말용 legacy 버전으로 분리되어 제공됩니다.

단말 브랜드
Confluence 문서에 따르면 STB 브랜드는 Humax, Airties, Vestel 세 가지가 있으며, 개발·검증에는 보통 Humax 이미지를 사용합니다. 릴리스 패키지의 framecode(예: Humax용 frame3709/frame4091, Legacy용 frame3729/frame4002)는 ZTE SMS(송출 시스템)에 지정되어 있어 별도 요구가 없는 한 변경하지 않습니다.

주요 기능

Live TV 시청
OIPF Video Broadcast Object로 방송 채널을 출력합니다. 채널 전환, 신호 약함(SignalWeak), 미가입 채널(Unsubscribed) 처리 등을 LiveTVController가 담당합니다.
EPG / TV 가이드
전체 채널·시간대 편성표를 제공하는 가이드 화면입니다. GuideController와 ui2022/guide가 편성 데이터를 렌더링하고 프로그램 상세로 연결합니다.
미니가이드 / 인포 배너
시청 중 채널·프로그램 정보를 띄우는 미니가이드와 인포 배너입니다. MiniGuideController가 타임아웃 기반으로 표시·자동 숨김을 제어합니다.
채널 리스트 · 필터
채널 목록과 즐겨찾기, 장르·구독 기준의 채널 리스트 필터링을 제공합니다. 최근 스프린트에서 필터링 규칙과 디자인이 개선되었습니다.
검색 / 검색 상세
콘텐츠명·채널 검색과 결과 상세 화면입니다. SearchController·SearchDetailController와 화상 키보드(OSK)가 연동됩니다.
VOD / 시리즈 상세 · 재생
VOD·시리즈(시즌/에피소드) 상세와 재생을 제공합니다. VodPlayController·TVDetailController와 SeriesUtil 등 시리즈 모델이 사용됩니다.
녹화(Recording)
프로그램 녹화 예약·관리 기능입니다. RecordingController가 녹화 목록과 에피소드 단위 녹화를 처리합니다.
예약 · 리마인더
방송 시청 예약과 리마인더 팝업을 제공합니다. ReminderController·ReminderPopupController가 시각 도래 시 알림을 띄웁니다.
결제 / PPV / 구매
유료 콘텐츠 구매(PPV)와 결제 흐름입니다. PPVController·PurchaseManager와 캠페인·쿠폰 팝업 컨트롤러가 함께 동작합니다.
부모 잠금 / 핀 관리
연령 등급에 따른 콘텐츠 잠금, 채널 잠금, PIN 입력·생성을 제공합니다. LockManager·PinController·ParentalLockChController가 처리합니다.
프로필 / 사용자 설정
사용자 프로필 선택과 환경설정을 제공합니다. ProfileController·ProfileManager·UserConfigManager가 프로필별 설정을 관리합니다.
설정 · 시스템 관리
언어·화면·시스템 설정과 함께 OTA 펌웨어 업데이트(OTAController), 전원 상태 관리(PowerController), 시계(ClockController) 등을 포함합니다.
PIP / 모자이크 / 5채널
PIP(화면 속 화면), 모자이크 채널(MosaicChannelController), 5채널 뷰(FiveChannelController) 등 다중 영상 화면을 지원합니다.
광고 / 캠페인 / 알림
Google IMA/GPT 기반 광고 삽입(AdController·AdBannerController), 캠페인·쿠폰 팝업, 알림 프레임(NotificationController)을 제공합니다.
CAS · 핑거프린트 · 보안
조건부 접근(CAManager·CasController), 핑거프린트 표시(FingerprintController), HDCP 처리(HDCPController) 등 보안·DRM 연동을 담당합니다.
하트비트 · 로그 업로드
서버 연결 상태 점검(HeartbeatController·ServerManager), 로그 업로드(LogUploadController), 모바일 접속(MobileAccessController) 등 운영 기능을 제공합니다.

아키텍처 · 모듈 구조

앱은 RequireJS(AMD) 모듈로 구성되며, 엔트리 HTML(index.html)이 라이브러리·설정·번들을 로드한 뒤 app/SysApp을 require해 new SysApp(...)으로 애플리케이션을 시작합니다. 코드는 크게 세 계층으로 나뉩니다. (1) tal/의 TAL(antie) 프레임워크, (2) static/core/의 플랫폼·시스템 추상화 레이어, (3) static/app/의 Tivibu 비즈니스 로직·화면 레이어입니다.

계층 관계는 다음과 같습니다. app 레이어의 컨트롤러는 화면 흐름과 비즈니스 로직을 담당하고, 방송 출력·채널 제어·키 입력 등 하드웨어에 가까운 동작은 core 레이어를 통해 추상화합니다. core는 다시 OIPF/HbbTV 미들웨어 API(oipfObjectFactory 등)와 TAL의 device 추상화를 사용합니다. 외부 연동으로는 ZTE의 EPG 서버(콘텐츠·편성 API, framecode 단위), EAS 서버(개통·로그인), MES(WebSocket 메시지 채널), 그리고 Google IMA SDK/GPT(광고)가 있습니다. require.config.js·index.html에 comp: static/comp 별칭이 정의되어 있으나 해당 디렉토리는 현재 존재하지 않으며, UI 컴포넌트는 static/app/ui/comp·static/app/ui2022/comp에 위치합니다.

핵심 동작 흐름

STB 부팅 시퀀스 (Confluence 기준)

  1. 미들웨어(MW) → localApp 구동STB이 켜지면 미들웨어가 먼저 localApp을 구동합니다. localApp은 클라이언트 시작 전 STB 환경(네트워크 연결, DNS, NTP, EAS connectivity)을 점검하고, 문제가 있으면 에러를 노출한 뒤 120초 후 failsafe 모드로 전환합니다.
  2. EAS 로그인 페이지 → 개통 판단localApp이 EAS(ZTE) 서버의 Login 페이지에 단말 값(stbmac, stbip, stbid, stbmodel, terminaltype, language, vendor, systemversion, startupurl)을 전달합니다. 개통된 단말이면 EPG 서버로 리다이렉트하고, 미개통이면 Provisionid 입력 화면을 노출합니다.
  3. EPG 서버 → SYSAPP 로드Login 페이지가 STB의 UP 영역에 loginstatus·sessionid·interfaceurl·epgdomain·usertoken·framecode 등을 기록하고, framecode(예: frame2799/4091)로 식별되는 EPG 서버 저장소에서 본 SYSAPP 클라이언트를 로드합니다.
  4. SysApp 초기화 → 부팅 화면index.html이 lib/configs/bundle을 로드하고 new SysApp(...)을 생성합니다. Türk Telekom 로고와 진행바가 있는 부팅 화면(static-loading-screen)이 표시됩니다.
  5. NavSIMain → 컨트롤러·매니저 구성SysApp.run()이 app/NavSIMain을 로드해 initialize()를 호출하고, 부팅·홈·가이드·채널·전원·잠금·CA·녹화·구매·하트비트 등 50종 이상의 컨트롤러를 초기화합니다.
  6. Live TV 진입초기화가 끝나면 채널 데이터·편성 정보를 받아 SystemInterface의 Video Broadcast Object로 첫 채널 방송을 출력하고, 사용자 입력 대기 상태로 전환합니다.

Live TV 시청 · 채널 전환 흐름

  1. 리모컨 키 입력리모컨 키가 core/controller/KeyEventManager로 전달되고, deviceconfig.js의 키맵에 따라 채널 업/다운·숫자 입력 등으로 해석됩니다.
  2. 채널 결정 · 권한 점검ChannelRing·ChannelList가 다음 채널을 결정하고, 부모 잠금(LockManager)·구독(Unsubscribed)·CA(CAManager) 조건을 점검합니다. 잠긴 채널이면 PIN 입력을 요구합니다.
  3. 방송 튜닝SystemInterface가 Video Broadcast Object로 해당 채널을 튜닝합니다. 신호가 약하면 SignalWeakController가, 미가입이면 UnsubscribedChController가 안내 화면을 표시합니다.
  4. 미니가이드 표시MiniGuideController가 현재·다음 프로그램 정보를 인포 배너로 띄우고, 설정된 타임아웃이 지나면 자동으로 숨깁니다.

릴리스 패키징 흐름 (Confluence 기준)

  1. release_all 빌드grunt release_all을 실행하면 default·legacy 두 종류를 각각 debug/release 로그 레벨로 빌드해 release/ 폴더에 4개 zip을 생성합니다.
  2. framecode별 패키지 산출산출물은 framecode로 구분됩니다. Humax Release frame3709.zip, Humax Debug frame4091.zip, Legacy Release frame3729.zip, Legacy Debug frame4002.zip입니다.
  3. FTP 업로드 · 릴리스 메일Türk Telekom이 지정한 SFTP에 버전 폴더를 만들어 업로드하고, 릴리스 노트와 함께 해당 버전에서 수정한 Jira(VLTRANLAND) 내용을 포함한 릴리스 메일을 발송합니다.

빌드 · 실행

빌드는 Node.js 환경에서 Grunt로 수행합니다. 의존성 설치 후 목적에 맞는 Grunt 태스크를 실행합니다.

# 1) 의존성 설치
npm install

# 2) 기본 빌드 (dist/ 생성: 번들 + 720p CSS + index.html)
npx grunt              # 또는 grunt-cli 전역 설치 시: grunt

# 3) 로컬 개발 서버 (browser-sync + watch, dist 서빙)
npx grunt test

# 4) 난독화 포함 빌드
npx grunt build

# 5) 릴리스 패키징 (난독화 + portal.jsp 생성 + zip, default/legacy 전체)
npx grunt release_all

Gruntfile.js에 정의된 주요 태스크는 다음과 같습니다.

  • default — prebuild(clean/copy/concat/less:default) → requirejs:build(번들, 비난독화) → processhtml:default. 산출물은 dist/index.html, dist/js/bundle.js입니다.
  • legacy — 구형 단말용 빌드. less:legacy(720p_legacy.less)를 사용하고, index.html 빌드 시 애니메이션 비활성화 디바이스 모디파이어(antie/devices/anim/noanim)를 주입합니다.
  • build / build_legacy — uglify로 난독화한 빌드입니다.
  • release / release_legacy / release_all — debug/release 두 로그 레벨로 빌드 후 release/frameXXXX.zip으로 패키징하고 portal.jsp를 생성합니다.
  • test — default 빌드 후 browserSync + watch로 개발 서버를 구동합니다.

빌드 시 RequireJS 번들 엔트리는 app/NavSIMain이며, app/SysApp과 다수의 antie/devices/* 모듈(미디어플레이어 html5, 스토리지 cookie, css3transform 애니메이션, parentalguidance 등)이 함께 포함됩니다. processhtml 단계에서 log_level(debug/error)과 is_legacy(true/false) 변수가 index.html 빌드 토큰에 주입됩니다.

환경 설정 · 디버깅

  • PC 브라우저에서 디버깅하려면 static/app/AppConfig.js의 AppConfig.PC_BROWSER를 true로 설정합니다. 기본값은 false(STB 모드)입니다.
  • 단말 설정·키맵·코덱·레이아웃은 deviceconfig.js에서 PC/STB로 분기해 정의합니다. 기준 레이아웃은 720p입니다.
  • 실제 STB 개발 시에는 PC에 웹 서버를 띄우고, STB의 inspector 콘솔(포트 19222)에서 window.location 또는 startupurl(UP 영역) 설정으로 PC의 개발 클라이언트를 로드합니다(Confluence 기준).

산출물 형태는 일반 빌드의 경우 dist/(index.html + js/bundle.js + 720p CSS), 릴리스의 경우 framecode 단위 zip(release/frame3709.zip 등)과 portal.jsp입니다.
