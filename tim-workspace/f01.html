홈 · 내비게이션 엔진

com.altimedia.nav.engine의 Navigator가 DestinationSpec 선언과 Plane(z-order 층) 기반으로 화면 스택을 관리하고, KeyRouter가 리모컨 키를 중첩 목적지까지 재귀적으로 라우팅합니다. 실제 화면 배치는 옛 screenlayer 모듈을 대체한 com.altimedia.nav.app(AppFragment·NavGateway)이 맡고, 홈 화면은 GNB·행 목록 기반 새 UI(ui/home)로 전면 교체됐습니다.

기능 개요

이 엔진은 Fragment 어휘를 전혀 모릅니다. Destination 인터페이스와 DestinationSpec(id·plane·factory 선언)만 다루고, 실제 화면 생성·배치·제거는 DestinationHost(어댑터)에 위임합니다. 화면이 놓이는 z-order 층은 Plane으로 앱이 직접 선언합니다 — Background·Screen(exclusive)·Overlay·Popup·System(independent) 5개 층을 nav/app/AppPlanes가 선언하며, Overlay는 팝업 아래·화면 위에 상시 오버레이(미니가이드 등)를 끼우기 위해 최근 추가됐습니다.

모든 변경 연산(activate/deactivate/closePlane/closeAll)은 suspend이며 Mutex로 직렬화됩니다. exclusive 평면의 나머지 목적지를 숨기는 시점이 host.place() 이후로 조정됐습니다 — 이전 화면을 먼저 숨기면 새 화면이 그려지기 전까지 아무 화면도 없는 구간이 생기고, 그 아래가 플레이어 표면이면 그 사이의 크기 조절이 그대로 보이는 문제가 있었기 때문입니다(구 screenlayer는 정리가 느려 우연히 가려져 있던 결함). deactivate가 위에 쌓인 목적지를 정리할 때도 Plane.independent(로딩·시스템 경고)는 예외로 남겨, 실패를 알리는 에러 팝업이 자신을 띄운 화면과 함께 사라지지 않도록 합니다.

설계 포인트 — 뷰를 직접 만지지 않는다
Navigator는 활성/비활성 전환을 Destination.onActiveChanged() 콜백으로 통보만 하고, 실제 포커스·표시 적용은 각 목적지가 스스로 합니다. 매니저가 외부에서 뷰를 직접 조작하면 앱이 별도 트랜잭션을 걸었을 때 되돌릴 주체가 없어지기 때문입니다.

screenlayer 폐지 → nav/app 흡수

레거시 :screenlayer 모듈은 삭제됐고, 그 역할(ViewBinding 부착, 앱 공통 Fragment 베이스, 레이어 컨테이너 연결)은 com.altimedia.nav.app의 AppFragment/AppScreenFragment/AppPlanes/NavGateway/NavHostGate가 나눠 흡수했습니다. NavGateway는 Activity 스코프인 Navigator를 ViewModel·싱글톤이 빌려 쓰는 통로로, 화면(목적지) 밖에서 nav를 다뤄야 하는 코드가 이걸 거칩니다. 홈·설정·라이브TV 등 모든 화면·팝업이 이 경로로 통일되면서, 화면마다 제각각이던 레거시 ATVScreen/ATVPopup 상속 트리도 함께 정리되는 중입니다(→ f08 팝업 참고).

홈 화면 — Figma 기반 신규 UI로 교체

HomeScreen은 옛 menu/MenuView·sub/(카테고리·TV가이드·검색·앱목록·상세 등 다수 서브 화면) 구조를 걷어내고, GNB(상단 탭)·탑 배너·OTT·Recommended For You·Continue Watching·Hot Pick's 6개 행으로 구성된 단일 세로 목록 UI로 전면 교체됐습니다. 행 렌더링은 자체 rvx(RecyclerView 확장 위젯) 어댑터 체계 — ArrayObjectAdapter·ItemBridgeAdapter·ClassPresenterSelector — 위에서 HeroPresenter·ContentRowPresenter·ContentCardPresenter가 담당합니다. 아직 API 연동이 없어 데이터는 HomeContent 고정값이고 카드 선택은 로그만 남기며, 프로필 로그인만 ui/home/subview/profile의 새 팝업 체계로 연결돼 있습니다.

흐름. activate는 락 안에서 동일 id 정리 → root 정리 → 인스턴스화 → 인자 검증(onArgs) → 포커스 판정(applyActivation) → 실제 배치(place) → 스택 push 순서로 진행되고, exclusive 평면 숨김과 활성 통보는 place 이후로 미뤄져 화면 전환 사이에 빈 화면이 보이는 틈을 없앱니다.

관계. Navigator는 DestinationStacks(내부 저장)와 KeyRouter(키 라우팅)를 소유하고, 실제 화면 생성·배치는 DestinationHost 구현체에 위임합니다. 앱 쪽의 AppFragment(구 screenlayer 대체)가 Destination을 구현해 실제 화면이 되고, Activity보다 오래 사는 ViewModel·싱글톤은 NavGateway를 통해서만 Navigator를 빌려 씁니다.

핵심 코드

nav/engine/Navigator.kt — activate: place 이후로 미뤄진 exclusive 숨김·활성 통보
val becomesActive = applyActivation(newDestination = destination, previousTop = previousTop)

host.place(destination, spec.plane)
stacks.push(destination)

// exclusive 평면이면 같은 평면의 나머지를 숨긴다. **place 뒤에** 하는 것이 중요하다.
// 먼저 숨기면 이전 화면이 사라진 뒤 새 화면이 그려질 때까지 아무 화면도 없는 구간이
// 생긴다. 그 아래는 플레이어 표면이라 그 사이에 일어나는 플레이어 크기 조절이 그대로
// 보인다. 구 screenlayer 는 정리가 느려서 그 구간이 우연히 가려져 있었다.
if (spec.plane.exclusive) {
    stacks.of(spec.plane)
        .filterNot { it === destination }
        .forEach { if (!host.isHidden(it)) host.setHidden(it, true) }
}

if (becomesActive) {
    destination.onActiveChanged(active = true, from = previousTop?.spec?.id)
}
return destination
nav/app/AppPlanes.kt — 앱이 선언하는 5개 평면(Overlay 신설)
object AppPlanes {
    val Background = Plane("background", depth = 10)
    val Screen = Plane("screen", depth = 20, exclusive = true)
    val Overlay = Plane("overlay", depth = 30)
    val Popup = Plane("popup", depth = 40)
    // 로딩, 토스트, 시스템 경고 — 아래에서 무엇이 닫히든 휩쓸리지 않는다.
    val System = Plane("system", depth = 50, independent = true)

    val all = listOf(Background, Screen, Overlay, Popup, System)
}
