서비스 인터페이스(SI) 추상화

core-kt/si가 채널·프로그램·재생 백엔드 접근을 ChannelRepository/ProgramRepository 인터페이스로 추상화하고, impl-mock(목업)과 impl-tt4k(기존 Türk Telekom 연동 재사용)가 Hilt @Module로 각각 다른 구현체를 바인딩합니다.

기능 개요

core-kt/si/core는 ChannelRepository·ProgramRepository(도메인 인터페이스)와 Channel·Program·Reminder(도메인 모델), ChannelPlayerAdapter(재생 어댑터 인터페이스)를 정의합니다. 이 계약을 두 모듈이 각각 다른 데이터로 구현합니다 — si:impl-mock은 MockChannelRepository/MockProgramRepository가 TestChannelData/TestProgramData(고정 목업 데이터)로 즉시 응답하고, si:impl-tt4k는 ChannelLocalDataSource·ApiModule(Retrofit)로 기존 Türk Telekom TT4K 백엔드 연동 코드를 그대로 재사용합니다.

구현 선택은 Dagger Hilt @Module @InstallIn(SingletonComponent::class) 바인딩(SIModule)으로 이뤄집니다. 같은 인터페이스(ChannelRepository)를 어느 모듈의 SIModule이 앱 그래프에 올라가는지에 따라 목업 또는 TT4K 구현으로 교체할 수 있어, TIM 전용 백엔드가 아직 없는 지금 단계에서도 UI·재생 로직을 실데이터 없이 개발할 수 있습니다(구체적으로 어느 조합/설정이 앱 그래프에 올라가는지는 gradle 모듈 구성 추가 확인 필요).

impl-tt4k 안에도 또 한 겹의 mock 스위치가 있다
si/impl-tt4k의 ApiModule은 DataConfig.useFakeData 플래그로 FakeChannelApiImpl과 실제 Retrofit 백엔드 호출을 런타임에 전환합니다. 즉 목업 여부는 모듈 선택(빌드타임)과 useFakeData 플래그(런타임) 두 층위로 관리됩니다.

흐름. ChannelRepository 호출부(예: LiveTvViewModel)는 어느 구현체가 바인딩됐는지 알 필요가 없습니다. 목업/실데이터 전환은 Hilt 모듈 선택(빌드타임)과 impl-tt4k 내부의 useFakeData(런타임) 두 층위에서 이뤄집니다.

관계. ChannelRepository 하나의 계약에 MockChannelRepository와 ChannelLocalDataSource(TT4K) 두 구현이 경쟁하며, 각각 자기 모듈의 Hilt @Module이 어떤 구현을 앱 그래프에 제공할지 결정합니다.

핵심 코드

si/impl-mock/.../SIModule.kt — 목업 구현 바인딩
@Module
@InstallIn(SingletonComponent::class)
object SIModule {
    @Singleton
    @Provides
    fun provideChannelRepository(): ChannelRepository {
        return MockChannelRepository()
    }

    @Singleton
    @Provides
    fun provideProgramRepository(channelRepository: ChannelRepository): ProgramRepository {
        return MockProgramRepository(channelRepository = channelRepository)
    }
}
si/impl-tt4k/.../ApiModule.kt — useFakeData 런타임 스위치
@Module
@InstallIn(SingletonComponent::class)
object ApiModule {
    @Singleton
    @Provides
    fun provideChannelApi(
        @Qualifier.DynamicRetrofit retrofit: Retrofit,
        @ApplicationContext context: Context,
    ): ChannelApi {
        return if (DataConfig.useFakeData) {
            FakeChannelApiImpl(context = context)
        } else {
            retrofit.create(ChannelApi::class.java)   // 실제 TT4K 백엔드 호출 (요약)
        }
    }
}
