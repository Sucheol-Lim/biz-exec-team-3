서비스 인터페이스(SI) 추상화

core-kt/si가 채널·프로그램·재생 백엔드 접근을 ChannelRepository/ProgramRepository 인터페이스로 추상화하고, impl-mock과 impl-tt4k가 Hilt @Module로 각각 다른 구현체를 바인딩합니다. 같은 core-kt 저장소 안에서, v8.26 RFQ 스펙을 대상으로 한 data2/domain2라는 병행 계층이 18개 도메인 그룹으로 새로 구축됐습니다.

기능 개요

core-kt/si/core는 ChannelRepository·ProgramRepository(도메인 인터페이스)와 Channel·Program·Reminder(도메인 모델), ChannelPlayerAdapter(재생 어댑터 인터페이스)를 정의합니다. 이 계약을 두 모듈이 각각 다른 데이터로 구현합니다 — si:impl-mock은 MockChannelRepository/MockProgramRepository가 고정 목업 데이터로 즉시 응답하고, si:impl-tt4k는 ApiModule(Retrofit)로 기존 Türk Telekom TT4K 백엔드 연동 코드를 그대로 재사용합니다. 이 계층은 이번 변경 구간에서 로직 변경 없이 app-tv-android에서 core-kt 저장소로 물리적으로 이전됐을 뿐입니다.

같은 시기, core-kt의 data/domain 모듈 안에 com.tim.core.data2/com.tim.core.domain2 패키지가 신설되어 v8.26 RFQ 스펙(5.1~5.30 그룹)의 API를 그룹 단위로 구현하고 있습니다 — 세션/인증, 사용자·프로필·기기, 채널/EPG, VOD, 즐겨찾기, 검색, NPVR, 추천, 상품/구매, 3rd-party 결제, 배너, 최근채널 등 18개 domain2 Repository(SessionRepository·ChannelRepository·VodRepository·BookmarkRepository·SearchRepository·NPvrRepository·FavoriteRepository·RecommendRepository·ProductRepository·PaymentRepository·BannerRepository·RecentChannelRepository·DeviceRepository·ProfileRepository·ParentLockRepository·ColumnRepository·UserRepository·EpgRepository)로 나뉩니다. 이 계층은 기존 si와 별개로 data/domain 모듈 안에 위치하며, 공통 응답 모델도 si와 다른 DataResponseDto/BaseResponse(v8.26 스펙 전수 확인 결과 공통 필드가 returncode/errormsg 뿐임을 반영)를 새로 둡니다.

방어적 파싱 — @EmptyStringToEmptyList
TT4K류 백엔드가 빈 목록을 [] 대신 ""(빈 문자열)로 내려보내는 경우가 있어, data2의 리스트 필드는 Moshi @EmptyStringToEmptyList 어노테이션으로 두 형태 모두 예외 없이 파싱되도록 방어합니다. DTO 필드명 대소문자 불일치, Retrofit @Path/@Query 순서 오류 37건 수정 등도 같은 구간에서 함께 정리됐습니다.

핵심 코드

si/impl-tt4k/.../ApiModule.kt — useFakeData 런타임 스위치 (변경 없음, core-kt로 이전됨)
@Module
@InstallIn(SingletonComponent::class)
object ApiModule {
    @Singleton
    @Provides
    fun provideChannelApi(
        @Qualifier.DynamicRetrofit retrofit: Retrofit,
        @ApplicationContext context: Context,
    ): ChannelApi {
        return if (DataConfig.useFakeData) {
            FakeChannelApiImpl(context = context)
        } else {
            retrofit.create(ChannelApi::class.java)
        }
    }
}
data2/remote/dto/DataResponseDto.kt — v8.26 공통 응답 필드는 두 개뿐
/**
 * v1(BaseResponseDto)과 같은 역할이지만 상속하지 않는다 — v8.26 스펙(5.1~5.30 그룹 전수 확인)의
 * 공통 응답 필드는 returncode/errormsg 뿐이고, v5.9에만 있던 errorcode/debugmsg는 없다.
 * Moshi codegen은 상속으로 필드를 가져오지 않으므로, 각 하위 DTO가 두 필드를 자신의 주
 * 생성자에 override val + @Json으로 다시 선언해야 실제로 역직렬화된다.
 */
@JsonClass(generateAdapter = true)
open class DataResponseDto(
    @Json(name = "returncode") open val returnCode: String? = null,
    @Json(name = "errormsg") open val errorMessage: String? = null,
)
