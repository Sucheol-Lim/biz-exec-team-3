재생 오케스트레이션

PlayOrchestrator(800줄)가 core-kt/domain의 PlayStarter·PlayStateHolder·CurrentPlayControl 3개 역할 인터페이스를 구현하고, 실제 화면·핸들러 관리는 새로 분리된 PlayHub(477줄)에 위임합니다. 15개 Play*UseCase가 URL·권한 조회를, 7종 PlayHandler가 콘텐츠별 재생 진행을 맡습니다.

기능 개요

기존에 하나였던 PlayOrchestrator(1,082줄)가 두 계층으로 분리됐습니다. com.tim.core.domain.play(core-kt)에 새로 정의된 세 역할 인터페이스 — PlayStarter(재생 시작만), PlayStateHolder(지금 무엇이 재생 중인지 조회만), CurrentPlayControl(재생 중인 것의 복귀·정지·이어보기 저장만) — 를 PlayOrchestrator가 모두 구현해 호출부는 필요한 역할만 주입받습니다. 실제 "핸들러 딕셔너리 보유·화면 열기·재생 지시"라는 재생 서피스 자체는 앱 쪽 PlayHub로 옮겨져, PlayOrchestrator는 UseCase 호출과 팝업(종료 확인 등)만 남기고 PlayHub를 Lazy 주입으로 순환 없이 참조합니다.

PlayHub는 VodType(DEFAULT·SINGLE·SERIES·PREVIEW·TRAILER·TS_TV·RECORD·PPV·PL_TV 9종)을 키로 7개 BasePlayHandler 구현체를 매핑합니다 — RECORD/PPV는 같은 NPVRPlayHandler를, DEFAULT/TRAILER는 같은 TrailerPlayHandler를 공유합니다. 핸들러는 DI가 아니라 PlayHub가 함수 참조(::playJust 등)를 직접 넘겨 생성합니다. PlayOrchestrator는 playSingleVodUseCase·playSeriesVodUseCase·playTsTvUseCase·playNPVRUseCase·playPPVUseCase·playFiveChannelUseCase·playMyTvUseCase 등 15개 Play*UseCase(전부 core-kt/domain/usecase/play)를 주입받아 URL·권한을 먼저 조회한 뒤, 결과에 따라 hub.startPlay(...)/hub.resumePlay(...)로 실제 재생을 위임합니다.

설계 포인트 — 세 역할로 쪼갠 이유
과거 PlayCoordinator 하나가 "재생 시작"과 "현재 상태 조회"와 "재생 중인 것 제어"를 모두 떠안고 있었습니다. 재생바처럼 현재 콘텐츠만 따라가면 되는 화면은 PlayStateHolder만, 홈 복귀·전원 종료처럼 "이미 재생 중인 것"만 상대하는 코드는 CurrentPlayControl만 주입받게 나누면서, 화면이 실제로 쓰지 않는 책임까지 함께 주입되는 문제를 없앴습니다.

흐름. 화면은 PlayStarter 인터페이스로 PlayOrchestrator를 호출하고, 오케스트레이터는 UseCase로 URL·권한을 조회한 뒤 실제 화면·핸들러 전환은 PlayHub에 넘깁니다. 재생 종료(FINISHED) 시 북마크 저장과 다음 콘텐츠 안내는 여전히 핸들러 안에서 처리됩니다.

관계. PlayOrchestrator는 core-kt에 정의된 세 역할 인터페이스의 유일한 구현체이고, 실제 콘텐츠별 재생 진행은 PlayHub가 VodType 키로 보유한 7종 핸들러가 맡는 전략 패턴 구조입니다.

핵심 코드

core-kt/domain/.../play/CurrentPlayControl.kt — 세 역할 중 하나, "이미 재생 중인 것"만 상대
/**
 * 지금 재생 중인 것을 다룬다 - 화면 복귀, 정지, 이어보기 저장.
 * 새 재생을 시작하지는 않는다.
 */
interface CurrentPlayControl {
    fun showCurrentVodPlaying(restart: Boolean = false, onActivate: (() -> Unit)? = null)
    fun saveCurrentBookmark(callback: (Boolean) -> Unit = {})
    fun stopCurrentPlaying(forceStop: Boolean = false, callback: (PlayResult<*>) -> Unit = {})
}
ui/play/PlayHub.kt — VodType별 핸들러 딕셔너리(함수 참조로 생성)
private val handlers by lazy {
    mapOf(
        VodType.DEFAULT to TrailerPlayHandler(::playJust, vodAdapter, channelAdapter, appStateProvider, navigator),
        VodType.SINGLE to SingleVodPlayHandler(::playJust, ::emitUiUpdateEvent, vodAdapter, channelAdapter, vodRepository, addBookmarkUseCase, appStateProvider, navigator, navGateway),
        VodType.SERIES to SeriesVodPlayHandler(::playJust, ::setCurrentContent, ::emitUiUpdateEvent, vodAdapter, channelAdapter, vodRepository, dataRepository, addBookmarkUseCase, getNextSeasonFirstEpisode, appStateProvider, navigator, navGateway),
        VodType.TRAILER to TrailerPlayHandler(::playJust, vodAdapter, channelAdapter, appStateProvider, navigator),
        VodType.TS_TV to TsTvPlayHandler(::playJust, ::emitUiUpdateEvent, ::setCurrentContent, vodAdapter, channelAdapter, channelRepository, channelBillReportRepository, programRepository, dataRepository, vodRepository, addBookmarkUseCase, appStateProvider, navigator, contextProvider),
        VodType.RECORD to NPVRPlayHandler(::playJust, ::emitUiUpdateEvent, vodAdapter, channelAdapter, channelRepository, channelBillReportRepository, vodRepository, addBookmarkUseCase, appStateProvider, navigator),
        VodType.PPV to NPVRPlayHandler(::playJust, ::emitUiUpdateEvent, vodAdapter, channelAdapter, channelRepository, channelBillReportRepository, vodRepository, addBookmarkUseCase, appStateProvider, navigator),
        VodType.PL_TV to PlTvPlayHandler(::setCurrentContent, startOverAdapter, channelAdapter, channelRepository, channelBillReportRepository, programRepository, fingerPrintRepository, appStateProvider, navigator),
    )
}

fun handlerOf(type: VodType?): BasePlayHandler? = handlers[type]
