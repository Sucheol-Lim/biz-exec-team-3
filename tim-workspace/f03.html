기능 개요

PlayOrchestrator는 TsTvPlayHandler(과거 프로그램/타임시프트), PlTvPlayHandler(플레이리스트 TV), NPVRPlayHandler(네트워크 PVR), SingleVodPlayHandler/SeriesVodPlayHandler(단편/시리즈 VOD), TrailerPlayHandler, PreviewPlayHandler 7종의 BasePlayHandler 구현체를 보유하고, 각 핸들러는 PlayFiveChannelUseCase·PlayNPVRUseCase·PlayPPVUseCase 등 14개 UseCase로 실제 재생 URL·권한 조회를 위임합니다.

모든 핸들러는 공통으로 @VodAdapter(PlayerAdapter, VOD 재생용)와 @ChannelAdapter(ChannelPlayerAdapter, 채널 튜닝용) 두 재생 어댑터를 주입받고, ChannelRepository·ProgramRepository·VodRepository·DataRepository(SI 계층)로 콘텐츠 메타데이터를 조회합니다. 핸들러 자신은 재생 엔진을 직접 다루지 않고, requestPlay(playInfo, logParam, stopCurrent, onError, onResult) 콜백을 통해 상위(오케스트레이터)로 재생 요청을 전달하는 구조입니다.

공통 UseCase 계층 — Five Channel / MyTv / PPV
개별 콘텐츠 재생 외에도 PlayFiveChannelUseCase(모자이크 5채널 동시 재생)·PlayMyTvUseCase·PlayPPVUseCase(유료 시청)처럼 여러 핸들러가 공유하는 횡단 UseCase가 별도로 분리되어 있어, 특정 재생 시나리오(구매·모자이크)가 핸들러 경계를 넘나들 때도 중복 구현을 피합니다.

핵심 코드

ui/play/handler/TsTvPlayHandler.kt — 핸들러 시그니처와 상태 전이 주석
/**
 * 채널 과거 프로그램 재생
 * state :
 *   [PlayerState.FINISHED]
 *     - addComplete & saveBookmark()
 *     - showNextPopup()
 *     - tuneLive() / nextPlay()
 */
class TsTvPlayHandler(
    private val requestPlay: (PlayInfo, VodLogParam, Boolean,
        (ErrorCodeDescription) -> Unit, (PlayResult<PlayResultData>) -> Unit) -> Unit,
    @VodAdapter private val vodAdapter: PlayerAdapter,
    @ChannelAdapter private val channelAdapter: ChannelPlayerAdapter,
    private val channelRepository: ChannelRepository,
    private val addBookmarkUseCase: AddBookmarkUseCase,
    // ... channelBillReportRepository, programRepository, dataRepository, vodRepository 등
) : BasePlayHandler {

    override fun startPlay(playInfo: PlayInfo, stopCurrent: Boolean, onSuccessPlay: () -> Unit) {
        if (playInfo !is PlayInfo.Channel) return
        val channel = channelRepository.getChannel(id = TTChannelId(channelCode = playInfo.channelCode))
        requestPlay(playInfo, VodLogParam(contentCode = playInfo.program.prevueCode, /* ... */), /* ... */)
    }
}
