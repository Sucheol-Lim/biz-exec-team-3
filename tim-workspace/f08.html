기능 개요

모든 팝업은 ATVScreen을 상속하는 ATVPopup<VB>를 기반으로 합니다. 애니메이션(슬라이드/페이드)이 필요한 팝업은 BaseAnimationPopup을 한 겹 더 거치고, 단순 확인창(FailSafeRecoveryPopup 등)은 ATVPopup을 직접 상속합니다. 리모컨 좌/우 키로 버튼 포커스를 이동하고 OK 키로 확정하는 패턴이 반복되며, 팝업은 닫힐 때 layerManager.deactivateLayer(this)로 자기 자신을 레이어에서 제거합니다.

도메인별로 ott/(로그인·가입·QR결제·PIN), bundle/·coupon/·purchase/(프로모션·결제), FailSafeRecoveryPopup·GlobalErrorPopup·ProvisionErrorPopup(장애·에러), OtaUpdatePopup(OTA)로 40여 개 팝업이 분류됩니다. 콜백은 대부분 ConsumeCallback<Int>(버튼 인덱스를 소비하는 콜백)로 호출부에 전달되어, 팝업 자신은 "무엇을 눌렀는지"만 알리고 후속 처리는 호출부가 맡습니다.

설계 포인트 — keyMonopoly로 키 독점
FailSafeRecoveryPopup은 init { keyMonopoly = true }로 키 입력을 독점합니다(f01의 DestinationSpec.keyMonopoly와 같은 개념). 페일세이프처럼 사용자가 반드시 응답해야 하는 팝업에서, 아래 화면이 리모컨 키를 가로채지 못하게 합니다.

흐름. 팝업은 버튼 포커스 이동과 OK 확정만 자체 처리하고, 실제 "무엇을 할지"는 콜백을 통해 호출부로 위임합니다.

핵심 코드

ui/popup/FailSafeRecoveryPopup.kt — 좌우 포커스 전환 + OK 확정 콜백
init { keyMonopoly = true }

override fun onKeyDown(keyCode: Int, event: AltiKeyEvent): Boolean {
    lastFocusView = requireActivity().currentFocus
    when (keyCode) {
        ATVKeyCode.KEY_RIGHT, ATVKeyCode.KEY_LEFT -> when (lastFocusView) {
            binding.btnOk -> binding.btnCancel.requestFocus()
            binding.btnCancel -> binding.btnOk.requestFocus()
        }
        ATVKeyCode.KEY_EXIT, ATVKeyCode.KEY_PREV -> layerManager.deactivateLayer(this)
        ATVKeyCode.KEY_OK -> {
            if (binding.btnOk.hasFocus()) {
                layerManager.deactivateLayer(this)
                onButtonClick?.invoke(0)
            } else if (binding.btnCancel.hasFocus()) {
                layerManager.deactivateLayer(this)
                onButtonClick?.invoke(1)
            }
        }
    }
    return true
}
