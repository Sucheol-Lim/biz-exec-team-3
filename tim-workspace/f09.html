빌드 플레이버 · 기존 자산 재사용

기능 개요

PlatformFlavor enum(build-logic/convention)이 platform 단일 차원(dimension)에 세 플레이버를 등록합니다.

  • tivibuEv — 기본(isDefault=true) 플레이버. applicationId = "tivibu.android.stb", minSdk 26/targetSdk 36.
  • stvOtt — Smart TV OTT용. applicationId = "com.ttnet.tivibutv"(Türk Telekom Tivibu TV 그대로), minSdk 26/targetSdk 36. Staging 빌드타입은 이 플레이버에서만 활성화됩니다(androidComponents.beforeVariants).
  • zteAosp — ZTE AOSP 단말용. applicationId = "com.zte.aosp", minSdk/targetSdk는 override 없이 프로젝트 기본값을 그대로 씁니다.

세 플레이버의 리소스 라벨은 app_name_tim_stb(tivibuEv·zteAosp) / app_name_tim_ott(stvOtt)로 이미 TIM 브랜드로 바뀌어 있지만, applicationId는 그대로입니다. 코드 주석에는 "Google Play 정책(2026-11-01 시한) 대응으로 tivibuEv/stvOtt는 targetSdk 36/minSdk 26으로 상향하고, zteAosp는 기존 값을 유지한다"는 날짜가 명시된 근거가 남아 있어, 플레이버별 SDK 정책이 서로 다른 일정으로 관리되고 있음을 알 수 있습니다.

설계 포인트 — LauncherDataProvider authority도 플레이버별
tivibuEv 플레이버는 manifestPlaceholders["launcherDataProviderAuthority"] = "tivibu.android.stb.data.provider"를 별도로 오버라이드합니다. 런처 데이터 제공자 authority까지 플레이버마다 다르게 고정해야 할 만큼, 기존 TT 자산과의 결합이 깊다는 뜻입니다.

관계. PlatformFlavor enum 하나가 Gradle 플레이버 등록의 유일한 원천(source of truth)이며, configureFlavors() 확장 함수가 모든 모듈(app/library)에서 동일하게 재사용됩니다.

핵심 코드

build-logic/convention/.../Flavor.kt — 플레이버별 applicationId·SDK 하한
// base on STB model name (as much as possible)
enum class PlatformFlavor(
    val dimension: FlavorDimension,
    val isDefault: Boolean = false,
    val key: String,
    val applicationId: String? = null,
    // Google Play 정책(2026.11.1 시한) 대응: tivibuEv/stvOtt flavor에 대해 targetSdk 36 / minSdk 26 로 상향.
    // 나머지 flavor(zteAosp) 는 기존 minSdk/targetSdk 값을 유지한다.
    val minSdk: Int? = null,
    val targetSdk: Int? = null,
) {
    tivibuEv(FlavorDimension.platform, true, key = "PLATFORM_TIVIBU_EV",
        applicationId = "tivibu.android.stb", minSdk = 26, targetSdk = 36),
    stvOtt(FlavorDimension.platform, key = "PLATFORM_STV_OTT",
        applicationId = "com.ttnet.tivibutv", minSdk = 26, targetSdk = 36),
    zteAosp(FlavorDimension.platform, key = "PLATFORM_ZTE_AOSP",
        applicationId = "com.zte.aosp"),
    ;
}
app/build.gradle.kts — stvOtt 전용 staging 변형만 활성화
androidComponents {
    beforeVariants { variantBuilder ->
        val flavorName = variantBuilder.productFlavors.firstOrNull()?.second
        val buildTypeName = variantBuilder.buildType
        if (buildTypeName?.contains("staging") == true) {
            val enableStaging = flavorName == PlatformFlavor.stvOtt.name
            variantBuilder.enable = enableStaging
        }
    }
}
