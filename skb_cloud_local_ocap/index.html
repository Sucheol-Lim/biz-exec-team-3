개요

본 프로젝트는 SK브로드밴드 케이블(TBroad) 셋톱박스(STB)에 직접 탑재되는 OCAP(OpenCable Application Platform) 기반 Local 애플리케이션입니다. STB의 OCAP/MHP(Multimedia Home Platform) 런타임 위에서 Java TV Xlet(javax.tv.xlet.Xlet) 형태로 구동되며, 미들웨어가 애플리케이션 디스크립터(ocap.host.application)를 읽어 부팅 시 자동으로 로드·실행합니다. 채널 전환, 홈 화면, 각종 팝업, VOD 제어 등 가입자가 화면에서 직접 사용하는 방송 기능 전반을 담당하는 네이티브 미들웨어 앱입니다.

이 앱의 가장 큰 특징은 클라우드(Cloud) 연동 하이브리드 구조입니다. UI 화면과 세션을 서버 측 클라우드 앱(com.tbroad.cloud.ep3)과 연계해, STB 로컬에서 처리하는 방송 제어와 클라우드에서 렌더링되는 화면을 결합합니다. 로컬 앱은 com.tb.cloud 패키지를 통해 클라우드 서버와 세션·키 입력·PIP 화면을 주고받으며, 클라우드 서버는 Docker 컨테이너 기반으로 운영됩니다.

또한 이 앱은 SK브로드밴드의 부가 서비스 플랫폼인 Windmill(UPMS/ACMS/Search/RCMD/OneAd 등)과 연동되어 사용자 프로파일, 광고, 추천, 쿠폰 등 서비스 데이터를 받아옵니다. 방송 신호 품질을 주기적으로 수집해 서버로 전송하는 TiMS 품질 계측, STB 상태/CAS/대기모드를 관리하는 Monitor, 케이블 대역폭 효율화를 위한 SDV(Switched Digital Video) 등 운영 사업자 관점의 기능도 함께 내장하고 있습니다.

분석 기준 브랜치 OCAP_log_2025
현재 분석 대상인 OCAP_log_2025 브랜치는 로그/방송 품질 계측 관련 작업이 집중된 작업 브랜치입니다. 최근 커밋 다수가 TiMS 품질 계측(튜너 ID 전달, standby 시 계측 제외, 특정 SMT 모델 제외, UDP 전송 전환 등) 개선에 집중되어 있습니다. 기본 브랜치는 master이며, UI/UX 작업용 OCAP_uiux_2025, 8VSB 작업용 OCAP_8VSB 등 별도 작업 브랜치가 존재합니다.

주요 기능

채널 탐색·전환 (Navigator)
ChannelController·ChannelDatabase·ChannelRing·ChannelZapper로 채널 목록 순회와 전환을 처리합니다. OCAP 전용 채널 구현(navigator/channel/ocap)과 TBroad 채널 구현(navigator/channel/tbroad)을 포함합니다.
FCC 고속 채널 전환
navigator/channel/fcc에서 FCC(Fast Channel Change)를 구현해 채널 전환 시 영상 표시 지연을 줄입니다. standby 상태에서는 FCC tune이 일어나지 않도록 제어합니다.
홈 화면 · 팝업 UI
com.tb.home.ui에 홈 화면과 35종 이상의 팝업(home/ui/popup), 리스트/컴포넌트 UI가 모여 있으며 소스 비중이 가장 큽니다. 자가진단(SelfDiagnosticsHandler), 음성검색(VoiceSearchManager)도 포함합니다.
클라우드 연동 (하이브리드)
CloudHomeMain·CloudConnector·CloudKeyHandler·CloudSessionRuleChecker가 서버 측 클라우드 앱과 세션·키·화면을 연계합니다. ICS·TLS 서버·워커(cloud/ics·cloud/tls·cloud/worker)로 세분화되어 있습니다.
방송 품질 계측 (TiMS)
TiMSManager가 SNR·power level 등 방송 신호 품질을 주기(PeriodicCollectionHandler)/일별(DailyCollectionHandler)로 수집해 UDP(TiMSUDPSender) 또는 Inform 형태로 서버에 전송합니다. COQP(tims/coqp)는 JSON으로 품질 데이터를 업로드합니다.
STB 상태 모니터링 (Monitor)
Monitor가 STB 상태·키 입력을 감시하고 대기모드(StandbyModeControl — svc), 배터리, 가상 마우스 등 시스템 레벨 제어를 담당합니다.
CAS 수신제한 연동
monitor/ca에서 Alticast CAS와 Nagra CA(AltiCaHandler·NagraCaHandler·CaManagerImpl)를 처리하고, TBroad CA Adaptor를 통해 수신제한·미리보기(PreviewInfo)를 다룹니다.
SDV 스위치드 디지털 비디오
SDVInit이 SDV(Switched Digital Video)를 초기화하고, CCP·MC·매니저(sdv/ccp·sdv/mc·sdv/manager)로 대역폭 효율적인 채널 할당을 처리합니다.
Mini EPG · 채널 예약
com.tb.miniepg가 간이 편성표(Mini EPG)와 채널 예약(miniepg/reserve)을 제공합니다.
VOD 재생 제어
com.tb.vod의 재생/제어 UI와 매니저, Castis VOD 연동(com.castis.vod.control), 에러 코드(VODErrorCode)로 주문형 비디오 재생을 다룹니다.
Windmill 데이터 연동 (cappl.dm)
cappl.dm이 Windmill UPMS/ACMS 등 서비스 API(cappl/dm/api), HTTP, 인증(TbroadAuthorization)을 제공합니다. 사용자 프로파일·광고·추천 데이터를 라이브/위성/개발 환경별 URL로 가져옵니다.
쿠폰 · 부가 서비스
coupon 패키지가 쿠폰 시스템(내부/외부 쿠폰 서버) DTO와 연동을 담당하고, OneAd 광고·홈초이스 앱스토어 등 부가 서비스 진입점을 제공합니다.
푸시 메시지 처리 (PMS)
pms 패키지와 PushMessageEventHandlerImpl이 서버 푸시 메시지를 수신·처리하고 UDP 피드백(PMS_FEEDBACK_IP)을 전송합니다.
채널맵 · 플랫폼 정보 (OOB)
ChannelMapManager·OOBManager·PlatformInfoManager가 OOB(Out-Of-Band) 경로로 채널맵·플랫폼 정보를 수신·갱신하고, IframeManager가 인밴드 데이터를 관리합니다.

계층 · 외부 연동 관계

최상위에 OCAP/MHP 미들웨어(org.ocap.*·javax.tv.*·org.dvb.*·org.davic.*)가 있고, 그 위에서 본 Xlet이 실행됩니다. 앱은 (1) 케이블 방송망(인밴드 SI·OOB 채널맵)과 직접 통신하고, (2) Windmill 플랫폼 서버(UPMS/ACMS/Search/RCMD/OneAd)와 HTTP로 연동하며, (3) 클라우드 서버(cloud.properties의 SERVER_ADDR·포트)와 세션을 맺고, (4) CAS/CA Adaptor를 통해 수신제한을 처리합니다. 클라우드 서버는 Docker 컨테이너로 운영되며 Testbed/Live/Bare 환경으로 구분됩니다(Confluence 클라우드 시스템 분석 참조).

빌드 시 형제 저장소 의존
build.xml의 cloud_java_compile 타깃은 본 저장소의 java/뿐 아니라 인접 저장소 ../skb_cloud_local_ocap_adaptor/java(속성 SRC_CLOUD)도 함께 컴파일합니다. 즉 본 저장소만으로는 빌드가 완결되지 않으며, skb_cloud_local_ocap_adaptor 저장소가 형제 디렉토리로 함께 존재해야 합니다.

핵심 동작 흐름

1) 부팅 · 초기화 시퀀스

  1. 미들웨어가 디스크립터 로드STB 부팅 후 OCAP 미들웨어가 ocap.host.application을 읽어 windmill.wind.tb.App을 자동 기동합니다(auto_start=true, priority 255).
  2. initXlet → HomeMain.initApp.initXlet이 HomeMain.getInstance().init(xletContext)를 호출합니다. 언어 초기화, NavEventQueue 준비 후 핵심 매니저 초기화가 시작됩니다.
  3. 하위 매니저 일괄 기동TiMS 품질계측(TiMSManager.init), SDV(SDVInit().init), Monitor(Monitor.init), 채널 매니저(TBChannelManager), 채널맵(ChannelMapManager.start), OCAP 채널 DB 등을 차례로 띄웁니다.
  4. startXlet → 데이터 수신 시작App.startXlet이 HomeMain.start를 호출해 플랫폼 정보(PlatformInfoManager), OOB 수신(OOBManager.startRetrieving), 광고/캠페인(HomeIAdManager·CampaignDataManager)을 가동합니다.
  5. 클라우드 세션 연결 · 홈 표시클라우드 연동(CloudHomeMain) 세션이 수립되고 홈 화면이 표시됩니다. 이후 가입자 키 입력을 받아 채널/메뉴/팝업을 처리합니다.

2) 채널 전환 흐름

  1. 키 입력 수신리모컨 채널 키(또는 클라우드 경유 키, CloudKeyHandler)가 Navigator로 전달됩니다.
  2. 채널 선택 · 차단 확인ChannelRing/ChannelDatabase에서 대상 채널을 결정하고, 차단 채널·수신제한(CAS)·연령 제한 여부를 확인합니다. DCA 자동완성 리스트에는 차단 채널을 표시하지 않습니다(최근 커밋).
  3. 튜닝 · FCCChannelController가 ServiceContext를 통해 튜닝을 수행합니다. FCC(Fast Channel Change)로 전환 지연을 줄이며, standby 상태에서는 FCC tune을 막습니다.
  4. SDV / 영상 표시SDV 대상 채널이면 SDV 매니저가 대역폭을 할당합니다. 영상이 표시되고 Mini EPG·채널 배너 등 UI가 갱신됩니다.

3) 방송 품질 계측 흐름 (TiMS)

  1. 수집 핸들러 기동TiMSManager가 주기 수집(PeriodicCollectionHandler)과 일별 수집(DailyCollectionHandler)을 별도 쓰레드로 운영합니다.
  2. 신호 품질 측정튜닝 중인 ServiceContext의 power level·SNR 등을 튜너 ID와 함께 측정합니다. standby 상태나 일부 SMT 모델(SMT-C3022/C5010/C5011/C5012)은 계측 대상에서 제외합니다.
  3. 서버 전송수집 데이터를 UDP(TiMSUDPSender) 또는 Inform(TiMSInformSender)으로 전송합니다. COQP(CoqpManager·JsonUploader)는 품질 데이터를 JSON으로 업로드합니다.

빌드 · 실행

빌드는 Apache Ant로 수행합니다. build.xml의 기본 타깃은 devel이며, 빌드 후 산출물 app.zip을 USB 경로(E:/app)로 복사합니다.

# 개발용 빌드 (app.zip 생성 후 USB 경로로 복사)
ant            # 또는 ant devel

# 전체 릴리스 빌드 (USB/Test/Sat/Live x Log/NoLog 8종 일괄 생성)
ant release

build 타깃의 흐름은 다음과 같습니다.

  1. 빌드 디렉토리 정리/생성(classes·_dist·_gen)
  2. java/·_gen/·어댑터 저장소(../skb_cloud_local_ocap_adaptor/java) 소스를 함께 컴파일(cloud_java_compile, javac source 1.3 / target 1.1)
  3. resources/·json/·ocap.host.application 복사
  4. lib/의 CAS(alti_cas_*.zip)와 CA Adaptor(tbroad_ca_adaptor.zip) 압축 해제
  5. 결과물을 app.zip으로 패키징(zip_app)

release 타깃은 배포 대상/로그 포함 여부에 따라 windmill.properties의 USB/LIVE/SAT 플래그와 com/tb/util/Log.java의 INCLUDE 값을 치환하며 다음 8종 산출물을 만듭니다.

local_<버전>_test_log.zip  / local_<버전>_test_nolog.zip

local_<버전>_live_log.zip  / local_<버전>_live_nolog.zip
