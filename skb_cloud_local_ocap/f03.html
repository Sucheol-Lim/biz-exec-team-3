홈 화면 · 팝업 UI

com.tb.home.ui가 홈 화면과 35종 이상의 팝업(home/ui/popup), 39종 컴포넌트(home/ui/comp)를 제공합니다. PopupControl이 레이어드 UI로 팝업 표시·키 입력을 통제하고, 자가진단(SelfDiagnosticsHandler)·음성검색(VoiceSearchManager)도 이 계층에 포함됩니다.

기능 개요

홈 화면·팝업 UI는 본 앱에서 소스 비중이 가장 큰 모듈입니다. 메인 홈 화면 자체는 상당 부분 클라우드 서버에서 렌더링되지만, STB 로컬에서 직접 그려야 하는 화면(블루투스 페어링, 저배터리 경고, 자가진단, 음성검색, 알림 팝업 등)은 com.tb.home.ui 패키지에서 그래픽으로 직접 구성합니다.

팝업의 표시·숨김·키 처리는 싱글톤 PopupControl이 일원화합니다. PopupControl은 OCAP LayeredUIManager 위에 팝업 전용 레이어드 다이얼로그(우선순위 MESSAGE_POPUP)를 생성하고, LayeredKeyHandler·PopupListener를 구현해 팝업이 떠 있는 동안 키 입력을 가로채 처리합니다. 각 팝업(예 SelfDiagnosticsPopup, VoiceSearchPopup, LowBetteryPopup)은 공통 베이스 Popup을 상속하고, PopupControl.getInstance().showPopup(popup)으로 화면에 올라갑니다.

자가진단은 SelfDiagnosticsHandler가 SelfDiagnosticsPopup/SelfDiagnosticsDetailPopup을 띄워 네트워크·신호·튜너 상태 등을 점검합니다. 음성검색은 VoiceSearchManager가 현재 서비스 상태(STATE_DATA_SERVICE 등)를 확인한 뒤 VoiceSearchPopup·VoiceSearchResultPopup을 통해 음성 입력과 검색 결과를 표시합니다.

시퀀스 다이어그램

흐름. 핸들러가 팝업 인스턴스를 만들어 PopupControl.showPopup()에 넘기면, 레이어드 UI가 생성되어 키 입력을 가로채고, 완료 시 dispose 됩니다. 다른 팝업(음성검색·블루투스 등)도 동일한 표시 경로를 탑니다.

관계. 모든 팝업은 공통 Popup을 상속하고, 싱글톤 PopupControl이 LayeredKeyHandler/PopupListener를 구현해 표시·키 입력을 통제합니다. 핸들러/매니저는 팝업을 만들어 showPopup()에 위임합니다.

핵심 코드

home/ui/SelfDiagnosticsHandler.java — 자가진단 팝업 표시
public void showSelfDiagnosticsPopup() {
    sdp = new SelfDiagnosticsPopup(shape, null, null);
    PopupControl.getInstance().showPopup(sdp);   // 공통 팝업 표시 경로
}

public boolean isVisible() {
    return (sdp != null && sdp.isVisible());
}
