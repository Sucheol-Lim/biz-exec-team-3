방송 품질 계측 (TiMS)

TiMSManager가 주기(PeriodicCollectionHandler)·일별(DailyCollectionHandler) 핸들러를 띄워 SNR·power level 등 방송 신호 품질을 수집하고, UDP(TiMSInformSender) 또는 COQP JSON(CoqpManager·JsonUploader)으로 서버에 전송합니다.

기능 개요

TiMS는 STB가 수신하는 방송 신호 품질(SNR, power level 등)을 주기적으로 측정해 운영 사업자 서버로 전송하는 품질 계측 모듈입니다. 싱글톤 TiMSManager.init()이 진입점으로, TLS 제어 서버(TLSServerController)를 띄우고 주기 수집 핸들러(PeriodicCollectionHandler)와 일별 수집 핸들러(DailyCollectionHandler)를 초기화합니다. 부팅 시 HomeMain.start()가 가장 먼저 TiMSManager.getInstance().init()을 호출합니다.

PeriodicCollectionHandler는 TVTimer 기반으로 설정된 간격(10/20/30/60초 등)마다 doIntervalSend()를 수행해, 튜닝 중인 ServiceContext의 신호 품질을 수집하고 TiMSInformSender로 UDP 패킷을 전송합니다. 전송 대상은 일반 서버(PERIODIC_UDP_IP)와 Adams 서버(ADAMS_UDP_IP) 두 곳입니다. 수집 간격은 DataCenter의 TIMS_PERIODIC_REPORT_INTERVAL 키 갱신으로 동적으로 바뀝니다.

COQP(tims/coqp)는 채널 단위 품질 데이터를 org.json.JSONObject로 직렬화해 JsonUploader.uploadJson()으로 HTTP multipart 업로드합니다. CoqpManager는 컬러키 이벤트 리스너로도 동작하며, msgSleep 스레드로 현재 채널 정보를 세팅한 뒤 접근 가능 채널 전체의 품질 JSON을 만듭니다.

standby · 특정 모델 제외 (최근 작업)
OCAP_log_2025 브랜치 최근 커밋들은 TiMS 개선에 집중되어 있습니다. (1) 측정 API에 튜너 ID를 전달, (2) standby(대기) 상태에서는 품질 계측 전송을 하지 않도록 처리, (3) 일부 SMT 모델(SMT-C3022/C5010/C5011/C5012)을 계측 대상에서 제외, (4) 전송을 Inform에서 UDP로 전환하는 작업이 반영되었습니다.

시퀀스 다이어그램

sequenceDiagram autonumber participant HM as HomeMain participant TM as TiMSManager participant PCH as PeriodicCollectionHandler participant DC as DataCenter participant SND as TiMSInformSender (UDP) participant SRV as 품질 계측 서버 HM->>TM: init() TM->>TM: TLSServerController.startTLSServer() TM->>PCH: init() PCH->>DC: addDataUpdateListener(TIMS_PERIODIC_REPORT_INTERVAL) PCH->>PCH: startTimer() loop 설정 간격마다 (10/20/30/60초) PCH->>PCH: timerWentOff() → doIntervalSend() PCH->>PCH: SNR·power level 수집 (tuner id 포함) Note over PCH: standby/제외 모델이면 전송 skip PCH->>SND: send(inform) SND->>SRV: UDP 패킷 (Periodic + Adams) end

흐름. TiMSManager.init()이 TLS 서버와 수집 핸들러를 띄우고, PeriodicCollectionHandler가 타이머마다 신호 품질을 수집해 UDP로 전송합니다. 대기 상태·제외 모델이면 전송을 건너뜁니다.

관계. TiMSManager가 주기·일별 핸들러를 소유하고, PeriodicCollectionHandler가 타이머/데이터 리스너로 동작하며 TiMSInformSender로 UDP 전송합니다. COQP 경로는 CoqpManager → JsonUploader로 JSON 업로드합니다.

핵심 코드

tims/TiMSManager.java — 수집 핸들러 일괄 기동
public void init() {
    if (Log.INCLUDE) {
        Log.message("[TiMSManager] init");
    }
    TiMSPannel.getInstance().show();
    tlsServerController.startTLSServer();   // TLS 제어 서버
    periodicCollectionHandler.init();       // 주기 수집
    dailyCollectionHandler.init();          // 일별 수집
}
tims/collect/PeriodicCollectionHandler.java — 일반·Adams UDP 전송기 구성
// 생성자: Periodic / Adams 두 서버로 UDP 전송기를 준비
informSender      = new TiMSInformSender("Periodic", TiMSDef.PERIODIC_UDP_IP, TiMSDef.PERIODIC_UDP_PORT);
adamsInformSender = new TiMSInformSender("Adams_Periodic", TiMSDef.ADAMS_UDP_IP, TiMSDef.PERIODIC_UDP_PORT);

public synchronized void init() {
    informSender.init();
    adamsInformSender.init();
    // 보고 간격을 DataCenter 키로 동적 갱신
    DataCenter.getInstance().addDataUpdateListener(DataCenterKey.TIMS_PERIODIC_REPORT_INTERVAL, this);
}
