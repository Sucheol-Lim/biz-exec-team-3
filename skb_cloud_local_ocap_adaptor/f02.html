앱 단위 컨텍스트

CladContext 가 TV/SI/Media/Config 하위 서비스를 lazy 생성해 반환하고, 메인/위젯 윈도우·세션 데이터·콜백 핸들러 등록을 앱(applicationId) 단위로 묶어 관리합니다.

기능 개요

한 Cloud App 이 어댑터를 통해 단말 기능에 접근할 때 그 모든 상태와 서비스를 묶는 단위가 CladContext 입니다. CladServiceManager.createCladContext(applicationId) 로 발급되며, 구현체 CladContextImpl 은 생성자에서 자신의 id(앱ID)와 위젯 윈도우 보관용 Hashtable 을 초기화합니다.

컨텍스트는 TV/SI/Config/Media 네 가지 하위 서비스를 lazy 방식으로 보유합니다. getTVService()/getSIService()/getConfigService()/getMediaPlayerService() 가 처음 호출될 때 해당 *ServiceImpl 인스턴스를 생성해 멤버에 캐싱하고, 이후 호출은 같은 인스턴스를 재사용합니다. 따라서 앱 하나당 각 서비스도 하나만 존재합니다.

또한 윈도우 제어(showWindow/hideWindow)는 AppManager 에 위임하고, 세션 데이터(setSessionData/addSessionData/getSessionData/getSessionDataAll)도 앱ID를 키로 매니저의 저장소에 보관합니다. Cloud→Local 콜백을 받기 위한 AppHandler 와 WindowMonitor 핸들러도 이 컨텍스트에 등록하며, onMessage/onHidden/onStopped 와 onMainWindowShown/onMainWindowHidden 통지가 등록된 핸들러로 전달됩니다.

설계 포인트
CladContextImpl 은 인터페이스 메서드뿐 아니라 AppHandler/WindowMonitor 통지 메서드를 자체적으로도 갖고 있어, AppManager 가 컨텍스트를 통해 등록된 핸들러로 콜백을 중계하는 어댑터 역할을 합니다. 핸들러가 등록되지 않았으면 통지는 무시됩니다.

흐름. 컨텍스트에 핸들러를 등록한 뒤 서비스는 최초 호출 시점에 lazy 생성되며, 세션 데이터·콜백은 AppManager 와 등록 핸들러로 중계됩니다.

핵심 코드

cladimpl/CladContextImpl.java — 서비스 lazy 생성과 세션/콜백 위임
public CladTVService getTVService() {
    if (tvService == null) {
        tvService = new CladTVServiceImpl();      // 최초 호출 시점에 생성
    }
    return tvService;                              // 이후 재사용
}

public void addSessionData(String Key, String value) {
    AppManager.getInstance().addSessionData(id, Key, value);  // 앱ID 기준 저장
}

public boolean onHidden() {                        // AppManager → 컨텍스트 → 핸들러
    if (appHandler != null) {
        appHandler.onHidden();
        return true;
    }
    return false;
}
