기능 개요

Cloud App 은 컨텍스트를 통해 임의의 문자열 키-값을 어댑터에 보관할 수 있습니다. 이 데이터는 앱 세션 동안 유지되는 키-값 저장소로, CladContext 의 setSessionData(Map), addSessionData(key, value), getSessionData(key), getSessionDataAll() 네 메서드로 다룹니다.

구현은 CladContextImpl 이 받아 자신의 앱ID(id)와 함께 AppManager 로 위임하는 구조입니다. AppManager 는 HashMap sessionMap 을 보유하는데, 키가 앱ID(Long)이고 값이 그 앱의 키-값 Map 입니다. 즉 앱마다 독립된 Map 을 갖습니다. 모든 접근은 SESSION_LOCK 동기화 블록 안에서 이뤄져 멀티스레드 환경에서 일관성을 유지합니다.

addSessionData 는 해당 앱의 Map 이 있으면 거기에 키-값을 추가하고, 없으면 새 HashMap 을 만들어 등록합니다. setSessionData 는 앱의 Map 자체를 통째로 교체하며, getSessionData 는 앱 Map 에서 키로 값을 조회(없으면 null), getSessionDataAll 은 앱의 Map 전체를 반환합니다. 내부적으로 키 헤더로 시작하는 항목을 일괄 삭제하는 removeSessionDataStartsWith 유틸도 있습니다.

설계 포인트
세션 저장소를 컨텍스트가 아니라 AppManager 싱글톤에 둔 이유는 앱ID만 알면 어느 경로에서든 동일 저장소에 접근할 수 있게 하기 위함입니다. 레거시 Java 환경이라 제네릭 없이 raw Map/HashMap 을 사용합니다.

시퀀스 다이어그램

sequenceDiagram autonumber participant Cloud as Cloud App participant CTX as CladContextImpl(id) participant AM as AppManager participant SM as sessionMap (HashMap) Cloud->>CTX: addSessionData(key, value) CTX->>AM: addSessionData(id, key, value) Note over AM: synchronized(SESSION_LOCK) AM->>SM: get(appId) → Map (없으면 new HashMap) AM->>SM: map.put(key,value) 후 sessionMap.put(appId,map) Cloud->>CTX: getSessionData(key) CTX->>AM: getSessionData(id, key) AM->>SM: get(appId).get(key) AM-->>Cloud: value (없으면 null)

흐름. 컨텍스트가 앱ID를 붙여 매니저로 위임하고, 매니저는 앱ID→Map 저장소에서 키-값을 동기화 블록 안에서 쓰고 읽습니다.

클래스 다이어그램

classDiagram class CladContext { <<interface>> +getSessionDataAll() Map +setSessionData(Map data) +addSessionData(String Key, String value) +getSessionData(String Key) String } class CladContextImpl { -long id +getSessionDataAll() Map +setSessionData(Map data) +addSessionData(String Key, String value) +getSessionData(String Key) String } class AppManager { -Object SESSION_LOCK -HashMap sessionMap +getSessionDataAll(long id) Map +setSessionData(long id, Map data) +addSessionData(long id, String key, String value) +getSessionData(long id, String key) String #removeSessionDataStartsWith(String keyHeader) } CladContextImpl ..|> CladContext : implements CladContextImpl --> AppManager : id 붙여 위임 AppManager o-- sessionMap : 앱ID→Map 보관

관계. 컨텍스트의 세션 API 는 전부 자신의 앱ID 를 더해 AppManager 의 동일 이름 메서드로 위임되고, 실제 저장은 sessionMap 한 곳에 모입니다.

핵심 코드

cladimpl/manager/AppManager.java — 앱ID 기준 키-값 추가/조회
// KEY=AppID, Value=Map
private HashMap sessionMap = new HashMap();

public void addSessionData(long id, String key, String value) {
    synchronized (SESSION_LOCK) {
        Long appId = new Long(id);
        Map newMap = null;
        if (sessionMap.containsKey(appId)) newMap = (Map) sessionMap.get(appId);
        else                               newMap = new HashMap();
        newMap.put(key, value);
        sessionMap.put(appId, newMap);
    }
}

public String getSessionData(long id, String key) {
    synchronized (SESSION_LOCK) {
        Long appId = new Long(id);
        if (sessionMap.containsKey(appId)) {
            Map map = (Map) sessionMap.get(appId);
            return (String) map.get(key);
        }
        return null;
    }
}
