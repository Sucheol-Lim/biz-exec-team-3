기능 개요

Cloud App 이 어댑터에 처음 진입하는 단일 창구가 CladServiceManager 인터페이스이며, Local 측 구현체는 CladServiceManagerImpl 입니다. 이 인터페이스는 ROP 64bit 태그 0xd855fbc474dc6a53 으로 식별되며, 클라우드 측 프록시(stub/Sd855fbc474dc6a53.java)와 1:1 대응합니다. 구현체는 생성자에서 createAppManager() 를 호출해 AppManager.init("com.alticast.cladimpl.manager.AppManager") 로 싱글톤 매니저를 먼저 준비합니다.

Cloud App 은 가장 먼저 getCloudAdaptorVersion() 으로 어댑터 버전 "1.0" 을 확인해 호환성을 점검합니다. 이후 createCladContext(applicationId) 를 호출하면 매니저가 해당 앱ID의 컨텍스트를 컨텍스트 맵에서 조회하고, 없으면 CladContextImpl 을 새로 만들어 addCladContext 로 캐싱한 뒤 반환합니다. 같은 앱ID로 다시 호출하면 캐싱된 동일 인스턴스를 돌려주어 앱당 하나의 컨텍스트가 유지됩니다.

그 외에 메인 윈도우 소유자 조회(getMainWindowOwner())와 Cloud/Device 앱 등록·시작·정지(registerCloudApps/startCloudApp 등) 시그니처를 제공합니다. 단 앱 등록·시작·정지 메서드는 본 저장소 구현체에서는 빈 본문(골격)이며, 실제 동작은 상위 플랫폼 연동 범위로 추정됩니다.

설계 포인트
CladServiceManagerImpl 은 Exportable 을 구현하므로 createSkeleton() 으로 자신의 서버측 디스패처 CladServiceManagerSkel 을 만들 수 있습니다. ROP 런타임은 이 Skeleton 으로 들어온 호출의 32bit 메서드 해시(예: 0xb2815b12 = getCloudAdaptorVersion)를 분기해 구현체 메서드로 위임합니다.

핵심 코드

cladimpl/CladServiceManagerImpl.java — 매니저 초기화와 컨텍스트 생성·캐싱
public CladServiceManagerImpl() {
    super();
    createAppManager();                       // AppManager 싱글톤 준비
}

public void createAppManager() {
    try {
        AppManager.init("com.alticast.cladimpl.manager.AppManager");
    } catch (Exception e) { e.printStackTrace(); }
}

public String getCloudAdaptorVersion() {
    return "1.0";                             // 호환성 확인용 버전
}

public CladContext createCladContext(long applicationId) {
    CladContextImpl context =
        (CladContextImpl) AppManager.getInstance().getCladContext(applicationId);
    if (context == null) {                    // 캐시에 없으면 새로 생성 후 등록
        context = createCladContextImpl(applicationId);
        AppManager.getInstance().addCladContext(context, applicationId);
    }
    return context;                           // 앱당 단일 컨텍스트 보장
}
