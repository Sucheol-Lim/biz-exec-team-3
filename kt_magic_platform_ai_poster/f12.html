인증·세션 관리

axios 인스턴스에 Bearer 토큰을 자동 주입하고, 만료 응답(resultCode 4010/4011) 시 토큰을 재발급해 원요청을 재시도합니다. 세션은 Pinia auth 스토어와 sessionStorage로 관리합니다.

기능 개요

인증은 user/src/api/index.js의 setInterceptor()가 만든 axios 인스턴스에 집중되어 있습니다. 요청 인터셉터는 useAuthStore().token(sessionStorage ak 키)을 Authorization: Bearer ... 헤더로 자동 주입합니다. 응답 인터셉터는 에러 응답의 resultCode를 검사해, 4010(액세스 토큰 만료)이면 api.auth.reissueToken()으로 새 토큰을 받아 setToken으로 저장하고 원래 요청(instance.request(config))을 재시도합니다. 재발급마저 4011이면 로그인 페이지로 보냅니다.

네트워크 오류나 5xx에 대해서는 axios-retry로 최대 2회(1초 지연) 재시도합니다. 세션은 Pinia auth 스토어가 토큰·로그인 사용자(user)·리다이렉트 URL을 sessionStorage와 동기화해 관리하고, LoginSessionTimer(300초)로 무활동 만료를 처리합니다. 편집 컨테이너(PosterEdit.vue)는 5분마다 PATCH /auth/magic/user/session으로 keepSession()을 호출하고, 클릭·키 입력·휠 이벤트마다 restartLoginSessionTimer()로 타이머를 갱신합니다.

세션 만료 처리
재발급 실패(4011 연속) 시 moveLoginPage()가 안내 알림을 띄우고 clearStore()로 토큰·사용자 정보를 제거한 뒤 루트(/)로 이동시킵니다. sessionStorage 키는 토큰 ak, 사용자 user입니다.

시퀀스 다이어그램

sequenceDiagram autonumber participant C as 컴포넌트 ($api) participant REQ as request 인터셉터 participant RES as response 인터셉터 participant AS as auth 스토어 participant AU as api.auth participant SRV as 백엔드 C->>REQ: API 호출 REQ->>AS: token 조회 (sessionStorage ak) REQ->>SRV: 요청 + Authorization Bearer SRV-->>RES: 에러 응답 (resultCode) alt resultCode == 4010 (토큰 만료) RES->>AU: reissueToken() AU-->>RES: { accessToken } 또는 4011 alt 재발급 성공 RES->>AS: setToken(accessToken) RES->>SRV: 원요청 재시도 instance.request(config) else 4011 RES->>AS: clearStore() → 로그인 페이지 end else 5xx / 네트워크 오류 RES->>SRV: axios-retry 최대 2회 재시도 end

흐름. 모든 요청에 Bearer 토큰이 자동으로 붙고, 만료(4010)는 재발급+재시도로, 영구 만료(4011)는 로그아웃으로, 일시 장애(5xx)는 재시도로 처리합니다.

클래스 다이어그램

classDiagram class ApiIndex { +setInterceptor(instance) +moveLoginPage() } class AuthStore { -token -loginUser +setToken(newToken) +setLoginUser(user) +restartLoginSessionTimer() +clearStore() +logout() } class AuthApi { +reissueToken() +logout(token) } class PosterEdit { +keepSession() } ApiIndex ..> AuthStore : token 조회/저장 ApiIndex ..> AuthApi : reissueToken PosterEdit ..> AuthStore : restartLoginSessionTimer PosterEdit ..> AuthApi : PATCH session keepSession

관계. 인터셉터(ApiIndex)가 AuthStore 토큰을 읽고 AuthApi.reissueToken으로 갱신하며, 편집 컨테이너가 세션 유지 타이머를 돌립니다.

핵심 코드

user/src/api/index.js — Bearer 주입 + 4010 재발급·재시도
instance.interceptors.request.use(config => {
    const token = useAuthStore().token
    config.headers.Authorization = `Bearer ${token}`     // 자동 주입
    return config
})

instance.interceptors.response.use(
    response => response,
    async error => {
        const { config, response } = error
        const resultCode = response?.data?.resultCode

        if (resultCode === 4010) {                        // 액세스 토큰 만료
            const { data: { accessToken, resultCode } } = await api.auth.reissueToken()
            if (resultCode === 4011) { moveLoginPage(); return }
            useAuthStore().setToken(accessToken)
            return instance.request(config)               // 원요청 재시도
        }
        if (resultCode === 4011) { /* 재발급 시도 후 실패 시 moveLoginPage() */ }
        throw error
    }
)
user/src/api/index.js — axios-retry로 5xx·네트워크 재시도
axiosRetry(instance, {
    retries: 2,                                   // 최대 2회
    retryDelay: () => 1000,                       // 1초 지연
    retryCondition: (error) =>
        error.response
            ? axiosRetry.isRetryableError(error) || error.response.status >= 500
            : true                                // 네트워크 오류도 재시도
});
