개요

이 저장소는 KT Magic(매직 플랫폼)의 웹 프런트엔드 가운데 "지니 포스터(Genie Poster)" 영역을 담당합니다. 사내 과제로는 AI Poster 고도화의 일부로, 자체 개발한 신규 AI 포스터 엔진을 매직 플랫폼에 적용하면서 결과 이미지를 후처리할 수 있는 이미지 편집툴을 신규 개발하는 작업에 해당합니다. 사용자는 포스터 프로젝트를 생성하고, 캔버스 편집 화면에서 이미지 내 텍스트를 제거하거나(텍스트 제거), 원본 이미지를 여러 배너 해상도로 확장(이미지 확장)한 뒤 결과물을 묶어서 내려받습니다.

대상 플랫폼은 PC 데스크톱 웹 브라우저이며, Vue 3 기반 SPA(Single Page Application) 형태로 동작합니다. 백엔드 AI 작업(텍스트 제거·이미지 확장)은 프런트엔드가 직접 수행하지 않고, genie-poster 프록시 API(/api/magic/proxy/genie-poster)를 통해 작업 요청 → 상태 폴링 → 결과 조회 방식으로 비동기 연동합니다. 텍스트 제거(REMOVE)와 이미지 확장(EXPAND)은 작업 완료 시 토큰을 차감하는 과금형 기능으로 설계되어 있습니다.

저장소(분석 디렉토리 기준)는 user 앱 하나를 중심으로 구성되며, 지니 포스터 외에 지니 숏츠(shortform), 대시보드, 분석 이력 조회 화면도 함께 포함합니다. 다만 본 과제의 핵심 산출물은 user/src/views/common/api/posteredit/ 하위의 포스터 편집 모듈입니다.

과금 모델
코드 상 토큰 차감량 기본값은 텍스트 제거 REMOVE = 20, 이미지 확장 EXPAND = 80 토큰입니다. 실제 작업을 보내기 전에 토큰 사용량 사전 조회 API(token-usage)로 예상 차감량을 확인하고, 작업 완료 시점에 차감되는 구조입니다.
모노레포 구성 참고
package.json에는 home·admin·login 앱용 빌드 스크립트도 정의되어 있으나, 현재 작업 디렉토리에는 해당 하위 폴더와 설정 파일이 존재하지 않습니다. 실제로 빌드 가능한 구성은 user 앱입니다. (모노레포에서 일부 앱만 분리된 형태로 추정)

주요 기능

텍스트 제거 (Text Removal)
포스터 이미지에서 텍스트 영역을 제거합니다. 전체(all) 자동 제거와 영역 선택(select) 제거를 지원하며, 작업 요청 후 상태를 조회해 결과를 반영합니다.
영역 그리기 도구
선택 모드에서 사각형(rect)·브러쉬(brush)·지우개(eraser) 도구로 제거할 영역의 마스크를 그립니다. 브러쉬·지우개 크기는 슬라이더(기본 24)로 조절합니다.
마스크 기반 부분 제거
선택 영역은 캔버스에서 마스크 이미지(maskImage)로 생성되어 요청 본문에 포함됩니다. 전체 제거 시에는 마스크 없이 imageUrl만 전송합니다.
이미지 확장 (Outpainting)
원본/텍스트 제거 이미지를 선택한 배너 규격으로 AI 확장합니다. 각 배너의 가로·세로 해상도와 원본 배치 위치(상/하/좌/우/중앙)를 지정해 일괄 생성합니다.
배너 템플릿 세트
Set-F(5종)·Set-S(10종)·Set-H(11종) 사전 정의 템플릿과 "직접 설정" 커스텀 옵션을 제공합니다. KT 서비스 화면(HomeTop, miniEPG, 빅배너 등)에 맞춘 규격이 포함됩니다.
결과 폴링 처리
확장 작업은 10초 간격으로 결과를 폴링합니다. 진행 중 상태를 콜백으로 갱신하고, SUCCESS/COMPLETED 또는 ERROR/FAILED 상태로 종료를 판정하며 AbortSignal로 취소도 지원합니다.
결과 조회·다운로드
확장 결과를 결과 화면(ResultArea)에서 카드로 표시하고, 전체/선택 항목을 ZIP(blob)으로 묶어 다운로드합니다. 불필요한 결과 이미지는 개별 삭제할 수 있습니다.
미리보기 확대/축소
Konva 캔버스 기반 미리보기에 5%~200% 줌 레벨과 줌 팝업, 전체화면 확대 보기를 제공합니다. 스크롤 줌과 초기 이미지 크기 보정 로직을 포함합니다.
원본 되돌리기 / 다시 편집
텍스트 제거 결과를 원본으로 되돌리거나(reset), 확장 작업을 초기화하고 다시 편집 단계로 돌아갑니다. 프로젝트 복제(copy)로 새 편집 세션을 시작할 수도 있습니다.
토큰 사용량 사전 조회
텍스트 제거·이미지 확장 각각에 대해 작업 전 예상 토큰 사용량을 조회하는 API를 호출하고, "작업 완료 시 N토큰이 차감됩니다" 안내를 노출합니다.
프로젝트 목록 관리
지니 포스터 프로젝트 목록을 jQuery DataTables로 렌더링하고, 날짜 범위(기본 최근 1개월) 검색, 페이지 길이 선택, 파일 업로드 기반 프로젝트 생성 모달을 제공합니다.
인증·세션 관리
axios 인스턴스에 Bearer 토큰을 자동 주입하고, 만료 응답(resultCode 4010/4011) 시 토큰 재발급 후 재시도합니다. 세션은 Pinia auth 스토어와 sessionStorage로 관리합니다.
다국어 지원
편집 모듈은 한국어/영어 로케일(ko.json·en.json)을 갖춘 자체 useI18n composable과 vue-i18n을 병행 사용해 UI 문구를 국제화합니다.

아키텍처 · 모듈 구조

계층 · 외부 연동

프런트엔드는 AI 추론을 직접 수행하지 않습니다. 모든 텍스트 제거·이미지 확장 작업은 VITE_GENIE_POSTER_BASE_URL(/api/magic/proxy/genie-poster)이 가리키는 매직 플랫폼 프록시 API에 위임됩니다. 개발 서버에서는 Vite 프록시가 /auth·/api·/nms·/login 요청을 개발 백엔드(http://121.129.58.89:83/, 추정)로 전달합니다. 이미지 확장처럼 시간이 걸리는 작업은 작업 ID(jobId)를 받아 폴링으로 완료를 기다리는 비동기 모델로 동작합니다.

핵심 동작 흐름

텍스트 제거 흐름

  1. 편집 진입프로젝트 목록에서 항목을 열면 /user/studio/poster/edit로 이동하고, PosterEdit.vue가 프로젝트 상세를 불러와 POSTER_STATE를 판정합니다(original 시작).
  2. 제거 영역 지정우측 패널에서 전체(all) 또는 영역 선택(select)을 고릅니다. 선택 모드에서는 사각형·브러쉬·지우개로 캔버스에 마스크를 그립니다.
  3. 토큰 사용량 확인postTextRemovalTokenUsage로 예상 차감 토큰을 조회하고 "작업 완료 시 N토큰 차감" 안내를 노출합니다.
  4. 제거 요청 전송전체 제거는 { imageUrl }만, 부분 제거는 캔버스에서 생성한 maskImage를 포함해 postTextRemoval(projectId, requestBody)로 전송하고 jobId를 받습니다.
  5. 상태 조회·반영getTextRemovalStatus로 진행 상태를 조회하고, 완료되면 textRemovedImageUrl을 미리보기에 반영하며 상태를 text_removed로 전환합니다.

이미지 확장(아웃페인팅) 흐름

  1. 템플릿 선택이미지 확장 팝업에서 Set-F/Set-S/Set-H 또는 "직접 설정"을 고르고, 배너별 원본 배치 위치(상/하/좌/우/중앙)를 지정합니다.
  2. payload 구성requestImageExtension이 현재 이미지 URL과 함께 각 배너의 name·width·height·alignment 항목 배열, 템플릿 type을 요청 본문으로 만듭니다.
  3. 확장 작업 생성postImageExpansion(projectId, requestData)로 작업을 생성하고 jobId를 받습니다.
  4. 결과 폴링pollingImageExtensionResultsWithCallback이 10초 간격으로 getImageExpansionResult를 호출해 진행률을 갱신하고, SUCCESS/COMPLETED면 완료, ERROR/FAILED면 실패로 종료합니다(AbortSignal로 취소 가능).
  5. 결과 표시·다운로드완료된 배너들을 ResultArea에서 카드로 보여주고, 선택 항목을 postDownloadImages로 ZIP(blob) 다운로드하거나 개별 이미지를 삭제합니다.

인증 · 세션 흐름

  1. 전역 가드라우터 진입 시 로그인 사용자가 없으면 /login으로 리다이렉트하고, 기본 진입은 분석 이력 화면으로 보냅니다.
  2. 토큰 주입axios 요청 인터셉터가 sessionStorage의 액세스 토큰을 Bearer 헤더로 자동 주입합니다.
  3. 만료 처리응답 resultCode가 4010/4011이면 토큰 재발급(reissueToken) 후 원요청을 재시도하고, 재발급 실패 시 세션 만료로 로그인 화면으로 이동합니다.

빌드 · 실행

package.json 스크립트와 user/vite.config.user.js에 근거한 명령입니다. 현재 작업 디렉토리에서 실제로 동작하는 구성은 user 앱입니다.

# 1. 의존성 설치
npm install

# 2. user 앱 개발 서버 (host 0.0.0.0, 포트 4013)
npm run dev-user

# 3. user 앱 프로덕션 빌드 (dist/user 로 출력)
npm run build-user

# 4. 빌드 결과 미리보기 (포트 4173)
npm run preview-user

# 빌드 + 미리보기 한 번에
npm run build-preview-user

환경 설정. user/.env의 VITE_GENIE_POSTER_BASE_URL(현재 값 /api/magic/proxy/genie-poster)이 지니 포스터 프록시 API 베이스 경로입니다. 개발 서버 프록시는 user/vite.config.user.js에서 /auth·/api·/nms·/login을 http://121.129.58.89:83/(개발 백엔드, 추정)로 전달합니다. 루트 .env/.env.example에는 각종 LLM 제공자 API 키 항목이 있으나 프런트엔드 런타임이 아니라 보조 도구용으로 추정됩니다.

산출물. build-user 실행 시 dist/user에 정적 자산이 생성되며, 앱은 base: '/user/' 경로로 서빙됩니다.

동작하지 않는 스크립트
dev-home·build-home·dev-admin·build-admin·dev-login·build-login은 각 앱 폴더·설정 파일(home/vite.config.home.js 등)이 현재 디렉토리에 없어 그대로는 실행되지 않습니다.
