개요

이 저장소는 KT Magic 플랫폼의 AI 숏폼(지니 숏츠) 기능을 담당하는 Vue 3 단일 페이지 애플리케이션(SPA)입니다. 사용자가 원본 영상을 업로드하면 백엔드 Magic 엔진(/api/magic, /nms/magic)이 AI 분석을 거쳐 세로형 숏폼 영상을 자동 생성하고, 이 프런트엔드는 생성 요청, 진행 상태 조회, 결과 확인, 그리고 타임라인 기반 영상 편집과 재인코딩까지의 사용자 흐름을 화면으로 제공합니다.

콘텐츠 유형은 쇼핑, 영화드라마, 영화, 드라마, 예능, 뉴스로 구분됩니다(shortformContentValue.js의 CONTENT_TYPES). 유형에 따라 요약형, 테마형, 인물형, 예고편형, 클립형, 하이라이트형 등 숏폼 생성 방식을 선택할 수 있으며, 예컨대 쇼핑 콘텐츠의 테마형은 "상품소개·상품강점·활용법·시연" 네 가지 테마 구간을 추출해 숏츠를 만들고, 인물형은 특정 등장인물만 찾아 숏츠로 구성합니다.

대상 플랫폼은 데스크톱 웹 브라우저입니다. 업로드 시 Safari 쿠키 처리 분기(auth.js의 ensureSafariCookies)가 존재하는 점으로 보아 Chrome·Safari 등 주요 브라우저를 함께 고려한 것으로 보입니다(추정). 영상 미리보기는 Konva 캔버스로 렌더링하며, 자막·텍스트·로고·BGM·내레이션 등 요소를 타임라인 위에서 직접 편집합니다.

사업 맥락 — 협업 분담
사내 Confluence(ORGAPPDEV)에 따르면 본 과제는 KT의 AI 숏폼 고도화 사업의 일부로, AI 엔진은 KT, 백엔드 및 AI 엔진 연동은 어뮤즈랩(Amuze), 편집툴 고도화(UX·개발)는 알티미디어가 담당합니다. 1차에서 어뮤즈랩이 전체를 개발했고, 고도화 단계에서 사용성이 약했던 편집툴 부분을 알티미디어가 외주 개발하는 구조입니다. 본 저장소는 그 결과물에 해당하며, 커밋 이력의 amuze source update는 어뮤즈랩 측 소스 반영 흔적입니다.
현재 빌드 범위
루트 package.json은 home·admin·user·login 네 개의 빌드 타깃을 정의하지만, 이 저장소에는 실질 애플리케이션인 user/ 타깃만 소스로 포함되어 있습니다. home/·admin/·login/ 디렉토리와 해당 config는 이 저장소에 없어(별도 저장소이거나 미포함, 추정) 현재 상태로는 dev-user/build-user만 동작합니다. 또한 권한(roleId) 기반 admin↔user 라우팅 가드는 대부분 주석 처리되어 비활성 상태입니다.

주요 기능

AI 숏폼 자동 생성
원본 영상을 Magic 엔진에 보내 세로형 숏폼을 자동 생성합니다(aiShortformGenerationE2E). 콘텐츠 유형·생성 방식·클립 수·인물 수·영상 비율 등을 설정해 요청합니다.
콘텐츠 유형별 생성 방식
쇼핑·영화·드라마·예능·뉴스 등 유형별로 테마형·인물형·예고편형·클립형·하이라이트형 등 생성 방식을 선택합니다. 유형마다 영상 비율 목록과 생성 개수 제한이 다릅니다.
대용량 청크 업로드
tus-js-client 기반 TUS 프로토콜로 /api/magic/tus/upload/files에 100MB 단위 청크 업로드합니다. 이전 업로드 이어올리기(resume)를 지원합니다.
타임라인 영상 편집기
저장소에서 가장 비중이 큰 모듈입니다. 비디오·이미지·텍스트·자막·로고·BGM·내레이션 요소를 타임라인 위에서 배치·이동·리사이즈하며 편집합니다.
Konva 미리보기 캔버스
Konva + vue-konva로 편집 미리보기 레이어를 렌더링하고, vue3-draggable-resizable·interactjs로 요소를 드래그·리사이즈합니다.
텍스트·자막 편집
텍스트 박스 정렬, 화면 기준 정렬, 폰트·색상·라인하이트·박스 높이 등 자막/텍스트 스타일을 세밀하게 조정합니다(최근 커밋 다수가 텍스트·자막 박스 로직 개선).
BGM·내레이션 사운드
wavesurfer.js로 BGM·내레이션 파형을 표시하고, Typecast 음성 생성(voiceGenerationTypecast) 및 내레이션 샘플을 활용합니다.
스타일 템플릿
템플릿 탭(TemplateTab.vue)에서 로고·자막·팝업 스타일이 적용된 템플릿을 미리보기하고 적용합니다. 사용자 스타일 템플릿 추가도 지원합니다.
실행 취소·자동 저장·세션 복구
historyManager(undo/redo), autoSaveManager(자동 저장), sessionRecoveryManager(세션 복구), elementClipboardManager(요소 복사/붙여넣기) 컴포저블로 편집 안정성을 확보합니다.
단일/멀티 편집기 분기
진입 래퍼 ShortformHighlightEdit.vue가 jobId 유무로 멀티/팝업 편집기와 단일(Legacy) 편집기를 지연 로딩하고, 팝업 모드에서는 좌측 메뉴를 숨깁니다.
결과 확인·다운로드
생성 잡 결과를 폴링·표시하고 유형별로 그룹핑하며, 해시태그·설명 편집, 영상 다운로드, 편집기 진입을 제공합니다.
재인코딩 저장
편집 결과를 NMS에 저장(putEditParams)하고 aiShortformEncoding으로 재인코딩을 요청해 최종 숏폼 영상을 산출합니다.
대시보드·분석 이력
chart.js 기반 Bar/Doughnut 통계 대시보드와, 사용자·그룹별 숏폼 생성 잡 이력을 날짜·상태로 조회하는 분석 이력 화면을 제공합니다.
인증·세션 관리
axios 인터셉터가 Bearer 토큰을 주입하고 4010 시 토큰 재발급·재시도, 4011 시 로그인 페이지 이동을 처리합니다. 무활동 시 로그아웃되는 세션 타이머를 운용합니다.

아키텍처 · 모듈 구조

계층 · 외부 연동

프런트엔드는 개발 서버에서 vite.config.user.js의 프록시를 통해 https://amuzlab98.synology.me/로 /auth·/api·/nms·/login 요청을 전달합니다. /api/magic 계열은 어뮤즈랩이 연동한 KT AI 엔진의 잡 생성·결과 조회·인코딩을 담당하고, /nms/magic 계열은 편집 파라미터 저장·잡 이력·결과 상태·스트리밍을 담당합니다. /nms 프록시는 쿼리스트링의 token을 Authorization: Bearer 헤더로 변환하고 영상 스트리밍을 위해 Range 헤더를 전달합니다.

핵심 동작 흐름

숏폼 생성 → 편집 → 재인코딩 흐름

  1. 앱 진입 · 인증App.vue에서 authStore.login()으로 sessionStorage의 사용자/토큰을 검증합니다. 로그인 사용자가 없으면 /login으로 이동하고, 루트 접근 시 분석 이력 화면으로 보냅니다. 세션 타이머가 무활동을 감시합니다.
  2. 생성 설정ShortformHighlight.vue에서 콘텐츠 유형과 생성 방식(테마형·인물형·클립형 등), 클립 수·인물 수·영상 비율·로고·자막·BGM·인트로 등 파라미터를 설정합니다. 진행 중 작업이 있으면 분석 이력으로 이동을 안내합니다.
  3. 업로드upload 스토어가 tus 프로토콜로 /api/magic/tus/upload/files에 100MB 청크 단위로 영상을 올립니다. 이탈 시 이어올리기를 지원하며 진행률을 표시합니다.
  4. 생성 잡 요청generateRequest가 조립한 파라미터로 aiShortformGenerationE2E 잡을 요청합니다. 어뮤즈랩이 연동한 KT AI 엔진이 영상을 분석해 세로형 숏폼을 생성합니다.
  5. 결과 폴링·확인ShortformHighlightResult.vue가 getResult/getNmsResult로 잡 결과를 폴링·표시하고 유형별로 그룹핑합니다. 해시태그·설명 편집, 다운로드, 편집기 진입 버튼을 제공합니다.
  6. 타임라인 편집편집기 진입 래퍼가 jobId 유무로 Multi/Legacy 편집기를 로딩합니다. 비디오·텍스트·자막·로고·BGM·내레이션 요소를 타임라인에서 배치·편집하고, undo/redo·자동 저장·세션 복구로 작업을 보호합니다.
  7. 저장 · 재인코딩편집 결과를 putEditParams로 NMS에 저장하고 aiShortformEncoding으로 재인코딩을 요청해 최종 숏폼 영상을 산출합니다.

API 토큰 인터셉터 흐름

  1. 요청 인터셉터모든 요청에 Authorization: Bearer <token> 헤더를 주입합니다.
  2. 응답 코드 분기응답 resultCode가 4010이면 토큰을 재발급하고 원요청을 재시도하며, 4011이면 로그인 페이지로 이동시킵니다.
  3. 재시도axios-retry가 5xx·네트워크 오류에 대해 최대 2회까지 재시도합니다.

빌드 · 실행

빌드 명령은 루트 package.json의 scripts에 근거합니다. 이 저장소에 포함된 user 타깃 스크립트를 사용합니다.

# 1. 의존성 설치
npm install

# 2. user 개발 서버 실행 (Vite, --host 0.0.0.0, 포트 4013)
npm run dev-user

# 3. user 프로덕션 빌드 (출력: dist/user)
npm run build-user

# 빌드 결과 미리보기
npm run preview
  • 환경 설정 파일 — user/vite.config.user.js (base /user/, 포트 4013, @ 별칭 → user/src, /auth·/api·/nms·/login 프록시 → https://amuzlab98.synology.me/). 루트 vite.config.js는 plugin-vue만 설정된 기본 개발 서버용입니다.
  • 산출물 — dist/user/ 디렉토리에 정적 SPA 번들(HTML/JS/CSS)이 생성됩니다.
  • dev-home/build-home, dev-admin/build-admin, dev-login/build-login 스크립트도 정의되어 있으나, 대응하는 home/·admin/·login/ config 디렉토리가 이 저장소에 없어 현재 상태로는 실행되지 않습니다.
