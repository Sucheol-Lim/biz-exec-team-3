qrator 상위 컨트롤러

여러 서브앱(brk·sharpUi·각 트리거·shoppingKey·cuetoneAD)의 표시/숨김을 stateManager로 통제하는 본체입니다. 기본 활성 서브앱은 brk이며, 활성 앱 전환(currentApp)과 가시성(show / show.inactive / hide)을 관리하고 옵저버와의 postMessage 라우팅을 담당합니다.

기능 개요

qrator는 IIFE로 작성된 단일 전역 객체로, 방송 화면 위에 떠 동작하는 여러 서브앱을 하나의 위젯 프로세스 안에서 통제합니다. qrator.init()이 호출되면 셋톱 정보를 초기화(_initStbInfo)하고, _initSubApps()로 brk·sharpUi·bomChannelTrigger·bomVodTrigger·cmpChannelTrigger·shoppingKey·cuetoneAD를 차례로 subApps 맵에 등록하고 초기화합니다.

가시성 전환의 핵심은 stateManager입니다. 상태값은 init / show / show.inactive / hide 네 가지이며, show(appId, isVisible, isFakeActivate)는 _setCurrentApp(appId)로 활성 서브앱을 바꾸고 컨테이너 표시 여부를 정한 뒤 showAppAfterAddKeyEvent()를 통해 OwnerAppHandler.showApp()으로 단말의 키셋(keyset)과 입력 활성화를 갱신합니다. hide()는 결제 모듈을 정리하고 옵저버에 obs_notifyHide를 통보하며, 활성 앱을 다시 qrator로 되돌립니다.

키 입력은 가시 상태에 따라 두 경로로 갈립니다. 보일 때는 handleKeyWhileShown이, 숨겨졌을 때는 _handleKeyWhileHidden이 동작해 쇼핑키·위젯키·*키(VK_F11)·#키(VK_F12) 등을 해당 서브앱으로 분기(_bypassToSubAppWithKeyEvent)합니다. 외부 옵저버/홈포탈 메시지는 postMessage.listener가 받아 메서드별로 적절한 서브앱에 전달합니다.

show.inactive(fake show) 상태
트리거가 단말을 가리지 않고 BOM 앱만 백그라운드로 띄우는 경우를 위해 showFake()가 존재합니다. 이때 상태는 show.inactive가 되고 활성 앱은 fake로 표시되어, 화면을 점유하지 않으면서도 키 입력만 받을 수 있습니다.

흐름. init에서 서브앱을 모두 등록하고 옵저버에 app_ready를 보낸 뒤, 옵저버 메시지나 키 입력에 따라 show/hide로 활성 서브앱과 가시성을 전환합니다. 표시 시 OwnerAppHandler가 단말 키셋과 입력 포커스를 함께 갱신합니다.

클래스 다이어그램

classDiagram class qrator { +init() +show(appId, isVisible, isFakeActivate) +showFake(appId) +hide(appId, isVisible, isKeepState) +setCurrentApp(appName) +getCurrentApp() +sendPostMessage(from, to, message, cb) } class stateManager { -state -visibility +init() +show() +showFake() +hide() +setVisibilty(isVisible) +changeToShow() +changeToShowInactive() +changeToHide() } class postMessage { -fromApp -callbacks +send(from, to, message, cb) +listener(event) +sendAppReady() +sendNotifyHide() } class OwnerAppHandler { +showApp(appId, keyEventListener) +hideApp(keyEventListener) +createTvPayModule() +setKeyset(subApp) } class OwnerAppProxy { +show() +hide(flag) +activateInput(gainFocus, keyPri, uiPri) +setValueWithKeyset(type, value, at) } class subApps { +brk +sharpUi +bomChannelTrigger +bomVodTrigger +cmpChannelTrigger +shoppingKey +cuetoneAD } qrator *-- stateManager : 소유 qrator *-- postMessage : 소유 qrator --> OwnerAppHandler : 키셋/표시 위임 OwnerAppHandler *-- OwnerAppProxy : 소유 stateManager --> subApps : show/hide 전파 postMessage --> subApps : qMessage 라우팅

관계. 전역 qrator가 내부에 stateManager·postMessage를 두고, 단말 키셋/표시 제어는 OwnerAppHandler(내부 OwnerAppProxy)에 위임합니다. subApps 맵을 통해 각 서브앱으로 키/메시지를 분기합니다.

핵심 코드

qrator/js/main.js — stateManager.show: 활성 앱 전환과 키 등록
show: function (appId, isVisible, isFakeActivate) {
    if (stateManager.isShow() && currentApp === appId) {
        return false;                       // 이미 같은 앱이 show 중이면 무시
    }

    _setCurrentApp(appId);

    if (stateManager.isNotShow() && isFakeActivate) {
        stateManager.changeToShowInactive(); // 화면 미점유(fake) 표시
    } else {
        stateManager.changeToShow();
    }

    stateManager.setVisibilty(isVisible);   // #container show/hide
    stateManager.showAppAfterAddKeyEvent(appId, isFakeActivate);
},
qrator/js/main.js — _initSubApps: 서브앱 등록 (기본 hide)
subApps[ConstAppName.brk] = brk;
subApps[ConstAppName.brk].init(true, stbInfo, $("#brk_container")[0]);
