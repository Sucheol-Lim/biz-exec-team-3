개요

이 프로젝트는 KT olleh tv 웹 미들웨어 환경에서 구동되는 BOM(Brokering Open Market) 언바운드(unbound) 웹 애플리케이션입니다. package.json의 description은 "bom(qrator, widget ui, brokering) unbound, web application"으로 명시되어 있으며, 단말 위젯 패키지인 .wgt 형태로 빌드되어 셋톱박스에 배포됩니다. public/src/index.html의 저작권 헤더에는 "BOM(Brokering Open Market) System version 1.0 / Copyright kt corp"가 명시되어 있습니다.

앱의 매니페스트(public/src/config.xml)는 W3C Widget 규격(http://www.w3.org/ns/widgets)을 따르며, 위젯 id는 dvb.appId:4e30.3009, 이름은 "Smart AppStore", 설명은 "olleh tv Web Middleware Smart AppStore", 해상도는 1920×1080, 버전은 2.6.4로 정의되어 있습니다. 즉 KT olleh tv의 스마트 앱스토어/브로커링 진입 위젯에 해당합니다.

대상 플랫폼은 OIPF/HbbTV 계열의 웹 미들웨어를 탑재한 KT olleh tv 셋톱박스(STB)입니다. index.html에 <object type="video/broadcast"> 방송 객체와 OIPF 단말 API 래퍼(oipfUtil.js)가 포함되어 있어, 방송 스트림 위에 오버레이로 떠 동작하는 TV 단말 웹 앱임을 알 수 있습니다. 사내 Confluence 기준 BOM 언바운드는 Web(본 저장소, UHD/AOSP/ATV/Smart 형상)과 ACAP(별도 저장소) 두 형상으로 나뉘며, 본 문서는 그중 Web 형상을 다룹니다.

언바운드(unbound) 앱이란
특정 채널(bound)에 종속되지 않고 단말 전역에서 동작하는 애플리케이션을 의미합니다. 본 앱은 APP_TYPE.UNBOUND(4) 타입으로, 옵저버(observer)·홈포탈 같은 외부 단말 컴포넌트와 비동기 메시지로 협의하며 방송 화면 위에 위젯/트리거 UI를 표시·종료합니다.

주요 기능

qrator 상위 컨트롤러
여러 서브앱의 표시/숨김 상태를 stateManager(init / show / show.inactive / hide)로 관리하는 본체입니다. 기본 활성 서브앱은 brk이며, 활성 서브앱 전환과 가시성을 통제합니다.
Brokering 위젯 UI (brk)
BOM 서버와 연동해 위젯 상품 목록/상세를 표시하는 핵심 UI입니다. brk_api, brk_amoc, brk_itemList, brk_detailList, brk_oipf, brk_liveAgent 컴포넌트로 구성됩니다.
샤프(#)키 처리 (sharp)
리모컨 # 키로 실행 가능한 BOM 앱을 선택하는 sharp UI입니다. 채널뷰(chview), 비밀번호(pwd), 아람(aram), 서비스 에러 팝업을 제공합니다.
BOM 채널 트리거
특정 채널 시청 시 노출되는 채널 연동형 BOM 캠페인 트리거입니다. 시청 시간(watchingTime)·노출 시간대(display_time) 조건과 바운드/언바운드 앱 실행 상태를 확인해 표시합니다.
BOM VOD 트리거
VOD 재생 시작 시점에 노출되는 VOD 연동형 BOM 캠페인 트리거입니다. 트리거 블록 상태가 아닐 때 동작합니다.
CMP(캠페인) 채널 트리거
스케줄 푸시 기반 캠페인 편성정보 트리거입니다. 알림형(REACT_TYPE=1)과 반응형으로 나뉘며, 다른 앱 실행 시 노출 방식(EXEC_TYPE)에 따라 분기 처리됩니다.
큐톤(Cue-tone) 광고 트리거
방송 큐톤 광고 메시지 수신 시 광고 연동 트리거를 노출합니다. BOM 서버의 getCuetoneCmpInfo(BW016) 응답으로 캠페인 정보를 받아 처리합니다.
쇼핑키 / 결제 연동
리모컨 쇼핑키 입력 시 결제 모듈(tvpay)을 연동하는 서브앱입니다. payModuleView로 TV 결제 라우터(tvpay_module)와 연결됩니다.
요청-응답 메시지 라우터
메서드별 큐·인플라이트·타임아웃(기본 5000ms)을 가진 비동기 메시지 라우터입니다. 옵저버/홈포탈 등 외부 컴포넌트와의 메시지 교환을 직렬화합니다.
qDaemon 백그라운드 매니저
시나리오 관리를 위한 내부 매니저 묶음입니다. 채널 트리거(chTriggerManager), 스토리지 데이터(storageDataManager), 라이브 에이전트(liveAgentManager)를 관리합니다.
동적 서브앱 로딩(부트스트랩)
app-manifest의 선언을 loader가 순차 로드한 뒤 qrator.init()으로 기동하는 부트스트랩 구조입니다. 모듈 번들러 없이 클래식 스크립트로 동작합니다.
링크 타입별 실행 분기
link_type에 따라 BOM 앱 실행(1)·채널 이동(2/8)·매시업(4)·홈포탈 VOD/카테고리/시리즈(5/6/7)·위젯 재시작(11)·안드로이드 네이티브/브로드캐스트 인텐트(21/22) 등으로 분기합니다.
서비스 미지원 단말 안내
미지원(ACAP 등) 단말에서 전체 화면 안내 이미지를 표시합니다. 원격 이미지 서버를 우선 시도하고, 네트워크 오류나 https 미지원 시 로컬 리소스로 대체합니다.
3-프로파일 빌드/배포 파이프라인
Gulp 기반으로 L(운영)/S(BMT)/D(개발) 3종 프로파일을 빌드해 .wgt로 패키징하고, 빌드 환경값(build-env.js) 주입 후 FTP로 일괄 업로드합니다.

아키텍처 · 모듈 구조

계층 · 외부 연동

구조는 (1) 공통 코어/유틸 계층(common/js), (2) 상위 컨트롤러 계층(qrator), (3) 서브앱 계층(apps/*)으로 나뉩니다. 외부 연동은 크게 두 갈래입니다. 하나는 단말 내부 컴포넌트와의 postMessage 기반 비동기 메시지(옵저버 4e30.3000, 홈포탈 4e30.3001, 매시업 매니저 4e30.3020)이고, 다른 하나는 BOM 서버군과의 HTTP 연동입니다. 빌드 프로파일별 엔드포인트는 config-*.json에 정의되며, 운영(L) 기준으로 e7works(mapi.bom.kt.com/unbound), sharp_ui(mapi.bom.kt.com/sharpui), live_agent(agent.bom.kt.com), cache/image(img.bom.kt.com), tvpay_module(paygate.tvhub.co.kr)로 연결됩니다.

핵심 동작 흐름

1) 앱 부팅 시퀀스

  1. index.html 로드방송 <object type="video/broadcast">와 라이브러리(jQuery·Underscore·Backbone·CryptoJS·keyEvent), 공통 유틸·코어 스크립트를 순서대로 로드합니다.
  2. 매니페스트 기반 동적 로딩app-manifest가 선언한 서브앱 스크립트 트리를 loader.loadAppScripts(...)가 순차적으로 로드합니다.
  3. qrator.init() 기동document ready 후 bootstrap이 qrator.init()을 호출합니다. 상태를 init으로 두고 storageDataManager·chTriggerManager 등 매니저를 초기화합니다.
  4. 기본 서브앱 표시stateManager가 기본 활성 서브앱 brk를 show 상태로 전환하고 키 이벤트를 등록해 사용자 입력을 받기 시작합니다.

2) 채널 트리거 표시 흐름 (Web, Confluence 시나리오 기준)

  1. 채널 이동 성공 감지onChannelChangeSucceeded 콜백으로 채널 이동을 감지하고, 동일 채널 재튜닝이 아닌 경우에만 캠페인 표시 처리를 시작합니다.
  2. 기존 트리거 종료 + 캠페인 시작진행 중인 vod/bom/cmp 트리거를 종료한 뒤 현재 채널 캠페인 처리를 시작합니다.
  3. 노출 조건 평가하루 보지 않기 설정, 채널 sid 매칭, 노출 스케줄(DISP_TIME/display_time), 시청 시간(watchingTime), 사용자 동의·패키지 코드 등 조건을 확인합니다.
  4. 반응 타입(REACT_TYPE) 분기반응 항목이 있으면 캠페인 조건(플랫폼/가입상품/마케팅 동의/관심지수 등) 체크 후 CMP 트리거를, 없으면 BOM 트리거를 표시합니다.
  5. iframe/앱 상태에 따른 최종 표시미디어 재생 시간(getMediaTime())으로 iframe 노출 여부를 판단하고, 바운드/언바운드 앱 실행 상태와 obs_requestShow 응답에 따라 표시하거나 종료합니다.

3) 큐톤 광고 트리거 처리 흐름

  1. 큐톤 메시지 수신방송 Cue-tone 광고 메시지를 수신하면 큐톤 광고 트리거 처리를 시작합니다.
  2. BOM 서버 조회getCuetoneCmpInfo(BW016)로 stbType(WEBAPP=2)·serviceType(OTV/OTS) 등을 담아 캠페인 정보를 요청합니다.
  3. 라우터를 통한 직렬화요청-응답 라우터가 메서드 큐로 요청을 직렬화하고, 5000ms 타임아웃 내 응답을 처리합니다.
  4. 트리거 표시 및 충돌 처리수신한 캠페인으로 광고 트리거를 노출합니다. 실행 중 채널 트리거 요청이 오면 큐톤 트리거를 제거 후 채널 트리거로 전환합니다.

빌드 · 실행

빌드는 gulpfile.js에 등록된 task 이름을 기준으로 합니다. 산출물은 단말 위젯 패키지 .wgt(zip) 형태이며, 빌드 타임에 public/dist/common/js/core/build-env.js로 런타임 환경값(serverTo, endpoints, versions, generatedAt)이 주입됩니다.

1. 설치 · 환경 설정

npm i
cp .env.example .env   # FTP/로컬경로/릴리스 메타 입력 (.env는 커밋 제외)

.env 주요 항목은 FTP_HOST/USER/PASS/REMOTE_PATH(기본 원격 경로 /home/01_kt-web-bomunbound/), RELEASE_PATH/WORKING_PATH, RELEASE_VER/RELEASE_BRK_VER/RELEASE_TEST_TO입니다. 프로파일 엔드포인트는 config/config-live.json·config-bmt.json·config-develop.json 3개가 필요하며 키는 e7works, sharp_ui, live_agent, cache, image, tvpay_module입니다.

2. 프로파일별 dist 빌드

gulp dist:live      # L (운영)
gulp dist:bmt       # S (BMT)
gulp dist:develop   # D (개발)

distPipeline은 setTarget → cleanFiles → uglifyJs → copyCommonFiles → copyResFiles → createBuildEnv → verifyDistBuildEnv 순으로 동작합니다.

3. 패키징 (.wgt 생성, 업로드 없음)

gulp package:live
gulp package:bmt
gulp package:develop

packagePipeline은 dist 빌드 후 makeReleaseRule → createWgt → recordArtifact로 .wgt를 만들고 아티팩트를 기록합니다.

4. 릴리스 (패키지 + FTP 업로드)

gulp release:live | release:bmt | release:develop   # 개별 업로드
gulp release:all                                    # L/S/D 일괄 빌드 후 한 번에 업로드
gulp release:all --ver 3.9.01 --brkV 3.9.02 --date 20250905 --testTo K2  # CLI 인자가 .env보다 우선

release:all은 resetArtifacts → package:live → package:bmt → package:develop → deployAll 순으로 3개 .wgt를 모아 일괄 업로드합니다. 산출물 파일명 패턴은 KT-BRK-QRATOR-WEB-V<버전>_<YYYYMMDD>_<testTo>_<serverTo>.wgt, FTP 경로는 <FTP_REMOTE_PATH>/<YYYYMMDD>_V<버전>/입니다.

5. 로컬 미리보기 · 테스트

gulp server     # browser-sync로 public/dist 서빙 (먼저 gulp dist:* 필요)
npm run tt      # mocha (public/test/**, timeout 30s)
README와 task 이름 차이
기존 README의 gulp default·gulp package_live·gulp release_all 표기는 현재 gulpfile.js의 실제 task 이름(dist:*, package:*, release:*)과 다릅니다. 실행 시에는 위 colon(:) 표기를 사용해야 합니다. 또한 package.json의 기본 test 스크립트는 미설정(exit 1) 상태이며 실제 테스트는 tt로 실행합니다.
