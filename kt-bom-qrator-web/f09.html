요청-응답 메시지 라우터

메서드별 큐(_queues)·인플라이트(_inflight)·타임아웃(기본 5000ms)을 가진 비동기 메시지 라우터입니다. 옵저버/홈포탈 같은 외부 컴포넌트와의 postMessage 요청-응답을 메서드 단위로 직렬화해 응답 누락·경합을 방지합니다.

기능 개요

RequestReplyRouter는 IIFE 싱글턴으로, postMessage가 본질적으로 "보내고 잊는" 단방향이라는 한계를 메서드별 요청-응답 큐로 보완합니다. 사용 전 register(method)로 허용 메서드를 등록하고, setTransport(fn)으로 실제 전송 경로(qrator의 postMessage.send)를 주입합니다. qrator._initPostMessage가 기동 시 OBS_REQUEST_SHOW·OBS_IS_LOADING_UNBOUND_APP 두 메서드를 등록합니다.

요청은 sendSerial(opts)로 등록합니다. 같은 메서드의 요청은 _queues[method]에 쌓이고, _startNext가 인플라이트가 비어 있을 때만 큐 맨 앞 항목을 꺼내 전송합니다. 전송과 동시에 _scheduleTimeout이 TTL(기본 5000ms) 타이머를 걸어, 응답이 오지 않으면 onTimeout을 호출하고 큐를 진행시킵니다. 즉 한 메서드는 동시에 하나의 in-flight 요청만 갖습니다.

응답 소비는 handleResponse(event)가 담당합니다. 들어온 메시지의 method가 등록·인플라이트 상태면 현재 항목의 onReply(msg)를 호출하고 큐를 한 칸 진행한 뒤 true(소비 완료)를 반환합니다. qrator.postMessage.listener는 이 반환값을 보고 소비된 메시지는 더 이상 일반 분기로 넘기지 않습니다. CMP 채널 트리거(f06)가 옵저버 표시/조회 요청에 이 라우터를 직접 사용합니다.

왜 직렬화가 필요한가
여러 서브앱이 동시에 옵저버에 obs_requestShow를 보내면 응답이 뒤섞일 수 있습니다. 메서드별 단일 in-flight 보장으로 "어느 요청의 응답인지"가 항상 명확해지고, 타임아웃이 무응답 상황에서 큐가 멈추지 않도록 보호합니다.

시퀀스 다이어그램

sequenceDiagram autonumber participant APP as 서브앱 (예: cmpChannelTrigger) participant RRR as RequestReplyRouter participant TR as transport (postMessage.send) participant OBS as Observer participant LIS as postMessage.listener APP->>RRR: sendSerial({method, payload, onReply, onTimeout}) RRR->>RRR: _queues[method].push(item) RRR->>RRR: _startNext() (인플라이트 비어있으면) RRR->>RRR: _scheduleTimeout(5000ms) RRR->>TR: _transportSend(from, to, payload) TR->>OBS: postMessage OBS-->>LIS: 응답 메시지 LIS->>RRR: handleResponse(event) alt 등록 + 인플라이트 RRR->>APP: item.onReply(msg) RRR->>RRR: _finishCurrent() → _startNext() RRR-->>LIS: true (소비 완료) else 타임아웃 발생 RRR->>APP: item.onTimeout() RRR->>RRR: _shift / _startNext() end

흐름. sendSerial로 큐에 적재 → in-flight가 비면 transport로 전송하고 타임아웃을 건다. 응답이 오면 handleResponse가 onReply를 호출하고 다음 항목을 진행하며, 무응답이면 타임아웃이 큐를 해소합니다.

클래스 다이어그램

classDiagram class RequestReplyRouter { -_allowed -_queues -_inflight -_timers -_transportSend +register(method) +unregister(method) +setTransport(fn) +sendSerial(opts) +handleResponse(event) bool } class QueueItem { +from +to +payload +onReply +onTimeout +ttlMs } class qrator_postMessage { +send(from, to, message, cb) +listener(event) } RequestReplyRouter o-- QueueItem : _queues per method qrator_postMessage --> RequestReplyRouter : setTransport / handleResponse RequestReplyRouter --> qrator_postMessage : _transportSend 콜백

관계. RequestReplyRouter는 메서드별로 QueueItem 큐를 보관합니다. 전송은 qrator의 postMessage.send를 transport로 주입받아 수행하고, 수신 측 listener가 handleResponse로 응답을 소비합니다.

핵심 코드

qrator/js/request-reply-router.js — sendSerial / _scheduleTimeout
function sendSerial(opts) {
    if (!opts || !_allowed[opts.method]) return;       // 미등록 메서드는 무시
    _ensure(opts.method);
    _queues[opts.method].push({
        from: opts.from, to: opts.to, payload: opts.payload,
        onReply: opts.onReply, onTimeout: opts.onTimeout, ttlMs: opts.ttlMs
    });
    _startNext(opts.method);                           // 인플라이트 없으면 즉시 전송
}

function _scheduleTimeout(method, item) {
    var ttl = item.ttlMs > 0 ? item.ttlMs : DEFAULT_TIMEOUT;   // 기본 5000ms
    _clearTimer(method);
    _timers[method] = setTimeout(function onTimeout() {
        _clearTimer(method);
        if (typeof item.onTimeout === 'function') item.onTimeout();
        _shift(method); _endInflight(method); _startNext(method);
    }, ttl);
}
qrator/js/request-reply-router.js — handleResponse: 등록+인플라이트 응답만 소비
function handleResponse(event) {
    var msg = event && event.data;
    if (!msg || !_allowed[msg.method]) return false;
    var method = msg.method;
    _ensure(method);
    if (!_isInflight(method)) return false;
    var item = _peek(method);
    if (!item) return false;

    _finishCurrent(method, function () {
        if (typeof item.onReply === 'function') item.onReply(msg);
    });
    return true;   // 소비 완료 → 상위로 더 넘기지 않음
}
