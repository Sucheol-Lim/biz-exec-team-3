쇼핑키 / 결제 연동

리모컨 쇼핑키 입력 시 현재 채널/VOD 상태에 맞는 링크 데이터를 골라 BOM 앱 실행·채널 이동, 또는 TV 결제 모듈(tvpay)을 띄우는 서브앱입니다. 결제 라우터(BOM-ROUTER)는 qrator가 자식 애플리케이션으로 생성·표시합니다.

기능 개요

쇼핑키 입력은 위젯이 보이든 숨겨졌든 qrator가 가로채 shoppingKey.keyEventListener(event)로 전달합니다. 핸들러는 현재 채널 타입(oipfUtil.getChannelType)을 먼저 확인합니다. 일반 영상 채널이면 옵저버에 isLoadingUnboundApplication으로 유튜브 등 다른 앱 실행 여부를, 이어 홈포탈에 getCurrentVODInfo로 VOD 재생 여부를 확인한 뒤 적절한 링크 데이터를 고릅니다. 데이터 채널은 "DATA", 그 외는 "DEFAULT" 링크를 사용합니다.

선택된 링크는 runShoppingApp(linkData, contentId)에서 link_type으로 분기합니다. 1이면 qrt_runBrokeringApp 메시지로 BOM 앱을 실행(req_cd: 'SHOP'), 8이면 triplet 파싱 후 brk.linkTypeConverter로 채널 이동, 10이면 qrator.createTvPayModule()로 TV 결제 모듈을 호출합니다. 링크 데이터 자체는 shoppingKeyModel이 관리합니다.

결제 모듈은 qrator가 직접 생성합니다. createTvPayModule()은 로딩바를 띄우고 옵저버에 obs_requestShow를 보낸 뒤, 승인되면 OwnerAppHandler.createTvPayModule()로 TVPAY_MODULE URL(단말 SAID·서비스 ID·모델·펌웨어 쿼리 포함)에 자식 애플리케이션을 만들어 표시합니다. 로드 완료 시 liveAgentManager.tvpayModuleStartLog로 노출 로그를 남기고 로딩바를 닫습니다.

payModuleView.js 비어 있음
매니페스트가 가리킨 apps/shoppingKey/js/view/payModuleView.js는 현재 빈 파일입니다. 실제 결제 모듈 생성/표시 로직은 qrator/js/main.js의 createTvPayModule/OwnerAppHandler.createTvPayModule에 구현되어 있어, 본 문서는 그 구현을 근거로 작성했습니다.

시퀀스 다이어그램

sequenceDiagram autonumber participant U as 사용자/리모컨 participant Q as qrator participant SK as shoppingKey participant HP as 홈포탈/옵저버 participant BRK as brk participant PAY as TVPAY 결제모듈 U->>Q: 쇼핑키(keyCode.SHOPPING) Q->>SK: keyEventListener(event) SK->>HP: isLoadingUnboundApplication() HP-->>SK: res / args SK->>HP: getCurrentVODInfo() HP-->>SK: VOD 재생 상태 SK->>SK: runShoppingApp(linkData, contentId) alt link_type = 1 SK->>BRK: qrt_runBrokeringApp (req_cd=SHOP) else link_type = 8 SK->>BRK: linkTypeConverter(8, params) else link_type = 10 SK->>Q: createTvPayModule() Q->>HP: obs_requestShow HP-->>Q: yes Q->>PAY: createApplication(TVPAY_MODULE url) PAY-->>U: 결제 화면 end

흐름. 쇼핑키 → 채널/VOD/유튜브 상태 조회 → 링크 데이터 선택. link_type에 따라 BOM 앱 실행·채널 이동·결제 모듈 호출로 갈리며, 결제는 qrator가 옵저버 승인 후 자식 앱으로 띄웁니다.

클래스 다이어그램

classDiagram class shoppingKey { -callback +init() +keyEventListener(event) +qMessage(event) } class shoppingKeyModel { +checkShopKeyData() +getLinkData(fromApp, tunerType, sid) } class qrator { +createTvPayModule() +destroyTvPayModule() +setCurrentApp(appName) } class OwnerAppHandler { +createTvPayModule() } class liveAgentManager { +tvpayModuleStartLog(bomSaId, contentId) } class brk { +qMessage(event) +linkTypeConverter(linkType, datas, options) } shoppingKey o-- shoppingKeyModel : 링크 데이터 shoppingKey --> brk : BOM앱/채널 실행 shoppingKey --> qrator : 결제 모듈 호출 qrator --> OwnerAppHandler : 자식 앱 생성 qrator --> liveAgentManager : 결제 노출 로그

관계. shoppingKey가 shoppingKeyModel에서 링크 데이터를 받아 brk(BOM앱/채널) 또는 qrator(결제)로 분기합니다. 결제 모듈은 qrator가 OwnerAppHandler로 생성하고 liveAgentManager로 노출 로그를 남깁니다.

핵심 코드

apps/shoppingKey/js/main.js — runShoppingApp: link_type 분기
switch (linkData.link_type) {
    case 1 :   // BOM앱 실행
        brk.qMessage({ data: {
            method: 'qrt_runBrokeringApp',
            app_id: linkData.link_param1, scene_id: linkData.link_param2,
            addition_id: linkData.link_param3, req_cd: 'SHOP', content_id: contentId
        }});
        break;
    case 8:    // 채널이동 (triplet 파싱 후)
        brk.linkTypeConverter(linkData.link_type,
            [linkData.link_param1, linkData.link_param2,
             linkData.link_param3, linkData.link_param4],
            { fromApp: "SHOP", content_id: contentId });
        break;
    case 10:   // TV페이 모듈 호출
        qrator.createTvPayModule();
        break;
}
qrator/js/main.js — OwnerAppHandler.createTvPayModule: 결제 라우터 URL 생성
this.createTvPayModule = function () {
    const url = commonProperty.TVPAY_MODULE + "?termId=" + stbInfo.SAID
        + "&serviceId=" + oipfUtil.getChannelLoctor(oipfUtil.getActualChannel())
        + "&termModel=" + stbInfo.stbModelName + "&fwVersion=" + stbInfo.firmwareVersion;
    return ownerAppProxy.createApplication(url, true);   // 자식 애플리케이션 생성
};
